以下、ログから抽出したツール関連の話題です。モデル（NAI、illustrious、FLUX、Wan、Qwen-Image、anima、Z-Image、LTX）に関する話題は除外しています。ただしQwenシリーズのうち画像生成以外（ツール・エージェント・LLM等）の話題は含めています。

## MMD
- 1ミリも使い方がわからないままMMDでモデルをぬるぬる踊らせることができた。下地の知識があれば自分で改良できるが、少し直すレベルでもトークンを消費してcodexにやってもらう必要がある（228）

## ComfyUI（comfy）
- minimaxの画像参照は便利だが、静止画モデルでも使おうとしたらWF（ワークフロー）がややこしすぎる（243）
- Claude codeにKrea2のlora作りを手伝わせていたら、comfyuiがどういうものか理解しているので手伝えませんと言われた。二次絵ならいくらでも手伝えるとのこと（250）
- 長時間連続生成していると画面がブラックアウトして「デバイスに問題が発生したため再起動します」となる事象があり、ComfyUI側の要因の可能性も示唆されている（399, 403）
- ComfyUIの実行中にブルースクリーンが発生する場合はGPUのVRAM不足、高負荷によるドライバクラッシュ、熱暴走、電源不具合が主因（409）

## Codex
- Codexはデフォルトでは書き込み権限はサンドボックス内だが、読み取り権限は「PC内ほぼ全て可能」な状態。VSCodeで使う分はリスク低だがComputer Useだとリスクが高まる（270）
- codexに作らせているが、自分でちょっと勉強したらすぐできる作業だったかもしれないと感じている。トークンと時間をかけたことに後で気づく日が来るかもしれない（292）
- Codexにいじらせたせいでギップルするとぶっ壊れるようになった（293）
- いちいちトークンを消費させるより、まっさら状態で環境を新しく作らせて速やかに前環境を再構築できるような引き継ぎの工夫を入れたほうがいい（302）

## Claude code
- Claude codeにKrea2のlora作りを手伝わせていたら勝手に画像を見られて勝手にキレられた。実写系はAIに手伝わせたらだめ。25歳ぐらいのつもりが未成年判定された（245）

## ChatGPT
- ChatGPTのProプランに500ドルが追加されるとの噂、月70000の時代へ（327）
- ChatGPT特有のザラザラ感があり、スケールアップに通せば多少マシになる。GPTで顔だけ参照用として作らせたほうが便利で細かい修正もきく（369, 376）
- 汎用のローカルエージェントで対話サポートを受けながら画像生成を作れるようになった。企業サービスの相談みたいな要望に対して分類をAI側に提案させると自分が知らない路線も作りやすい（377）

## minimax
- minimaxの画像参照は便利（243）
- minimax h3 ref2va 1f Lora学習の考察：minimaxのLoraは画像・人物・背景・モーション全てに影響する。ref2vaで使う参照画像との相性は超重要で学習素材と近いほど効果が高い。Loraと参照画像の相性が良くても動画の動きが重くなりがち。学習は最初はref2vaの1f学習jsonl方式がお勧めで作業内容が一番単純（249）
- ref2vaで使う参照画像とLoraで使った学習画像に差があると効果が大暴れして逆に悪化する。学習設定と動画生成プロンプトをテキストで同じ場所に置いた（316）

## Extender
- Extenderで、Clip毎にValidatedすると次のClipでは参照画像を変えてもいい。論理的にはClip1毎に最大9個だが動画全体では無限に参照画像を使える。試しに画像18個使ってClip6個の動画を作ったが問題なく出来た（370）
- Extenderは毎回繋げたのを出すがめんどいので、そのクリップだけ確認して後から繋げることはできないか（379）

## 画像ビューワ（>>195関連）
- 右クリ↓で閉じる機能が便利で自炊本をまた読むようになりアナログ模写も捗った（277）
- 画像に吹き出しと縦書き台詞を付けられる機能をきぼんぬ（296）
- フォントと色と輪郭を選んで縦書き横書き指定して入れたら、確定前にホイールでサイズをいじれたりするとええね（300）
- タグ機能まであり、複数選択からのタグ付けも便利。素材管理にも使えそう。タグデータはEXIF内にあるのか？（395）
- ソース公開しているのでChatGPTで勝手に機能追加して使ってくれて全然ええで（364）

## Krea2（ツールとしての使用感・ノード等）
- Krea2はclothes lift, skirt lift, panties pullのトリプルコンボは無理だった。danbooru語は効かないから自然文。複数のエロモデルとエロLoRAを試したがダメだった（278）
- 半脱ぎ状態をきっちり自然言語で自動キャプショニングしてくれるLLMはたぶんない。DanbooruTaggerだとそのまま出るのでエロやるならDanbooru履修してくれてるほうがいい（291）
- Krea2はエロ表現なら部族語しか理解できないほうが上だが、動画素材として使うなら圧倒的背景力のKrea2を使いたくなる（325）
- grokにkrea2用のワイルドカードを作らせればいい（334）
- Krea2はプロンプトが複雑に絡み合っていてポーズの一部分だけ修正が上手くいかない。直そうとした一語で他の細かい部分が変わる。ポーズガチャで当てることもできない（363）
- Krea2は検閲解除できるがloraもノードも入れると画像の質感が全く変わって元の良さがなくなる。プラスチックみたいな質感が酷くなる（373）
- Krea2のスライダーは結構優秀。デカさ系はプロンプトで細かいニュアンスを伝えるよりsliderで数値でいじったほうが確実（385, 387）
- Krea2はアニメ調ならバイパスするだけで簡単にデカくなるが実写系はエンハンスかけてもなかなかデカくならない（389）
- KJnodeのKrea2 Prompt weightを入れてprompt強調が効くようにしている（408）

- LoRA素材でソシャゲのカードを使いロゴやアイコンを消す編集をQIE2511とQI2.1で両方やった。QIE2511は2割ぐらい変な絵だったがQI2.1は500枚をバッチでぶん回して変な絵0枚ですごい（320）

## 量子化（W6A8）
- W6A8という変態的な量子化が来ている。INT8の2割減のモデルサイズでW4A8より誤差3分の1で実行速度も5090だと速くなる（INT8よりは遅くなる）（418）
- モデルが小さい＝速いではない。4bit以下で無理やり量子化するより6bitや8bitの方が変換処理をスキップできて速い。4bit直接処理できるGPUは家庭用だとRTX50だけ（421）
- RTX 50はINT4非対応でFP4対応だからNVFP4は速いがINT4(W4A4)やW4A8は遅い。RTX 2040はFP4非対応でINT4対応だからNVFP4は遅いがINT4(W4A4)やW4A8は速い（423）

## ハードウェア・環境（ツール実行環境として）
- 工房5090の最安を買ってガワは手放そうと思ったがエージェント用のスーパークリーンPCとして活用している。ストレージ盛っておけばよかった（287）
- 3060から5070Tiに変更でグラボ以外そのままでやったらファン能力が根本的に足らなくて排熱が追いついていない。静止画は余裕だが動画で連続生成すると落ちる（422）
- Lora作成Jobをいくつもぶち込んで10時間くらい学習させっぱなし（GPUほぼ常時フルロード、熱風吹き出す）でも特に落ちない（417）
- 長時間連続生成でのブラックアウトについて、電源交換をまず試すべき。電源はメーカー保証が残っているかもしれない（414）
- GPUのPLを強めに入れても落ちるならソフト・OS・器材・半導体側の可能性。安定するなら電源や排熱の問題（416）
- うちの場合は何もせずにしばらく放置して思い出したように生成すると突然クラッシュする。GPU出力は70%に制限していて温度も上がらない（426）
