**抽出されたツール関連話題（モデル関連は除外）**

### ComfyUI（comfy）関連
- **導入・移行のタイミングと理由**
  - Anima登場時やMiniMax H3（特にH3）が出た頃がComfyUI移行の良いタイミングとされ、「WANやLTXよりWF簡単」「ネイティブサポートが充実」「カスタムノードが減った」「完成度高いテンプレWFが用意されている」ため初心者でも扱いやすい。
  - 静止画メインだった人がWan時代にComfyUIを避けていたが、後からキャッチアップが大変だった反省から「さっさとComfyUIした方が結局楽」との声。
  - Forge/A1111からComfyUIへの完全移行（A1111系ツール完全削除）をして後戻りできない状態にした事例あり。理由は「拡張性を捨てない」「動画生成でComfyUIの優位性が高い」。

- **ワークフロー管理・保存の利便性**
  - PNGにワークフローとプロンプトを自動格納できる（VAEデコード後にバッチで初期フレーム保存）。
  - ドラッグ&ドロップでワークフロー復元可能。バージョン管理（日付付け、エクスポート、NAS保管）や変更履歴記載がしやすい。
  - 10ErosやminimaxのワークフローでもPNG保存が便利と評価。

- **速度・最適化関連**
  - SageAttention（--use-sage-attention） vs kitchen vs 標準の比較（sageが素の出力に近く、kitchenは構図が変わる場合あり）。
  - Triton-windows + sageattentionのインストール手順と、RTX40xxでも使える可能性。
  - ComfyUI起動時間のムラ、VRAM節約（iGPU出力、ウィンドウ最小化）、fp16 accumulationなどの設定。
  - adaptive（balance）やBlock cache T8との速度比較。

- **UI・操作性**
  - 「Comfy“UI”なのにUIがゲロカス」「ノード多すぎてわけわからん」「Easy〇〇は初心者向けじゃない」との不満。
  - 一方で「ノードベースは非エンジニア向けインターフェイス」「今はChatGPT/CodexにWF作らせたり解説させたりできるので簡単」との肯定的意見。
  - エージェント（LLM）経由でインストール・最適化・WF構築・プロンプト作成まで全部任せられる点が強み。

- **その他の使い方**
  - 複数タブ開きっぱなし対策（ブックマーク、保存）。
  - ref2v/fl2vのプロンプト記述のしやすさ（公式ガイド準拠）。
  - i2v/ref2vノードの挙動（複数画像渡し、first/last frame）。

### webUI / Forge / A1111系関連
- **使い分け**
  - Forgeはリアス（illustrious系）、Forge neoはAnima、Comfyはmm（MiniMax）で分けて運用している事例。
  - 静止画メインならA1111ライクなUIにこだわる意味はあるが、動画では「ComfyUI嫌ンゴは意味がわからない」との意見。
  - WebUIは「拡張性を捨てるだけなので天下取るのは無理」との評価。

- **移行を避ける理由**
  - 使い慣れたUIにこだわりたい、気持ちよく生成できるかどうかが大事。
  - 拡張機能導入段階で躓いた、ノードの繋ぎ方がわからないなどのハードル。

### その他ツール
- **Stability Matrix版**：メタデータ保管処理が不完全になる場合あり（ComfyUIのPNG保存機能に影響）。
- **Codex / エージェントツール**：ComfyUIのWFを丸投げで作成・改良・解説させる用途。UI作成や全自動生成（翻訳→企画→プロンプト→生成→連結）まで任せられる。

**特にツール選択の理由として明記されていた点**
- ComfyUIを選ぶ最大の理由：H3/Animaなどの新機能のネイティブサポートが早く、WFがシンプルになり、テンプレやLLM支援で学習コストが下がった。
- 速度・品質バランスを重視してComfyUI内の各種attention（sage/kitchen）やキャッシュを検証。
- 動画生成・ref2v/i2vの扱いやすさでComfyUIが優位。
