**抽出されたツール関連話題（ComfyUI系中心）**

以下、ログから**ツール（ComfyUI / ワークフロー / ノード / カスタム機能など）**に関する記述のみを抽出しました。モデル名自体は除外しています。

### 1. ComfyUI + Kitchen Attention / Sol-Attn
- **言及**: `kitchen attn + sol + turbo` の組み合わせ、`Comfy Kitchen`（C++/CUDAで最適化したGPUカーネル実装）、`Patch Sol-Attn (MiniMax)` ノード。
- **選ばれている理由**:
  - 行列演算を高速化できる
  - 長尺動画生成時の爆速化（15秒程度の動画が高速化）
  - Spectrumオンと併用でさらに速くなるケースあり

### 2. Context Loop（MiniMax H3用ワークフロー）
- **言及**: Context Loopを使ったシーン追加・連結生成、`Approve&continue` ボタンの使い方、エディターノードでのプロンプト追加。
- **選ばれている理由**:
  - シーンを後から追加して繋げられる
  - VRAM/RAM使用量が動画を繋げてもほぼ変わらない（無限に繋げられる可能性）
  - 低スペック環境（RAM32GB）でも動作する最適化の恩恵を受けやすい

### 3. Latent Upscaler / VAE upscale
- **言及**: LTXで使われていた技術を転用したLatent Upscaler、VAE upscaleとの比較。
- **選ばれている理由**:
  - 高解像度生成時の時間短縮を目的とした技術
  - 通常のhires fix的な使い方が可能

### 4. Refiner / Refine
- **言mentioned**: H3のアプスケ時にRefineで回す、refinerとの違い。
- **選ばれている理由**:
  - アプスケや拡大時の画質調整に使う
  - ただし処理が遅いため手が出しにくいという声も

### 5. ComfyUIの起動オプション・メモリ最適化
- **言及**: `--fast-disk`、`pinned memory` のオンオフ、RAM使用量の調整。
- **選ばれている理由**:
  - RAM消費を大幅に抑えられる（RAM32GB環境で動作可能になった）
  - ただし生成時間が増えるトレードオフあり
  - 低スペック勢がH3を楽しむための環境整備として重要視されている

### 6. その他のComfyUI関連ツール・機能
- **MiniMax H3専用ノード / WF**（サンプルワークフロー、Video latentとAudio latentの分離）
- **カメラモーションのサンプル動画**（ComfyUIで作られたもの）
- **cc_nanobananaフォルダ**（自動生成される出力フォルダの問題）
