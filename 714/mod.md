# 流行モデル概観
スレ上で最も議論を集め流行しているのはMoss-Image（MOSS）である。森羅万象を出せる万能性、日本語プロンプトへの強さ、自然言語でのキャプション付けの優秀さが評価されており、NSFW（ガッツリエロ）出力や3次元（実写）用途で期待が集まっている。次いでAnimaが「貧者の味方」としてLoRA学習の手軽さや破綻率の低さから根強い人気を持つ。Krea2は画質の上限の高さや自然言語力が評価されるが、物理的に重くNSFW制限が厳しいため、MOSSへ一択化が進むケースが見られる。

# 各モデルの選定理由と知見

## Moss-Image（MOSS / モス）
**強み・選ばれる理由**
- 森羅万象を出せる万能モデルであり、Animaのような1girl偏重バイアスが少ない。LLMの理解度が高く適当にやっても形になる。3次で好き放題やれることに真価がある（109, 157, 924, 755）。
- 日本語での生成が強く、タグで出ない体位も日本語で構図を書けば出せる。逆さま構図でほぼ破綻しない（47, 763）。
- 自然言語や構造化プロンプトでのキャプション付けが圧倒的に優秀。LLMエージェントにJSONやBBOXで指示を出す柔軟な運用が可能（71, 81, 157, 216）。
- Krea2が物理的に重いため、MOSS一択になっているケースがある。エロワードを入れればガッツリ無修正が出る（256, 437）。

**課題・採用しなかった理由**
- LoRA学習に15000〜20000stepが必要で時間がかかる。1発10時間かかる試行錯誤はキツいとされる（24, 41, 76, 684）。
- 元モデルが高性能すぎるため素人が作ったLoRAで破綻が生じる。animaと比較して破綻率が高く、タグでも自然文でも溶けたり増えたりする（744, 745）。
- 指の溶けが起こりやすい。画風が不安定で短いプロンプトでは破綻しやすく、出力がフラットで明るい傾向がある（40, 53, 120）。
- ポン出しの解像度が低い。1girlポン出し層とは致命的に相性が悪いとの指摘がある一方、1girlポン出し向けとの見方もあり意見が分かれる（218, 749, 751）。
- 「くぱぁ」を理解せず部族語の「spread pussy」等に変換が必要。頼んでいないのにピアスをつけてくる（223, 720）。
- モデルが重く、paperspace pro環境では無理という声。プロンプトエンハンサーを入れると遅くなり低スペには厳しい（76, 481）。

**Tips・実測設定**
- Sampler: Euler、Scheduler: SGM Uniformは指が溶けやすく、er_sdeが安牌（59, 64）。
- 公式shift=5.0は1K付近の適正値。ネイティブ2Kならshift=10.0が必要。shiftを下げると擬音の描画ができる（130, 140, 145）。
- FFN層のみの学習は破綻し、FFN_down層のみの学習が画風補正に有効。CAME LR 5e-5 / RAdamScheduleFree 2e-4等の設定言及あり（65）。
- プロンプトエンハンサーはsubgraphから外に出して個別利用推奨。bboxes使用時はoff固定がいい（482）。
- エマノン（@Emanon_14）のnote「MOSS-imageのLoRA作成まとめ」が話題（65）。
- sd-scriptsで学習時の推奨引数：`--timestep_sampling shift --discrete_flow_shift 2.0` または `--timestep_sampling truncated_logit_normal --logit_mean -1.09 --logit_std 0.95 --discrete_flow_shift 1.0`（919, 923）。
- LoRA学習のプリセットはanima用のものが使える。CAME30枚、バッチ1の600step、RTX5090環境で20分（914, 946）。
- `moss_SFT`ではクオリティ系呪文は不要。短くても `A masterpiece illustration.` のような自然文が良い（363）。
- 部族語（ダンボールタグ）には対応しておらず、たまたま英単語として拾っているだけ。`2K` `4K` のような短いタグでは描き分けできない（368, 374, 385）。
- `visible 〇〇` が効くため `closed mouth and visible tongue tip out downward.` のように指定すると安定する（383, 387）。
- ネガティブに `piercing` `earrings` を推奨。ネガティブ側の `low quality` `lowres` は効いてる気がしない（411, 712）。
- 3,40行くらいにプロンプトを描き込むと良い。実写系は解像度低く暗く画質悪い方がリアルに見る（756, 488）。
- VRAM16GB(4080s)環境で `--vram-reserve-mib` を調整（3800から7800に増加）で速度低下ほぼ解消。94tok/sで快適（440）。
- ArgonにMOSSの公式スキルを渡すとシンプルなプロンプトでリッチな絵を作るのが上手い（740）。
- MOSS Model Block Merger、MOSS LoRA Extractor等のツールが登場しつつある（757）。
- base/SFT/DMD/FTモデルがあり、baseが1番良いとの意見。FTは絵柄に困る場合に良い（769, 770）。

## Anima
**強み・選ばれる理由**
- 「貧者の味方」でLoRA学習に要する時間やコスト面でMOSSより扱いやすい。破綻率が低い（39, 41, 684, 744）。
- アニメ系1girl偏重のバイアスが強く、素材の多様性への配慮が適当でも問題ない。2次しか興味ないなら十分（201, 226, 755）。
- int8に高速化LoRAの速度に慣れすぎてMOSSに切り替えづらいという声（655）。
- 通常のAnimaのみで作ったイラストでも問題なく仕上がる（103, 106）。
- mossからanimaへ完全に乗り換えた報告あり。mossのキャラLoRAはanimaのデータセット流用で覚える（748, 921）。

**課題・採用しなかった理由**
- キャラや画風の再現に慣れるとMOSSの甘さが目立つが、MOSSの学習難易度の高さからAnimaに残留する層もいる（41, 655）。
- moss以降のモデルのように詳細部分を指定して描写する機能がない。SDXL同様に手動で学習強度を変える必要がある（253）。

**Tips・実測設定**
- `One obsession_Animav5` を基本モデルとして使用する例がある（105）。
- `hakushiMixAnima` とSnapRefの組み合わせでLoRA代わりになるか実験。ずれる部分はプロンプト補正可能（38）。
- Animaで作成した2Dイラストを3Dモデル化し胸揺れアニメーションを作成する試み（227）。

# 総評
1. MOSSは万能性と日本語・自然言語への強さから3次・NSFW用途で主流になりつつあるが、LoRA学習の重さ・破綻率の高さ・高スペック要求により、Anima等の既存モデルから完全移行できないユーザー層が残留する二極状態となっている。
2. Krea2は画質と自然言語力で上限が高いが、NSFW制限の厳さとモデルの重さが足枠となり、用途によってはMOSS一択に切り替わるケースが発生している。
3. MOSSのLoRA学習やプロンプトエンハンサー、Sampler・Scheduler等の具体的な設定値・運用知見がスレ内で蓄積しつつあり、fizgigやsd-scriptsの引数、VRAM予約量調整等の実測データが共有されている。
4. Animaは学習の軽さ・破綻率の低さ・1girlバイアスによる扱いやすさから「2次しか興味がない」層に十分選ばれ続ける一方、MOSSのキャラLoRA学習にanimaのデータセット流用やプリセット流用が可能であることが判明しつつある。
