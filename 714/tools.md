# 元の本文
今回とくに盛んに議論された話題は、ComfyUIワークフロー調整、Strata等のローカルLLM実行環境と画像生成環境の併用、及びLoRA学習・3Dモデル化周辺のツール挙動である。

※レス番号が統合元パート内の通し番号である場合は、元スレの通し番号とは限らない。

### ComfyUI ワークフロー・ノード挙動
- ModelSamplingAuraFlowが環Nightly + Node2.0で挙動が狂い、入力値が2回目以降別の値に勝手に上書きされる不具合が報告されている (130)。
- Prompt Enhancer（PE）はリビルドのようになり、内部LLMが9Bと小さめのため別LLMを噛ませた方がよいとの見解がある (907)。おまかせにするとMOSS本体が指示を全部描こうとして構図が破綻する (905, 906)。テンプレート内のPEにdanbooruタグを入れると出力が破綻する原因になっている指摘もある (910, 925)。
- MOSS初回用のテンプレートWFは分かりにくく、別のbboxを使いやすいWFが推される (931)。
- P-H3-Image用の専用ConditioningノードとテンプレートWFが存在する (956)。3060/12GB・RAM32GB環境でテンプレートt2iが148秒で生成された実績がある (970)。
- カスタムノードやH3の高速化LoRA追跡は一苦労であり、公式配布分のみに絞るユーザーがいる (983, 984)。
- Claude Sonnetに「WAN2.2用のAttention Map CaptureをMOSS-Imageに移植」と頼み1ドル未満で実装でき、改行やカンマにも文脈依存で反応することが確認された (902)。

### Strata・LM Studio等のローカルLLM実行環境
- 選ばれている理由：Strataは使えるモデルの脳のデカさが桁違いで、システムプロンプトで見違える結果が出るため (86, 91)。TE PEは理解力に限界があるため、練ったシステムプロンプトならIQ3_Sが推奨される (86)。最新ターミナル版ではスペック不足モデルも動くようになった (574)。
- 併用のしんどさ：起動が重くモデル解放・読み込みに時間がかかるためLM Studioに移行することが多い (439)。5090単独では使いづらい (618)。
- ComfyUI等との併用：VRAM 16GB環境で`--vram-reserve-mb`を7800に増やすことで併用時の画像生成速度低下が解消し、94tok/sで動く (94, 440)。2GPU+RAM128GB環境で片方にStrata、もう片方で画像・動画生成の運用例がある (340)。
- GPU別ツール割り当て案として5090=Strata、4090=Krea/Moss/Qwen、6000=H3が提示されている (632)。

### ComfyUI環境構築のエージェント運用とセキュリティ
- チャッピーにComfyUI環境構築を相談したが素人でも分かる盛大なハルシネーションがあった (133)。
- Gemini（Argon）でのComfyUIプロンプト作成に差が出るかという質問がある (831)。
- 1からComfyUI環境構築やカスタムノード作成ができるとの報告がある (641)。
- セキュリティ：Pythonやuvを更新していないと偽URL判定できずウイルス入りカスタムノードを入れられるリスクがある (33)。チャッピーにリポジトリのコードや推移的依存関係を確認させる対策例がある (34)。ローカルLLMでの常時/毎回監視ができないと厳しいとの見解 (36)。
- サプライチェーン攻撃対応としてpipやuvのライブラリ更新が必要 (713)。pip更新はサボりがち (713, 714)。

### Hermes Agent・Cursor・antigravity等のエージェント・コーディングツール
- Hermes AgentにComfyUIのAnimaを使わせて漫画描かせを試みたが上手くいかない (116)。
- Cursorでゲーム開発のコード書きに併用し33%消費した経験がある (911)。
- antigravityはコードを勝手に4回消して再現しようとしたため使用を止めた (539)。antigravity経由だとArgonが別枠で使えるため推奨される (879)。

### LoRA学習ツール（Fizgig / sd-scripts / RedRayz GUI）
- Fizgigでstyleプリセットで画風LoRAを回し、Per-image lossでエポック目安を確認できる (104, 108)。サンプルは成功例に見えるが実生成では「足りねぇ…」になる (175)。
- MOSSの画風LoRAはFizgigで150〜200epoch程度煮込めば大体できる (357)。40枚程度のデータセットだと小さいためエポック多めにするよう表示される (394)。
- sd-scriptsでMOSS LoRA学習時、`--timestep_sampling shift --discrete_flow_shift 2.0`等の引数追加が必要。RedRayzニキのGUIでは「追加の引数」欄に入れる (919)。別の推奨引数として `--timestep_sampling truncated_logit_normal --logit_mean -1.09 --logit_std 0.95 --discrete_flow_shift 1.0` がある (923)。RedRayzニキのAnima用プリセットがMOSS（CAME）でもそのまま使える (946)。

### 3Dモデル化ツール（xreal one / Tripo / きゃらくる / Daz等）
- xreal oneを使用しハード側で3D処理しており楽しい。動画は30FPSになるが生成なら合わせられる (213)。
- BlenderやTripoでエロ3Dモデルを作る作例がXに出始めている (215)。Tripoやきゃらくるで生成は可能だが服の裏地等の裏面作り込みができるか疑問 (222)。遠くから見るのは良いが修正しようとすると無理ゲー (219)。
- 3Dはガチでシコれるレベルは無料ツール+手放しやArgon等でも無理 (217)。
- きゃらくるは一定ラインまで早く到達できるとの推奨がある (232)。最終的なものを作る時はローカルで動かせるようにしないといけなそう (273)。
- Dazでmorphを作って再現させる形が整えやすく楽そうとの意見がある (234)。3面図を作り360度動画も作れる時代になった (282)。

### SnapRef / モデルマージ・抽出ツール群
- SnapRefをLoRA代わりに使う実験（hakushiMixAnima + SnapRef）。プロンプトで補えばなんとかなりそう (38)。「無いよりはマシ」レベル (163)。
- MOSS Model Block Merger、Multi-Model Merger、LoRA Extractor、LoRA Block Weight、LoRA Merger、LoRA Resize、Model Saver等のCLIツール群が整い始めているとの評価 (757-758)。

### 画像・メタデータ処理ツール類
- 自作画像ビューワ「Nivis Viewer」を更新（不具合修正・処理改善）(509)。サムネの拡大縮小はホイール等で対応予定なし (572, 580, 610)。
- danbooruのDBをローカルで閲覧できるツールをAIエージェントに頼んで導入。日本語入力でも正式表記に辿り着く (706, 710)。danbooruのオートコンプリート用タグファイル更新を試みたがメンテダウン状態 (699, 704)。
- danbooruツール類とは別に、メタデータ閲覧ソフト、画像からプロンプト作成ソフト（キャラクター認識あり）、自動でモザイクをかけるソフトが紹介された (364)。
- SikiでURLが化ける問題がアップデートで修正された (4)。

### 音声生成・TTS系ツール
- sunoは無料枠があり、ローカルでは全く届かない領域 (29)。自キャラのキャラソン用声モデル作成を試み挫折 (35)。
- irodoriは日本人が日本語のみを対象にオタク的使い方を想定して作られており使いやすさは圧倒的 (321)。VoiceStudioはirodoriに太刀打ちできそうにない (315)。
- エロチャットに音声がないと物足りなくなりTTSがなければ飽きていたとの報告がある (819)。

### API・クラウド関連の利用
- kromaはNSFWが出ないためKrea2使用時に推奨されるが容量が非常に大きい (405, 406)。
- museはNAIのAPIを渡すことでざっくりした指示と絵コンテでキャラクタープロンプトを細かく配置して生成する。NOOBでも手軽にできるレベルまで降りてきた (342)。
- Google Cloudの3ヶ月45000円フリークレジットでArgonを試せる。期間限定でproよりAPI使用料が安い（VertexAI経由限定）(829)。
- PrunaAI（P-H3-Image）はRedditの反応も微妙で誰も驚かなかった。Anima等で既に可能なのではとの見解がある (759, 797, 804, 806, 810)。

### 翻訳・キャプション系LLM運用
- MOSS-LoRAのキャプション付け（NSFW含む）はQwenの方が良く、Gemma4君はあやふさな表現になる (115)。Gemma4 31BよりQwen 3.8 27Bの方が漢字込み画像の自動キャプションに良さそう (143)。Qwen3.8FN（PE）に部族語キャプションを通すと日本語でもちゃんと出る (204)。
- 選ばれている理由：Qwen3.8FNはパラメータで殴れる分キャプション品質が上でGemma4より優れているため (182)。
- StrataでQwen3.8 Flash Nextを使いプロンプトを作成したところ創造性と理解力が高くエロ描写も対応した (328)。
- 翻訳専用LLMについてエロ翻訳に使えるか関心がある (861)。翻訳用途ではGoogle翻訳やDeepLでもエロが通る (854)。

### パラメータ・ sampler挙動の知見
- Flow shiftパラメータ（shiftは面積の平方根に比例）。ネイティブ2Kならshift=10.0が適正 (130, 168, 176)。
- er_sdeが安牌、res_multistepは破綻しやすい (64)。

### 環境・OS・ハードウェア関連
- Windows 11 26H2アップデートでメモリ消費が大幅に減少した (985)。
- AI時代の利点として、ブラウザアドオンを自作できるようになったことが挙げられている (244)。
- GPU1基につき年間2000ドルのソフトウェアライセンス費用を別途請求する案をNVIDIAが検討中というニュース (787, 794)。
- Claude SonnetをハーネスにDeepSeekを繋いで利用しているユーザーがいる (991)。

### 総評
1. **ComfyUIとLLM実行環境の併用においてVRAM割り当て調整が実用上の鍵となっており**、`--vram-reserve-mb`の設定で16GB環境でも94tok/sを維持しつつ画像生成の速度低下を回避する運用例が確立されている。
2. **Strataの起動の重さからLM Studioへの移行が進んでいるが**、ターミナル版でのスペック不足モデル動作やIQ3_Sのシステムプロンプト処理能力など、用途によってStrataを選ぶ理由も残存している。
3. **LoRA学習・キャプション付け周辺ではFizgig・sd-scripts・Qwen3.8FNの組み合わせが実績を示しており**、RedRayzニキのGUI経由でMOSSにAnima用プリセットが流用できるなどツール間の互換性が確認されている。
4. **3Dモデル化ツール（Tripo・きゃらくる・Daz等）は一定ラインまでは到達できるが修正・裏面作り込みが無理ゲーとの指摘が複数あり**、遠景用途と手修正の前提で割り切るか、Daz等のmorph再現に頼る方向性が示されている。
