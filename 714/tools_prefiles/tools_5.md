# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI (comfy)

- MOSS用テンプレートワークフロー内にPrompt Enhancer（サブグラフ内）が噛ませてあり、テンプレにdanbooruタグを入れると出力が破綻する原因になっているとの指摘がある。システムプロンプトもデフォルトのままである可能性が示唆されている [910][925]
- MOSSを初めて触る用途では、テンプレのワークフローより別の（bboxも使いやすい）ワークフローの方がわかりやすいとの紹介がある [931]
- P-H3-Image用の専用Conditioningノードが存在し、テンプレートにP-H3用のWFがある。最新のComfyUI (v0.44.0)で確認されている [956]
- P-H3-Imageのテンプレートt2iは、3060/12GB・RAM32GB環境で148秒で出力されたとの実績報告がある [970]
- カスタムノードの更新を追うのが一苦労であり、H3の最速設定が現状どうなっているか分からない状況 [983]
- 動画生成においてComfy公式配布以外の高速化LoRA等は追うのを諦め、公式配布のみに絞っているユーザーがいる [984]

## Prompt Enhancer / TIPO

- Prompt Enhancerの挙動が以前あったTIPOに似ており、プロンプトの＋αというよりリビルド（まるっと作り直し）のようになっている。内部LLMが9Bと小さめのため、enhancer用のLLMを別に突っ込ませた方がよいかもしれないという見解がある [907]
- PE（Prompt Enhancer）におまかせにすると、MOSS本体が指示されたものを全部描こうとするため構図が破綻するパターンがかなりある [906][905]

## A1111

- SD1.5時代、A1111にどのタグが生成画像のどの部分に影響しているかを可視化する機能（ヒートマップ）があった。自然言語で同等のことができるかという疑問が提示されている [886]

## Attention Map（ヒートマップ可視化ツール）

- Claude Sonnetに「WAN2.2用のAttention Map CaptureをMOSS-Imageに移植して」と頼んだところ、1ドル未満で実装できた。MOSS-Imageが改行やカンマにも文脈依存で反応することが確認された [902]
- 単語細切れだと混乱する部分もあり、mediumやshotで目だけに反応するなど挙動に疑問点がある [903]

## antigravity

- antigravity経由だとargonが別枠で使えるため推奨される。通常チャットで消費すると3.8まで使えなくなる問題がある [879]

## Cursor

- ゲーム開発のコード書きでCursorを併用し、33%を消費した経験がある。プロンプト単体では一度にそこまで消費しない [911]

## Tagger / Embedding

- 出力結果とプロンプトを比較する用途で、Embeddingやtaggerでできそうとの意見がある [894]

## sd-scripts / RedRayz GUI

- MOSSのLoRA学習にsd-scriptsを使う場合、`--timestep_sampling shift --discrete_flow_shift 2.0` を追加するよう指示がある。RedRayzニキのGUIでは「追加の引数」欄に入れる [919]
- 別の推奨引数として `--timestep_sampling truncated_logit_normal --logit_mean -1.09 --logit_std 0.95 --discrete_flow_shift 1.0` が提示されている [923]
- RedRayzニキのAnima用プリセットがMOSS（CAME）でもそのまま使えるとの情報がある [946]

## Fizgig

- FizgigでのLoRA学習のコツを掴んだ直後に新しいモデルが出たという状況 [987]

## その他ツール関連

- 翻訳専用のLLMが出たらしく、エロ翻訳に使えるか関心がある [861]
- 翻訳用途ではGoogle翻訳やDeepLでもエロが通る [854]
- Qwen vl等の画像認識モデルで、何がどう表現されているかを翻訳・駆使して分解して使うアプローチが紹介されている [872]
- Windows 11 26H2アップデートでメモリ消費が大幅に減少したとの報告がある [985]
- Claude SonnetをハーネスにDeepSeekを繋いで利用しているユーザーがいる [991]
