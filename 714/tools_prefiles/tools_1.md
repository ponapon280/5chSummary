# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI / ワークフロー
- ModelSamplingAuraFlowが環Nightly + Node2.0で挙動が狂っており、入力した値が2回目以降別の値で勝手に上書きされる（キャッシュ関連の不具合と推測）との報告 (130)
- ワークフローのPE（プロンプトエンハンサー）では思通り画像が出ず、具体的なロジックのシステムプロンプトを書いているが難しいとの声 (78)
- 「プロンプトエンハンサーはたたき台止まり」との見解 (80)
- Hermes AgentにComfyUIのAnimaを使わせて漫画描かせを試みたが上手くいかない（参考サイト読ませ・スキル作成も試行） (116)

## カスタムノード / セキュリティ
- Pythonやuvを更新していなかった場合、偽URL判定できなくなりウイルス入りのカスタムノードを入れられるリスクがある (33)
- カスタムノード導入時、チャッピーにリポジトリのコードや推移的依存関係も確認させている対策例 (34)
- セキュリティ問題はイタチごっこで第二弾もあり、ローカルLLMでの常時/毎回監視ができないと厳しいとの見解 (36)

## 環境・SDK・関連ツール
- SDXL, Anima, Mossの比較出力を提示（題材：水晶の龍のシンシア） (120)
- SnapRefをLoRA代わりに使う実験（hakushiMixAnima + SnapRef）。プロンプトで補えばなんとかなりそう (38)
- Anima SnapRefは「無いよりはマシ」レベル (163)
- Strata（ローカルLLM）のIQ3_Sをシステムプロンプト処理に使う推奨 (86)
- StrataのTE PEは理解力に限界があるため、練ったシステムプロンプトならIQ3_Sを推奨 (86)
- Strataを実際に使ってクラウドの凄さを再認識し家庭用限界を実感したという報告 (95)
- Flow shiftパラメータ調整の知見（shiftは面積の平方根に比例）。ネイティブ2Kならshift=10.0が適正 (130, 168, 176)
- er_sdeが安牌、res_multistepは破綻しやすいとの評価 (64)
- Fizgigのstyleプリセットで画風LoRAを回している。Per-image lossでエポック目安が分かる (104, 108)
- FizgigのLoRAサンプルは成功例に見えるが実生成では「足りねぇ…」になる (175)

## 3Dモデル化ツール
- 3Dモデル化はこのスレで話題にしてよいか確認 (200)
- xreal oneを使用。ハード側で3D処理してくれ楽しい、動画は30FPSになるが生成なら合わせられる (213)
- BlenderやTripoでエロ3Dモデルを作る作例がXに出始めている (215)
- Tripoやきゃらくる等で3Dモデル生成は可能だが、裏面（服の裏地等）の作り込みができるか疑問 (222)
- 3Dはガチでシコれるレベルは無料ツール+手放しやArgon等でも無理 (217)
- Tripo生成モデルは遠くから見るのは良いが修正しようとすると無理ゲー (219)
- animaで作った元絵を3Dモデル化し胸揺れを試している作例あり (227)

## Qwen（画像生成以外の話題）
- MOSS-LoRAのキャプション付け（NSFW含む）はQwenの方が良い。Gemma4君はあやふさな表現になる (115)
- Gemma4 31BよりQwen 3.8 27Bの方が漢字込み画像の自動キャプションに良さそう (143)
- Qwen3.8FN（PE）に部族語キャプションを通すと日本語でもちゃんと出る (204)

## 選ばれている理由
- Strataは使えるモデルの脳のデカさが桁違いで、システムプロンプトで見違える結果が出るため選ばれる (86, 91)
- Qwen3.8FNはパラメータで殴れる分キャプション品質が上で、Gemma4より優れているため選ばれる (182)
