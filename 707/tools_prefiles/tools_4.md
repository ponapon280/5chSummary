## 抽出結果

### ComfyUI / ComfyUI関連ワークフロー

- **ComfyUI標準ノードへの置き換えによる高速化**: comfy標準ノードに置き換えたら3分かかっていた生成が1分になった。VRAM 8Gの3070環境（639）。
- **Node 2.0への移行**: create bounding boxesノードがNode 2.0必須のため、2.0へ移行する動き（639, 682）。
- **If/Else Switchノードによる切替**: BBoxを使う/使わないケースの切り替えにIf/Else Switchノードを複数使用。ただしミュートにはならない課題あり（655, 699）。
- **Fast groups bypasser**: Node 2.0でも機能自体は生存。トグルボタンのon/off表示が正しくないがオンオフ自体は可能（757）。
- **ComfyUI最新版の高速化**: ComfyUI最新版にしたら生成が1.7倍速になった（745）。
- **公式ノードによる爆速化**: 非公式ノードでは5倍遅かったが、公式ノード来てから爆速になった（806）。
- **Codexでワークフロー最適化**: CodexにSpectrumを作らせてワイ環120→90秒に高速化（806）。codexを「願望実現ツール」と呼ぶ声あり（635）。

### バウンディングボックス（BBox）機能

- **BBoxによる位置指定**: Anima比でBBox形式で正確に位置を指定できるのがMOSSの売り（755）。
- **bbox座標ルールの違い**: ideogram4とMOSSで微妙にbboxの座標ルールが異なる。DiT的にはセンター0が良いが、手動の場合y座標を先にするのが混乱しやすい（795）。
- **LLM連携のbbox出力ノード**: ideogram4で作成したLLM連携bbox出力ノードをMOSSのbboxルールに修正すれば使えそう（821）。
- **bboxのお手軽さ**: bboxはお手軽に構図を変えられて便利（829）。

### ワークフロー・生成設定（Kijai氏のWF等）

- **Kijai氏のWF設定**: steps25/cfg2.5/er_sde/simple。文字を入れる場合はsteps50/cfg3.0/euler/sgm_uniformの方が正確性が上がるが時間は倍になる（693）。
- **steps50/cfg3.0/euler/sgm_uniformが安定**: 複数ユーザーがこの設定に落ち着いた。25stepは少なすぎる（694, 695, 696）。
- **指の溶けやすさ**: Kijai氏のWFで指が溶けやすく、手の輪郭線が肌色に溶けがちで腹部や太ももと合体する（689, 691）。
- **Kijai氏の人物像**: 3Dテクニカルアーティスト畑の人でプログラミング経験は浅いとの情報（739）。元3Dモデラー・デザイナー（704）。スレ上では「神」とも（703）。

### 量子化・高速化・VRAM要件

- **int8による高速化**: comfyにMOSSでint8を使った場合に3割高速化の更新が入った（656）。VRAM16G、MEM96G環境で確認（662）。
- **int8_convrotの比較**: bf16とint8_convrotを比較しても生成時間はほとんど変わらない（818）。
- **8step DMD**: ちょっと劣化激しくてダメな感じ（639）。sft用の8step DMDはもう来ている（803）。
- **VRAM要件**: MOSSはモデル5GB・TE9GBのためVRAM12GBの4070tiだと厳しい（814）。VRAM16GB未満には人権なさそう（816）。一方VRAM8GBで動かしているスレ民もいる（742）。低スペなら4bit版を使えばよい（817）。
- **AnimaとのVRAM比較**: AnimaはVRAM6.5GB程度だがMOSSは16GB必要（816）。
- **解像度の上限**: MOSSの公式上限は2Mピクセル。公式グラディオでは4Mピクセル（アプスケ入りか）（809）。

### 生成速度の比較

- **Anima vs MOSSの速度**: 同サイズ同ステップでAnima 9秒・MOSS 12秒程度（805）。Anima bf16 25Steps vs MOSS int8_convrot 25Steps（Turboなし）なら生成時間はほとんど変わらない（818）。
- **Anima 2.9bでの参考値**: 解像度1024x1024・24Stepで生成時間13秒（RAM32G・RTX4070Ti）（811）。
- **Qwen-image-2.1との体感比較**: MOSSの生成時間はQwen-image-2.1と体感変わらない。Flux.2出た当初の20倍遅い状況に比べれば軽い（813）。

### LoRA学習ツール・環境

- **ai-toolkit対応**: ai-toolkitがMOSSに対応しているため手軽にLoRA学習可能（783）。
- **Kohyaニキの対応予定**: kohyaがMOSS対応するらしい。対応後に学習を開始するユーザー多数（771, 812）。
- **Civitaiでの学習実績**: mossimage_sft, dim32/alpha32, adamw8bit, unet lr 1e-4, constant 2000steps, 68imagesで約53分でLoRAトレーニング完了。123MB。ただしcivitaiにアップロードしたLoRAがgenerateで使えなさそうな問題あり（808）。
- **Base推奨**: LoRAトレーニング時はベースモデルの使用が推奨される。日常使用にはSFTが適切（810）。
- **画風LoRAのキャプション手法**: MOSS開発者が「loraの画像キャプションはこれでやるとええぞ」まで言及している（785）。

### 画像認識・編集ツール（Qwenシリーズ・その他）

- **Qwen Image 2.1の編集位置づけ**: 「編集：Qwen Image 2.1」と位置づけられているが、編集というより修正の域との指摘（729, 733）。
- **QwenImage2.1の学習懸念**: GPT画像からの学習汚染が疑われる点でQwenImage2.1も同様との指摘（671）。
