# 生成AIモデル関連話題抽出レポート

## MOSS（MOSS-Image-Base / MOSS-Image-SFT）

### 基本情報・スペック
- 開発元は上海の大学中心の研究チーム（638, 772）
- 学習データ32億枚で訓練（758）。総計3億枚学習との記述もあり（732）
- モデルサイズ5GB、TE 9GB。VRAM12GBの4070tiだと厳しく、VRAM16GB未満には人権なさそう（814, 816）
- VRAM8GBの3070でも動かしているスレ民がいる（639, 742）。低スペなら4bit版を使用（817）
- 公式での解像度上限は2Mピクセル。公式gradioでは4Mピクセルまである（アプスケ入りか）（809）

### 生成速度・高速化
- comfy標準ノードに置き換えで3分→1分に短縮。VRAM8Gの3070（639）
- ComfyUI最新版で生成が1.7倍速に（745）
- int8で3割高速化の更新がcomfyに入った（656, 662）。VRAM16G、MEM96G環境で確認（662）
- 非公式ノードでは5倍遅かったが公式ノード来て爆速に（806）
- 同サイズ同ステップでAnima 9秒、MOSS 12秒程度（805）
- bf16とint8_convの比較ではAnimaと生成時間さほど変わらない（809）
- CodexにSpectrum作らせてワイ環120→90秒に（806）

### 品質・特徴
- BBox形式で正確に位置指定可能。Anima比で日本語が描ける、Krea2比でBaseで二次元エロが出せる（755）
- 硬系NSFWではCG集のような感じになる（643）
- プロンプト追従力・構図制御力はNAIより上というスレ上の見方（697）
- danbooruタグのみで出力するとSD1.5初期のような画質になる（762）
- `(large breasts:2)`のような強調表現が効かないっぽい（800）
- steps25/cfg2.5/er_sde/simple（kijai設定）だと指が溶けやすい。steps50/cfg3.0/euler/sgm_uniformの方が正確性上がるが時間は倍（689, 693, 694）
- 25stepは少なすぎる。公式準拠のsteps50の方が品質安定（695, 696）
- アクション内容・コマ割りをAIに作らせると品質落ちる。プロの指示が必要（676）
- 手の輪郭線が肌色に溶けがち、腹部や太ももと合体することがある（691）
- ポン出しマンにはバウンディングボックスの扱いが難しい（782）

### GPT画像（チャッピー）の学習汚染疑惑
- MOSSの生成物にGPTimageの荒れ具合が兼ね備えられており、GPT画像が学習素材に含まれてそう（670, 673）
- デフォで出てくる子がGPTimageのデフォ子に似ている（673）
- スレ上の推測：GPTでの大量の入力プロンプトと出力画像の組（写像）を蒸留させているためポテンシャルがあるが、ガビガビ病遺伝は仕方ない（681）

### Reference Image・機能対応
- Reference Image非対応（634）。ref版はまだ学習方法の検討段階（765）
- 開発者によればsimple SFTでGIF生成やreference-based generationを有効化できる見込み（652）
- ref機能がないとlora作成が必要になりanimaやリアスに戻ってしまう（658, 705）

### LoRA学習
- LoRA作成環境：ai-toolkitが対応（783）。kohyaがMOSS対応予定（771）
- SFTでの画風学習は撃沈。baseでやる推奨（660, 810）
- SFT版でアーティストスタイルがはっきり効いたのは〇incosのみ（794）
- LoRAトレーニング実績：sft, dim32/alpha32, adamw8bit, unet lr 1e-4, constant 2000steps, 68images。civitaiで約53分完了。123MB（808）
- ベースモデル使用推奨。baseはフォトリアリスティック傾向、SFTは美的品質が優れる（810）
- 強力なtaggerモデルが出ないとTEの能力を引き出せない懸念（831）

### Animaとの比較・移行
- Animaの上位になりそう。ポン出しはリアス、構図詰めるならMOSS（710, 721）
- Anima比で学習も生成も遅いのが厳しい（680）
- Anima 2.9bから移行検討する声あり。版権キャラは難しい（763）
- Animaより生成時間5倍だと使えない。2倍くらいに収まらないと乗り換え無理（802, 811）
- Anima時代のクソ雑自然言語でも形になる（684）
- キャラ描き分けはanimaほど正確ではない（682）
- int8で高速化来れば重くない。絵柄LORAはどうせ作るのでanimaから移行する声（669）
- Animaは速度に振ってた。MOSSは質に振った選択肢（683）

### 今後の展開
- 公式でアニメ版モデル（二次特化バージョン）製作中。Turboも作る予定だがアニメ版が最優先（720, 723, 768, 773）
- redditにMOSS開発者が降臨（663）。loraの画像キャプション方法まで指示している（785）
- MOSSのLoRAが既に出回っている（711）

## 選ばれている理由（MOSS）
- Animaから久々の直球二次エロモデルで活気づいている（797）
- 二次元はPC持ってないならNAI、持ってるならMOSSというところまでは来た（716）
- 日本語が描けてBBoxで位置指定可能、Baseで二次元エロが出せる、配置も決められて背景や色合いが綺麗（690, 755）
- プロンプト追従力・構図制御力がNAIより上で、ローカル環境で個人微調整可能（697, 700）
- Animaの上位になりうる。質に振った選択肢（683, 721）
- ローカル版NAI来そうという期待（760）
