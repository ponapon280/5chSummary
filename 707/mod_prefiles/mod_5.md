# 生成AIモデル関連話題抽出レポート

## MOSS / MOSS-Image

### 基本情報・性能
- SD1.5→Pony→リアス→Anima→MOSSというモデル移行の歴史（832）
- テキストエンコーダー(TE)が大きく、言語理解力が高い。Anima(0.6B)と比較してTEの大きさが正義だったとするスレ上の見解（904）
- 部族語（danbooruタグ）適性が高い一方、ガチャ適性も高く画風が暴れる傾向（855）
- 日本語の自然文で生成可能。破綻率が高い気はする（913）
- キャラ名 is… の記述だけでキャラが混ざりにくい（909）
- BBOX区切りでコマごとに処理するため、4コマ×2話構成でも崩れない（939）
- 矢と失の書き分けができる（902）。難しい漢字も出せる（941）
- 質感の表現がダントツ（915）
- 指は綺麗に描けることがあるが、不意にSD1.5レベルで溶けることがある。指・腕の本数を意図的に増やすのは簡単（923、955）
- 50step CFG3 1248x1664で5090だと1枚26秒（915）
- 5070tiで1024x1536が8.5秒程度（916）
- 9060XT + ComfyUIで1024×1024の25stepで約1分（881）

### 高速化・量子化
- DMDloraを強度0.8の12stepで速度十分（839）
- ベースモデルで180秒から90秒程度まで高速化できた。質を落とさずこれ以上は限界（845）
- int8だとAnimaと変わらん速度で出る（953）
- 8stepDMDlora使用時、CFGを落とさないと関係ない車の絵を描き始める（875）
- ComfyUIのmainブランチ最新のint8 convrotとModel Sparse Attentionを当てて速くなったが、まだ遅め（962）

### LoRA・学習
- LoRA学習はKrea2の2/3くらいの速さのs/it。SFTの方が覚えが良さそう（892）
- LoRA作成環境が出るまでは様子見という意見（837）
- 画像キャプショニングのパイプラインが公開された（912）
- 画風LoRAで安定させられるのではないかという懸念（856）

### アニメモデル・今後の展開
- アニメモデルを作成中。エディットモデルも検討中だがデータセット確保が難しいためアニメモデル優先（912）
- 公式のアニメモデル対応が来たらという期待（953、957）
- 1865トークンのクソ長システムプロンプトと秘伝のタレでアニメ塗りになりつつあるという報告（968）

### Forge Neo対応
- Forge Neo用のMOSS-Image拡張が既に出ている（869）
- Forge Neoを最新版(2.30)に上げる必要がある（982）

### VRAM要件
- VRAM16GBで足りるかという質問。VRAM12GBでも動くという意見（905、926）
- RAM16GBの低スペでもminimaxを動かしている環境からMOSSに参入できるかという質問（891）

### 比較
- Krea2よりMOSSが上位互換という意見（857）
- 二次絵的にはKrea2はNanoBanana、MOSSはgpt-image2という感じ（899）
- 言語理解度はMOSSが高い。星屑の境界が正しく出る（900）
- ケーキの大きさ・厚さ・形のバランスもMOSSが自然（903）
- Krea2は指が強いが腕が生えることがある（965）
- 三次元(実写)はAnimaより圧倒的にマシだが、Krea2に慣れてるとスンとなるレベル（928）
- 三次では構図制御力を活かせない、用途がない（929）
- Ideogram 4と比較すると、MOSSはパーツ単位の細かい位置指定はできなさそう（940）

### 選ばれている理由
- エロができるローカルGPT imageと考えたら破格（908）
- chatgptみたいな絵柄でエロがきちんと出る。チャッピーマスピ顔が好きな人に最高（991）
- 部族語が使える上に自然言語にも強く、ローカルでそれができるのは大きい（948）
- TEと構図制御力が売り（961）
