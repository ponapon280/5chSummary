## ComfyUI

### H3-Image / MOSS向けワークフロー構築とノード選定
- H3-Image向けに4MPや8MPで生成した画像を縮小保存するワークフローを作成中。長辺1024px縮小だと縦長・横長画像が小さくなりすぎる課題があり、総画素数ベースでの縮小が議論された（134, 153, 160, 165）
- 標準ノードだとワークフローが巨大化するため、pythonでカスタムノードを自作する選択が取られた。現在ならAIで数秒で生成可能（249, 251）
- 同一プロンプト・同一シードでも縦横比を変えると奇形が発生するため、解像度設定ワークフローは重要（252）

### MOSS-Image Edit ノードとテンプレート問題
- MOSSのEDIT機能はComfyUIにビルトイン済み（`Text Encode MOSS-image Edit`ノード存在）。ただし後付editのため性能には期待薄（322）
- ComfyUI公式ワークフローに入っているプロンプトエンハンサーが不要すぎると指摘。MOSSワークフローのテンプレートもbboxを足しただけの使いまわしで雑（626, 635）
- プロンプトアップスケーラーONで服を勝手に着せる挙動が出る。切ると解消。プロンプトエンハンサーは勝手に乳を盛る機能ではない（371-372, 379-380）

### MOSS向けカスタムノードとパフォーマンス
- MOSS公式ノードでbbox指定可能。Node2.0を有効化が必要（868, 869, 871, 895）
- カスタムノード「KJPromptBuilderMoss」：json圧縮出力チェックで効かないことがある（871, 895）
- カスタムノード「MOSS Layout YDR」：解像度選択可能、生成結果が自動キャンバスに入り画像を見ながらbbox配置可能（878, 895）
- ComfyUIアプデ後、画像ドロップやキュー投げが激重に。以前は100件で1秒程度だったが1件数秒かかるよう劣化（872）

### museとの連携自動化
- museで漫画を指示→museがプロンプト作成→ComfyUIに投げ→museが加工画像を表示するworkflowを構築。スマホ1アクションで完結（884, 904, 914, 949）
- コマごとの素材画像作成→1ページ組み合わせ→セリフ吹き出し挿入→エロ擬音事前学習→公開用モザイク処理まで自動化するワークフロー事例（884）

### セキュリティ：ComfyUI-Easy-Use拡張機能の脆弱性
- 拡張機能「ComfyUI-Easy-Use」1.4.1以前にパストラバーサル系脆弱性（CVE-2026-123790）。海外WFにほぼ必須の人気拡張機能（649, 651, 750, 771）
- 最新バージョン（9/29修正）に更新していれば問題ない。信頼できないWF経由での侵害リスクがあり、エージェントでのチェック推奨（662, 761, 765, 774）
- カスタムノードはPythonコードそのもので何でもできてしまう。無名ノードにはユーザー入力をevalするコードも普通に入っている（663, 769）
- 対策として、codex等のエージェントに使っていないExtensionの削除や怪しいコード精査を実施した例が報告（656, 657）
- スレ上では、高性能AIエージェント（Opus5.5）に自作させる方が、悪意を防げる分バイブコーディングの方がマシという見方がある（940, 941, 944）
- comfyanonymousやkijaiが見向きもしないツールがあるが、エロ対応への期待は薄とのスレ上の見方（977, 984）

### clipファイル破損事例
- clipファイル破損でバックアップもなく10時間分の作業が消失。セルシスに送付で修復不可能だったが、内部画像のみzipで送付され3時間で7割復旧（938）

## Strata / LMStudio / llama.cpp（ローカルLLM実行ツール）

### Strataの用途と選定理由
- 画像認識でプロンプトを作らせる用途で強い。コード書かせる用途にも向く（361, 367）
- 初期状態でweb検索可能でトレンドのエロ知識を拾える点が便利（466）
- チャッピーとStrataを入れ制限解除し、MiniMax h3のskillを読ませて詳細なプロンプトを書かせた例（472）
- 画像生成と併用する場合のVRAMリザーブ目安：16GB環境なら7600〜7800、12GB環境でも3800程度（速度低下あり）で併用可能（336, 364）
- 動的メモリ制御手順：Elastic VRAMモード起動→画像生成直前に`/v1/vram API`でVRAM解放→生成後にComfyUIモデルアンロード→Strata予約解除（323）
- 画像生成処理をスクリプト化・スキル化し、「えっちなやつよろしく」で自動実行させる事例。体位プロンプト等のスキルを作り込むとガチャ率向上（351）
- 起動速度は思ったより早くセットアップ後のフットワークは軽い（361）
- エロプロンプト書きを拒否された事例あり。代わりに動画アプリを作らせたら完成し、プログラミング知識なしでも自分の考えたものが作れるとの感想（370）
- LLM用途では今後VRAM32GBでも量子化程度で限界との見方（578）
- エロ画像キャプション付けの代替としてdeepseekharnessと組み合わせ可能。ただしLoRAがないと綺麗な出力が得られない（888, 950）
- 無検閲版QwenをTextencoderにした方がエロ出やすいか検討したが、スレ上では特に変わった感じはしなかった（369, 374）

### Strataへの批判・代替
- 「純正Strataまだ使ってんのかRAMとVRAMの無駄」との指摘（373）
- RustingStrataはvisionがないとの指摘（384）

### LMStudioが選ばれる理由
- 困っていないため乗り換え動機がない。gemma4が丁度良い（357）
- エロチャやエロプロンプト出力用途なら十分。ESP持ちユーザーがgemma4 31Bでエロプロンプト出力（358, 360）
- 早々にAVX1非対応となり古いPC環境では不向き（815）
- Strata・Qwen3.8-Flash-Next IQ3_SでのキャプショニングとLM Studio製モデルで大差ないとの感想（375）

### llama.cpp
- v1.0.0到達。動的なexpertオフロードが入りStrata風の仕組みになった（777, 778, 808）
- スレ上ではredditで「いまさらstrata風実装は遅すぎ」と叩かれているとの報告。互換性重視で最新実装を後回しにしたためとされている（808）
- 選ばれる理由：互換性重視でメンテナンス継続できStrataの元になれている。AVX1しかない古い中古ノートPC等でも動くため、なんちゃってLLMサーバーとして再利用可能。LMStudio等はAVX1非対応となったため古い環境を支える役割がある（808, 815）

### DeepSeek Flashへの乗り換え
- ほぼ無料で気軽に使え、稚拙な指示でも満足できるエロを出してくれるためStrataやGemmaから乗り換えた（375）

### 量子化ツール（int8）
- MOSS-Imageのint8量子化：bf16でマージしてから量子化する手順。int8でマージするとエラーが出る。画期的だがひと手間増えるとの感想（975, 976, 979）

## Viggle / ref2va / fl2va（動画・swapツール）

### Viggle Remake（fl2va）
- AVスクショを元素材にしたswap編集で高精度。モザイク有り元画像でも差し替え画像が無修正なら無修正になる（672, 722）
- 選ばれている理由：swap精度が良く実用的（実写4/5、アニメ1/5）。1枚のswap編集済み画像があればhigh precisionな差し替え可能（672, 722）
- 制限：FL2VAベースのため音声参照はできない（747）
- Viggle Remake等でv2vを試したが、見慣れた動きを別キャラにしただけではドパれなかった。予想外の動きが欲しいならref2vaに動画を食わせた方が良いとの指摘（381-382）
- Context-Loop理解で「15秒の壁」を突破した報告（378）

## LoRA学習ツール（Fizgig / sd-scripts / musubi-tuner）

### Fizgig
- MOSS-Image Turbo Trainプリセット＋muonオプティマイザで学習試行中（88）
- 学習時間が長い指摘。RTX 4060Ti 16GBでsd-scripts（causal-conv1d導入）より遅い（Fizgig 4時間半 vs sd-scripts 5時間半、条件差あり）（106, 168）
- fastプリセットが速く品質もまとも。解像度512でも劣化なし。train attention only推奨。更新頻度が高いので毎日チェック推奨（184）
- CAME設定について問われる声。解像度512で試したら小物が溶けるゴミしか出来なかった報告（221）
- 総step数50%まで0.25MP・残り1MPで学習、画像毎LR適用・学習が捗ってない画像のLR一時低下オプションを使用例（208）
- キャラLoRAはKohya_lora_param_guiでCAMEを使う方が出来が良いか変わらないという意見（218）

### sd-scripts / Kohya_lora_param_gui
- MOSS学習にsd-scriptsを対応させるにはpython環境構築が手間。Windowsではcausal-conv1dとflash-linear-attentionの公式ホイールがなく自ビルドか野良ビルドが必要（140）
- causal-conv1d未導入だと学習に20時間程度かかる事例。flash-linear-attentionは未導入でも学習に影響なし（146, 158）
- RTX 4060Ti 16GBで60枚・1024x1024画像を解像度512で学習。VRAM消費10GB前後。sd-scripts（causal-conv1d導入）で5時間半（168）
- RTX 5060Ti環境で60枚なら2時間で十分な学習結果（最適化入る前のsd-scripts）（179）
- anima用バッチファイルの必須コマンド置き換えとノイズシフト追加でMOSS用に流用可能（100）

### musubi-tuner
- sd-scriptsのMOSS対応問題に対する代替として言及（152）

### キャプショニング・タグ付けツール
- Qwen3.8FNに長文キャプションを考えさせたものとFizgigのflorence自動キャプションを比較し、学習品質に特に差は見られない（174）
- taggerはオワコンかとの質問に対し、「ローカルモデルにタグを補助的に投げて自然文を書かせる」「むしろtaggerの部族語だけに戻した方が出来がいい」との意見（899, 901, 902）

## クラウドGPU（runpod / vast.ai）

### runpod
- 単純なグラボとの値段比較ならクラウドGPUはグラボ購入より安いが、ストレージ維持費用とモデル・LoRAの保存送信手間が面倒。LoRA学習用途なら良いが生成・普段使いには不便（644, 676）
- モデルのファインチューンでrunpod使用経験：データセットと生成物の転送に時間がかかりストレージも大容量借りると高い。pro6000で一日1万円程度で完全に消費される。グラボは売却できるためレンタルGPUはお得感がない（637）
- 値上げと空き不足：ここ数週間で二度値上げしRTX 5090が$0.99/hから$1.39/hに。vast.aiの倍の値段。最近は空きがない。スレ上では「ローカル大正義」の結論（674, 691, 732, 923）
- グラボは売却して買い替え資金に充てられ（売却益が出ることもある）、それを加味すると限定的用途以外クラウドGPUは安くない（691）

## H3 Image Studio / H3-Image（画像編集ツールとしての運用）

### 編集能力と制約
- フェイススワップ機能があるが雑コラ感が出る。解像度を高くできるが基本的な編集能力はH3 Image Studioが上。人物合成時、余計な書き換えしないのは長所だ顔だけ書き換えると雑コラ感が出る（53, 59, 62）
- ローカルにいい画像編集モデルが来たと評価。プロンプトガイド提供あり（63, 65）
- t2i性能には期待しない方がいい（68）

### キャラクターシート問題と回避策
- H3 Imageの編集で雑コラになる原因は従来使えていたキャラクターシートが使えないため。バラして個別の複数参照画像にしたら雑コラにならず指示に正確な画像ができる（349）
- 純正よりP-H3の方が参照力が強い（103）
- 安定性向上バージョンが出れば評価が変わるという見方（114）

## 総評

1. **ComfyUIのカスタムノードは強力な自動化手段だが、セキュリティリスクが構造上不可避である**。ComfyUI-Easy-Useの脆弱性報告を受け、エージェントで拡張機能を精査・削除する運用や、AIで自作するアプローチが実践されている。無名ノードのevalリスクが指摘される中で、ワークフロー自動化と安全性の両立が現場課題となっている。

2. **画像生成とローカルLLMのVRAM共有を動的に制御する実運用パターンが確立しつつある**。StrataのElastic VRAMモードとAPI連携で画像生成時にVRAMを解放し、生成後にモデルアンロード→予約解除を行う手順が具体化されており、12GB環境でも併用可能な目安が示されている。

3. **クラウドGPU（runpod）の値上げと空き不足により、ローカルGPU保有の優位性がスレ上で強く再確認された**。ストレージ維持費用・転送手間・売却不可能性を加味すると限定的用途以外クラウドは割高との結論。グラボの売却益を見込んだ資金回収がローカル優位の根拠。

4. **museがGemini拒否後のエロ画像キャプション・コーディング代替として実用化されているが、制限回避の運用ノウハウが必要**。警戒モードへの移行をコンテキストクリアで回避する手法や、tailscale入りVM付きという構成の危険性が指摘されており、制限付きツールを実運用に載せる際のトレードオフが顕在化している。
