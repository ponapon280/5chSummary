**抽出結果（ツール関連のみ）**

### 1. **Forge Neo / forge-anima系**
- **言及箇所**: 445, 446, 458, 602, 605
- **内容**:
  - Anima 3.8B / 2.9B を動かすために使用。
  - 3.8Bは通常のForgeでは動かず、専用拡張機能（https://github.com/GumGum10/forge-anima-3.8B）が必要。
  - 拡張機能を入れることでTE（Text Encoder）とアダプターを自動認識させる。
  - 理由として「3.8Bを動かしたいからForge Neo + 拡張機能を選択した」と明記されている。
  - 2.9Bはneo対応済みという情報も出ている。

### 2. **ComfyUI**
- **言及箇所**: 516
- **内容**:
  - Anima生成の合間に並行して使うツールとして言及。
  - LLM（llama.cpp）と同時に動かしている例あり。
  - 特に「生成しながらLLMも動かしたい」用途で選ばれている。

### 3. **llama.cpp**
- **言及箇所**: 509, 512, 516, 522, 554, 565
- **内容**:
  - MoEモデルのオフロード（n-cpu-moe）で使われている。
  - FreeTokenと比較して「VRAMに収まるモデルならllama.cppの方が速い」との評価。
  - 静的オフロード（ロード時にexpertを固定でVRAMに載せる）という特徴が指摘されている。
  - 理由として「安定性・速度を重視する場合に選択」との文脈あり。

### 4. **FreeToken**
- **言及箇所**: 454, 455, 491, 492, 493, 494, 495, 507, 512, 516, 522, 535, 552, 565
- **内容**:
  - MoEモデルのexpert部分を動的にVRAMにロード/オフロードする新技術。
  - llama.cppの静的オフロードより効率的で、5090単体で120B級モデルが実用速度で動く点が評価。
  - RAM（DRAM）へのオフロードが強く、VRAM容量が少ない環境でも高速度（25tok/sなど）が出せる。
  - 理由として「VRAMが足りなくてもDRAMからストリーミングすれば実用速度が出る」「expertを動的に載せ替えるのが強み」と複数回強調されている。
  - 特に「大きなMoEモデルをローカルで動かしたい人向け」と位置づけられている。

### 5. **ollama**
- **言及箇所**: 627
- **内容**:
  - ComfyUIワークフロー内でプロンプト生成に使用。
  - ハングアップや繰り返し出力などの挙動で問題が発生した事例あり。
  - 特に「生成後にプロンプト作成をollamaに任せる」用途で使われている。

### 6. **その他（周辺ツール）**
- **Minimax H3**（575, 624など）：動画生成ツールとして言及。プロンプト作成やアップスケール用途で使われており、Grokと組み合わせてプロンプトを作らせる流れで選択されている。
- **krea2**（441）：実写画像生成の試行で言及されているが、詳細なツールとしての言及は薄い。

**モデルに関する言及はすべて除外**しています。QwenはLLM用途（非画像生成）のみ拾っています。
