**抽出結果**

### **anima**（最も言及が多い）
- **主な話題**:
  - Anima 3.8B（実験的プレビューモデル）の存在と評価
  - Text Encoder（TE）の弱さ（Qwen3-0.6b使用）が繰り返し指摘されている
  - 公式の「VRAM 8GB民を切り捨てない」方針が特徴として挙げられている
  - LoRAの再現性が高い反面、教師データの影響を強く受ける
  - 3.8Bは学習解像度がまだ低く実用レベルではないという意見

- **選ばれる理由（または選ばれない理由）**:
  - **選ばれる点**: 自分でLoRAを作れば世界が変わる、Danbooruタグとの相性が良い、VRAMに優しい
  - **選ばれない点**: 絵柄が「子供の落書きみたい」、TEが弱い（長文・自然言語に弱い）、重い

### **NAI（NovelAI）**
- **主な話題**:
  - NAI v5の話が複数
  - 精密参照の強み、版権キャラの再現性
  - 複数キャラの書き分けや漫画1P生成が強い
  - アーティストタグ一覧対応

- **選ばれる理由**:
  - 版権キャラの再現性が高い
  - 精密参照が強い
  - 複数キャラ対応や漫画生成で有利
  - 自然言語＋タグのバランスが良い

- **比較での言及**: 「animaでもできるけどNAIの方が強い」「NAIの取り柄は版権キャラの強さだけ」という意見が複数

### **Z-Image（Z-Image Turbo / ZIT / ZIE）**
- **言及**: 1件のみ
  - Minimax H3とZ-Imageを合体させているという話
  - 「Minimaxの細部を認識する部分にZ-Imageのその部分を突っ込んで細部の描写を向上させた」という内容

### **LTX（LTX-2.3 / ltx2.3）**
- **言及**: 1件のみ
  - 「LTXでもハゲるほどの時間かければ理論上出来なくはなかった（実際は誰もやらない）」という文脈で、H3との比較として出てくる

**抽出されたモデル関連話題（除外対象除く）**

### 1. Minimax H3（H3 / mini MAX / MinimaxH3）
- **主な話題**:
  - プロンプト追従性の高さが最大の強み。複雑・長文の指示や物理演算・重力理解が得意で、従来は難しかった動画（例: 特定のフェチ表現や連続ストーリー）が簡単に作れる。
  - 日本語自然文対応が強い（TEがQwen3VL-32b級と高性能）。LLMでプロンプトを整形して投入するワークフローが確立されており、Animaのようなタグ中心より自然言語が通りやすい。
  - i2v/ref2vでのアニメキャラ生成も話題。PinkCherryと比較され、「i2vならPinkCherryでも十分」という意見も。
  - 速度・品質面でKitchen Attention + Patch Sol-Attnなどの最適化が議論され、15秒動画生成の実用性が評価されている。

- **選ばれる理由（抽出）**:
  - 「H3なら簡単に出来る」レベルのプロンプト追従性。
  - 日本語対応とTE性能の優位性。
  - 公式skills仕様書があるためLLMにプロンプト生成を任せやすい構造。

### 2. PinkCherry
- **主な話題**:
  - Minimax H3の代替としてアニメエロ動画（特にi2v）で言及。
  - 「i2vならPinkCherryでも十分」という評価。
  - ref2v（参照動画）はまだ厳しいという指摘あり。

### 3. Krea（Krea2 / Krea辺り）
- **主な話題**:
  - アニメ調生成の選択肢として名前が上がる。
  - AnimaのLoRA依存を避けたい場合の代替候補として「Krea2のアニメチューンモデル」の方が良いという意見。

### 4. その他の言及（軽微）
- **Rubin / Rubin Spark**: 将来的な民生向け高性能GPU/モデルとして2028年頃の登場を期待する話。
- **seedance / seedance2.5**: 物理演算・重力理解が優れている動画モデルとして言及。背景設計やロケ地指定の再現性も話題。

**除外対象（anima系・NAI系・FLUX・Wan・Qwen-Image・Z-Image・LTX）は一切抽出していません。**
