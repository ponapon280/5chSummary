# なんJ AI画像生成スレ レポート

## モデル別動向

### MOSS（moss / moss-image）
- 三次元出力はポン出しで70点、サンプラー変更で見慣れたモデルになるとも（249, 285）
- VRAM16GBないとしんどい（344）
- 画風が安定しない（330）。顔にAI感がある（270）
- 美人・体型向上指示なしだとガチの一般人が出る（285）
- 背景が強力（400）。トイレ完璧に出せるか未検証（365）
- 4コマ漫画量産に有用。タイトル・セリフ・json出力をLLMに書かせ、jsonをコピペで実行可能（384, 416）
- LLMの創作能力が上がれば更に伸びしろあり（402）
- 美マンオブザイヤー狙える（431）

### MOSS LoRA
- ドット絵画風LoRAをcivitaiでトレーニング。MOSS Image Base, dim32/alpha32, AdamW8bit, LR 1e-4, constant 1700steps, 100images(x8 scaled), 1024 res。1時間14分で2000ステップ終了（372）
- 適当な設定で50分学習でもそれなりにいける。CAME使用。生成遅い（373, 400）
- animaと比較して、かかる時間の割に出来がもう一歩。英文なしタグのみでもそれなりに絵が出る（400, 435）
- キャラLoRAは再現できているが、素材より高精細になる現象あり（356）
- LoRAが続々登場し始めている。トリガーワードにgemma4キャプション使用が検討される（409）

### MOSS機能面
- 画像参照・画像編集は現時点で未対応。画像参照版を自作したと主張する者はいるが非公開。公式ワークフローで画像入力を繋げられる箇所があり、低精度ながら画像参照的な運用は可能（291, 293, 294）
- bboxは区切りが柔軟で、強いプロンプトを入れた箱の影響が周囲に及ぶ。要素同士のインタラクトのため必要（275, 279）
- 定点カメラ漫画に向く（305）。フキダシのしっ尾の向きが指示通りになる（317）

### Krea2
- 空想上の超絶美少女写真に優れる。ChatGPT（チャッピー）は現実に存在しうるレベル、に至ってはその辺にいるレベルしか出さない（234）
- エッチくできなかったため埃を被っている（232）
- identity editのv2は画像に忠実だがガビガビになる（311）
- civitaiの写真風・低解像度写真LoRAの活用が推奨される（290）

### Minimax
- パルクール等のアクションが可能で素の性能が高い（287）
- 遠景でキャラが小さくなると顔や髪を維持できず溶ける（343, 412）
- 1.6MP作成でも輪郭がボケ、アップスケしてもボヤケたまま拡大される。SAM3での切り抜きにも支障（313, 316）
- 細部ボヤけはAI生成物をAI学習した特徴の一つ（314）
- グロは一応出る。ゾンビに腹部破られて腸が出る描写は可能（401）
- アニメキャラで少し動くと顔や手が溶ける。ターボを切ると多少マシ。De-RoPE処理ノードで引き延ばしてスローモ再生成→縮める修正も可能だが時間がかかり完全修正ではない（432）

### WAN
- 非エロなら性能高い。犬や猫の画像を入れると自然に動く（281）
- パルクール等のアクションは不可で、動画生成の気さえ起きなかった（287）

### Anima / リアス
- anima・リアス・MOSSで同一素材のLoRAを作成したところ、クオリティはanimaが一番。MOSSは時間の割に出来が足りない（435）
- nsfwを入れると画質が落ちるためsafe入れたままエロを出した方が綺麗な絵が出る。勢い重視のんほぅ画像ならnsfw抜き（280）
- リアスは陰毛の描き方が良すぎて乗り換えられない（425）。設定煮詰めている分美人が出る（249）

### ChatGPT（チャッピー）
- 現実に存在しうるレベルの美少女しか出さない（234）
- 1枚ずつ画像を作らせると時間がかかる（251）
- ComfyUI関連のpythonファイル作成に利用し、Ultimate Lora Loader移行時のメタデータ不具合を解決（427）

### Gemma4 / LLM全般
- プロンプト生成だけならreasoning有効のgemma 4 e4Bで充分。シスプロを少し書けば規制も100%無効化可能（376）
- 3060 12gbでエロ漫画プロンプト作成にgemma12bを使用したが上手くいかない。31Bかstrata推奨。構造組み立てはstrataに分がある（337, 342）
- gemma-4-12bを4090でvLLM/SGLangフレームワーク使用、同時100多重で合計1600token/s（364）

### Strata
- メインメモリとVRAM合計32GBで動作可能（357, 368）
- MoE効率化が本質ではなくN-gramのSSDオフロードが本質。MoEのみならFreeToken等の別ツールが向く（370）
- N-gramを持たない小規模LLMには意味がない。DeepSeek-V4.1-FlashはEngramがN-gramとほぼ同じためStrataで扱いやすい（370）

### DeepSeek V4.1 Flash 1017
- SOTA級で無料化。Gemini・ChatGPT無料枠は終わったとの評価（354）

## ComfyUI / ツール関連
- MOSSのノードで自作画像ビューワ「Nivis Viewer」更新。バグ取りと改善がメイン、1.2以降速度改善（278）
- MOSS画像参照ノードはComfyUI最新版で動かなくなる。修正方法あり（378）
- Nodes2.0対応でPower Lora LoaderからUltimate Lora Loader Civitai移行時、Save Image w/ Metadata UniversalでLoRAが拾えなくなる問題。rgthree.py元にpyファイル追加で対応（427）
- 背景動画からキャラ切り抜きはAEで楽だが普通の背景だとうまく行かない。ロトブラシは汚くなり、ltxは時間かかる（268）
- 緑背景以外からの切り抜きにベストなツールの問いがあり（268）

## 生成技術・ノウハウ
- MOSS ComfyUIテンプレWFでエロエロプロンプト作成にはLoad CLIP→Generate Text途中にLoRA強度1で挟むとuncensored化（381）
- 衣装画像入力lora無しでも強引に突っ込めば衣装参照がある程度可能（298）
- comfy公式テンプレートのネガティブプロンプト初期値に「nsfw」が入っている（271）
- フキダシ文字入れはbbox方式が覇権。配置・透明度・大きさ・形の正解が分からなくなる手作業より自然（256）
- AIによる4コマはクソおもんない。きらら式にすればつまらなくても一応読める（308, 315, 319）

## NSFW / 規制関連
- スレ民はエロ前提でハードルを高くしているが、非エロなら性能は高い（281）
- NSFWだと公式っぽさが崩れて微妙になる。NAIも同様、Qwenの宿命か（282）
- エロを犠牲にしたデータセットで作られたものは使う価値ないとの主張（286）
- Grokは以前ロリエロモブレイプを出せたが最近厳しくなった（350, 355）
- 腟内断面図・コンドーム射精絵はまだプロンプトだけで作れない（371）

## 中国モデル規制
- 中国政府が海外へのモデル移転・稼働を禁止。API提供は可。falがminimaxオープンソース化を無かったことにしている可能性（369, 380）
- 既に公開済みのモデルで打ち止めかとの問いあり（396）

## その他話題
- ペットのAI動画生成について、死別したペットを動かす需要あり。Xで勝手に亡くなったペットの動画を生成して炎上した事例あり（295, 297, 312）
- AIで故人を再現する事例。法廷で遺族がAI再現した被害者の姿を再生（333）。ディジタルイタコ需要の指摘（335）
- 実写映像にアニメキャラを被せてvlogを作りたいという相談。動画AIだと3Dで不自然、チャッピーで1枚ずつは時間かかる。良い方法を模索中（251, 260, 421）
- 万紫千紅をクリアしMOSSに注力との報告（407）
- 世界樹シコシコニキは優秀なベンチマークとの評価（258）
