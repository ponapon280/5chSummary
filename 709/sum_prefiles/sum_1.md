# MOSS ローカル運用・学習・検証スレ まとめレポート

## 1. MOSS ローカル環境・推論

- **ForgeNeo での非公式動作**：MOSS は ForgeNeo で動作する（非公式）。BBOX 拡張も導入可能（>>42, >>47, >>73）。
- **3060 での高速化**：ワークフローを調整し 8steps LoRA を使用することで、3060 環境で 1MP の画像を 10秒 を切る速度で生成。SDXL より速くなったと報告（>>43）。
- **4K 解像度は遅い**：3060 環境では軽くて速いが、4K サイズにするとさすがに遅い（>>151）。公式の推奨解像度は 4MP (2K) まで（>>160）。
- **VRAM 負荷**：sd-scripts で MOSS LoRA 学習を試したところ、VRAM に収めても重い。unsloth の offload より block_swap の方が速いと kohya ニキが指摘（>>19, >>53）。LMStudio を起動しながら 31B モデルを動かすと VRAM から溢れる（>>138）。

## 2. MOSS LoRA 学習

- **sd-scripts での学習**：sd-scripts で MOSS LoRA 学習を実施。CAME を使用すると Anima の倍くらい処理時間がかかるが、問題なく学習できる。衣装は色や形状をざっくり指定すれば学習される（>>127）。int8conv の base で作成した LoRA は学習がイマイチだったため、bf16 の base で STEP 数を増やして再検証中（>>94）。
- **Fizgig の活用**：Fizgig で画風 LoRA を作成。7000 ステップで平均 Loss 0.67（>>218）。kohya_lora_param_gui がおま環で動かなかったため ai-toolkit を使用。CAME 実装がないためrequirements.txt への追加や optimizer.py へのチャッピー（ChatGPT）を用いた実装追加などの工夫が必要（>>64, >>116）。
- **学習時間の目安**：4070s 環境・1000step・1024×1024 で約 1時間20分（>>168）。3 時間回して LoRA 学習成功した報告あり（>>45）。5 時間回しても Loss が下がりっぱなしで底打ちしなかったケースも（>>171）。
- **タグ付け**：部族語＋自然言語でやるべきか悩む声。画風 LoRA はそのままで機能したが構図 LoRA は悩みどころ（>>123）。Z-Image 時代のデータセット（先頭にトリガー、LLM 出力キャプション、Tagger 出力タグ）を Krea2 や MOSS で使い回している。日本語併記は不要だが問題は起きていない（>>211）。
- **版権キャラ LoRA の限界**：衣装やポーズ参照 LoRA は実用的だが、版権キャラの目のデザインなど細部が違うと台無しになる。個人が手を出すのは厳しい領域（>>144）。

## 3. MOSS ポン出し性能・評価

- **ポン出しで高品質**：LoRA 無しのポン出しでここまでいけると評価（>>51, >>67）。部族語がそこそこ使え、調整しなくてもリアスに近い絵が出る（>>35）。
- **漫画生成**：BBOX 指定だけで漫画フォーマットが自然に整い、ポン出しで綺麗な漫画台詞が出る（>>31, >>80, >>83, >>85, >>86）。
- **版権キャラ**：有名キャラは結構出る（>>59）。ただしキャラ名ポン出し性能はリアス相当かやや劣る。マイナーキャラは他キャラが混ざる印象（>>76）。
- **3次元（実写）**：Base モデルで素人感のある実写がよく出る（>>131）。3次は Krea2 に比べると画質がイマイチだが、エロ系で壁にぶち当たりにくくプロンプト流用ですんなり移行できる（>>224, >>231）。
- **8steps の品質**：MOSS 8steps で得られる画像はかなり微妙。同じ速度なら kroma (krea2 turbo) と品質差があり、キャラ再現性は Anima の方が上（>>155）。turbo 抜きでも特化型モデルには単純な画像品質で負ける印象。テキストレンダリングや一般化能力は高い（>>157）。

## 4. Anima との比較・移行状況

- **Anima から MOSS へ**：Anima は DiT の有効性を示したもので 1.5 や Pony のようなもの。キャラや絵柄は Anima、自由度とオブジェクトの美麗さは MOSS で一長一短（>>49, >>60）。
- **Anima の将来**：Anima は成長する可能性が薄くなった。MOSS のアニメ版が出るまでは Anima メインで行く声もある（>>91）。RX9060XT+Neo で Anima が使えるようになってからまだ 2 ヶ月（>>75）。
- **MOSS アニメモデル待ち**：次はアニメモデルが予定されており、それを待つ声が多い（>>58, >>61, >>69, >>90, >>117）。

## 5. ツール・UI 周辺

- **MOSS 専用 UI**：MOSS 専用 UI を自作して使っているユーザーあり。ComfyUI 使えず ForgeNeo も使っていないニッチな層向けになる予測（>>140, >>142）。専用 UI を作っても 1円 にもならない（>>137）。
- **BBOX ノード fix 版**：MOSS Image の BBOX ノード fix 版をクラシックでも使用可能にした。幅と高さを取得してキャンバスサイズを即時反映、Alt＋左クリックで重なってるボックス選択、ダブルクリックで直接プロンプト入力などに対応（>>124）。
- **RedRayz**：MOSS に暫定対応（>>179）。

## 6. 文字入れ・漫画制作

- **文字入れの要望**：MOSS で i2i や inpaint で既存画像への文字入れを試みる声。denoising を上げないと文字が出てこないが、上げすぎると絵柄が変わる（>>166, >>177, >>185）。
- **手書きフォントとの比較**：文字入れは手作業でも慣れが必要で、ポン出しで手軽に日本語が入る MOSS は貴重（>>180, >>182）。
- **漫画制作の理想**：キャラ 3 人を指定してコマごとに動きを指定できるソフトがあれば超絶需要がある（>>165）。ネーム力は身につけるべきという声も（>>201）。

## 7. Krea2 動向

- **Krea2 の状況**：Krea2 は 3 がオープンウェイト確定したため待機状態（>>202, >>205）。MOSS と比較すると画質は Krea2 が上だが、エロ系で壁にぶち当たりやすい（>>231）。

## 8. LLM 動向（MiniMax 等）

- **MiniMax**：LLM で 1位 になりそう。コーディング性能は Astra・Opus5 Max 並みで DeepSeek v4.1 1017 未満。23日にウェイト公開予定でエージェント用特化型（>>97, >>100, >>101, >>110）。
- **LLM ベンチマーク**：benchmaxxing と連呼されている（>>125）。「さっさと使わせろ」という声（>>113）。
