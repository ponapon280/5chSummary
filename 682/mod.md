# 元の本文
**レポート：ログから見る生成AI動画・画像モデルの動向（2026年時点）**

### 冒頭まとめ：流行っているモデル
ログ全体を通じて、**MiniMax H3（H3 / MMH3 / MiniH / minimaxH3）** が圧倒的に話題の中心であり、**現在最も流行・採用が進んでいるモデル**として位置づけられています。旧来のWan、LTX系を置き換える「新基準」として多くのユーザーが主力採用しており、「H3登場による断捨離」が共通のテーマです。選ばれる主な理由は、長尺（15〜30秒クラス）生成の安定性、プロンプト理解力・キャラ一貫性・日本語性能の高さ、参照機能の優秀さ、ワークフローのシンプルさ、エロ・NSFW対応の柔軟性です。これにより、以前の複雑なLoRA多段構成から脱却した実用的な運用が可能になった点が評価されています。[[1]](https://www.minimax.io/blog/minimax-h3)[[2]](https://fal.ai/minimax-h3)

他のモデルは用途特化で残るか、H3に押されて廃棄・HDD移行の傾向が強いです。

### 主要モデルの詳細と選定・廃棄理由
ログから抽出された主なモデルについて、言及内容・選ばれている（または廃棄される）理由をまとめます。

**MiniMax H3（最も活発に議論・採用）**  
- **選ばれている理由**（ログから複数確認）:  
  - 長尺生成・Context Loop / Motion Contextの自然さ。  
  - プロンプト理解力・キャラ一貫性・カメラワーク・日本語（感情表現・リップシンク）の優位性。  
  - Reference機能（ref2va系）の精度が高く、画像・音声参照で任意のキャラ動画生成が可能。  
  - ワークフローのシンプルさ（Wan時代の複雑なスパゲッティ状態から脱却）。  
  - エロ・グロ対応の強さ、低ステップ（8step）でも実用速度。  
  - 1枚絵からLoRA学習データ量産に活用可能。  
- H3の登場で「エンドユーザーの最低ラインが切り上がった」「他に選択肢がない」という声が多数。ComfyUI導入のきっかけにもなっています。fl2va（通常生成・品質重視）とref2va（参照特化・音声参照可能）の住み分けも活発に議論され、ref2vaのバグ指摘から「refワークフローでもfl2vaを使う」手法が推奨されています。[[3]](https://xhinker.medium.com/minimax-h3-everything-i-know-after-days-of-testing-what-works-what-not-648e4df78128)[[4]](https://lmsysorg.mintlify.app/cookbook/diffusion/MiniMax/MiniMax-H3)

**Wan（Wan2.2など）**  
- H3登場後に廃棄・HDD移行が多数。ストレージ占有量（数TB）が大きい点が主な廃棄理由。  
- 残す理由（少数）：シームレスループ作成可能、画質・エロ速度でまだアドバンテージがある、時々良い派生モデルが出る可能性。  
- 全体として「もう要らん」「H3で代用可能」との評価が優勢。[[5]](https://huggingface.co/Wan-AI)

**LTX（LTX2.3 / LTX2.5 / LightX2Vなど）**  
- 高速化モデルとしてturboと比較されるが、H3に品質で劣る（画質のガビり、動きの崩れ、日本語性能の弱さ、エロ苦手）との声多数。  
- 選ぶ理由：生成速度が非常に速い（H3の数十倍という報告も）。  
- 廃棄・敬遠傾向が強く、「H3があれば不要」「動きの幅が減る懸念」も指摘。LTX2.5リリースで一部再評価の動きあり。[[6]](https://ltx.io/model)[[7]](https://venturebeat.com/technology/ltx-2-5-can-generate-a-10-second-ai-video-from-an-image-in-just-6-8-seconds-on-nvidia-superchips-and-its-open-weights)

**anima**  
- LoRA作成・参照画像生成・1枚絵用途で残されている。  
- 選ぶ理由：danbooru系アニメモデルとして安定したキャラ生成・LoRA学習に強い（H3生成画像を補助素材に活用するワークフローも報告）。  
- 課題：解像度上げ時のノイズ、Hires fixとの相性悪さ、画質の不安定さ。H3との併用構成（リアス・anima・H3）が定着しつつある。[[8]](https://huggingface.co/circlestone-labs/Anima)

**FLUX系（fl2va / ref2va）**  
- H3内のバリエーションまたは関連ワークフローとして議論。  
- fl2va：通常生成・T2V/i2Vでの画質・安定性が高い。  
- ref2va：参照（画像・音声）用途に強く「手放せない」声もあるが、T2V単体だとノイジー・品質低下の指摘あり（公式バグ認識中）。  
- 住み分けが明確で、refワークフローでもfl2va推奨の声多数。[[9]](https://www.reddit.com/r/StableDiffusion/comments/1vk6j2w/anyone_figure_out_how_to_get_fl2va_quality_with/)

**illustrious（リアス / IL）**  
- エロ表現・細部描写・仕上げ用途・参照画像作成でまだ出番あり。  
- 「エロと細部でまだ出番ある」「思い出補正で捨てきれない」理由で残す人が多く、H3との3本柱構成例が見られる。

**その他のモデル**  
- Krea2：静止画・素材作成・LoRA学習用途でH3と併用。  
- Qwen-Image / Z-Image / NovelAI：言及少なく、選択的に残すor廃棄の報告のみ。  
- 高速化関連（Sage Attention、Comfy Kitchen Attention、turbo系）：画質とのトレードオフを意識した議論が多い。

### 全体傾向
H3の登場が最大の転換点で、「実用性・品質・シンプルさ」を重視した断捨離が進んでいます。残す基準は「今実際に使っているか」「特定用途（LoRA学習・参照・エロ細部）に必要か」です。速度重視ならLTX、安定アニメ画像ならanima、参照特化ならref2va系という棲み分けが見られます。
