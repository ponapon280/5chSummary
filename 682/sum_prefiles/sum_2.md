**なんJ（5ch）スレッド要約レポート**

### スレッド概要
このスレッドは、主にローカル環境でのAI動画生成（特にComfyUI）を中心に、**モデル管理・ストレージ整理・生成品質・ワークフロー改善**を議論している。  
話題の中心は **MiniMax H3（H3）** の登場によるモデル断捨離で、Rias・Anima・Krea2・H3の3〜4モデル体制に移行する人が多数見られた。

### 1. モデル保有・断捨離の傾向
- **現在主流の構成**：Rias + Anima + H3（±Krea2）
- **ほぼ全消しされたモデル**：Wan2.2/2.3、LTX2.3、Pony、Illustriousなど
- **理由**：H3の性能が非常に高く、容量の大きい旧モデルを保持するメリットが薄れた
- 思い出補正で残している人もいるが、「ストレージの余裕を取る方が大事」という意見が優勢

### 2. 技術的な話題
| テーマ | 主な内容 |
|------|---------|
| **Ref2VA vs FL2VA** | Ref2VAは参照は強いが画質・音質がFL2VAに劣る。FL2VAにRef2VAの参照層をマージした方が良いという報告あり |
| **Attention Backend** | Comfy Kitchen Attention / Sage Attentionの比較。Sage Attentionがやや優勢だが、環境次第で差が小さい |
| **生成時間** | 解像度（0.4MP→0.6MP）と尺（10秒→20秒）で急激に時間が増える。VRAM16GBでも15秒超は厳しい報告多数 |
| **参照画像サイズ** | `ref_image_size=max`にすると生成時間が大幅に伸びるため、match推奨 |
| **否定形プロンプト** | まだ効きが不安定。否定したい要素を「消す」方向で書く方が確実という意見 |

### 3. ハードウェア関連の話
- **VRAM12〜16GB**：H3は軽量化すれば動くが、余裕はない
- **RAM**：64GB以上推奨。32GBだと厳しい
- **ストレージ対策**：`pip cache purge` + `uv cache clean`で30GB程度空くというTipsが共有された
- 大型モデル（LLM含む）を複数持っている人は、動画モデルよりLLMの方が容量を圧迫しているという声も

### 4. その他の傾向
- **NSFW寄り**：フェラLoRAやセリフガチャ、キャラ参照でのエロ動画生成の話がかなり多い
- **ツール更新**：Irodoriの更新、ComfyUI新ノード（Comfy Kitchen Attention、Spectrum Applyなど）の話題
- **生成Tips**：Context-Loop、Model Preview Override、Motion Contextなどの新機能検証が活発

### まとめ
H3の登場により、**「Wan・LTX時代から完全に移行した」**という空気感が強いスレッド。  
現在は「Rias・Anima・H3」の3モデル体制を軸に、**参照機能の精度向上**と**生成時間の短縮**を模索している段階にある。  
ストレージ容量と生成品質のトレードオフをどう取るかが、参加者の主な関心事となっている。
