# 元の本文
**なんJスレッド要約レポート: MiniMax H3（minimax_h3 / H3）**

### スレッド概要
本スレッドは、MiniMax H3（通称H3）のリリース直後に活発化したローカル動画生成モデルの評価・技術共有スレッド。Wan2.2やLTX2.3との比較が中心で、特にNSFW用途での性能評価が多い。全体として「Wan2.2からの明確な世代交代候補」「ゲームエンド級」との評価が支配的で、「ローカルでここまで高品質な動画が作れるようになった」という強い興奮が見られる。

### モデル仕様
- **2系統のバリエーション**が存在：
  - **FL2VA**（First/Last-frame to Video）：先頭・末尾画像を指定する比較的軽めのモード。
  - **Ref2VA**（Reference to Video）：複数画像・動画・音声を参照するフル性能モード。
- テキストエンコーダーも大規模（最小構成で数十GB規模）。
- int8量子化版（pruned_int8_convrotなど）やint4版が公式・コミュニティから提供されており、軽量化モデルが主流。
- 出力は最大2K解像度、5〜15秒程度のクリップで、ネイティブステレオ音声（セリフ・効果音・BGM）も同時生成可能。

### ハードウェア要件と動作環境
- **推奨スペック**：RTX 4090/5090クラス + RAM 64〜128GB（96GB以上が快適）。
- **最低ライン**：RTX 3060（12GB）+ RAM 64GBでも低解像度・短尺で動作確認あり（ただしページファイル使用や低解像度推奨）。
- VRAM 16〜24GB + RAM 64GBクラスが現実的なボーダーライン。低スペック勢はint4/int8量子化やEasyCacheで軽量化を模索。
- ComfyUI 0.30.0以降が必要で、公式テンプレート（T2VA/FL2VA/Ref2VA対応）が提供されている。

### 生成品質と評価
- Wan2.2やLTX2.3と比べて**一貫性・プロンプト追従性・動きの自然さ・日本語対応**で優位という声多数。
- 特に顔の一貫性、細かい動作（片目ウィンク、服の変化、スカートめくりなど）、カメラワークが素直に出る。
- 2D/アニメ系でのキャラ一貫性・画質も高評価。参照機能（Ref2VA）が強く、絵コンテ＋複数参照画像での生成が実用的。
- 短尺（5〜15秒）は実用的だが、長尺化や高解像度では時間がかかる。

### NSFW対応
- オープン版は検閲が緩く（またはほぼ無い）という報告が相次ぐ。「おっぱい」程度は普通に出る。
- 過激な性行為シーンはまだ不安定（形状の崩れや消失）だが、期待値は非常に高く「おしっこ・排泄系は比較的強い」という声も。
- LoRA待ちの意見も多いが、ベースモデルだけで一定のエロ表現が可能と評価されている。

### ワークフローと最適化
- 主流の高速化手法：SageAttention（特にTriton版、必須級）、TeaCache/EasyCache、Torch Compile、Sol-Attn（長尺向き）。
- 低解像度（0.4〜0.5MPix）生成＋後段アップスケールが推奨。
- 公式ワークフローをベースに、参照画像活用のRef2VワークフローやLLM（Grokなど）によるプロンプト整形が共有されている。
- 5090環境で0.5MPix・10〜15秒動画が数分〜10分程度で生成可能という報告多数。

### 課題と制限
- 生成速度が遅め（数分〜十数分）。最適化で改善するが、まだ発展途上。
- メモリ消費が激しく、VRAM/RAMオーバーフローが発生しやすい。
- 複数人物の同時制御や音声制御（中国語混じり、BGM/ボイスが勝手につく）が不安定。
- ライセンスが厳しく、米国・EU・韓国などで利用制限の可能性（日本国内は比較的緩いとの見方）。出力物の公開に関する条項も議論されている。
- 量子化版は画質低下の報告あり。

### コミュニティの反応と総評
スレッドは非常に盛り上がっており、「Wan2.2とLTXはもう用済み」「新時代・革命的」という声が多数。無検閲で高品質なローカル動画生成が実現したことに強い期待が寄せられている一方で、生成速度・極端なNSFWの安定性・長尺化はまだ課題として認識されている。  
今後のLoRA普及とさらなる高速化ワークフローの登場で、さらに評価が上がる可能性が高いと見られている。MiniMax H3は現時点でローカル動画生成の新王者候補として注目を集め、特にNSFW用途でのポテンシャルが高い。
