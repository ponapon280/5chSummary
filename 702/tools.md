## ComfyUI

### 移行理由と立ち位置
Forge/ReforgeからComfyUIへの移行が進んでいる。理由は「AIにお好みのカスタムノード簡単に作ってもらえる」ため（>>179）。画像だけ出すのではなく他ツールと連携させるならComfyUIは必須という意見（>>198）。一方で、Forge/Reforgeでは欲しいものがポン出しできるため移行できていない声もあり（>>163, >>185）、LLMに質問しながらでないと使えないという声もある（>>185）。

### Strata連携とAPI経由の自動生成
ComfyUIのOpenAI互換カスタムノードからStrataを動かすことは可能だが、モデルのアンロードが効かない問題がある（>>205）。ComfyUIの既存ノードでStrataでのi2tと処理後のアンロードを実現する構成も報告されており、Strataのモデルアンロードはcomfyui-requestnodesのRest Api Nodeを使用。プロンプト出力を空文字に変換してrequest_bodyに入力することで実行トリガとしている。ロード時間が約24秒、i2t処理含めて約40秒で完了し、LM Studio/gemma-4-12b-it-uncensored@q8_0の既存フローより20〜30秒短縮された（レス243）。Strataにエロ画像を渡し、前後シチュエーションを考えさせてForgeNeoやComfyUIのAPIで画像生成させる自動生成フローも確認されており、体位変更や絶頂シーン、再生成指示を出すレベルで動作している（>>138）。

### Strata・ComfyUI間のVRAM競合対策
VRAM16GB環境でStrataとComfyUIを併用するとVRAMが被るため、bat処理でモデルのロード/アンロードを管理する運用が組まれている。Strata起動時にComfyUIのモデルをクリア、ComfyUIで画像/動画モデルロード前にStrataをアンロード、OpenWebUIでチャットやツール使用時にComfyUIのモデルをクリア、等の処理を実装（549）。

### フリーズ・停止問題
最新版Pull後にComfyが停止する現象が確認されている（4時間使用で2回、中国語ログが出る、レス312）。H3生成中にComfyUIが止まり、pythonが応答不能になりタスクキルすら受け付けず再起動が必要になる現象も報告され、ComfyUI 0.36.0〜0.38.0でpythonフリーズを確認（レス315）。メモリ関連の可能性があり、RTX3070+RAM64GBでは止まるがRTX5090+RAM192GBでは止まらないとの対比がある（レス320）。古いカスタムノードがワークフロー内で使っていなくてもあるだけでぶっ壊れる要因になるため、ネイティブノードとエージェント自作のシンプルなカスタムノードだけで再構築が推奨されている（レス324）。

### エージェント機能・パッケージ配布
ComfyUIにも公式エージェント機能が実装される予定。クラウドでは実装済み、ローカルは数週間後（レス331）。Install.bat / Start.bat形式でインストール・起動可能なパッケージも作成されており、空き容量100GB推奨、日本語プロンプトを適切な英文プロンプトに変換する機能付き（レス322）。

### UI・ノード関連の不具合と対応
- パラメータ変更時のクリック無視問題（>>152）
- Power Lora Loaderの矢印クリック無反応。原因はrgthreeとComfyUI新フロントエンド干渉。フロントエンドを1.39.19まで戻す回避策がある（>>172）。rgthreeが修正、本体とノードをgit pullすると解消（>>177, >>182）
- ComfyUI_frontend v1.53.6にアップグレードすると画像(webp)からワークフローが読み込めなくなる。v1.52.7にダウングレードで解消、latestのv1.56.2を試す提案あり、JSONで回避可能（536, 538, 540）
- ノードの繋ぎ方次第で埋め込みプロンプトが消えて読み込みできなくなる問題（>>126）
- 生成画像の自動アップロード機能がオフにできず「恐ろしくて好きに作れない」との懸念。「Comfyクラウド」の話題ではないかとの推測あり（631, 634, 635）

### カスタムノード・拡張
- フォルダごとにlora選択できるローダーが便利だが表示がでかい（>>167）。plaguekindカスタムノードにもPower LoRAローダーに似たものが入っている（>>168）
- was node旧版更新停止時にcodexに新バージョン対応で暫定対処させた。自分用カスタムノードとして自作した方が後々便利（>>174, >>175, >>176）
- jevノードのTypedDecisionノードとStart Loopノードを組み合わせてフォルダを利用した自動判定が可能（>>161）
- strata+QWEN3.8にpromptを書かせるノードを作成。与えられたキーワードをもとにランダムで要素を補完させる仕組み（718）

### minimax・動画統合
minimax導入方法が分からずcodexに頼み「赤ん坊でも使えるUI」を作ってもらった。配布用作らせる予定（>>110, >>121, >>127）。画像も動画も音声もComfyUIで生成できるようにしたカスタムノードを作成。v4-largeは標準UIだとVRAM不足で動かなかったがComfyUIならDynamic VRAMに対応させて動かせた（>>183）。MiniMax H3でDaSiWaのワークフローを使っている人が多いが、高速化が弱くクソ遅いため最適化で1日潰したという報告（505）。

### 生成遅延
生成が遅過ぎ、NEOの3倍くらいかかる。ネット調査とAI相談でチューニングしても直らず、クリーンインストールの可能性も示唆（レス350）。

## Strata

### 選定理由
ローカル動作のため機密文書や社外秘のソースコードも漏洩リスクなく使えるのが気持ちよいと評価（483）。prompt生成においてgrokよりstrataの方がかなり良いとの評価（694）。Blender等のMCP操作がLM StudioからのGemma4ではできなかったため、strataでqwen3.8 flash next環境を作った（598）。規制解除版でエロ画像を渡しても安全フィルターが出ない（>>135）。ただしq4を使いたかった場合はStrataではなくFreetokenを使用しているとの声もあり、大して変わらないはず（787）。

### 規制解除・ガードレール
セットアップ時の最終質問の回答をyにする（>>150）。規制解除版でも素は猫かぶっているため、システムプロンプトで口説いてエロを全開放させる必要がある（651）。未成年系はガードレールが残っており、スクリプトに「18+」と書いてあるためAIが騙されている状態（662）。インストール時に`START-HERE.bat --setup --experimental-speed-projection on`のオプションをつけるとガバガバになる（625）。規制解除版をインストール出来たが画像読み込みは本家しか出来ないという問題も発生（>>879）。

### 性能・リソース消費
4080s/9900X/192GB環境でIQ3_S オプション規制解除版：初回 Thought for 33.7s / 2,430 tokens / 63.9tok/s、2回目 Thought for 4.1s / 588 tokens / 63.4tok/s、現時点最速77.5tok/s（>>113）。5090でVRAMフル使用、RAM74GB程度、デコード125t/s（717）。Strataで70token/sくらい出ている（>>936）。ただしトークンの上限が大手チャット程ないためそこで気を使う。会話中に他の生成が出来ないのもストレス（>>970）。

### 量子化モデルの選択
- IQ3_XXSならOrcaRouter、IQ3_Sならmradermacher（714）。ただしGrokくんは「IQ3_SならmradermacherはStrataで使えない」と言う（750）
- IQ4入れると10tok/s下回るためorcarouterのiq3_xxsを使用（715）
- orcaRouter版IQ3_XXSはDLしただけではStrataで使えないため、手順書のmdファイルを熟読するかAIにやってもらう必要がある（723）
- RAM 64GB以下組はStrataで軽い目のqwen原版モデルを使って無修正コマンド入れてやらせるのが良い（725）

### 他ツールとの連携
OpenAI互換・Anthropic互換のAPIが用意されており、LM Studio、Bionic、その他エージェントと接続可能（>>199, >>211）。Unsloth Desktopでも使える。Bionicより手軽だがエージェント機能は至れり尽くせりではない（565）。BionicにはOpenAI互換API経由でローカルLLMを使うカスタムプロバイダ機能がないため使えない。代わりにOpenWebUIを使用（565, 566, 594）。素のUIはシンプル過ぎで画像のDrag & DropもできなかったためClaudeにlibreChatの導入とStrataの連携をやってもらった（612）。アプデ後は素のUIでもDrag & Dropできた（623）。LM Studioで動かしてるが際どい質問は答えないで思考だけで止まる問題（>>194）。LM Studioではプラグインが必要（>>211）。LMSTUDIOとBionicでStrataの8080に繋ごうとしてもエラー出るという報告（>>200）。

### MCPサーバー接続
Strataの設定変更でMCPサーバーとして同venv内にcomfy.exeとcomfy-mcp.exeをインストールし、別venvのComfyUIと接続確認できたが、RAMの空き容量が数GBになりメモリ不足に陥る状態（>>913）。StrataにMCPで検索APIを繋げて使わせようとしている（>>967）。6.1sol高でMCPを使い10時間以上作業させても使用量5%も減らない燃費の良さを見せたが結果が出せなかった（528）。

### 動作環境
グラボ2枚挿し＋RAM128GBあれば常駐させて画像・動画生成できる（488）。メモリ128GB＋5070Ti環境でも余裕（607, 608）。Flash Next Q4はMTPなしならメモリ128GBクリアでVRAM8GBでもギリ行ける、12はあった方がいい（616）。swift1.5を入れた場合、メモリ64GBだと実用は厳しくスワップ発生する（605）。Google Colab上でも構築可能だが跡を残さない前提（>>209）。

## irodori (irodoriTTS)

IRODORIで遊んでいたら10時間溶かした。革命すぎる（>>43）。1年以上前からあるとの指摘（>>44）。参照音声なしの場合、声の性別がseed値でランダムガチャになる。男女くらいは選ばせて欲しい（>>132）。VoiceDesignで性別制御できる可能性（>>133）。囁き声を出す方法が分からない、Gemini TTSと比べて弱い（>>213）。絵文字で制御できるらしいが効果はいまいち（>>223）。UI自作中だがバチっと決まらず、チャッピーにUIイメージ画像を生成させ、それをベースにUI作らせている（>>180, >>181）。

VoiceDesignで好みの声をサンプリングし、通常版でリファレンス音声として指定するのが基本の使い方（レス253, 259）。VoiceDesignで作成、キャプション「耳元でささやくような小声で,優しく,ASMR」、参照ファイルや絵文字は不使用（レス245）。ボイスクローンでテンション調整が難しいという課題。生成した音声をリファレンスとしてボイスクローンで別テンションのセリフを読ませると感情が引き継がれてしまう。効率化の方法としてseed値固定で1個20秒くらいのセリフをCaptionでバリエーション変えながら6個作成し、全部ぶち込んで一番効かせたいファイルを一番上に持ってくる手法が推奨（476）。irodoriで作った音声をMiniMaxで喋らせる用途で使用（699）。

根拠: >>43, >>44, >>132, >>133, >>180, >>181, >>213, >>223, 245, 253, 259, 476, 699

## MiniMax（H3 / i2i / ツール全般）

MiniMaxのi2iを使ったが画質がちょっと粗くなる。差分作成には精度が欲しい（>>88）。LoRAなしだとイカせる気概の動きにならない（>>153）。H3でフェラチオ検証：8stepターボでもプロンプト書き方次第で細かい動き制御可能。20stepならさらに追い込めると予想（>>99）。H3でおっぱいの弄り方を研究、単語や言い回し一つ変えるだけで動きが変わる（>>115）。H3でcharacter sheetを作る用途で使用、ファッションセンスが悪くない、回転させても二次も三次もええ感じ（746, 757）。mmh3のref2vaを使ってキャラ参照して動画作成まで到達（748）。

リップシンクは3種類（Context Loop使う方法、音声参照を使う方法、テキストを使う方法）。Context Loop標準リップシンク以外は上手くいかないという報告（702）。irodoriで作った音声を喋らせるとリップシンクがズレる問題（699）。H3スタジオの使用感：低スペ環境（3060の12G、メモリ32G、352x512）で約8分で生成可能。UI完璧。改善要望として完成時の通知音、生成後のかかった時間の表示、UI部分のテキストのコピペ改善（789）。

orbit撮影LoRA：読み込んだ画像をorbit撮影できるLoRA。被写体の頭部をorbitで撮影でき、任意の角度で動画をスクショすればリファレンスシートを作るのに便利。モデルの変形がかなり抑えられるのが利点。プロンプトだけで360度アークショットが生成できるため必要性が不明という指摘もある（>>918, >>920, >>926）。

根拠: >>88, >>99, >>115, >>153, 699, 702, 709, 746, 748, 757, 789, 918, 920, 926

## 総評

1. **StrataがローカルLLM運用のハブとして機能している**：規制解除版を軸に、ComfyUIのOpenAI互換ノードやRest Api Node経由でi2t自動生成フローを構築し、OpenWebUI/librechatをフロントに据え、MCPで検索APIやComfyUI操作を繋ぐエージェント運用が複数ユーザーで実証されている。ただしVRAM競合対策としてbatによるモデルロード/アンロード管理が必須になっており、運用の複雑さが障壁となっている。

2. **ComfyUIの安定性問題が深刻化している**：バージョン0.36.0〜0.38.0でpythonフリーズが複数報告され、古いカスタムノードの存在だけでぶっ壊れる要因になることが判明した。ネイティブノードとエージェント自作のシンプルなカスタムノードだけで再構築する方針が推奨されており、ツール間連携が進む一方で基盤の不安定さが課題である。

3. **Codexをはじめとするコーディングエージェントがツール自作の前提になっている**：ComfyUIのカスタムノード作成、UI構築、ワークフロー自動化、学習ツールのPR作成に至るまで、LLMにコードを書かせて自分用ツールを作る手法が広く浸透している。「既存のものを探す前に自分で作っちゃうようになった」という声がその傾向を示している。

4. **プロンプト生成のLLM依存が進んでいる**：Krea2、MiniMax H3、Ideogram等で自力のプロンプト力では足りなくなり、ローカルLLM（Strata+Qwen3.8等）や無料Grok、ChatGPTにプロンプトを作らせる手法が主流化している。ワークフロー内にプロンプト生成ノードを組み込む試みも出ており、生成パイプラインの自動化が一段進んでいる。
