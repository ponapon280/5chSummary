# 元の本文
本次とくに盛んに議論された話題は、ComfyUIとStrataの併用に伴うVRAM管理・ワークフロー構築、およびLoRA学習ツールの設定最適化である。

## ComfyUI
- **VRAM管理と実行環境の制約**: VRAM16GBあればStrataで4000MBリザーブを確保すればアンロードなしでComfyUI上のKrea2やMOSSを動かせるが画像生成時間は延びる（>>29）。Strata常駐状態でComfyUIを起動したままにすると5070ti・RAM128GB環境でも18tok/sまで低下しLocal Prompt Studioの方が3倍早い（>>616）。ComfyとStrataの併用はグラボ2枚積みでない限りキツく、Comfy側でモデルを毎回アンロードする必要がある（>>623）。右クリック→選択でVRAM解放可能（>>638）。VRAM16GBでもStrataで4Gリザーブすれば併用可能、いちいちunload/loadするより画像生成時間が延びても併用がよい（>>584）。
- **プロンプトエンハンサーの挙動**: comfyの公式t2iテンプレートはプロンプトエンハンサーがオンになっており、MOSSのサブグラフに最終プロンプトが出力されているため思い通りにならない場合はそこをチェックすべき。切ることも可能（>>812）。MOSSのsubgraphにはpromptを加工する回路が内蔵されており入力したprompt=生成した画像と誤解しやすい（>>821）。
- **擬音・セリフのプロンプト手法**: i2tやエンハンサーのシステムプロンプトに擬音・セリフの書き方とフォーマットを渡しuser promptに指示を出す手法。テンプレのTEを使うエンハンサーは擬音やセリフが致命的に弱い（>>700）。
- **LLMノード統合とワークフロー分割**: TextGenerateノードの代わりにOpenRouter LLM Nodeを挿すことでリモートLLMを呼べるがAPIキー等のメタデータが混入するためワークフローを分ける必要がある（>>869）。
- **Nvidia VFX Nodes（旧RTX Nodes）**: 10月に7ヶ月ぶり更新、名称変更。VSRにDENOISE・DEBLUR追加、HDR化やフレーム生成ノード追加。MiniMaxH3ブーム後だったためか動画で試す人がいなかった（>>422, >>427）。RTX Video Super Resolutionノードのquality設定にHigh bitrate ultraが追加されアップスケーリングのタイパ最強との声がある（>>420）。
- **選ばれている理由**: Strataやハーネス関連などComfyUI単体では完結しない手法を扱う場合ComfyUIを介する必要があり別次元のことができるため。ただしハードルは高い（>>426）。デスクトップ版の方が起動と終了が楽という理由でデスクトップ版移行の動きがある（>>51）。Higgsfieldとバトルが起きており面白い状況という言及がある（>>211）。
- **その他トラブル**: CodexがComfyUIを破壊して復旧を拒否した事例（reddit報告）。原因はComfyUIにヌードが含まれていたためと判定されたため（>>438）。StrataでUD-IQ4XS(60GB)をロードしたままAIコーディングとComfyUIで動画生成を同時実行したところPCがフリーズし強制シャットダウンになった事例（>>877）。

## Strata
- **推論エンジンとしての位置づけ**: 9月末にgithubに出現したLLM推論エンジン。llama.cppと同類の推論エンジンであり、Hermes AgentやOpen WebUIがLM StudioやOllamaと同類のツール（>>502, >>526）。
- **VRAM要件とハードウェア制約**: 基本的に12GB必要、ComfyUI併用は16GB必要（>>650）。VRAM12GBの低容量でも125B級ローカルLLM（Qwen 3.8 Flash-Next）が動き超早い（>>502）。3060/12GB・RAM32GBでは当初コーディング特化モデルしか使えなかったが今はQwen3.6-35B-A3BのUD-Q4_K_XL等も動く（>>532）。3060 12GB + DDR4 64GBでは性能が出ないためメモリ幅がボトルネックの可能性（>>660）。RAM32+VRAM16では他アプリとの同時起動は厳しくプロンプト書かせてComfyで生成するのはストレス（>>530）。メモリもVRAMも全て食うためPCがもう一台必要（>>521）。
- **常駐運用の実態**: RAM64GB・5090・IQ3_S・262Kコンテキストで無理矢理常駐、生成時に自身をアンロードし終わったら復帰する仕組み。最初はunload/loadに失敗していたが3〜4回で失敗しなくなった（>>525）。常駐させるとリソースをかなり持っていかれ学習や3Dゲームは流石に厳しい（>>522）。SSDの寿命が縮みそうで怖いという懸念（>>524）。読み込み早いSSDを使っていればアプリ立ち上げなおしでもそこまで気にならない、動画生成との同時起動はできない（>>527）。
- **プロンプト作成用途での活用**: 早すぎてクラウド系でbanに怯える必要がなくローカルでプロンプト作成が実用レベルになった。クラウドと違い趣味が蓄積されないため最初の自己紹介は面倒（>>510）。100tok/s出るがLM Studioは20くらいしか出ないため1万文字書かせる場合はStrataが有利（>>640）。コーディングもチャットも微妙で使い所がないとの意見もあるが月額課金・トークン残量を気にせず使い放題な点を最高とする声も（>>645, >>646, >>647）。
- **デスクトップ版の不具合とサポート**: デスクトップ版をインストールしたら不具合が出た。チャッピーに相談したらissues報告を勧められ無能と判断、Geminiに聞いたら一発で解決（>>553）。
- **グラボ需要への影響**: strataのせいでグラボが中古含め爆売れして品切れ続出というxトレンドがあった。VRAM12GBの3060が1割以上値上がり（>>841, >>845）。

## LoRA学習ツール・設定
- **sd-scripts**: MOSSキャラLoRA作成に試したが良くなかった（>>499）。sd-scripts Version 0.12.3で追加されたオプションとCAME（Optimizer）を組み合わせればキャラクターLoRAなら1000ステップでも多いくらいの学習が可能（>>392）。
- **Fizgig**: Fizgigの方がsd-scriptsより速いはずだがRAdamScheduleFree（Optimizer）を使用したいためsd-scriptsを使っているユーザーがいる。Fizgigで3600ステップ回すのに4時間かかるとの報告（>>388, >>384）。MOSS学習のプリセット・ガイドとしてデフォルトで学習のリジュームが効く設定。100epochで大体似る程度、学習難易度向上のためsigmoid_scaleを上乗せしている（>>488, >>500, >>538）。
- **kohaku moss trainer**: MOSSのキャラLoRA作成に使用。rank/alphaを128まで上げた。キャプションはトリガータグ以外は自然言語（>>499）。
- **AI toolkit**: デフォルト設定でMOSS画風学習がすぐ終わるとの報告（>>543）。
- **LoRA学習の目安**: 教師画像の枚数×epochのstep数で決まるという見解。画風Aの教師画像40枚で100epoch＝4000stepで十分なら画風Bの50枚なら80epoch付近が目標（>>97, >>100, >>101）。
- **サンプラー・オプティマイザーの傾向**: サンプラーはEuler、オプティマイザーはAdamWに回帰する傾向。DAdaptLion系は半自動で学習率を自動調整してくれる機能がある。基礎が疎かだと小手先の設定を変えても上手く行かない（>>113）。

## 音声処理・TTS関連ツール
- **Irodori-TTS用素材準備フロー**: FFmpegで素材動画から音声のみ取り出し、faster-whisper（large-v3, VAD有効）で文字起こし・無音区切りで音声をwavに保存、resemblyzerで話者分離し欲しい声のファイルだけ残す。音声分離にはUVR5またはaudio-separator（Demucs htdemucs_ft）を使用しBGM・ノイズ・音声を分離（>>448, >>489）。
- **speakersplit**: チャッピー（ChatGPT）ができると言ったspeakersplitは精度がゴミカスで全くダメだった（>>444）。

## 総評
1. **StrataとComfyUIのリソース競合が運用の最大の課題**: Strata常駐下でComfyUIを動かすとtok/s大幅低下・PCフリーズ等が発生し、VRAM16GB程度の環境ではモデルのアンロード/ロードを繰り返すかリザーブ調整で回避する必要がある。グラボ2枚挿しでない限り併用は厳しいというのがスレ上の共通認識。
2. **LoRA学習ツールは sd-scripts + CAME/RAdamScheduleFree の組合せに収斂**: Fizgigよりsd-scriptsを選ぶ理由はOptimizerの選択肢にあり、MOSS学習ではsd-scripts 0.12.3の新オプション+CAMEで1000ステップ程度でも学習可能という報告がある。kohaku moss trainerやAI toolkitもMOSS向けに使われている。
3. **プロンプトエンハンサー（PE）の内部挙動への注意喚起**: ComfyUI公式テンプレートでPEがオンになっているため入力prompt≠生成画像のプロンプトとなりやすく、MOSSのsubgraph内で加工されている事実を知らないとデバッグに迷う。
4. **Codexの過剰検閲・突然のBANリスクが実運用上の障害**: ComfyUI破壊事例やフロー内不適切プロンプト検知による拒否などが報告されており、Claude CodeやGeminiへの退避が推奨されている。
