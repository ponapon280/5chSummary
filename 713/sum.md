# LoRA学習の最適化とモデル別の習熟難易度

**モデル進化に伴うLoRA作成の難化**
モデルがリアス→Noob→ANIMA→MOSSへ進化するにつれLoRA作成が難化しているとの声がある（36）。ANIMAで半年間概念LoRAを作り続けてもNoob時代の再現度に及ばず、MOSSはANIMA以上に難しいとされる（36）。一方で個人の感覚差があり、ANIMAが一番簡単でMOSSが一番難しいという見解（52）や、画風LoRAであればANIMAの方が効きが良いという声（55）もある。LoRAの覚えの良さについては「Krea2 >> Noob ≧ MOSS > Anima > その他SDXL」とのランキングがある（230）。

**LoRA学習の設定とノウハウ**
学習の目安は「教師画像の枚数×epochのstep数」でおおよそ決まるという見解（97, 100, 101）。画風LoRAの設定例として、ANIMAならCAME, LR3e-05, 32dim/32alpha, 1024 res, cosine 1000step前後で十分という報告（103）や、MOSSではfizgigのプリセット（adamw, rank16, 5e-5）で教師画像40〜50枚の場合4000〜5000stepやらないと覚えないとの声（106）がある。最終的に多くのユーザーはAdamWに回帰する傾向にあり（107）、DiT系ではタイムステップサンプリング設定により一概にconstantが悪いとは言えないのが難しさ（111）。「覚えてくれない」場合はステップ数を一桁上げて10時間オーバーで実験することが推奨される（128）。

**MOSS-ImageのLoRA学習**
MOSS-Imageは細部はダメだが雰囲気はAnimaより素材寄りで、学習時間は重い（229）。kohyaによる検証では教師画像70枚ちょっとで200epoch、15,000step相当でようやく効くようになり、lr 1e-4, dim(rank)=16, alpha=16, constant, AdamW8bit, samplingはshiftで2.0が用いられた（473, 538）。Rank/alphaを128まで上げた方が良いとの報告（499）や、ランク上げると生成時の破綻が増える印象（529）もある。画風LoRAを作ったらめちゃめちゃ使えたという成功報告（564）や、MOSSでは最低でも画像1枚あたり100回ループが必要（Krea2は40回程度）との指摘（388）がある。

**TE進化とキャプション**
TEの進化でLoRAのキャプションが思いっきり効くようになっている（39）。MOSSのsubgraphにはpromptを加工する回路が内蔵されており、シンプルなpromptでリッチな画像が出るため、入力したprompt=生成画像と誤解しやすい（821）。テキストエンコーダの更新を切っていると未知の物追加で再現性が落ちがち（209）。animaやmossはモデル側のテキスト管理部分の更新をしないのが推奨、トリガーワード以外のタグを細かく付けてもほぼ意味がない（511）。gemma4で自然言語キャプションを作成したが「かなりアホの子」で複雑なのは厳しいとの報告（774）や、MOSS公式はモデル作成時にgemma4でタグ付けしており相性が良いとの見解（702）がある。

**LoRA学習素材のフロー**
Irodori-TTS用LoRA素材作成フローとして、FFmpegで音声抽出→audio-separatorで分離→faster-whisperで文字起こし→resemblyzerで話者分離の手順が紹介された（448）。また、自動話者判別して切り出してくれるAIを求む声がある（434）。

# ローカル推論環境とハードウェア

**Strata推論エンジンの台頭**
9月末にgithubに出現した推論エンジンStrataは、VRAM12GBで125B級ローカルLLMモデルQwen 3.8 Flash-Nextが動く（502, 526）。llama.cppと同類の推論エンジンでありテキストエンコーダーではない（514, 526）。メモリもVRAMも全部食うためPCがもう一台必要という問題（521）や、常駐させると学習や3Dゲームは無理という指摘（522）がある。RAM64GB・5090・IQ3_S・262Kコンテキストで無理矢理常駐させている事例（525）や、5070ti・RAM128GB・Comfy起動済みの状態だと18tok/sまで下がる報告（616）がある。「コーディングもチャットもあかん」という声（645）がある一方で、月額課金を気にせず使い放題な点が最高という肯定意見（647）もある。

**GPU価格とVRAM事情**

# MOSS-Imageの特性と各モデルの使い分け

**MOSS-Imageの位置づけ**
MOSSは海外ではアニメモデルとしてより自然な三次モデルとして認識されている（555）。国内スレでもアニメモデルと思われていない（556）。promptに忠実だがdanbooruタグ単純羅列では不向きで、VLM/LLMで自然言語プロンプトを補強する必要がある（238, 240）。GPT image感が強く手描きイラスト風から離れやすい（399）。用途としては漫画、文字入れ、厳密な構図制御が必要な場合に適し（240）、BBOXで文字やキャラの配置ができる（554, 557）。

**Krea2 / Kromaとの比較**
Krea2は可愛い顔が作れるがリアルさと引き替えで、プロっぽく鮮やかだがCG臭く子供等身で大人顔になる傾向がある（594, 756）。MOSS出現後、9月終わりにKrea2から全面的に乗り換えた報告が多数ある（575, 607, 563）。今はKrea2よりKromaが良いとの声（918）や、krea3を待望する声（743）もある。

**モデル選択フロー**
1girlでいい → リアス、一枚絵でいい → anima、漫画・文字入れ・厳密な構図制御 → moss、という使い分けが提示された（402）。

# 画像生成のプロンプト運用と品質

**擬音・セリフとプロンプト戦略**
擬音を自然言語とDanbooru語（部族語）のどちらで出すかについて、部族語は忘れてComfyUIのi2tやエンハンサーのシステムプロンプトに擬音やセリフの指示書とフォーマットを渡す方法が紹介された（700）。箇条書きに整えた指示書より、描きたいものを後先考えず書いた指示の方が品質が良いことがある（772）。MOSSではaesthetic, intricate details等の鉄板品質向上ワードがかなり強く効き（255）、promptワードから連想ゲーム的に絵柄が引っ張られる傾向がある（255）。

**編集の反復と破綻**
元画像に対して「綺麗に整えて」と編集依頼を5回繰り返した結果、グロ画像にはならなかったがチーズが幾何学模様になった事例（886）。使う側の審美眼が狂っているだけとの指摘（875）や、元絵を一部残して修正してを繰り返す限り誤差蓄積は避けられないとの分析（876）がある。長尺動画ポン出しすると途中の誤差を引きずって最後に破綻するのと同じ現象（933）。

**Copilotの品質**
AIグロ飯はCopilotとされ、Copilotほんまにクオリティ低い年との評価（860）。ただしカツ丼の画像生成→味噌汁の文字をメニューに変更等の軽微な修正であればそれほど乱れないとの報告（878）もある。

# その他の動向

**CivitAIの運用**
CivitAIでハズレ担当者にモデられると二度とunpublish解除されない。NSFW目的でもロリLoRAでもない健全な画風LoRAが「リソースの説明が不十分です」で非公開になり、修正しても意義申し立てが却下され5日も待たされた事例（43）。設立4周年記念のチーム戦イベントが開催中で、ランダムにチームが割り当てられ一番弱い青チームになったという報告（676）。

**新モデル・サービス動向**
Metaの新AI「Muse」は高品質なエロチャットを無料でやりまくれるという情報だが、エロ規制が既存AIより少し緩いだけで性能はゴミとの厳しい評価（215, 468）。noobのチームが作っている10Bオーバーのモデルに期待する声（222）。MiniMaxH3のrefmodsは手軽な上に再現性も高く静止画用に良い（61）。MiniMaxH3で3次の生成をずっとやっていて2次を全然やっていない人がいる（38）。3D系ではTripoくらいしか使い物にならないとの評価（57, 59）。動画生成では0.5MPの5秒動画が27秒で生成可能になりかなり速くなった（304）。渋うごイラは150枚制限のため12秒24FPSを半分に間引くとちょうどいい（332, 334）。ai画像生成での120fpsお試しとしてMMH3 T2V 4stepTurboを8stepで使用、RTX Video Super Resolutionで2倍、RTX Frame Generation 5で120fpsにする手法が紹介された（565）。

# 総評
1. LoRA学習はモデル進化（ANIMA→MOSS）に伴って難化し、特にMOSSではstep数や学習時間の大幅な増加、OptimizerやTE更新設定の工夫が求められるようになり、個人の感覚差も大きいことが確認された。
2. Strata推論エンジンの登場によりローカルLLMの実用性が向上したが、常駐運用にはRAM64GB・VRAM12GB以上のハードウェアリソースが要求され、ComfyUI等との併用ではメモリ競合が課題となっている。
3. MOSS-Imageは三次モデル寄りの高自由度とprompt忠実度でKrea2等既存モデルから乗り換えるユーザーが相次いだが、LoRA覚えの悪さとdanbooruタグ非適合という特有の課題を抱えている。
4. OpenAI等大手AI企業の過剰検閲に対するスレ上の反発が根強く、アルトマンの「PCにDRAMを積むな」発言がローカルAI推進派の結束を強めると同時に、検閲リスク回避の観点からローカルLLM（Qwen, Gemma等）への移行検討が活発化している。
