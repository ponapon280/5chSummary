## 掲示板ログ要約レポート

### モデル別用途・性能評価

**Claude（Opus 5.5 / Codex / ClaudeCode）**
- 値段とチボリセ以外は全てにおいてClaudeが上との評価（447）
- Opus 5.5は成人同意ならエロも可能（447）
- コーディングメイン用途に適するが、技術的に怪しい内容に触れるとファールバックが掛かる。使用枠がwebとCCで共通のため、レート使い果たすと調査もできず単独契約では使いにくい（454）
- Opusの速さに慣れると今のGPTはキツすぎるとの感想（449）
- デスクトップ版ClaudeCodeのGUIが地味に良く、Codexと2枚使いで痒いところに手が届く（484）
- FlashAttentionのビルド済みファイルをClaudeが適切に引っ張ってくるが、それはClaudeに情報が握られていることをも意味する（579）
- Codexに内部的に残っていた不適切プロンプトの安全な内容への置換依頼は応じたが、基準が不明確（456）。エロ動画の通否基準も見えない（457）。そのままBANになる可能性も指摘（459）

**ChatGPT（チャッピー）**
- 推論性能が高く、ふんわりした依頼をカタチにする能力は段違い。ただし禁欲的で絵が出せないのが弱点（445）
- リサーチはまだGPTの方が安定する（449）
- 検索用途に適する（454）
- PlusプランでWebもCodexも6.1 sol程度の賢さであればずっと使える（462）
- 画像生成はメモリで趣味嗜好を把握済みだと一発で希望に近い結果が出る（467）
- 「チャッピーの絵」は赤みがかったイラスト風、少し装飾過多で人物なら判別しやすい（476）
- H3プロンプト作成では15000文字に達し、自分で書くのは無理な領域（629）。ローカルLLMより露骨に差が出る（634）
- 被害報告や忠告が多数出ている中でまだ使おうとするのは自殺願望としか思えないという強い忠告あり（460）。ただしサブスクである限りどのサービスも同様で、現時点でスルーされているだけとの反論も（471）

**Gemini（ジェミニ）**
- 文章作成用途に適する（447, 454）
- 最近のGeminiが一番好みの文を書くとの評価（495）。スマホでも気軽に使えるmuse相当のGoogle製アプリを希望する声あり（495, 503）
- デスクトップ版Strataの不具合について、GPTに相談してもissues報告を勧められるだけで無能、Geminiに聞いたら一発で解決（553）

**Muse**
- エロ規制が既存AIより少し緩いだけ、性能は比べるまでもなくゴミとの厳しい評価（468）
- 画像生成クオリティがイマイチ。アリス悪役令嬢化をMuseで試したが何度リテイクしてもダメで、チャッピーでは一発で成功（467）
- LLM部分も特に緩くはない。スマホで手軽に画像音声連携エロを体験できる点で評価されている（469）
- 日本市場を強く意識しローカライズ、アメリカの次に日本展開。ただし日本語力はイマイク（470）
- 無料でも使い切れない程度の上限あり（503）
- ロリを拒否した事例あり（582）

**各モデルの使い分け（スレ上の見解）**
- 文章のGemini、コーディングのClaude、検索のChatGPT（454, 447）

### Strata（推論エンジン）関連

- 9月末にgithubに出現。VRAM12GBで125B級ローカルLLMモデルQwen 3.8 Flash-Nextが動く画期的な推論エンジン。超早い（502, 526）
- llama.cppと同類の推論エンジンであり、テキストエンコーダーではない（514, 526）
- メモリもVRAMも全部食うためPCがもう一台必要という問題（521）。常駐させると相当なリソースを持っていかれ、学習や3Dゲームは無理（522）
- RAM64GB・5090・IQ3_S・262Kコンテキストで無理矢理常駐させている事例あり。生成時に自身をアンロードし終わったら復帰する仕組み。最初はロード失敗したが3～4回で失敗しなくなった（525）
- 5070ti・RAM128GB・Comfy起動済みの状態だと18tok/sまで下がる。Local Prompt Studioの方が3倍早い（616）
- RAM32GB＋VRAM16GBで動作確認あり。ただし他アプリとの同時起動は厳しく、メモリ解放や起動に時間がかかりプロンプト書かせてComfyで生成するのはストレス（530, 537）
- 最初は3060/12GB・RAM32GBでコーディング特化モデルのみだったが、現在はQwen3.6-35B-A3BのUD-Q4_K_XL等、普通のモデルも使えるようになった（532）
- flash-nextにしてからqwen3.8-27bやgemma4-31bは全く使わなくなった。創作力はどれも微妙だが、ツールやスキルを複数食わせてもバカにならないのが消去法でflash-next（541）
- SSDの寿命が縮むと怖いという指摘に対し、書き込みでなくRAMから溢れさせてなければ別とする反論あり（527）
- ローカルLLMでプロンプト作成が実用的になり、クラウド系でbanに怯える必要がなくなった（510）

### MOSS（画像生成モデル）関連

**基本評価・特徴**
- 海外ではアニメモデルとしてより自然な三次モデルとして認識されている（555）。国内スレでもアニメモデルと思われていない（556）
- 三次の多様性に強い。BBOXで文字やキャラの配置ができる（554, 557）
- Turboだと硬いおっぱい、通常だと自然な柔らかいおっぱいになる（609）
- 日本語指示でも書き方次第でめちゃくちゃ変わる。漢字の造語まで持ち出すのもあり（622）
- int8で50step・sft・サンプラーer_sde・スケジューラーsimpleで綺麗な生成が可能（613, 615）
- 覚えが悪い場合、animaで学習→animaでガチャして覚えやすい構図の絵を生成→mossに学習という手法が提案された（592）。個性的な絵柄へはsaiっぽい絵柄より難しい（596）

**Krea2との比較**
- Krea2は可愛い顔が作れるがリアルさと引き換え。MOSSはアマチュア感、Krea2はプロっぱく鮮やか（594, 573）
- MOSS出現後、9月終わりにKrea2から全面的に乗り換えた報告多数（575, 607, 563）

**BBOX機能**
- BBOXが便利すぎて戻れない。逆フェラ等の難しいプレイも簡単に出せる（560）
- reverse cowgirlとPiledriverは出しにくく、BBOXを使っても安定しない（559）

**キャプション・プロンプト**
- 長く詳細なキャプションで学習。テキストエンコーダは4,096 tokensまで読む。短・中・長の3つのバリアントがある（585）
- 自然言語のキャプションの方が露骨に多様性が出るが、崩れやすい（588, 581）
- danbooru語（部族語）は概念にない服や機械を作るのに使える。定量的な試行が可能な部族語モデル特権（644）

**LoRA学習**
- kohyaによる検証：教師画像70枚ちょっとで200epoch、15,000step相当でようやく効くようになった。lr 1e-4, dim(rank)=16, alpha=16, constant, AdamW8bit, samplingはshiftで2.0（473, 538）
- Fizgigプリセットで100epochくらいあれば大体似ると思っていたが生焼けだった（493）。150～200epoch必要という意見も（488）
- rank/alphaを128まで上げた方が個人的に良かった（499）
- ランク上げると生成時の破綻が増える印象（529）
- 画風LoRAを作ったらめちゃめちゃ使えたとの報告（564）

### LoRA学習全般

**Irodori-TTS用LoRA素材作成フロー（448）**
1. FFmpegで音声抽出
2. audio-separator（Demucs htdemucs_ft）でBGM・ノイズ・音声分離
3. faster-whisper（large-v3, VAD有効）で文字起こし、無音区切りでwav保存
4. resemblyzerで話者分離

**LoRAキャプション論争（501, 511, 512, 515, 519）**
- トリガーワードは短いワード1つが無難（512）。単体LoRAで差分を気にしないならトリガーワード不要でStep回せば覚える（515）
- 詳細に書くと画風がトリガーに吸収されないかもしれないというAIの指摘に混乱（501）
- animaやmossはモデル側のテキスト管理部分の更新をしないのが推奨。トリガーワード以外のタグを細かく付けてもほぼ意味がない（511）
- TEが賢くなり自動キャプションで十分だが、覚えさせたい情報を覚えられるキャプションを書くには元モデルの理解を把握する必要がある（519）
