# 生成AI関連「ツール」話題抽出レポート

## ComfyUI / comfy
- **museとcomfyuiを繋いで画像を出す手法が話題に**（505）
- Comfyのビデオ生成ワークフローで120fps出力を試行。MMH3 T2V 0.5メガピクセル 4stepTurboを8stepで使用、RTX Video Super Resolutionで2倍、RTX Frame Generation 5で24fps×5=120fpsを生成（565）
- **MOSS生成後にGPU使用量が減らない問題**について。comfyのテンプレワークフロー使用時、末尾にeasycleanGPUusedを付けて強制的にVRAM解放している。他モデルでは自動で下がる（568）
- ComfyとStrataの併用はグラボ二枚積みでない限りキツい。Comfy側でモデルを毎回アンロードする必要がある（623）
- ComfyUIの右クリック→選択でVRAM解放が可能（638）
- Strata常駐状態でComfyUIを起動したままにすると、5070ti・RAM128GB環境でも18tok/sまで低下。Local Prompt Studioの方が3倍早い（616）
- VRAM16GBでもStrataで4GリザーブすればComfyUIと併用可能。VRAM32GBなら調整次第で余裕。いちいちunload/loadするより画像生成時間が延びても併用がよい（584）

## Strata（推論エンジン）
- **9月末にgithubに出現したLLM推論エンジン**。VRAM12GBの低容量でも125B級ローカルLLM（Qwen 3.8 Flash-Next）が動き、超早い。27B級にVRAM32GB必須だった時代から125B級がVRAM12GBで動く時代に突入（502）
- 推論エンジンでありllama.cppと同類。ツールではなく推論エンジン。Hermes AgentやOpen WebUIがLM StudioやOllamaと同類のツール（526）
- **プロンプト作成用途での活用**。Strataは早すぎてクラウド系でbanに怯える必要がなく、ローカルでプロンプト作成が実用レベルになった。クラウドと違い趣味が蓄積されないため最初の自己紹介は面倒（510）
- StrataはメモリもVRAMも全て食うためPCがもう一台必要という問題がある（521）
- 常駐させるとリソースをかなり持っていかれる。生成ならVRAMのマージンを多めに取ればいけるが、学習や3Dゲームは流石に厳しい（522）
- RAM64GB・5090・IQ3_S・262Kコンテキストで無理矢理常駐。生成時に自身をアンロードし終わったら復帰する仕組み。最初はunload/loadに失敗していたが3〜4回で失敗しなくなった（525）
- 読み込み早いSSDを使っていればアプリ立ち上げなおしでもそこまで気にならない。動画生成との同時起動はできない（527）
- **SSDの寿命が縮みそうで怖くて使えない**という懸念（524）
- RAM32+VRAM16で動作確認。単体使用なら使えるが他アプリとの同時起動は厳しく、メモリ解放や起動に時間がかかるためプロンプト書かせてComfyで生成するのはストレス（530）
- 3060/12GB・RAM32GBでは当初コーディング特化モデルしか使えなかったが、今はQwen3.6-35B-A3BのUD-Q4_K_XL等の普通のモデルも動くようになった（532）
- プロンプト作るだけならStrataを動かさなくてもよいのでは、という指摘（625）
- 100tok/s出るがLM Studioは20くらいしか出ないため、1万文字書かせる場合はStrataが有利（640）
- Strataのデスクトップ版をインストールしたら不具合が出た。GPTに相談したらissues報告を勧められ無能と判断。Geminiに聞いたら一発で解決（553）
- MOSSのプロンプトをStrataに書かせるフロー。MOSSで生成できませんと3回失敗した後に4回目で成功した（551）
- dskjalニキのnoteにあるMOSS向けシスプロ（3つの長さのキャプションに対応）をスキルとしてStrataに読ませている（585）

## LM Studio / Ollama / llama
- プロンプト書かせ用途でLM Studioのbionicにスキルを読ませて使用。MOSSのスキルを見せるとたまにシェルコマンドを使い始める問題がある（627）
- llamaで自動sleep（VRAM解放）オプションを知ってからllamaのみ使用。comfyUI側は右クリックでVRAM解放可能（638）
- プロンプト書かせだけならLM Studioで十分という意見。スキルの管理・呼び出しはbionicの方が楽という話を聞いた（637,643）
- strataは100tok/sだがLM Studioは20程度（640）

## Hermes Agent
- Strata常駐用途でHermes Agentを推奨する声（516）
- Open WebUIと並ぶツール。LM StudioやOllamaと同類（526）

## Local Prompt Studio
- Strata常駐状態のComfyUI併用環境より、Local Prompt Studioの方が3倍早い（616）

## argon
- オナニースレでargonの話をすると異端者扱いされる。脱獄不要で無料のmuseが流行るため仕方ない（513,517）
- vertex経由ならまだフリークレジットで使える。ただしロリや非同意はpro3.1より厳しい（547）
- スマホで手軽に使えるという点でmuseに類する用途。Google AI Proの価値が出てきた（597）

## Muse
- スマホで手軽に画像・音声連携エロを体験できる部分で評価される。STや自作で既にやっている人には魅力なし（469）
- チャットアプリではなく最初からエージェントアプリでアバター機能を重視。日本市場を強く意識しローカライズしている（470）
- 無料でも使い切れない程度の上限がある（503）
- Googleもmuseくらい手軽に使えるアプリを出してほしいという要望（495）
- 画像生成のクオリティは根本的にイマイチ。タイポや誤字が多い（467,466）
- 既存のAIよりエロ規制が少し緩いだけで性能は比べるまでもなくゴミ（468）
- museに自分の性癖がバレるのは恥ずかしい（580）
- ロリを拒否された報告（582）

## Codex / Claude Code
- デスクトップ版Claude CodeのGUIが地味に良い。Codexと2枚使いしている。痒い所に手が届く（484）
- Codexはエロゲ解析等で使用しているがある日突然発狂・BANの可能性がありほどほどにするべき（457,458,459）
- Codexにフローを弄らせた際、内部に残っていた不適切プロンプトを検知して拒否されたが、該当部分の安全な置換を依頼すると作業続行した（456）
- ツールとして、本題と無関係な部分の変更をユーザーに強いる時点で終わっている（464）
- 接続していないノードに罠テキストを仕込むことでクラウド破壊WFを配布できる仕組みが話題に（465）

## プロンプトエンハンサー（PE）

- 群衆比較画像で同一日本語指示をPE通して生成（589）

## 画像生成以外のQwen関連
- Strata上でQwen3.8-Flash-Nextをプロンプト作成に使用。創作力はどのモデルも微妙だが、ツールやスキルを複数食わせてもバカにならないのが消去法でFlash-Next（541）
- Qwen3.8-27bやgemma4-31bはFlash-Next導入後全く使わなくなった（541）
- H3のプロンプト作成でチャッピーとローカル（Qwen3.8-Flash-Next含む）で露骨に差が出る。ローカルはあっさりしすぎ（634）
- StrataでQwen3.6-35B-A3BのUD-Q4_K_XLが動くようになった（532）

## LoRA学習関連ツール
- **kohaku moss trainer**：MOSSのキャラLoRA作成に使用。類似性の高いキャラ学習ができた。rank/alphaを128まで上げた。キャプションはトリガータグ以外は自然言語（499）
- **sd-scripts**：MOSSキャラLoRA作成に試したが良くなかった（499）
- **fizgig**：MOSS学習のプリセット・ガイド。デフォルトで学習のリジュームが効く設定。100epochで大体似る程度。学習難易度向上のためsigmoid_scaleを上乗せしている（488,500,538,585）
- **AI toolkit**：デフォルト設定でMOSS画風学習がすぐ終わるとの報告（543）
- **UVR5**：音声分離に使用。Irodori-TTS用素材準備フローの2番手順でBGM・ノイズ・音声を分離（448,489）
- **audio-separator**（Demucs htdemucs_ft）：音声分離ツール。素材準備フローで使用（448）
- **faster-whisper**（large-v3, VAD有効）：文字起こし・無音区切りで音声をwavに保存（448）
- **resemblyzer**：話者分離ツール。欲しい声のファイルだけ残す（448）
- **FFmpeg**：素材動画から音声のみ取り出す（448）
- **emojitts**：faster-whisper相当の機能がある可能性が言及（489）
