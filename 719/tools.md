## ComfyUI / comfy

- **リモート操作**：自宅PCのローカルComfyUIをスマホから操作する手法が共有された。起動オプション`--listen`でPC側IPアドレスをスマホブラウザで叩く方法やRDP使用が挙げられているが、`--listen`での公開は「セキュリティガバガバ」との指摘がある（326, 342, 350）。Tailscale使用の記述もあり（339）。
- **ワークフロー構築の自動化**：Anima使用時にforge neoからcomfyに移行し、Claudeにforge生成イラストを渡してcomfyワークフローを再現してもらった。「comfyめっちゃええわ AIのおかげで理想の環境構築出来る」と評価（>>116, >>226）。Claudeにcomfyを使って生成を指示するだけでワークフローを通さずに済むという手法もある（>>118, >>123）。
- **ドラッグ＆ドロップでワークフロー再現**：ComfyUI生成画像をドラッグ・アンド・ドロップするとメタデータからワークフローを再現できるtips（345）。
- **エージェント連携の試み**：エージェントに素材を渡し、comfyUIのminimax h3で作成させるワークフローが言及（>>814）。museのVM環境が貧弱なためcomfy環境を再現してフルオート化を試みたがOOMになるとの報告（>>824）。museはGPUがないためクラウドGPUを繋ぐか自宅ComfyUIを使わせる必要があるとの指摘（>>836）。
- **メモリ管理**：comfyのメモリ管理が優秀と聞き、16GBメモリ・64GB環境でもSSDスワップせず使えるか質問。「メモリよりでかいモデルじゃなければ扱えるくらいの認識でええ」との回答（>>57, >>59）。
- **生成速度**：同じグラボでもComfyUIでの生成速度がどんどん上がっている現象が報告（>>124）。
- **カスタムノードのエラー**：Animaの日本語文字入れLoRAを試した際、`SpectrumKSamplerModGuidance`のエラーが治らず使用できなかった（368, 384）。
- **バージョンアップ**：ComfyUI v0.46.0リリース報告（383）。

（>>57, >>59, >>116, >>118, >>123, >>124, >>226, >>814, >>824, >>836 / 326, 342, 345, 350, 368, 383, 384）

## Strata / PolyStrata

- **ビルドによる最適化**：自分でビルドしたところモデル読込みが8秒程度で終わり、速度とRAM消費が改善。Gemma4も使えるようになりアプリ自体は30MB未満（>>695, >>698）。最適化するなら自分の環境でビルド推奨だが、作ったアプリは誰でも使える。rustupをインストールし公式buildコマンドを打つだけで完了（>>701, >>702, >>703）。
- **速度比較検証**：PolyStrataでgemma 4をテスト（コンテキスト65.5K, reasoning on）、小説執筆させた結果、llama-server (b12559)で35.31tok/s、Unsloth Desktopで37.7tok/sに対し、PolyStrataでは105.1tok/sを記録（>>716）。シングルモード選択で速度向上可能との指摘：2GPU環境だが5070ti単体+64GBで約2倍の速度（>>84, >>85）。
- **エージェント用途**：チャッピーにskillsを作らせ、strataとDSHを使用して小説管理プロジェクトを構築。1話ごとにjsonファイルを作成し、登場人物・人物間関係・世界観・時系列・複線などの抽出を自動化。コンテキスト最大256k設定で一度も溢れずtok/s速度も落ちない（>>663, >>686）。
- **画像生成パイプラインへの組み込み**：「クソ落書き -> strata -> MOSS+BBOX」のワークフローで使用（>>549, >>554）。3060 12GB環境では遅く、1時間やり取りしてmoss連携させた最後に何もプロンプト指示していないのに画像を出してきたとの報告（>>796）。
- **SSD負荷問題**：Strataをぶん回していたらモデルをリード中のSSDマウントが外れ、シャットダウン→30分放置で復旧。リード専用でもSSD負担が大きい（258）。
- **モデル対応制約**：Strata本家は無改造だとGemmaを動かすのは無理。Gemma4の31BはStrataでも動かないが26BA4Bならサクサク動く（>>595, >>599）。「rustingstrata」を試す声も（>>597）。
- **コスパ比較の議論**：スレ上の見解として、ローカルStrata運用（1重, 100token/s未満）ならGPT TerraやClaude Haiku等の格安APIで月1000円程度で済むのではないかとの比較がある（399）。Qwen3.8FNと同等のクラウドAIで無料・使い放題のものを探す声に対し、完全無料はないが月額のみのアグリゲーターならそのクラスが使えるとの情報（261, 281, 296）。
- **批判的意見**：「ロリのおっさんがプロンプト作るくらいしか脳が無いstrataとかいうゴミ」との発言（>>128）。

（>>84, >>85, >>128, >>549, >>554, >>595, >>597, >>599, >>663, >>686, >>695, >>698, >>701, >>702, >>703, >>716, >>796 / 258, 261, 281, 296, 399）

## fizgig (LoRA学習ツール)

- **Moss LoRA学習での実運用**：素材画像単位でLOSSを評価し「このぐらいがええ感じやで」と教えてもらえ、学習中に一目で評価できるツールがある（>>111）。Image PrepはDetail cropsとResize only、Captionsは元画像にqwen3.8FNで付け、切り抜き画像はfizgigの自動キャプションを使用。Trainingはmossのfastプリセット、train attention onlyとPer-image adaptive LRにチェック、解像度0.75〜0.25MP、1万step程度（>>189）。
- **プリセット調整の知見**：moss standardプリセットは学習率をもう一段下げた方がいいとの感想（367）。プリセットそのままでもlossがヨコヨコする現象が報告（>>184）。sd-scriptsに慣れすぎているためパラメータのいじり方が分からないとの声（>>126, >>176）。

（>>111, >>126, >>176, >>184, >>189 / 367）

## 総評

1. **ComfyUIのエージェント経由ワークフロー構築が実用化しつつある**：Claudeにforgeの生成イラストを渡してワークフローを再現させる、あるいは生成指示だけでワークフローを通さずに済ませる手法が報告され、AIエージェントによるComfyUI環境構築の自動化が実効性を持ち始めている。

2. **Strata/PolyStrataは自分ビルドで大幅に速度向上するが、SSD負荷とモデル制約が実運用上の壁となっている**：PolyStrataを自環境でビルドすることでllama-serverやUnsloth Desktopの約3倍のtok/sを記録した一方、SSDマウント外れやGemma4の31Bが動かない等の制約が報告されており、ローカルLLM実行環境の高速化と耐久性・互換性のトレードオフが顕在化している。

3. **NVIDIAドライバのSSD大量書き込み問題がStudioドライバでも発生しており、ログ削除・バージョンダウン以外に根本対策がない状態が続いている**：621.14以降のドライバでログを毎回全書き出しする仕様が原因と分析され、Game Ready・Studio両ドライバで問題が報告されている。

4. **LoRA学習はfizgigの自動評価ツールが重宝される一方、sd-scripts経験者はパラメータ設定に戸惑い、プリセット調整の知見が個別に蓄積されている**：mossのfast/standardプリセットそのままだとlossがヨコヨコする、学習率を下げた方がいい等の知見が出ているが、統一的な指針には至っていない。
