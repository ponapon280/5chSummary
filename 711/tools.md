- **Node 2.0移行の回避**: Node 2.0は評判が悪く、バグるものができるためスレ民も回避している（859, 866, 868）。
- **KJNodesによる代替**: Node 2.0未対応でもBox編集が可能な「MOSS-Image Prompt Builder KJ」があり、`ComfyUI-KJNodes`をアプデすれば利用可能。標準のBBox editorより使いやすく、Ideogram 4.0時代から使い慣れているため選ばれている（861, 864, 868）。

- **impact packの不具合**: impact packのノードが壊れまくっており、comfyの実装と噛み合っていない（25）。
- **標準loraローダーの使い勝手**: 標準のloraローダーが使いにくいという指標があり、トリガーワードや推奨強度を管理できるカスタムノードの推奨を求める声がある（207）。
- **comfy desktopへの移行**: 普通のcomfyからcomfy desktopの方が管理楽になったと聞いて導入したという報告（225）。
- **スパゲティノード結束バンド**: カスタムノードでノードを束ねる機能が評判を集めているが、機能的な利点が分からないという声もある（680, 682, 684）。
- **プロンプト生成アプリからノードへ**: moss用のプロンプト生成アプリを作ろうとしていたユーザーが、チャッピーに相談したところ「ComfyUIでお絵描きで指示できるノードがある」と教えられ、アプリ自体が不要と判断された。選定理由は「ComfyUIでやるならアプリいらんやん」という判断（663, 670, 675, 697）。
- **jsonワークフロー**: BBoxのjsonはcaptionに必要事項を辞書形式（key: value）で書き、BBoxにはPerson1やText1といったkeyを書くだけでよい（571）。
- **キャプション作成の手法**: 自然文キャプションはStrataとComfyUIでワークフローを組むかハーネスでやる方が早い。健全ならチャッピーを使ってもよい。選定理由はしょぼいLLMだと見落としが多いため（953）。
- **オーディオ参照**: 参照元の音声を`audio_ref_0`に繋ぐだけで機能する。プロンプトに入れたセリフ以外は参照音声として扱われず単に再生されるだけになる注意点がある（993）。
- **bf16計算の特性**: bf16が中心で、モデルの重みや活性値の計算は様々に変わる。INT8で計算していてもBF16に戻したり、処理に都合にいいように複雑に精度を変化させながら計算する。diffusersは基本的に同じ精度で計算するのとは対照的（367）。
- **不具合報告**: frontend1.57.4環境で`.json`読み込み時に「ワークフローが見つかりません」となる不具合がある（937）。

## GPUアンロックツール（制限解除）

- **ComfyUI生成レポート**: 3090でH3が4分39秒から3分31秒に短縮、実消費電力も24%削減。3060でKleinが18.09秒から11.01秒に39.13%短縮、演算処理だけ見ると45.16%短縮、実消費電力も35%削減（531）。
- **RTX 5090は物理的に困難**: VF PRIVが切られており物理的に5090のアンロックは無理。GPU内部の独立したRISC-Vプロセッサ内でセキュリティ処理が完結し、不正アクセスを検知すると起動後わずか数秒で強制クラッシュ（Xid 119エラー）する。スレ上のジョークとして「顕微鏡を見ながら超極細のハンダゴテで基盤の物理eFuseを焼き切るしかない」と飛び交っている（566, 567, 568, 581）。
- **Windows環境での運用**: Windowsでもアンロック可能。PowerShellの操作が必要で、再起動したらロックに戻る（573）。3060のWinアンロックbatが配布されており、毎回起動式のため安心（778, 779）。起動のたびにおまじないが必要でだるいが、イベントトリガーやUI起動時にBAT実行するように手を加えれば解決できる（891, 892）。
- **加速効果とPLの影響**: bf16処理系で50-60%加速。INT8はほぼ加速しないが、MiniMaxH3（MMH3）のINT8ConvRotでは30%加速する場合がある（335）。PLなしで約80%の伸びに対し、PL50では25%の伸びに激減する（363）。
- **選ばれている理由**: 4090（ロック時）がアンロックで演算速度2倍になれば5090より画像動画生成が速くなるため。INT8で5000番台の効果が薄かった原因でもある（271, 380, 404）。AIやってたら避けて通れない道とされ（565）、消費電力まで削減される点も評価されている（562, 531）。アンロック結果を見れば5090はドブ川に投げ捨てて良さそうというスレ上の評価もある（541）。
- **50シリーズの状況**: 5000番台はセキュアブート仕組みが変更されており別の突破口が必要。アンロック進めていたユーザーも諦めている（667, 791, 794）。
- **AIによるツール改造**: Windows 4090環境向けのツールがgithubにあり、AIに「使えるようにして」と投げたところ1時間以上ゴリゴリと改造・コーディングを続けている報告がある（904）。ただしパラメーターはデバイスIDやオフセットの違い程度であり、手動でやれば10分かからない。AIに作らせるのはトークンの無駄との指摘もある（909）。
- **Proシリーズ**: RTX Pro4000は最初からロックされていない（794）。
- **40xxと30xxの展望**: Windowsで可能になる情報が出そろうのを待つ声あり（342, 432）。

（244, 246, 248, 263, 266, 268, 271, 335, 342, 363, 380, 404, 432, 435, 531, 541, 543, 562, 565, 566, 567, 568, 569, 573, 575, 581, 582, 587, 667, 778, 779, 791, 794, 891, 892, 904, 909）

# 総評

1. GPUアンロックツールがスレ全体の最大関心事であり、3090や4090のアンロックでbf16処理系において50-60%加速かつ消費電力も削減される実測結果が多数報告された。一方5090はRISC-Vプロセッサによるガチガチのプロテクトで物理的に突破困難と判断されている。

2. ComfyUIはNode 2.0のバグ問題を回避しつつKJNodes等の代替ノードで運用する方向が定着しており、0.43デスクトップ版ではMOSS-Image Edit等のテンプレート追加で標準機能が拡充されている。

3. LoRA学習ツールはFizgigがプリセット選択のみの手軽さとマスク機能等の新機能追加で普及が進んでいるが、AI-Toolkitやsd-scriptsとポン出し品質を比較する文脈で継続的に検証されている。

4. エージェント・コーディングツール（Codex、Claude Code、Strata）をローカルPCで運用する際のセキュリティリスクへの警戒が高まっており、bwrapによるサンドボックス運用やサブPC分離の必要性が議論されている。
