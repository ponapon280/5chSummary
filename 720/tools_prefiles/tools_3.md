## 生成AI関連「ツール」話題抽出レポート

### ComfyUI (comfy, comfyui)

- **エージェント型ツール（Muse等）からのAPI経由操作**: これまで独立して使っていたComfyUIを、エージェントとしてのMuseがAPI経由でプロンプト等の指示を出して動かす運用形態が報告されている。現在はワークフローやノード自体を直接見ていない。NAI等も繋げられるはずとされる（518）。
- **エージェントとComfyUIの連携手法**: AIに相談した結果、ComfyUIとエージェントがjsonでお互いにやり取りする形が一番良いと提案された。リアルタイム生成を行うならこの方法が一番融通が利くという（632）。
- **Codexによる環境構築の自動化**: 新しいモデルが出た時にComfyUIの環境構築が面倒でCodexに丸投げすると、導入から動作確認、サンプル生成画像の作成まで完了させてくれるため、自分でやらなくなるという声がある（628）。また、テンプレートから公式WFを数クリックで出せる形式を活用する利用者もいる（635）。
- **スレ上の議論（エージェント利用 vs 手動ノード構築）**: ノードを繋いで実行するだけで目的が達成できるのにエージェント等を回りくどく使っているという意見（558）に対し、目的は絵や動画を手に入れることであり、エージェントは「ノードを繋ぐ作業すら人間から取り除く仕組み」であるとの反論（560）があった。一方で、言葉で説明するよりUI操作の方が速いこともあり、エージェントが常に最適解とは言えないという見方もある（562）。PCで直接ComfyUIをいじる以外に、ベッドでスマホから気楽にエージェントへ生成指示を出す使い方も便利という声もある（569）。
- **AIエージェントによるワークフロー構築のシミュレーション**: ComfyUIに新モデルを導入し、sfwとnsfwの画像をそれぞれ5枚ずつ生成してまとめシートを作成するまでのプロセスを、AIエージェント（またはLLM）がプロンプトの考案から検証、シート作成まで自動で完遂する様子が語られている（641）。

### WebUI (A1111, webUI)

- **プロンプト管理エディタの要件**: スレ内有志が作成中のプロンプト管理エディタについて、A1111等のWebUI向けに「プロンプトとネガティブプロンプトをまとめてコピー」する機能の要望が出た。形式例：`1girl, best quality \n Negative prompt: worst quality` をクリップボードに入れ、WebUIのプロンプト欄にペーストしてボタンをクリックすると両方が入力される操作を想定したもの（496）。

### プロンプト管理エディタ（スレ内有志作成ツール）

- **開発状況と機能**: プロンプトを管理できるエディタを作成中。Blueやred等の文字に色が付く機能、`｛｝`等の構文チェック機能、「,」やスペースを簡単に修正できる機能を実装済み。改造OKとしてログに公開されている（508）。
- **機能要望と議論**:
  - ワンクリックでP/NP（プロンプト/ネガティブプロンプト）をコピーするボタンの要望（477）。Ctrl+Cで済むという意見（481）に対し、コピーボタンがあればキーボードに触れる必要がなく、マウスだけで管理できるため利便性が大幅に変わるとの反論（482）。マウスの機能ボタンにCtrl+C/Vを割り当てればよいという意見（484）や、左手が塞がっている状況等を考慮するとボタンが必須という意見（502）もあった。最終的にレイアウトに余裕があるためクリップボードへのコピーボタンは実装予定（492）。
  - P/NPをタブ表示するのではなく、右側の余っているスペースにNPを表示できるようにし、レイアウトを変更できる設定があったら便利という要望（503）。また、使用フォントおよびフォントの大きさを変更できるかの質問もある（503）。

### nano-banana (nanobanana)

- **LoRA学習の素材水増し用途**: nsfw素材はQIEで、sfw素材はnano-bananaで素材を水増ししてからfizgigでLoRAを作成するというエージェント型AIのパイプライン例の中で言及（515）。

### sd-scripts

- **LoRA学習環境としての利用**: Moss-ImageのLoRA学習にsd-scriptsが使用されている。学習設定例として、素材数25枚、CAME、alpha 32、dim 32、learning_rate 5e-05、discrete_flow_shift 3、max_train_epochs 120、4090使用で約2時間30分という情報が共有された（538）。ただし、別の利用者はsd-scriptsは遅いのではないかと疑問を呈している（545）。
- **CosPar等の導入**: 記事にあったCosParとemoPulseの導入について、どちらか片方を使用し、CosParを選択したケースが報告された。導入方法は、GitからCosParのページを見つけ、schedulerフォルダごとsd-scripts直下に配置し、学習コマンドに`--lr_scheduler_type=scheduler.cospar.CosPar --lr_scheduler_args "min_lr_rate=1.0"`を追加する手順が解説された（495）。
- **データセット定義ファイルを用いたマルチキャラ・マルチ衣装LoRA作成**: 画像をサブフォルダに仕分けして固有のトリガーワードを割り当て、timestep_samplingのoffset指定を行うことで、マルチ衣装・マルチキャラLoRAを作成できる手法が紹介された。コンフィグファイルは長くなるが、1枚ずつタグを確認して割り当てるよりも楽とされる（473、501）。datasettageditorのポン出しタグとredrayzニキのプリセットそのまで学習を行っている段階の利用者もいる（509）。

### その他のツール・環境

- **Muse**: 音声入力とスタンプでの指示が可能で、マスクまで自分で設定しておまんこを描きなおしてくれるため便利と評価されている（505）。エージェントとしてComfyUI等のツールをAPI経由で操作する（518）。無料かつNSFW可（エロに寛容）であることが選ばれている理由。CodexやClaude Codeでも同様のことは可能だが、無料でエロOKならMuseを選ぶ理由になる（557、600）。
- **SnapRef (Snapref v2a)**: 画像1枚からキャラ出しができ、LoRAを作る必要がなくなるほど高性能という報告がある（453、459、460）。Animaのrefは3種類あり、そのうちSnapref v2aは良いという評価。Anima Reference Adapterはイマイチ、Anima Role Ref KVは未検証（469）。ただし、マルチキャラクターでは混ざりまくりでまともに使えないという課題も報告されている（614）。
- **fizgig**: LoRA学習ツールとして非常に楽であり、すべてfizgigで済ませるようになったという声がある（511）。赤ちゃん（初心者）でもLoRA学習ができるとされる（509）。Moss-ImageのLoRA学習にも使用されている（515、542）。
- **redrayzニキのGUIツール**: 学習コマンドに追加の命令を加える機能があり、CosPar等の導入にも利用可能（495）。プリセットが提供されている（509）。
- **KohakuMossTrainer**: sd-scriptsの遅さを懸念して使用。adamw、1024x1024、5090(PL80%)で3000stepなら1時間で完了すると報告されている（545）。
- **strata**: AIエージェントツールとして言及。Moss-Imageの最新学習環境を調べて設定ファイルを作成させたり、無検閲版Qwen 3.8 Flash Next等をHermesでフルコントロール許可してエロ込みでの利用に対応させたりする用途で語られている（510、524）。
- **datasettageditor**: LoRA学習用のタグ編集ツールとして言及。ポン出しタグをそのまま使用している（509）。
- **Codex / Claude Code**: ComfyUIの環境構築やワークフロー作成を自動化するコーディングツールとして言及。エロOKの点でMuseに劣るため、用途によって選択が分かれる（557）。
- **mate**: 2年くらいアップデートしていなかったが、通知が来てうっかりアップデートしたら重くなったという報告（526）。
- **siki**: レイアウト等をすべて好きに変えられるため便利とされている（503）。
- **HTMLボタンによるプロンプト管理**: 使いそうなプロンプトをすべてHTMLのボタンにし、押すとクリップボードに入るように設定。マウスのボタンにctrl+Vとenterを割り当ててマウスだけで操作する運用方法が紹介されている（487）。
