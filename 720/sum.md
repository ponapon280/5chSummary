# 元の本文
今回とくに盛んに議論された話題は、MOSSとAnimaのLoRA学習知見の蓄積、エージェント（Muse等）によるワークフロー自動化、そしてNAIの新機能とローカル環境の対立である。

### LoRA学習と環境構築
- **MOSSのLoRA学習**：学習に時間が掛かり難易度が高い（>>287, >>290）。kohya氏はAnimaより学習データと勾配ノイズのSN比が低いと指摘し、max_grad_normを0.01に下げる、解像度を下げる、学習率を下げてじっくり学習することを推奨している（>>317）。スレ上の目安として10000step前後で焼けるという意見が複数ある（>>314, >>318）。解像度を0.75MPや512に下げても劣化せず、3090で9時間や5070tiで6時間程度で学習可能との報告がある（>>120, >>633, >>638, >>680, >>692）。学習設定の具体例として、素材数25枚、CAME、alpha 32、dim 32、learning_rate 5e-05、discrete_flow_shift 3、max_train_epochs 120、4090使用で約2時間30分という知見が共有された（>>538）。CosParをsd-scriptsに導入する手法も共有された（>>495）。
- **AnimaのLoRA学習**：覚えが良すぎてキャラだけでなく画風まで学習されてしまうのが悩み（>>824）。1024より512の方が学習が上手くいき、身体構造が崩壊しにくいとされる（>>698, >>699）。
- **LoRAの必要性**：将来AIがプロンプトで絵柄再現可能になるという見方（>>706）がある一方で、画風は言語化できないため現在はLoRAが必要との反論（>>707）。
- **マルチキャラ・マルチ衣装**：キャラ・衣装単位でサブフォルダに仕分け、固有トリガーワードを割り当て、timestep_samplingのoffset指定で構築可能（>>473）。

### ComfyUI運用とエージェントによる自動化
- **ComfyUIの運用問題と代替ノード**：アップデートに伴いPower Lora Loaderが使えなくなる（>>226）やLC lora loaderで数値入力時に無限に値が増減するバグ（>>225）が報告された。rgthree氏はNode v2.0に移行しない宣言を出しており、代替としてネイティブノードのスタック形式（>>227）、Lora Manager（>>230）、Moss-Image Prompt Builder KJ等が提案された（>>229）。jupoニキのloaderは便利だったがGitデータが全消去されており、再配布の可能性が話題になった（>>249）。
- **ComfyUIの評価**：ノード配置と配線を延々やらされるクソゲーという批判（>>645）に対し、一度WFを作れば良いとの反論（>>654）や、エージェントに監督させるべきという意見（>>650）がある。Comfy Desktopへの移行が推奨されている（>>840）。
- **エージェント・ワークフロー自動化**：MuseをエージェントとしてComfyUIをAPI経由で操作し、ワークフローを見ずに画像生成からキャプション付け、学習監視まで全てを委ねる動きが活発（>>383, >>518）。出先のスマホから生成も可能（>>600）。無料かつNSFW可が利点で、CodexやClaude Codeより優位とされる（>>557）。チャッピーやエージェントにカスタムノードを作らせるのも有効（>>248, >>251）。エージェント運用半年で愛着が湧いたとの声や、絶頂時イラストへのmodificationを的確に提案するエロゲ共同制作事例がある（>>257, >>264）。

### 画像生成モデル・ツールの状況
- **MOSS**：ポン出しで1枚10分以上掛かる（>>63）が、オリジナルキャラの漫画が描けると高評価（>>129）。bboxが便利（>>164）だがサブグラフが分かりにくい（>>208）。プロンプト強弱はデフォルトでは効かず、kijaiのカスタムノードやnegpipで対応する（>>783）。小柄キャラの手が大きく描かれる問題がある（>>486）。AIエロ漫画作成では「moss一選」との声（>>965）。VRAM 16GBでは高速化LoRA使用時に容量オーバーする問題があり、w4a8_gptq等の小さいテキストエンコーダを使う解決策が提示された（>>912, >>914, >>915）。
- **Anima**：自然言語の自由度が高くローカルアニメモデル最先端との評価（>>164）。SnapRef登場で1枚からLoRA不要になった（>>453）。
- **SnapRef**：画像1枚からLoRA不要で生成可能（>>460）。v2sはスタイル参照特化だが、プロンプトでアレンジすると崩壊する（>>792, >>798）。LoRA抜きの人物差し替えが実用射程に入ったとの報告もある（>>921）。
- **NAI**：v5「精密参照」機能がリリースされ、LoRAなしでキャラ再現可能か注目された（>>934, >>942）。インペイント非対応や複数人参照が苦手という指摘（>>947, >>944）がある一方、画風制御が楽との評価（>>995）。「低解像度のゴミ」とローカルを擁護するユーザーとの対立が発生した（>>958, >>961, >>972）。
- **チャッピー**：プロンプトを任せるとカメラアングルが融通しない（>>269）。出力画像でネガティブスペースを同じ密度で埋め尽くす「ウォーリーを探せ状態」がデフォルト（>>475）。無料版は修正指示に従わないとの声（>>354）。6.2solがchatに来て解説が分かりやすいとの評価（>>693）。エロでBANされるリスクがある（>>730）。
- **Gemini**：モデル（Carbon, Neon, Argon）ごとの用途が語られ、日常会話ならArgonで十分とされた（>>201, >>211）。エロでBANされるリスクがあり、原因はGoogle Driveであるとの指摘がある（>>673, >>710, >>722）。
- **Muse**：無料でエロ翻訳に高品質（>>724）。エロは弱い（>>922）がセクハラ可能な秘書アプリとして使われている（>>937）。個人情報取得が懸念されている（>>732, >>745）。

### プロンプト・身体部位制御の技術
- **胸サイズ指定**：アンダートップcm指定は通らず、plump等で強度調節するのが早い（>>316）。カップサイズ指定は補助的に効くが他の単語に負けがち（>>392, >>400）。両方書く（>>162）、スケジュール構文 `[small breasts:medium breasts:0.4],` を使う（>>172）等の回答があった。上向き胸には `perky breasts` が有効（>>174）。
- **その他の部位**：腿の太さ指定は他部位も変化するため、骨盤（腰回り）の大きさ指定が有効だった（>>440）。Animaやリアスは胸サイズ無指定だと大抵巨乳が出る（>>319）。

### 検閲回避・投稿サイト運用
- **Pixiv規制**：湯気や光で乳首を完全に隠してもR18タグを強制付与されるようになった（>>532）。登録者数が激増し「世界一のイラストサイト」になったが、モザイクおま国仕様との声（>>646, >>649）。
- **Civitaiのロリ判定**：loli検索で怒られるため、ロリ系アーティストのLoRAを出しているユーザーを辿りciv_archiveを見る手法が提案された（>>222）。エロ出力制限や検索除外の対象となるが規約違反ではないとの見解（>>956, >>957）。キャプションを消し健全なショーケース1枚だけにして生存させた事例や、一度に複数unpublishされるとアカウント停止の3 strikeに至る恐れがあるとの注意喚起がある（>>990）。遊戯王ドラゴンメイドLoRAがラドリーのせいで未成年判定を受けた事例もあった（>>954）。
- **自動モザイクソフト**：動画用自動モザイクソフト（ブースで3500円）が正確との評価（>>71）。エージェントに作らせれば1時間でローカル（5090）の静止画・動画追従アプリが作れたとの報告がある（>>68）。ただし手や口が重なると精度が落ちるため、99.9%の正確さを求めるなら手動でフォトショが必要（>>74）。

### 総評
1. MOSSのLoRA学習はAnimaよりSN比が低く難易度が高いが、解像度を0.75MPや512に下げて10000step回すことで画風学習が可能という知見が蓄積した。
2. Muse等の無料LLMをComfyUIのAPIエージェントとして活用し、生成から学習までを完全自動化する動きが主流になりつつある。
3. SnapRefやNAI v5の精密参照機能が登場し、LoRAを作らずにキャラや画風を再現する手法の実用性が向上している。
4. PixivのR18タグ強制付与やCivitaiのロリ判定回避など、プラットフォームごとの検閲強化に対する運用術が共有された。
