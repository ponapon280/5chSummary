## ComfyUI：ノード・ローダー・ワークフロー運用

### rgthree Power Lora Loaderの不具合と代替案
rgthreeのPower Lora LoaderはNode 2.0で操作不能になる不具合が未だに直っておらず、bboxノードが2.0専用のため困る声がある（220）。rgthree氏はNode 2.0へ移行しない宣言をしており、Server起動時にその旨が表示されるため、対応しきれないrgthreeは捨てて自分に合うものを探すという意見がある（229, 239）。代替としてネイティブノードにPower Lora Loaderのようなスタック形式が追加されているという指摘（227）や、Lora ManagerのLora Loaderを使えば画面からLoRAを追加できて便利という推奨がある（230）。

### Ultimate Lora Loader (Civitai)
検索と操作性がイマイチで、未選択時に末尾のLoRAをメタデータ出力するバグがあり使用を取りやめた。Node 2.0移行をやめたためPower Lora Loaderに戻ったが、バグがあるためUltimate Lora Loaderを改造して使うことを検討中という報告がある（245）。

### jupoニキのloader
A1111風に画像一覧から選べてトリガーワード確認可能で超便利と評価。Node 2.0でも不具合なし。Gitのデータが全消しされているが、ライセンスはMITのため再配布は許可される（249）。

### Context系ノードとFrontend依存
rgthree Fast group muter/bypasserとContextはComfyUI最新化で連動しなくなり、workflowの書き直しが発生する（253）。Contextノード/スイッチは事実上必須と認識されているが、使っていない人もいる（255, 303）。frontendアップデート時の依存問題から依存パックを減らしたい意向があり、FromBasicPipeに移行したユーザーもいる（263, 326）。

### MOSS用WF・ノード運用
mossのテンプレートがサブグラフで構成されており分かりづらいという不満があり、サブグラフを使っていない古いバージョンを使っている（208）。推奨WFとして、rgthree氏がNode 2.0に移行しないためMoss-Image Prompt Builder KJやMoss-Layout-YDRを使うと良いというスレ上の推奨がある（229）。moss-layout-ydrのnodeを使うとobject指定で手等の配置が見えるため効果を感じられるが、キャラクター全体になると矩形からずれるためcharacter指定やcharacter_boxes指定が必要と考察されている（870）。キャラの位置指定ではなく頭・身体・手足等の細かいbbox指定でポーズ付けが可能で、promptに多く書く場合はobject指定で手足の位置を指定する方が良いとの見解がある（881, 929）。position:left等でも位置指定できるためガバガバbboxを使う機会はない（868）。

### VRAM容量問題と対策
moss使用時、高速化LoRAが1GBあるため、テキストエンコーダーを毎回VRAMから追い出す設定にしないとvram16gbを溢れてしまう（912）。TEを常時VRAMに乗せる必要性は疑問であり、RAMから読んでも遅くならないという意見がある（913）。VRAMに乗せたい場合、comfy-orgのhuggingfaceにある7.34GBのqwen3.5_9b_w4a8_gptq.safetensorsを使う手法が提案されている（914）。

### ComfyUI Desktop vs Stability Matrix
ComfyUIしか使っていないならデスクトップ版が便利と聞いたという質問（840）に対し、Comfy Desktopにはメリットが多く、Stability MatrixでComfyUIしか使っていないなら移行する価値があるという結論がある（842, 843）。

### 強度指定・negpip・KJNode
MOSSのプロンプトで強度指定（very hoge等や(hoge:2)）はデフォルトでは効かない。kijaiのカスタムノードかnegpipを入れると効くようになる（781, 783）。negpipを入れることで細い指示が可能になり、不慣れな英語より全部日本語で自然言語として書いたほうがいい結果になることも多く、日本語文章にもしっかり効果がある（785）。KJNodeのものも同じ機能を持ち、Clip Text Encoder(Positive)と入れ替え、modelも接続する必要がある（786）。

## エージェント・LLMによるツール操作の自動化と外部委託

### Muse（エージェント）によるComfyUI操作の丸投げ
使えそうなワークフローをAPI化し、モデルとノードを揃えて操作自体をMuseに任せる運用が報告されている。画像収集からキャプション付け、学習監視までMuseに委ね、人間は画像を見るだけという段階にも至っている（254, 383, 384）。ComfyUIとエージェントがjsonでお互いにやり取りする形が一番良いとAIに提案され、リアルタイム生成を行うならこの方法が一番融通が利くという（632）。Museは音声入力とスタンプでの指示が可能で、マスクまで自分で設定しておまんこを描きなおしてくれるため便利と評価されている（505）。複雑な画像も簡単な日本語の指示で作ってくれる（comfyuiと組み合わせて）（906）。無料かつNSFW可（エロに寛容）であることが選ばれている理由で、CodexやClaude Codeでも同様のことは可能だが、無料でエロOKならMuseを選ぶ理由になる（557, 600）。ただしアダルトの文章はダメと言われ、成年同士であることを説明すれば成人同意くらいならいける（922, 940）。エロに強いという評価は100%間違いという意見もあり（925）、日本語能力に課題があるとの指摘もある（928）。利点は無料で使えることとエージェント力で、各社のTrialプランとProプランの間ぐらいが無料で使える（924, 925）。Muse来てから簡単なツールをあれこれ作らせては大して使わないを繰り返している（895）。VPNサーバや自作通知サーバ等のlinuxサーバ的な使い方ができるかも問われている（960）。

### エージェントによるワークフロー構築・環境構築の自動化
新しいモデルが出た時にComfyUIの環境構築が面倒でCodexに丸投げすると、導入から動作確認、サンプル生成画像の作成まで完了させてくれるため自分でやらなくなるという声がある（628）。テンプレートから公式WFを数クリックで出せる形式を活用する利用者もいる（635）。ComfyUIに新モデルを導入し、sfwとnsfwの画像をそれぞれ5枚ずつ生成してまとめシートを作成するまでのプロセスを、AIエージェントがプロンプトの考案から検証、シート作成まで自動で完遂する様子が語られている（641）。

### エージェント利用 vs 手動ノード構築の議論
ノードを繋いで実行するだけで目的が達成できるのにエージェント等を回りくどく使っているという意見（558）に対し、目的は絵や動画を手に入れることであり、エージェントは「ノードを繋ぐ作業すら人間から取り除く仕組み」であるとの反論（560）があった。言葉で説明するよりUI操作の方が速いこともあり、エージェントが常に最適解とは言えないという見方もある（562）。PCで直接ComfyUIをいじる以外に、ベッドでスマホから気楽にエージェントへ生成指示を出す使い方も便利という声もある（569）。変な思い込みで必要ないことまでエージェントにさせていないか、配線つなぐくらいは自分でやった方がよく、監督をAIにさせればよいという意見がある（650, 652）。本当の意味でワークフローの流れを理解できていないと色々厳しく、パラメーターと工程を確認したいなら結局ComfyUIを起動してWFを見るのが一番良い（650, 661）。

## LoRA学習ツール・スクリプト

### sd-scripts
Moss-ImageのLoRA学習に使用されている。学習設定例として、素材数25枚、CAME、alpha 32、dim 32、learning_rate 5e-05、discrete_flow_shift 3、max_train_epochs 120、4090使用で約2時間30分という情報が共有された（538）。ただし別の利用者はsd-scriptsは遅いのではないかと疑問を呈している（545）。更新が来たとの報告があり、余ったVRAMがある場合は高速化の対象になるが、12GB環境では関係ないという指摘がある（143, 175）。Moss-image LoRA学習で特定のスケジューラーをsd-scriptsにコピーする手間が必要で、CosParを使用した例が報告された（295）。`--logit_mean -1.09 --logit_std 0.95 --sigmoid_scale 1`をコマンドから削除したらグラフが明確に変化し、これらは効いていると確認。`--show_timesteps`オプションでタイムステップ分布を確認可能（306, 312）。CosPar等の導入として、GitからCosParのページを見つけ、schedulerフォルダごとsd-scripts直下に配置し、学習コマンドに`--lr_scheduler_type=scheduler.cospar.CosPar --lr_scheduler_args "min_lr_rate=1.0"`を追加する手順が解説された（495）。データセット定義ファイルを用いたマルチキャラ・マルチ衣装LoRA作成手法が紹介され、画像をサブフォルダに仕分けして固有のトリガーワードを割り当て、timestep_samplingのoffset指定を行うことで作成できる（473, 501）。kohya氏の知見として、Moss-Imageのstyle系LoRAは学習データと勾配ノイズのSN比が低く、max_grad_normを0.01に下げる・解像度を下げてステップ数を稼ぐ・学習率を下げてじっくり煮込む等の対症療法が提示された（317）。AUTOMATIC1111がKoikatsuModsの最初期の作者であることが言及されている（228）。

### fizgig
LoRA学習ツールとして非常に楽であり、すべてfizgigで済ませるようになったという声がある（511）。赤ちゃん（初心者）でもLoRA学習ができるとされる（509）。スタンダード設定で87枚のキャラLoRAを70エポックで6時間超。まず40エポックでお試し推奨。解像度0.25MPのfastか0.5MP推奨かの問いあり（315, 374）。学習解像度0.75MPでも劣化を感じないとの報告（317）。Moss-ImageのLoRA学習にも使用されている（515, 542）。

### KohakuMossTrainer
sd-scriptsの遅さを懸念して使用。adamw、1024x1024、5090(PL80%)で3000stepなら1時間で完了すると報告されている（545）。

### redrayzニキのGUIツール
学習コマンドに追加の命令を加える機能があり、CosPar等の導入にも利用可能。プリセットが提供されている（495, 509）。

### datasettageditor
LoRA学習用のタグ編集ツールとして言及。ポン出しタグをそのまま使用している（509）。

## SnapRef

画像1枚からキャラ出しができ、LoRAを作る必要がなくなるほど高性能という報告がある（453, 459, 460）。Animaのrefは3種類あり、そのうちSnapref v2aは良いという評価。Anima Reference Adapterはイマイチ、Anima Role Ref KVは未検証（469）。ただしマルチキャラクターでは混ざりまくりでまともに使えないという課題も報告されている（614）。v2sのプレバージョンが来たが今回はキャラではなくスタイル参照に特化している（792）。画風のコピー性能は良いが、生成画像のノイズや細部の潰れがヤバく、プレバージョンのため本番に期待という評価（910）。とても実用レベルとは言えない。元画像っぽいのを再生成できるだけで、少しプロンプトを入れてアレンジすると崩壊する（798）。ふと見かけたキャラで即席オカズを作って雑に抜くのには十分（799）。絵柄が安定しないけどLoRAを作りたくない人にちょうどいい（800）。NAI4.5の精密参照くらいの精度はある（811）。LoRA抜きで人物差し替えが実用射程に入っており、MOSSで描いた画像をSnapRefで別キャラに差し替え可能。原理がインペイントのため、人物と重複・接触する部分は一緒にAnimaの出力で差し替えられる仕組み（921, 943, 968）。久々にノードポチおじになって楽しめたという報告もある（921）。

## プロンプト管理・操作ツール

### スレ内有志のプロンプト管理エディタ
プロンプトを管理できるエディタを作成中。Blueやred等の文字に色が付く機能、`｛｝`等の構文チェック機能、「,」やスペースを簡単に修正できる機能を実装済み。改造OKとしてログに公開されている（508）。ワンクリックでP/NPをコピーするボタンの要望（477）に対し、Ctrl+Cで済むという意見（481）、コピーボタンがあればキーボードに触れる必要がなくマウスだけで管理できるため利便性が大幅に変わるとの反論（482）、マウスの機能ボタンにCtrl+C/Vを割り当てればよいという意見（484）、左手が塞がっている状況等を考慮するとボタンが必須という意見（502）があり、最終的にレイアウトに余裕があるためクリップボードへのコピーボタンは実装予定（492）。P/NPをタブ表示ではなく右側の余っているスペースに表示でき、レイアウトを変更できる設定があったら便利という要望と、使用フォントおよびフォントの大きさを変更できるかの質問がある（503）。

### HTMLボタンによるプロンプト管理
使いそうなプロンプトをすべてHTMLのボタンにし、押すとクリップボードに入るように設定。マウスのボタンにctrl+Vとenterを割り当ててマウスだけで操作する運用方法が紹介されている（487）。ComfyUIで使ったプロンプトを引き出すためにわざわざComfyUIを立ち上げず、htmlファイル1枚完結でメタデータを読めるものが作れる（756）。

## その他のツール・サービス

### エージェントを用いたモザイク作成ソフト
AIエージェントに作らせると、静止画だけでなく動画の指定部位を自動追従してモザイクを付け続けるアプリをローカル環境（5090）でも1時間ちょいで作れた。ただし追従は四角領域になりがちで、多角形やフリーハンド風の領域指定は面倒（68）。BOOTHで3500円のソフトは動画用でもかなり正確だったが、チンポに手や口が重なると途端に精度が落ちるため人力レベルの99.9%の正確さは求められないという評価がある（71, 74）。

### strata

## 総評

1. **ComfyUIのノード構築をエージェントに外部委託する運用が実用段階に入っている**。Muse等のエージェントがAPI経由でComfyUIを操作し、プロンプト考案から検証・シート作成まで自動完遂するパイプラインが報告されており、「ノードを繋ぐ作業すら人間から取り除く仕組み」として評価されている一方、WF理解の重要性を唱える声も根強く、両者の議論が活発化している。

2. **rgthree系ノードのNode 2.0非対応がLoader選定の分岐点となっている**。Power Lora Loaderの操作不能バグが未修正で作者が移行しない宣言を出したことを受け、jupoニキのloaderやLora ManagerのLora Loader、ネイティブスタック形式Loader等への乗り換えが具体的に議論され、替代案が複数提示されている。

3. **LoRA学習環境がsd-scripts・fizgig・KohakuMossTrainerの三択に整理されつつある**。sd-scriptsはCosPar導入やデータセット定義ファイルによるマルチキャラ学習など高度な制御が可能だが遅さが指摘され、fizgigは手軽さで初心者に推奨され、KohakuMossTrainerはsd-scriptsの遅さを回避する選択肢として位置づけられている。

4. **SnapRefがLoRA不要のキャラ差し替え・スタイルコピー手段として実用射程に入り始めている**。v2aでキャラ参照、v2sでスタイル参照という棲み分けが示され、人物差し替えがインペイント原理で機能することが確認された一方、マルチキャラでの破綾やプロンプト追加時の崩壊など精度面の課題が残っている。
