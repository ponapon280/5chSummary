### 全体
- ComfyUI Nodes 2.0移行に伴うカスタムノード互換性問題、BBOX機能改善、FizgigによるMOSS LoRA学習環境整備が議論された。

### LoRA学習ツール（Fizgig / AI-Toolkit / sd-scripts等）
- Fizgig：低VRAM環境（8GB〜12GB）でのMOSS LoRA学習に有効でv8.6.0の類似性改善が高評価だが、Prodigy不可、更新後の速度低下、起動ハング等の報告あり（328, 399, 539, 602, 603, 657, 713, 749, 489）。
- sd-scripts / その他：MOSS対応の確認やdevブランチの推奨、RedRayz/ostris各氏の技法への期待、CodexによるMusubi tuner UI作成手法が挙がった（969, 306, 332, 344, 122, 131, 658, 327）。
- 学習所感：5090環境では素材32枚/100stepで2m38sで効果が出、100枚時は250Stepから効き1500Stepで過学習との報告（252, 298）。

### 3Dモデリング・プリビズ関連ツール
- Blender：背景動画を参考にした3Dモデル動作をMiniMax H3 R2Vへ入力し2Dアニメを生成する手法が提案。美少女モデリングは困難だがマイクラ程度ならCodexで可能とされる（47, 863, 882, 888）。
- tripo：イラストから美少女モデリングが可能でAstra/Opus5.5でアニメーションまで行えるが、絵柄の実用性に欠けるとの評価（865, 876, 889）。
- 「きゃらくる」：Codexを用いてBlender直接操作より良好な3Dモデルを作成（381）。

### ChatGPT（チャッピー）・LLMのツール的利用
- 環境構築・エラー修復：モデル名指定やスレログ投入により、GitHub検索に代わり環境構築やComfyUIの修復、LoRA環境構築に利用（961, 978, 944, 946, 958, 999）。
- UI作成：ComfyUIの複雑なノード管理を避けるためUI作成に利用。バックエンド利用によるローカル編集の可能性が指摘された（326, 336, 323, 318）。
- プロンプトエンハンサー：塗りのプロンプト作成やLM StudioへのMOSS公式skills導入によるエロプロンプト作成に利用。Qwen3.5 9Bでの劣化やLLMによる検閲文言挿入の報告あり（26, 346, 539, 914, 921）。
- 検閲・BANリスク：未成年ワード迂回によるBAN事例があり、Chrome翻訳やPC内部監視の懸念から隔離運用が推奨（355, 430, 349, 371, 394）。

### その他ツール
- LM Studio / Strata：検閲・BAN回避のエロプロンプト作成や、gemma4によるbooruタグの自然言語加工に利用（364, 539, 791）。
- どこでもロケハン：背景作成に便利との評価（428）。

### 総評
- LLMをComfyUIの構築・修復・UI作成やプロンプト強化に活用する動きが一般化する一方、検閲BANや監視リスクから隔離環境での利用が推奨されている。

# 元の本文
今回とくに盛んに議論された話題は、ComfyUIのNodes 2.0移行に伴うカスタムノードの互換性問題とBBOX機能の改善、およびFizgigによるMOSSのLoRA学習環境の整備である。

※以下のレス番号は元スレの通し番号とは限らない。

### ComfyUI / Forge Neo
- **Nodes 2.0移行とカスタムノード問題**: Nodes 2.0への移行に伴い、Power LoRA Loader等の代替ノードが必要となっている。代替としてComfyUI_EclipseやComfyUI_LC123_nodesが挙がり、標準のローダーを用いる場合は起動オプションに `--front-end-version Comfy-Org/ComfyUI_frontend@latest` を付ける必要がある（574, 898, 907, 911, 913）。ただし標準ローダーはCIVITAI連携やメモ機能がなく代替としては弱い（930）。Nodes 2.0のβマークは消えており移行は時間の問題と見る声があるが、解像度指定がバグる、tag補完が反応しない等の問題も報告されている（898, 901）。
- **BBOXノードの改善**: ComfyUIの`Create Bounding Boxes`ノードは使いにくく、解像度セレクターから幅と高さを接続しても反映されない不便さがあった（409, 810）。このため、Resolution SelectorのW/H出力をEmpty Imageノードに繋ぎ、Create Bounding Boxesのbackground入力に接続するワークフローが共有された（484, 495）。また、BBOX側のキャンバスサイズも即時反映されるよう自作された`ComfyUI-BBox-AutoRescale`や、ComfyUI-ppmに追加されたbboxノード、Strata制作のクラシックモード対応BBOXエディタノード等の代替が模索されている（802, 903, 972）。BBOX内にセリフや擬音を入れると選択できなくなる問題も指摘されている（464）。
- **アップデートと環境維持**: アップデート頻度が高く（998）、アップデートのたびにノードが壊れたり遅くなる問題があるためバックアップ必須とされる（150）。デスクトップ版ではスナップショットが自動作成されロールバックが可能だが（163）、アプデで壊れた環境をチャッピー（ChatGPT）にエラーログを貼り付けて修復させる運用が行われている（999）。
- **MOSS対応状況**: masterから引っ張ってこないとMOSSに対応できない。v0.41.3では「MOSS-Image レイアウトプロンプト」未実装、Stable版はv0.42待ちだが、Latest更新とComfyUI Desktopではテンプレートワークフローが追加済み（281, 291）。
- **Forge Neoの優位性と選定理由**: 画像生成の試行を繰り返す際やxyz比較（チェックポイント比較）を行う際、ComfyUIよりForge Neoの方が楽であるためForge Neoを選択する声が複数ある（138, 450, 454, 458, 466）。RTX 4070Ti (VRAM 12GB) 環境では、自動的にVRAM内に収まる設定になりMOSSを生成可能。Batch sizeを増やすと遅くなるため、BatchCountを増やす方が速い（230, 753）。
- **Forge Neoの高速化機能**: spectrum integrated有効化でAnimaの生成時間が10秒から5秒に短縮されるが、細部が潰れる等の欠点があり動画向き（247, 294）。sage attentionの起動オプション追加や、アップデートによるAnima生成の13秒→8秒高速化事例も報告されている（146, 241）。

### LoRA学習ツール（Fizgig / AI-Toolkit / sd-scripts等）
- **Fizgigの評価と選定理由**: 低スペ（VRAM 12GB）環境でも推奨設定ギリギリでLoRA学習が可能で、AI-Toolkitより低スペに優しい（328, 399）。VRAM 8GBでも50stepsで1時間半でMOSS用LoRAを作成できた事例がある（539）。v8.6.0でMOSSイメージの類似性が改善され、「もう全部Fizgigでええなこれ」と評価された（657, 713）。一方で、Prodigyが使えない（489）、v8.6.0更新後学習がめっちゃ遅くなった（749）、起動時にハングするトラブル（独立アプリ版の.bat起動で回避可能）といった報告もある（602, 603）。
- **AI-Toolkit**: モデルの自動ダウンロードや学習・推論環境がセットで用意され、ComfyUIに不慣れな層の手軽さが選定理由（200）。しかしデフォルト設定で5070ti環境・3000step・解像度512で30時間かかる等、低スペには優しくない（137, 217, 327）。5070tiでは解像度1024・1500stepのキャラクターLoRAは限界に近く、VRAM消費は13GB（142, 204）。
- **sd-scripts / その他**: MOSSのLoRA作成においてsd-scriptsの対応が確認され（969）、対応を待つ声やdevブランチを覗く推奨がある（306, 332, 344）。RedRayzニキのGUIや、ostrisニキの独自差分LoRA技法も待望されている（122, 131, 658）。また、Musubi tunerのUI作成をCodexに任せる手法も挙がっている（327）。
- **LoRA学習の所感**: 5090環境・素材32枚・サイズ768・step100で2m38sで効果が出る（252）。100枚で試すと250Stepから効き、1500Stepで過学習という報告あり（298）。

### 3Dモデリング・プリビズ関連ツール
- **Blender**: プリビズ制作で背景動画を参考に3Dモデルを動かし、MiniMax H3 R2Vに入力して2Dキャラアニメーションを生成する手法が提案されている（47）。0からの美少女モデリングは学習データ不足で難しく、Codexにモデリングさせてもクリーチャーになるが、マイクラ程度なら可能とされる（863, 882, 888）。
- **tripo**: イラストから美少女モデリングが可能。有料版を使い、Astra/Opus5.5でBlenderリギングからアニメーションまで行える。ただしゾンビみたいなbreak絵柄しかできず実用性はないとの評価もある（865, 876, 889）。
- **「きゃらくる」**: 3Dモデル作成にCodexを使用。Blenderを直接使わせるより良い成果物が得られる（381）。

### ChatGPT（チャッピー）・LLMのツール的利用
- **環境構築・エラー修復**: モデル名さえ分かればチャッピーに聞いて環境構築が終わるため、GitHubで探す時代ではなくなりつつある（961）。直近のスレログをAIに投入してから聞く手法も推奨される（978）。ComfyUIのアップデートで壊れた環境の修復や、LoRA作成環境の構築（Readme渡し）に利用されている（944, 946, 958, 999）。
- **UI作成**: ComfyUIは複雑になるとノードの線がごちゃごちゃするため、チャッピーにUIを作らせる用途が挙げられている（326, 336, 323）。ComfyUIをバックエンドとして使い、編集機能が実装されればローカル向け編集で天下取れる可能性の指摘もある（318）。
- **プロンプトエンハンサー**: ChatGPTに塗りのプロンプトを作成させる用途や（26）、MOSS公式skillsをLM Studioに導入してエロプロンプトを作成させる用途がある（346, 539）。Qwen3.5の9B等でエロプロンプトをenhanceさせると逆に劣化する懸念や、LLMが勝手に検閲文言を挿入する事象も報告されている（914, 921）。
- **検閲・BANリスク**: 未成年ワードの迂回試みでPro年間課金でもBANされる事例がある（355, 430）。Codexは裏で開いているChromeの翻訳表示を見て拒否したり、PC内部を覗きBANする危険があるため、隔離運用が正解とされる（349, 371, 394）。

### その他ツール
- **LM Studio / Strata**: チャッピーの検閲やBANを回避するためのエロプロンプト作成ツールとして選定されている。gemma4でbooruタグを自然言語に加工させる用途等（364, 539, 791）。
- **DWPose / openpose**: MOSS環境でDWPose人形を使った姿勢制御LoRAの作成や、SD1.5時代の棒人間作成に言及されている（664, 668）。
- **どこでもロケハン**: 背景作成に便利とのこと（428）。

### 総評
1. ComfyUIのNodes 2.0移行に伴うカスタムノードの欠落やBBOXの操作性低下が顕在化しており、標準ノードへの移行や自作ノード・代替ツール（Forge Neo等）への逃避が同時に進行している。
2. FizgigがMOSS対応や低VRAM環境（8〜12GB）での学習ツールとして覇権を握りつつあるが、更新による速度低下等の課題も抱えており、sd-scripts等の他ツールの対応も待たれている。
3. Forge Neoは、12GB VRAM環境でのMOSS実行やxyz比較・試行錯誤のしやすさからComfyUIと併用・あるいは一択で使われるツールとして定着している。
4. ChatGPT（チャッピー）やCodex等のLLMを、ComfyUIの環境構築・エラー修復・UI作成やプロンプトエンハンサーとして活用する動きが一般化する一方、検閲BANやPC内部監視のリスクから隔離環境での利用が推奨されている。
