### 全体
- 新モデルMOSSの環境要件・LoRA学習・プロンプト運用、ChatGPTの検閲リスクに伴う他LLM移行、ComfyUI Nodes 2.0移行トラブルが主要議題。
- 本レポートのレス番号は元スレの通し番号とは限らない。

### MOSSのVRAM要件・生成速度と最適化
- VRAM 16GB以下ではBatch sizeを増やすとオフロードにより低速化するため、1枚ずつの繰り返し生成が効率的 (345, 360)。

### MOSSのLoRA学習の難易度とツール対応
- AI-Toolkitのデフォルト設定で150時間かかる報告があり、画風LoRA作成はkrea2より難易度が高い (61, 137, 645, 654)。
- Fizgig（VRAM 8GBで1.5時間/50 epochs可能）やsd-scriptsが対応。Fizgig v8.6.0ではDiT Block22の学習改善が実施 (539, 540, 657, 669, 969)。
- 公式はBaseでの学習を推奨し、Base製LoRAはSFTでも動作する (815, 822)。RTX5090では素材32枚・100step（2m38s）で顕著な画風変化を確認 (252)。
- 絵師タグはほぼ無効なため、自前での画風LoRA作成が必要 (843, 886, 936, 937)。

### チャッピー（ChatGPT）の検閲リスクと他LLMへの移行
- Codex経由のローカルファイル走査による未成年関連ワード検出で、Pro課金者を含むBAN事例や生成拒否が頻発 (349, 355, 362, 369, 371, 394, 395, 430, 914)。
- エロプロンプト作成に寛容なGemini、言語力の高いClaude、安価でAPI利用可能なDeepSeekへの移行が推奨 (353, 356, 367, 368, 386, 447)。
- Codexによるカスタムノード/UI作成やエラー解決、参照機能の特化によるLoRA不要化の可能性など、利便性は依然として高い (321, 660, 999)。
- Codex等の全範囲読み込み機能への懸念があり、Googleドライブ上の画像はパスワード付きzip暗号化での対策が有効 (690, 707)。

### ComfyUI Nodes 2.0移行トラブルと代替ノード
- Nodes 2.0移行に伴うカスタムノードの不具合が報告されており、標準LoRA読み込みノードにはフロントエンド起動オプションが必要 (901, 913, 964)。
- 代替としてComfyUI_Eclipse（Fast Muter/Bypasser代用）、Ultimate Lora Loaderや標準ノード（Power LoRA Loader代用）が紹介。ComfyUI-ppmのbboxノードは2.0不要で動作 (898, 907, 911, 972)。
- ComfyUI v0.42.0でMOSSに正式対応し、v0.42.1まで高速アプデが継続 (638, 998)。ForgeはXYZ比較に便利で、特にBBOX利用にはForge Neoが推奨される (124, 126, 450, 458)。
- Create Bounding Boxでセリフ・擬音入力時に選択不能になる問題に対し、Resolution SelectorからEmpty Image経由でbackground入力に繋ぐことでアスペクト比を反映させる手法およびfix版が存在 (464, 484, 532, 802)。

### 総評
- MOSSは構図制御や文字入れでAI漫画のハードルを下げたが、版権キャラ・人体描写の破綻と学習コストが課題。
- ChatGPTのファイル走査によるBAN事例を受け、Gemini/Claude/DeepSeek等へ移行する潮流がある。
- ComfyUI Nodes 2.0の不具合により、代替ノードの利用やForgeの継続利用が活発化。
- AI漫画は最低限のスタートラインに達したが、BBOXガチャや構成力の不足から、真のAIでない限り限界との見方が大勢。

# 争点地図

## 1. MOSSの性能・表現力とAnima・リアス・Krea2との棲み分け
- **自然言語理解と構図制御**: 自然言語での指示が通り、左右の指定を間違えないなど構図制御の安定感が体感的に過去一 (488, 509)。BBOXによる領域指定が強力で、AI漫画作成が格段に楽になった (500, 526, 813)。
- **文字入れと漫画**: 日本語、漢字、オノマトペの描写が非常に綺麗で、数コマ漫画の生成が優秀 (193, 264, 325)。
- **身体描写の弱点**: 指が6本になりがちで諦めムード (68, 613)。ボテ出産描写で膣の位置がズレる (233, 246)。SkipLayerGuidanceDiTSimpleの使用で人体破綻は安定化するが彩度が落ちる (299, 316)。
- **版権キャラ**: 現状そっくりさん感が強く、1年以上前のモデルであるリアスやAnimaの方が優位 (301, 357, 393)。ただしAnimaは知識の忘却が深刻で、風景の整合性や背景描写はMOSSが上回る (679, 769, 861)。
- **Krea2との比較**: 実写系では一択状態だったKrea2だが、MOSS登場でKrea2関連をどうするか悩む声 (498, 891)。2MP 8stepならKrea2の方が7秒程度で速い (919)。
- **覇権の行方**: 「日本語が通るXL」のような使用感で、アニメ版MOSSとedit版が出てからが本番との見方 (390, 610)。完成後にクローズド化・サブスク化する懸念も指摘 (401)。
(11, 53, 104, 488, 509, 610, 861, 891)

## 2. MOSSのVRAM要件・生成速度と最適化
- **VRAM要件と低スペック運用**: 12GB環境ではAnimaよりカツカツだが可能 (716, 727)。8GBのサブ機でも普通に使用可能 (734)。低スペックにはint8モデルと8step DMDの使用が推奨され、2MP画像1枚が3秒で生成可能 (911)。
- **生成速度**: 5090環境でも2MP 50stepで26秒 (919)、4080sで2MP 8stepで9秒 (979)、VRAM6GB環境では8stepで25秒 (952)。TEのサイズがAnimaより10倍大きいことが遅さの要因 (231)。
- **TE高速化**: qwen製のTE高速化が進められており、ComfyUI対応後12時間でかなり高速化 (245)。Spectrum integrated機能はAnimaで10秒から5秒に短縮したが、MOSSは非対応 (247)。
- **同時生成**: Batch sizeを増やすとVRAM 16GB以下ではオフロードが発生して遅くなるため、1枚を繰り返す方が速い (345, 360)。
(230, 231, 245, 247, 345, 716, 911, 919, 952, 979)

## 3. MOSSのLoRA学習の難易度とツール対応
- **学習の重さと難易度**: AI-Toolkitのデフォルト設定では150時間かかるという報告 (61, 137)。画風LoRA作成はkrea2より難易度が高く、8割覚えるが最後の一押しが覚えない (645, 654)。
- **ツール対応**: FizgigがMOSSに対応し、VRAM8GBでも50 epochsで1時間半でLoRA作成可能 (539, 540)。sd-scriptsも対応 (969)。Fizgig v8.6.0でDiTのBlock22を学習対象に含める改善がされた (657, 669)。
- **学習の推奨設定**: LoRA学習はBase推奨（公式見解）。Baseで作ったLoRAはSFTでも動作する (815, 822)。RTX5090なら素材32枚、step100、2m38sで露骨に画風替え効果が出る (252)。
- **絵師タグの無効性**: MOSSの絵師タグは効かない、またはごく一部しか効かないため自身で画風LoRAを作る必要がある (843, 886, 936, 937)。
(61, 137, 252, 539, 645, 654, 815, 843, 886, 969)

## 4. チャッピー（ChatGPT）の検閲リスクと他LLMへの移行
- **検閲とBAN事例**: Codex経由でローカルファイルを覗き見し、未成年関連ワードを検出して生成を拒否・BANする事例が複数報告 (349, 369, 371, 394, 395)。Pro年間課金でもBANされた (355, 362)。最新版では「AIでエロ画像作ろうとするやつの言うことは信用できない」と拒絶 (430)。プロンプトエンハンサー利用中に検閲メッセージが挿入される事象も (914)。
- **代替LLMの台頭**: エロプロンプト作成には寛容で言語力が高いGeminiや、プロンプト作成の上手さで評価されたClaudeへの移行が推奨される (353, 356, 367, 368, 386)。DeepSeekは激安で頭が良くAPIでエロが使える (447)。
- **チャッピーの利点**: 参照機能が特化されればLoRA不要になる可能性。CodexでカスタムノードやUI作成、ComfyUIアプデ後のエラー解決に利用される (321, 660, 999)。
- **セキュリティ懸念**: Codex等はデフォで全範囲読み込んでサーバーに投げる機能があり恐ろしい (707)。Googleドライブのエロ画像はパスワード付きzip暗号化で解決可能 (690)。
(349, 362, 367, 386, 430, 690, 707, 914, 999)

## 5. ComfyUI Nodes 2.0移行トラブルと代替ノード
- **移行の不具合**: Nodes 2.0移行によるカスタムノードの不具合やバグが報告 (901, 964)。標準のLoRA読み込みノード利用にはフロントエンド起動オプションの付与が必要 (913)。
- **代替ノードの紹介**: Nodes 2.0を使わずに済む代替ノードが紹介。Fast Muter/Bypasser等の代替としてComfyUI_Eclipse、Power LoRA Loader代替としてUltimate Lora Loader (Civitai) や標準の「LoRAを読み込む（モデル）」ノード (898, 907, 911)。ComfyUI-ppmに追加されたbboxノードは2.0不要で使用可能 (972)。
- **ComfyUIとForgeの棲み分け**: comfy v0.42.0でMOSS正式対応 (638)。v0.42.1がリリースされアプデ頻度が高い (998)。ForgeはXYZ比較などに便利で現役 (450, 458)。Forge Neoが覇権でBBOXを使うならNeo推奨 (124, 126)。
- **BBOXノードの改善**: Create Bounding Boxノードでセリフや擬音を入れると選択不能になる問題。Resolution SelectorのW/H出力→Empty Imageノード→Create Bounding Boxesのbackground入力と繋ぐことでアス比が反映される (464, 484, 532)。fix版も作成 (802)。
(124, 464, 484, 638, 802, 898, 901, 964, 972, 998)

# 総評
1. MOSSは自然言語理解とBBOXによる構図制御、文字入れでAI漫画作成のハードルを大幅に下げたが、版権キャラや指・人体描写の破綻、重い学習コストが課題として残る。
2. チャッピー（ChatGPT）のローカルファイル覗き見によるBAN事例が頻発し、エロプロンプト作成におけるGeminiやClaude、DeepSeek等への移行がスレ上の潮流となった。
3. ComfyUIのNodes 2.0移行に伴うカスタムノード不具合が多発し、回避のための代替ノード利用やForge使い続けの動きが活発化した。
4. AI漫画生成は最低限のスタートラインに立ったが、セリフ・擬音のBBOXガチャや構成力の不足があり、0から1を作れる真のAIでない限り限界との見方が大勢を占めた。
