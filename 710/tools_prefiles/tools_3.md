## 抽出結果

### ComfyUI
- ComfyUIが壊れている可能性が言及され、普段使っているAdobe Fireflyと比較してプロンプトへの忖度のなさが指摘されている（478）
- MOSSの高解像度生成LoRA関連で、kijai娘がComfyUIの看板になりつつあるとの指摘（602）
- TextGenerateノードのコピー＆ペーストで日本語プロンプトが残っていた件への言及（497）

### WebUI
- ログ内に直接的な言及なし

### ツール全般・横断的話題
- 生成AI絵ソムリエ（どのツールを使ったか判別できるか）についての議論。横断的に全ツールを触っていないため判別は難しいという意見（446）。生成物だけ見てモデル判別はほぼ無理、ボロが出ているものだけ判別可能という意見（447）
- ネットを切って生成して初めてローカルと言えるという見解（453）

### kohya (sd-scripts / kohya_lora_param_gui)
- mossのloraキャプション作成にkohyaニキのスクリプトを使うのが簡単という推奨（457）
- kohya_lora_param_guiのサンプル数値でキャラLoRAを作ったが、MOSSでは等身から違ってしまう結果になったという報告（614）

### Fizgig
- MOSSのLoRA学習において、Fizgigがsd-scriptsの半分未満の時間でトレーニング終わるという報告。設定ミスの懸念あり（605）
- Fizgigはデフォ値が安全寄り（解像度低め、オフロード・量子化Autoで軽い設定）。手動で詰めれば品質寄りに設定可能。デフォだとbf16は選択されずVRAMがだだ余りする（617）
- krea2でもFizgigは学習解像度の初期値が512x512程度で非常に速かった。上げるとVRAMを食い遅くなる（621）

### AI-Toolkit
- MOSSのLoRA学習において、AI-Toolkitの方がFizgigより時間も短く出来も良かったという報告。ケースバイケースだが作者も模索中（610）

### Adobe Firefly
- 普段使っているAdobe Fireflyが、適当なプロンプトでも忖度してくれる点が分かるとの評価。モデル自体が固まっているのも要因か（478）

### Codex
- キャラLoRA素材のタグ追加・管理・画像確認をCodexに任せる手法の提案。生成時に固有名詞タグ付きプロンプトが必要だが、それもCodexにワンクリックで出して加算するカスタムノードを作ってもらって完成という構想（495）
- PCのセキュリティ確認をCodexに丸投げしたが、本当に大丈夫になったか分からないという報告（619）
- CodexよりChatGPTと話し合いながら進めた方がコーディングがうまくいきがちという意見（630）

### Claude Code
- ClaudeCodeに頼んでライブラリの一括対応をしてもらった。特定フォルダ下に環境を全部ぶち込んでいたのが役立った（634）

### irodori
- irodoriで声を作って何度も聞いているうちに、声は繰り返すと飽きてくるという感想。喘ぎ声を複数用意して動きや唇に合わせランダム再生するプレイヤーの提案（480）

### PixAI Tagger
- PixAI Tagger v1.0が出たので試したところ、かなり精度が良いという報告（618）
- Tsubaki3も優秀だったので悪くないとの評価（627）

### dasiwa (ワークフロー)
- MiniMax H3の長尺動画制作について、簡易的な方法ならdasiwaのワークフローでもできるとの情報（639）

### ideogram4
- ideogram4もAIでbbox含むプロンプト作成のLLMノードを作った3日間までがピークだったという振り返り（538）

### RTX 3000シリーズ BF16アンロック（ツール/ハック的話題）
- RTX3000シリーズでBF16を2倍速で実行可能だがNvidiaがカーネルで制限していた。WindowsでUNLOCK可能になった。3060のkrea2テストで30%の速度向上を確認（539）
- 3090でのUNLOCK結果が報告される（540）
- 3060は今回のNVIDIAナーフ解除高速化の対象外という情報（585）。ただしga104を採用した3060が存在するためワンチャンあるかもという話も（589）
- initramfsでロック解除できるという情報（595）
- INT8でも速くなるかについての確認（584）。int8でも早くはなるとの回答（586）
- 中古3090の価格高騰への言及（578）

### 選ばれている理由
- **kohya**: mossのloraキャプション作成において最も簡単な手段として選ばれている（457）
- **AI-Toolkit vs Fizgig**: MOSSのLoRA学習でAI-ToolkitがFizgigより時間も短く出来も良かったため選ばれる（610）。一方Fizgigはデフォ値が安全寄りで手軽だが、デフォ設定では品質が犠牲になる（617）
- **Adobe Firefly**: 適当なプロンプトでも忖度してくれる使い勝手の良さが選ばれる理由（478）
- **Codex**: タグ管理や画像確認を自動化でき、カスタムノード作成まで任せられるため選ばれる（495）
- **Claude Code**: ライブラリ一括対応を任せられるため選ばれる（634）
