# なんJ AI画像生成スレ レポート

## 1. モデル別動向

### MOSS-Image
- 実写系生成について、毛色が違いルーツが違うような気がするとの指摘。良いものも出るが変なのも出て触れ幅が大きい「暴れ馬」(271)
- 日本語プロンプトに強いが、photorealisticになりがちで「これじゃない感」が出る(259)。プロンプト通りに生成されるが「抜ける」イラストは作れない(261)。「恥じらい」が無いとの評価(262)
- 布や肌の質感は好評(276)。変なアングルもこなし、XLやAnimaでは無理だった角度も生成可能(290)
- デフォルトのステップ数について、30で実施しているユーザー(398)と50を推奨する声(407)あり。50に上げると文字表示が改善するとの報告(410)。ターボで4ステップでの生成報告もあり(402)
- サンプラーについて、DPM系が軒並み使えないものが出るとの報告(319)
- SEEDによるランダム性が高く、SDXL時代に戻った感があるとの指摘(328)
- bboxを触ってポテンシャルの高さを感じたとの報告。生成速度も思ったより遅くなく、FTが来れば完全移行できそう(279)
- オッドアイ等の左右の目の色固定やサイドテールの左右位置固定について、長いプロンプトで細かく指示すれば可能。複数回生成でも同じ方向に固定されることを確認したとの報告(322, 323)。ただしskill喰わせたLLMが勝手に左右を変換してしまうケースあり(323)
- 公式サンプルにブルアカが載っている(253)

### MOSS アニメモデル（未リリース）
- anime向けモデルを作っているという情報を信じているユーザーがいる(250)
- 公式は「最優先でリリースする」と発言しており、今から作るのではなく既に制作済みの可能性あり(by argon)(255)
- 現状のMOSSは30億枚学習した画像の一部にdanbooruが混じっているレベル。キャラ学習量はAnimagineやPonyより上、リアス以下(249)。booru全画像は1000万枚に満たないため、30億枚の中に追加するのは余裕という希望的観測(249)
- まだデータを集めている段階っぽいとの見方(297)
- 公的な研究組織がアニメ特化モデルを出すのは大胆との指摘(356)。有名になったため当局や中華ポリコレに目を付けられ、去勢されている可能性あり(246)

### Anikawa Anima

## 2. LoRA学習・FT関連

### MOSS LoRA学習
- timestep_sampling_offsetが勝利の鍵との書き込みから検証実施(281)
  - 通常offset-0.3、高品質offset-0.6、その他（全身）補正無し。数字設定はカン
  - 学習設定はanimaで実績のあるCAME設定を流用、Baseモデルでテスト
  - 学習時間約2時間、1300ステップ程度
  - 全体の平均点は確実に上昇。細部はアバウトすぎて駄目だが体型や雰囲気はもう少しというレベルに到達
  - 細部NGの原因は学習時の部族後プロンプト（※原文ママ）の可能性
- discrete flow_shiftを下げる（mode=shift + discrete_flow_shift=2まで）ことで明らかに覚えが良くなったとの報告(285)。顔アップデータではさらにtimestep_sampling_offsetを負に偏らせるのが良いとの見解(285)
- animaのデータセット流用でmossのSFTでoffset3種類を実施。animaの倍の時間がかかる割に、固めに学習していても存在しないボタンを勝手に付ける癖がある(334)
- 公式のアニメFTが控えている状況でBaseでFTを作るのは酷との意見(333)。ただしBaseを使った方が綺麗な可能性もあるとの見方(335)

### その他LoRA

- 絵柄LoRAや絵柄マージモデルは無駄にならない可能性。版権キャラLoRAは無駄になりそう(336)

## 4. セキュリティ・インフラ関連

### Python/パッケージ脆弱性
- Pythonがインドの簡単認証を悪用したパッケージインストールリスクでアプデ。ローカル民はpip、certifi、uv等の更新が必要(352)
- LiteLLMで正規パッケージインストールした一部に認証情報を盗むマルウェアが仕込まれる事象発生(352)
- stability matrixも対応アプデ済み(352)
- uvやvenvで配布から1ヶ月以内のバージョンのライブラリを導入しないオプション設定を推奨。0dayリスクが高くなっている(354)
- Python, PyTorch, ComfyUIを最新版にしている者だけがPHP脆弱性で停止中のサービスに石を投げて良いとのジョーク(355)
- Codexに仮想環境の見直しを実施させた報告(358, 375)。CodexはeMudhaar対策について「対応できてへん」と回答(375)

### モデルのバックドア懸念
- モデル自体にバックドアを仕込む系のポストが回ってくる。テキストエンコーダに使う分は問題ないかとの懸念(415)
- h3のシンギュラリティv2について、怖くてDLできないとの声(422)
- ckptは危険だがsafetensorsは安全という1.5時代の認識(426)
- エージェント系で動かさなければ大丈夫という見方。ローカルLLMはサンドボックス内で動かすユーザーあり(420)
- ツール利用系の行動内容とユーザー指示をJev系に投げておけば粗方防げるという見解(418)

### ハードウェア・インフラ動向
- Vera Rubinは個人では手に負えない。液冷ガチャポン(240)
- AIデータセンター一つ建設するだけでトン単位で銅を使用。これから「銅」がヤバくなる(325)
- モニターが来年前半にかけて2倍以上に値上がりするらしい(326)

- Apache Tomcatも最大深刻度の脆弱性(316)
