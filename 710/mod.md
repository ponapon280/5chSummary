# 🆕 新規トピック（前回からの差分）
### 流行の推測
- Moss-Imageが主流で、プロンプト追従性とLoRA知見の蓄積により実用段階にある。
- LoRA学習にはFizgigとAI-Toolkit、ローカルLLMにはDeepSeek、動画生成にはMiniMax H3が選定されている。
- Moss-ImageのBase/SFTの使い分けとLoRA学習パラメータの最適化が重点的に議論された。

### 強み・選定理由
- Moss-Imageは指示追従性が高く、キャラ名のみで服装再現が可能な「ポンシコ性能」に優れる(114)。
- bboxによる領域指定の自由度が高く(547, 885)、9bレベルのTEによりシンプルな日本語プロンプトでも機能する(491, 576)。
- 変なアングルや文字描画（AVパッケージ風、複数コマ漫画）が可能(290, 815, 962)。
- 実写用途でKrea3の代替として選定され(903)、布や肌の質感、SFTの下着の美しさが評価されている(276, 583)。
- Baseモデルではアーティストタグが機能する点が評価されている(473)。
- スレ上の評価として、MOSSより「ええケツ」が出るという指摘がある(681, 700)。

### Base vs SFTの使い分け
- Base：学習用モデルであり未調整生成には不向き(471, 474)。構図LoRAは素直に出るが低クオリティで指が崩れやすい(487, 512)。
- SFT：クオリティは高く指崩れも少ないが、構図が出にくく(487, 512)チャッピースタイルに偏るため好みが分かれる(486)。
- Baseのみでアニメは弱いと判断した者が、LoRA作成後に見直した事例がある(475, 481)。

### LoRA学習に関するTips
- オプティマイザーはRAdamScheduleFree以外（CAME, Prodigy等）はノイズ出力となり使用不可(493-503)。
- ツールはMOSS用工夫のある最新Fizgigが推奨されるが(99)、AI-Toolkitの方が短時間で高品質だった報告もある(610)。
- `timestep_sampling_offset`が重要で、通常0.3、高品質0.6で平均点が上昇する(281)。顔アップは負に偏らせるのが有効(285)。
- `timestep_sampling`をshiftに、`discrete_flow_shift`を1から3に変更すると覚えが良くなる(811)。sd-scriptsでshift/2.0指定は小物の覚えに有効(159)。
- Fizgig設定例：base_bf16, Target MP 0.25→1.05, 最大60Epoch, 4080s/46枚で1.5h〜5.5h(123)。dim/alpha 32/32, LR 0.0001, AdamW, 解像度704, 50Epoch(138)。総ステップ1300・解像度1024で約1時間40分(211)。
- CAME設定例：4e-05, dim/alpha 32/32, step120, sampling shift, flow_shift 3, offset 0-0.6(811)。
- バッチ2以上ではsdpaよりflash attnの方が早いとの言及があり、検証で速度向上が確認された(952)。

### 課題・制約
- ポン出しが重く(108)、ターボLoRAはステップ数による劣化と速度の兼ね合いが課題(922)。
- 人種指定が効きにくくAsianになりやすく(464, 465)、LoRA適用時に肌が黄色人種化することがある(501, 502)。
- 低ステップでの指崩れ(514)や、痩身キャラ（slender, skinny）の追従困難さが指摘されている(165)。
- 実写削除による背景劣化の可能性(115)があり、DPM系サンプラーが軒並み使用不可(319)。
- 「書いたものしか出ない」ため指定が大変な点(114)や、プロンプト・文字が長くなると正確に出力できない点(594)が課題。
- 解像度512のLoRAは品質的に否定的見解がある(216)。
- ニィロウ（原神）のタグ影響力が強すぎるため、重み調整とネガティブへの投入が推奨される(714)。

### アニメモデル待ち論争
- MOSSアニメモデルは「最優先でリリース」する方針だが、現在はデータ収集段階である(255, 297)。
- モデルを待つ層(603)がいる一方、現状でも満足するアニメイラストが出せ、リアルの持ち込みが体型維持に役立つとの反論がある(612, 613)。
- 有名化により当局や中華ポリコレによる「去勢」の可能性が懸念されている(246)。

### ステップ数
- 画像のみなら25〜30と50で大差ないが、文字入れには50が確実(500)。
- ターボで4ステップの生成報告があり(402)、速度と認識は良いが画風の制御が難しい(558)。

# 生成AIモデル関連話題レポート

## 流行の推測
本ログにおいて最も盛んに議論されているのは画像生成モデルのMoss-Imageであり、プロンプト追従性の高さとLoRA学習の知見蓄積が進んだことで実用段階に入りつつある。LoRA学習ツールとしてはFizgigとAI-Toolkitが、ローカルLLMとしてはDeepSeekがそれぞれ選定されている。また、動画生成のMiniMax H3も生成速度の改善報告とともに継続的に検証されている。

今回とくに盛んに議論された話題はMoss-ImageのBaseとSFTの使い分け、およびLoRA学習パラメータの最適化である。

## Moss-Image（moss, モス）

### 強み・選定理由
- 指示への追従性が非常に高く、細かく指定しなくてもバリエーションが付く（103）。キャラ名を入れるだけで服装等がある程度再現され、ポンシコ性能が高い（114）。
- bboxのおかげで要素同士の関係性を書かなくてよく、領域指定の自由度が高い（547, 885）。
- 9bレベルのTEを持つため翻訳に問題がなく、シンプルな日本語プロンプトでも機能する（491, 576）。
- 変なアングルもこなせ（290）、文字描画が可能でAVパッケージ風画像や複数コマ漫画が作れる（815, 962）。
- 実写用途において「Krea3待機していたがもうMOSSでええか」と選定される（903）。
- 布や肌の質感が好まれ（276）、SFT時点で下着が美しいとの評価がある（583）。

### Base vs SFTの使い分け
- **Base**: 構図LoRAの学習結果は素直に出るがクオリティが低く（487）、指が崩れやすい（512）。学習用モデルの位置づけであり、未調整での通常生成には不向き（471, 474）。
- **SFT**: クオリティは高いが構図が出ない（487）。指崩れはBaseよりマシ（512）。露骨にチャッピースタイルになるため好みが分かれる（486）。
- noteでSFTを使わずBaseのみでアニメは弱いと書いた者が、後ほどLoRAを作って見直している（475, 481）。

### LoRA学習に関するTips
- **オプティマイザー**: RAdamScheduleFree以外（CAMEやProdigy）はノイズ出力になり使えない（493, 494, 496, 503）。
- **学習ツール**: Fizgigの最新VerがMOSS用の細かい工夫を入れているため推奨（99）。一方でAI-Toolkitの方が時間も短く出来が良かったとの報告あり（610）。Fizgigはデフォ値が安全寄りで解像度も低いが手動で詰めれば品質寄りにできる（617）。
- **タイムステップサンプリング**: `timestep_sampling_offset`が勝利の鍵。通常offset-0.3、高品質offset-0.6でテストし全体の平均点は上昇、細部はアバウト（281）。`timestep_sampling`をsigmoidからshift、`discrete_flow_shift`を1から3に変更すると覚えが良くなる（811）。顔アップデータでは`timestep_sampling_offset`を負に偏らせるのが良い（285）。sd-scriptsで`--timestep_sampling shift --discrete_flow_shift 2.0`を入れると小物の覚えが良い（159）。
- **Fizgig設定例**: base_bf16, Target Megapixels 0.25→1.05, 最大60Epoch, 4080s/画像46枚で1.5h〜5.5h（123）。dim/alpha 32/32, 学習率0.0001, AdamW, 解像度704, 50エポック(8枚で400ステップ)（138）。総ステップ1300・解像度1024で約1時間40分（211）。
- **CAME設定例**: CAME 4e-05, dim/alpha:32/32, step120, timestep_sampling shift, discrete_flow_shift 3, offset 0-0.6（811）。
- トリガーワードの情報量がanimaより少なく、学習設定でキャラ詳細や衣装の補足が必要だが、補足すれば学習元の形状や色がきっちり出る（654）。複数キャラLoRAは3キャラ描き分け可能だがanimaより微妙に不安定（656）。複数のLoRAを全部白背景で作って組み合わせても悪影響はない（518）。animaで出した絵柄をmossで学習させる試みは再現できなかった（678）。
- krea2のときと同様に、fizgigは学習解像度の初期値が512x512になっているため学習がクッソ速い（621）。animaの解像度512loraは溶けるからゴミとの反論あり（216）。
- kohya師がmossの学習はバッチ2以上ではsdpaよりflash attnの方が早いと言及し、検証でちょっと早くなった（952）。

### 課題・制約
- ポン出しが重い（108）。ターボLoRAは8ステップで劣化しすぎ、30・40ステップは綺麗だが遅いため15〜20ステップくらいのが欲しい（922）。
- 人種指定が効きにくくEuropeanと書いてもAsianになる（464, 465）。LoRA適用時、肌の色が黄色人種になることがある（501, 502）。
- ステップ数が少ないと指が崩れやすい（514）。
- 痩せたキャラ（slender, skinny）のプロンプト追従が難しく腰骨盤腿が主張してしまう（165）。
- パンティーに小さいリボンをしつこく生やす問題がある（802）。これはリアスの頃から引きずっている問題（808）。
- anime coloringタグ入りで100枚以上出しても全部アニメ絵になった事象がある（724）。
- 実写削除の影響で背景が劣化する可能性がある（115）。DPM系サンプラーが軒並み使えない（319）。
- まだi2i/controlnetがきてない（455）。画像編集はanimaの画像をqwenに渡して合成する手間の代替が議論されている（662）。

### アニメモデル待ち論争
- MOSSアニメモデルは「最優先でリリースする」であり「最優先で作る」ではない。まだデータ収集段階（255, 297）。
- アニメモデル待ちおじさんの存在（603）がある一方で、「mossはアニメモデルいる？ってくら満足するアニメイラストでる」（612）、「リアルの持ち込みが体型を少しリアル寄りに保つ良い役割を担っている」（613）との反論。
- 有名になると当局や中華ポリコレに目を付けられ去勢される可能性が指摘されている（246）。

### ステップ数
- 画像のみなら25〜30程度と50でそこまで差はない。文字を入れさせる場合は50の方が確実に良い（500）。
- ターボで4ステップでの生成報告あり（402）。4stepにすれば速度も早く言葉の認識も良いが画風が難しい（558）。

### 派生モデル・ツール
- Forge Neoが公式にMOSS-Image対応（78）。
- chenkin氏がMOSS-ImageのEdit版をリリース。HFには未アップロード、ComfyUIネイティブ対応が進行中（284, 303）。
- MossAD-demo (moss anime diffusion) について言及あり。プロンプト流用だとbooruタグと絵師タグ調整が必要（848）。
- MOSS派生「MOSS_Image_waiNSFWIllustrious_v01.safetensors」（Size: 14.18 GB）が貼られたが、MOSSのDiTとしてはサイズがおかしい（BF16で約10.2GB、INT8で約5.4GBのはず）との指摘あり（424, 429, 431）。
- danbooru学習のアニメモデルが出たとの報告あり（995）。
- HuggingFaceやModelScopeではなくComfyOrgの方でsafetensorファイルを確認するよう案内（199）。
- 3060でもギリ動くことが確認された。学習ができるかは不明（793）。
- 12GB環境でforge neo + comfy両方立ち上げだとH3で0.8MP7秒、forge neo無しで1.0MP7秒（3分速い）。mossはcomfyの方がよさそう（909）。

## anima（アニマ）

### 強み・選定理由
- baseは制御が必要だが、一番お手軽だったアーティストタグがmossと違って機能している点が評価される（473）。
- baseはLoRAが効きやすく、mossのsftは露骨にチャッピースタイルになるため使いたくないがanima_baseみたいに使えるようになる気がしないという課題から選定される（486, 488）。
- SDXLでは不可能だったが、Anima以降のモデルは(固有名詞+汎用要素)タグでキャラ複数人まとめてのLoRAが作れる（495）。
- qwen0.6bでもleft/right cornerやviewなどの指示が普通に効く（562）。トリガーワードに入る情報量が多く一語で衣装まで再現される（654）。
- Kromaと比較され、anima並みに速い（turboであること）、髪はanimaの方が綺麗に生成される（275）。
- MOSSより「ええケツ」が出るというスレ上の評価がある（681, 700）。

### 制約・課題
- プロンプトへの追従性について「本当に書いたものしか出なくて大変だった」（114）。
- プロンプトがちょっとでも長いと正確に出力できない（594）。文字がちょっとでも長いと正確に出力できない（594）。
- 解像度512のLoRAは溶けるからゴミとの否定的見解（216）。
- ニィロウ（原神）のキャラタグ影響力が強すぎるため、ポジティブの重みを0.1にしてネガティブにも入れるのが良い（714）。
- miaomiaoのAnima版は肌がプラスチックみたいな感じで合わなかった。フィギュア画像でも学習させたのではないか（444）。
- deltamix anima 3.8b qwen3.5に画質変更系LoRAを入れまくった結果、元画像にシワが多くなりラバー感が出る問題（237）。

### その他
- Anikawa Animaが公開され「動画のお供にもよろしいやで」との触れ込み（272）。
- スレ上の見解として、MOSSのanime版モデルが出ない限りはanimaにしがみつくことになるという予想（249）。
- 理想の一枚ができたためanimaで思い残すことなしという報告（672）。

## illustrious（リアス, ill, IL）

### 評価・選定理由
- 作例に対して「リアス感があってとてもええね」との評価（65）。
- プロンプトは部族語が良いからリアス以外ダメという層が多いとスレ上で言及される（718）。
- MOSSの画像を見て「リアス卒業する時が来たかもしれんなぁ」と乗り換え候補として言及（871）。
- MOSSにおけるキャラの学習量はかつてのanimagineやponyより上、リアス以下程度とスレ上で評価（249）。

## MiniMax H3（minimax, MMH3, H3）

### 選定理由・評価
- プロンプトが効きまくりで楽しい（908）。

### 制約
- 生成に時間がかかる（525, 532）。ポンシコ用としては生成待ち中に射精しちゃって続かない（537）。

- MVスキルを食わせてもつまらん構成を出してくる（598）。三次の精液が作り物っぽすぎる（528）。

### Tips
- BF16とINT8 ConvRotの比較ベンチマーク：BF16 (video + audio) 253.27s → 158.05s (+60.2%)。INT8 ConvRot (video + audio) 155.07s → 118.21s (+31.2%)（983）。
- 12GB環境でForgeNeoとComfyを両方立ち上げた状態で0.8MPの生成が7秒。ForgeNeoを無しにした場合は1.0MPで7秒となり完了まで3分速かった（909）。

## 総評

1. Moss-ImageはBaseが学習用、SFTが生成用という位置づけが周知されていない問題があるものの、プロンプト追従性とbboxによる領域指定の自由度から実用段階に入りつつある。
2. LoRA学習においては`timestep_sampling`をshiftに変更し`discrete_flow_shift`を調整することが覚えの良さに直結する知見が蓄積されており、オプティマイザーはRAdamScheduleFree以外使えない制約が判明している。
3. animaはアーティストタグの機能やLoRAの効きやすさから依然として選ばれるが、MOSSのアニメモデル未リリースの間はしのぎとしての位置づけにある。
4. ローカルLLMとしてはDeepSeek-V4.1-Flash-1017がStrata環境で動作しエロ小説用途に選定されているが、システムプロンプトが大きいハーネスでは使えない等の制約がある。
