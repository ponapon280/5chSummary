# なんJ AI画像生成スレッド レポート

## モデル別動向・評価

### Anima (anima / anima)
- base 1.0がanima系の中で最も評価されており、「色々出せるのは大きい」「中でもbaseが1番良い」との声がある(88)。一方で「マージモデルを選ぶと硬直してリアスでええやんとなり、baseを選ぶと技術差で振れ幅がでかい暴れ馬」と制御難易度が指摘されている(114)。
- 上級者向けモデルと位置付けられ、「下手糞でも綺麗な絵出してくれるGPTと違ってanimaは上級者にしか使いこなせない」(108)。「驚き屋が驚いてくれないと伝播しない」ため難しいとの指摘もある(117)。
- 2.9B / 3.8Bについて：2.9は「カットオフが新しいのがメリットで追従性はほぼ変わらん」(160)とされる。「正式版がanima baseと同等以上であれば、データセットの新しさからそれなりに使う人は増える」(133)。「no loraで2026年前半までのキャラクターがでてるなら多くの人にとっては十分」(133)。
- danbooruタグが効きすぎる反面、自然言語で全てを理解させるほどは賢くないとの指摘(116)。狙った絵が明確なら細かく指定で近いものが出せる(191)。
- 欠点として「1girlポン出し（1girlのみ）で頼んでもいないのにチンポ刺さってる」(207)との報告あり。

### Krea (krea2 / krea3)
- krea2：ポン出しでカメラワークが変わらないanimaと違い、カメラワークの変化がある(184)。「krea2とかNai5見ちゃうとanimaの物足らなさがな」(93)と比較で優位性が語られる。画像編集において「大きな改変にはkrea」(219)。
- krea3：登場の噂あり(199)。画像参照機能があるとの報告(204)。ただし「オープンウェイトであってもideogramレベルの重量モデルだったら実質使えん」(231)。「サービスと完全にイコールじゃないので、オープンウェイトになるとしたらkrea2もローカル用にサイズとしてでてくるだろう」(233)。サービス展開よりローカル用途としての提供が見込まれる(233)。

### MiniMax (H3)
- KREA2で出せなかったリアルがqwen2.1で出せるようになり、さらに参照でH3もモリモリ出せることが判明した(83)。「minimaxとqwen image2.1が一番ここ最近のデカい事件」「クラウドでしか使えなかった動画や画像のAIに本当に近いものがローカルに来た」(203)。画像編集において「細かい改変にはminimax」(219)。Krea2と共に「ゲームチェンジャー」と認識されている(119)。
- Local Prompt StudioでRef2Vaを選ぶとminimax h3のルールに沿ったシステムプロンプトが自動適用される仕様だが、キャラクターのサブジェクト分けが弱い問題が指摘されている(99)。

### Qwen-Image (2.1 / 3.0)
- 2.1：人物描写は優れるが、風景や人工物の描写はkrea2と比べて劣る。「緻密な街の風景や架空メカを描かせるとXLか？みたいな破綻しまくった奴出してくることがある」(209)。「1girlポン出し」で二次絵を出してくる(164)。
- 3.0：proが出ているが、当時は「今更2.1？」と思われたとの振り返り(220)。
- ローカル環境：qwen image edit 2511の導入報告あり(131)。

### その他モデル
- **Kroma v0.3.1**：学習不足・未完成。正常位で乳揉む等の複雑な構成でクリーチャー化する。SAN値削られる。ただし「panties around one leg」等の他モデルでは出ないタグが出る(106)。別レスでは「ええ感じやな」(223)とも。
- **Tubaki3**：「非常に使いやすくなってたのが印象的」(201)。
- **Pony / Illustrious (リアス)**：2年前のモデルだが表現が広がった。ポン出しでアップ構図等を自動で見せてくれるためリアスからanimaに移行できない声もある(96, 103)。1girlポン出しテストで二次絵を出してくる(164)。

### チャッピー（ChatGPT / OpenAI）
- 「下手糞でも綺麗な絵出してくれるGPT」とanimaと対比されている(108)。「エースコンバットの理解度たけえなヲイ」(124)との反応あり。

### Gemini（Google）
- テキスト生成（NSFW執筆）用途の言及。Claudeと比較され「ドスケベ文章は得意なんやが指示に対して適当やからムカデ人間？OKOK！みたいに返してきてしれっと口同士接続されてたりとかするから後から確認が必要」(215)。画像生成モデルとしての言及なし。

### Claude（Anthropic）
- テキスト生成用途。現実世界の契約のように例外対応のセーフティネットがないと書いてくれないが、同意内容を逸脱せず忠実。停止の際の符丁等の定義文に3000字かかったとの経験談(215)。

## ツール・環境

### ComfyUI
- 0.37→0.39アップデートで問題なし(168)。ポータブル版使用時、アップデートで問題が出たら新規セットアップ推奨(217)。「update\update_comfyui_stable.bat」で安定版更新可能(232)。現在はデスクトップ版が便利とする声あり(217)。
- LoRA・WF配布あり(69)：騎乗位マ〇コLoRAにx-ray uterus等の学習を加えたもの。mmh3 fl2va 1f学習、dim/alpha 32/32。x-rayは参照画像必須。

### Local Prompt Studio (LPS)
- 翻訳見ながらプロンプト編集可能(86)。推奨モデルQwen3-8B Q4_KMをCPUで実行すると時間かかる(86)。
- 問題点：推奨モデルだとRef2Vaのプロンプト作成がうまくいかず、モデル変えると翻訳等がうまくいかない(194)。キャラクター複数参照時のサブジェクト分けが弱く、区別が曖昧になる(99)。
- モデルをGemmi4 26B uncensored IQ4 NLに変更すると小物や脇役までSubject設定する等、癖が強い(127)。
- LLM構成について：Qwen3 8Bはシステムプロンプトの規約を守れずJSON壊れるため、コンパイル部をPython・他をLLMのハイブリッド構成にしたとの報告(102)。

## スレの議論・動向

### 「技術追求」vs「ポン出し」論争
- ポン出し（簡単なプロンプトで出力してシコること）を批判する声と擁護する声が交錯。
- 技術追求派：「スレに居座って絵の品評してるガイジのほうは害しかない」(111)。「技術を追い求めてる人とやらの作った画像が一向にアップされない」(142)。
- ポン出し派：「大半の人は抜くために画像生成してる人がほとんどだから技術とかポン出しだとか関係なく抜ける画像作れるのが正義」(158)。「ポン出し技術を追及してる人もおるかもしれんで、プロンプトエンハンサーとかもそうやろ」(137)。
- スレの共通認識として「ここに技術追求してる人がいない」(150)。

### 2年間の進歩に関する振り返り
- 「1girlだと進歩を実感できない2年前」「手指を避けたり背景を描かなかったりと制約はあった」(156)。
- 「2年前はanimagine3とかillustrious1の頃」(153)。「1girlかつ複雑なポーズと背景が不要ならSDXLのほうが優れてさえいる」(193)。
- 「AnythingV3やPony時代にどう頑張っても出せなかった絵が今ではAnimaでポン出し出来る」(113)。「3年後くらいには誰でもポン出し可能になるだろう。現時点ではリアスAnimaポン出しで満足するのが賢い」(113)。

### 体型・性癖に関する議論
- うすほそ（薄い細身）派と盛る派の対立。「気を抜くとすぐに盛り始める。うすほその魅力を解さないガキどもが」(60)。「貧乳やスレンダー、うすほそのキャラを肉付き良く描いたりドカ盛りするのは有罪」(66)。
- 「身長高い貧乳キャラが本当に少ないからAI技術には感謝しかない」(70)。「公式巨乳キャラを並乳にできるAI最高」(76)。
- ふたなり：「玉つき」が支持される。「玉がないと射精に説得力が云々」(92)。「実写ふたなり大量射精とかAVでもお目にかかれない世界」(80)。
