## モデル別話題

### Gemini（Argon / Gemini 4 / omni / flash等）

今回とくに盛んに議論された話題は**Gemini Argonの創作・エロ生成能力とプラン制限**である。

- **エロ・創作用途での選定理由**: Argonは「エロの解像度が高すぎる」「これを待っとったんや さよならチャッピー」と評価され、エロ生成用途で選ばれている（675）。Qwenが出せない高解像度エロを出力できる点が比較優位として挙げられている（676）。Opus 5.5で作った漫画制作SkillsをGem化して検証したところ、説明を省く箇所の判断や演出のキレが段違いでAstraやOpus 5.5を超え、創作系でかなり強い（530）。
- **画像・動画生成**: 立ち絵1枚渡しただけでBlender連携の高度な3Dモデリングが可能で精度が「レベチ」（517）。元画像の維持力はH3に及ばないが（585）、動画生成はomniがref保持力に非常に強くref2vに特化しており、Argonはomniに指示を出す位置づけ（587）。
- **制限・コーディング能力**: Proプランでは5時間制限が厳しくチャットオンリー（525, 526）。コーディング系のベンチはAstraやOpus 5.5より低く「うんち」だが文章は明確に良い（564, 569）。ProユーザーにとってGemini 4のF系が出てからが本番と期待されている（554, 597）。GoogleアカウントBANリスクを考えるとエロには使えないとの指摘もある（609）。
- **バージョン比較**: エロが厳しくなったのは3.8あたりから（549, 551）。3.xの時代からエロ小説は作れていたがエロチャットは厳しくなった（539）。
- **その他**: WebサイトやアプリのUI変更が頻繁でうざい（488）。gemini叩きがインプ稼ぎ目的で増えているとの指摘がある（977）。

根拠: 488, 517, 525, 526, 530, 539, 549, 551, 554, 564, 569, 575, 585, 587, 597, 609, 675, 676, 704, 814, 821, 826, 977

### ChatGPT（チャッピー / GPT image / Codex）

- **画像生成用途での選定理由**: ドット絵ゲーム素材について「ドットバイドットでドット絵が作れるのは今んとこGPT imageだけ」であるため選ばれている（706）。勝手に素材を作成してゲームに組み込んでくれる機能が確認された（817）。三面図画像の作成にも使われ（736）、ペット機能で性癖に合致した選択肢が出たとの報告がある（738, 741）。
- **コーディング用途**: 全体の仕様を見て整合性を取るのが上手く、モックと実装をClaudeにやらせて仕上げとレビューをCodexにやらせるのが一番（629）。6世代のGPTはワークフロー自動化や量こなす作業系に強いがユーザーの望みを叶える能力は総じて低い（578）。
- **採用しなかった理由**: 過剰にテストしながら不具合を延々深掘りし袋小路に入りやすく腹立つ時がある（582, 583）。Codexはエロに厳しくinputフォルダの画像を理由に作業を拒否することがある（822）。5時間制限に関する言及もある（918, 919）。
- **利用減少の傾向**: Claude使い増加によりCodexのリセット枠が余り解解約検討中の声がある（903, 908）。土日に温存しようとするタイミングで強制リセットが発生するとの不満（906, 901, 923）。
- **その他**: claudとチャッピーに定期的に情報収集&要約させ、傍観者になったという利用者の変化（260）。チャッピーまたリセット入ってる？という報告（289）。

根拠: 260, 289, 299, 344, 582, 583, 629, 706, 736, 738, 741, 817, 822, 903, 908, 918

### Claude（Opus 5.5 / Claude 5 / 5.5 / 6.0 / 6.1）

- **コーディング・創作用途での選定理由**: 「コーディングはなんだかんだcloudeが優秀」と評価され（702）、0から作らせるのが良く「こんなの作ってくるのかよ」時が多々ある（629）。nsfw含めた趣味コーディングメインならClaudeであり、やりたい事を対話して形にする能力と相対的な安さが段違い（571, 578）。Claudeに手を出していないのはモグリとの声もある（581）。

- **実写背景+アニメキャラ融合用途**: opus5.5にardyn操作させて実写背景+アニメキャラの動画を作っている例がXにあり、自分のやりたいことを相談したらopusがアイデア出して作ってくれると推奨されている（341, 348, 352）。
- **利用偏重と制限**: Claude一辺倒になりCodexを使わなくなったという声（908, 909）。5時間制限の存在が指摘されている（910, 915）。opus5.5の頭が良すぎるのが原因との見解（912）。Blender MCPはClaudeが作ったとの記憶がある（946）。

### MiniMax（H3）

- **動画生成での選定理由**: V2V性能が良くref(V)2Vから解放される点が評価されている（242, 245）。実写背景にアニメキャラを融合させる用途で使用されている（882）。H3の参照能力がすごすぎるためfun controlnetは不要ではないかとの見方がある（667）。画像出力機能もあり、参照の三面図を入れてポーズと角度を指定すれば素材が増やせると説明されている（741）。
- **採用しなかった理由**: リファレンスに背景動画を入れると背景が再生成（変化）してしまう問題があり、カメラが大きく動く背景動画だとminimaxH3が独自解釈するためref2vaの枠組みでは難しいとの結論がある（291, 297）。ガチャになる点にイライラするという不満もある（900）。同じ画像を入れてループ動画作成を試みても最初と最後のフレームが微妙に違いループ動画にならない（803）。
- **編集用途**: 細かい改変に向くとされる（219）。
- **VRAM挙動**: デフォルトの状態だとStepが進んでも後半になっても1stepの時間は変わらなかったり増えたりする。高速化で後半stepになるにつれて1stepの処理時間を減らすようにしたらVRAM渋滞はなくなった（297）。
- **Seedance2.5との比較**: スレ上の見解として「H3とは再現力や保持力がダンチ」でSeedance2.5の方が優れるという主張がある（401）。

根拠: 83, 119, 184, 203, 219, 242, 245, 248, 249, 276, 291, 297, 308, 363, 401, 406, 667, 741, 768, 803, 882, 900

### Qwen-Image（QwenImage2.1 / qwen2.1 / qwen image edit 2511）

- **画像生成での選定理由**: Krea2で出せなかったリアルがゴリゴリに出せるようになり、参照でH3もモリモリ出せる（83）。1girlのみのプロンプトで二次絵を出してくる（164）。`qwen image edit 2511`でもびっくりする結果が出た（131）。
- **切り抜き用途での選定理由**: アニメーションWebPや連番画像に変換した後、QwenImage2.1で透過処理を行う手法が「現状一番きれい」にキャラを抜けるため推奨されている（874）。先頭フレームをQwenImage2.1で透過できるか確認し、きれいに抜けることを判断基準に使える（874）。1Mpxの画像1枚あたり透過に15秒かかる（880）。
- **描写の傾向・採用しなかった理由**: 人物の描写は優れているが、風景や人工物の描写はKrea2と比べかなり劣り、緻密な街の風景や架空メカを描かせるとXLレベルの破綻を起こすことがある（209）。
- **プロンプト作成ツールとしての評価**: 文章のクセが強すぎ、やたら「……」を多用し違和感が強い。文章やプロンプトを書かせるのには向いていない。プロンプト書かすならgemma4を使っている（570, 573, 586）。
- **ローカル利用**: minimaxとqwen image2.1がローカルで使えるようになった点は最近のデカい事件と評されている（203）。

根拠: 83, 131, 164, 203, 209, 570, 573, 586, 874, 880

### Anima

- **LoRA学習ベースとしての選定理由**: AnimaでLora学習に帰ってきたとの報告（458）。学習率0.0001 / 200ステップ / CAME / Animaの設定で5分で即席LoRAが完成した（807）。キャラLoRA素材にリアルの背景写真を加えるとrealistic系の効果が良くなり、3D強めでもキャラが破綻しにくい（785）。三面図ベースでのLoRA学習に使われている（736）。
- **画像生成での特徴・選定理由**: base 1.0は糞が出ないが癖がないので問題ない（82）。マージモデルを選ぶと硬直してリアスで良いとなるが、baseを選ぶと技術差で振れ幅が大きい暴れ馬になる（114）。自由文を使いこなせば狙った絵が明確なら細かく指定で近しいものができる（105, 191）。カットオフが新しいことがメリットと推測される（160）。
- **採用しなかった理由**: ポン出しシコ勢が特定の絵を出そうとしたがリアスの`close up, comic`のようなアップ構成が再現できずリアスへ戻した（96）。danbooruタグが効きすぎて制御が難しく、自然言語で完全に理解してくれるほど賢くない（116）。1girlを生成すると頼んでもいないのにチンポが刺さっている絵になることがある（207）。競合が出てこないことからdanbooru系画像生成AIはオワコンかもしれないとの見解がある（177）。
- **ControlNet**: 3Dボディポーズモデルはキャラクターのポーズを制御でき、カラー領域モデルは複数の被写体の境界を区別できる（333）。
- **バージョン期待**: 2.9Bや3.8Bについて、正式版がbaseと同等以上であればデータセットの新しさから使う人は増えると期待されている（133）。軽量小型を維持した方が長生きできるとされる（123）。

根拠: 82, 93, 96, 103, 105, 108, 113, 114, 116, 121, 123, 133, 160, 177, 191, 207, 257, 333, 458, 736, 785, 807, 988

- **採用しなかった理由**: オープンウェイトで公開されてもideogramレベルの重量モデルだと実質使えないという懸念がある（231）。Krea2がローカル用にサイズ調整されて出た経緯からKrea3もローカルで使えないサイズを出すメリットはないとの推測（233）。構図指示が誤解されて引き伸ばされた笑顔ばかりになる事象が報告されている（450）。
- **VRAM**: VRAM確保設定をすればKrea2でもオフロードなしで動くとの言及がある（795）。

根拠: 83, 119, 204, 209, 219, 231, 233, 237, 273, 283, 450, 477, 519, 795

### Strata

## 総評

1. **Gemini Argonがエロ・創作分野でチャッピー（ChatGPT）からの乗り換えを促進している**。Argonの高解像度エロ出力能力と創作スキル（漫画制作Skills等）がスレ上で高く評価され、Proプランの5時間制限やコーディング能力の低さという制約を上回る価値が見出されている。

2. **LLMコーディング利用がClaude（Opus 5.5）へ一本収束しつつある**。Claudeの頭の良さによりCodexを使わなくなったとの声が相次ぎ、Codexの5時間制限や袋小路に入る挙動が離脱理由として挙げられている。ただしClaudeにも5時間制限があるとの認識が示されている。

3. **動画生成ワークフローにおいてMiniMax（H3）が中心でありつつ、QwenImage2.1が切り抜き用途で不可欠な地位を確立した**。H3の背景再生成問題やガチャ性への不満はあるものの、実写背景＋アニメキャラ融合の主手法として定着している。QwenImage2.1による透過処理は「現状一番きれい」と評価されている。

4. **Animaは画像生成単体よりもLoRA学習ベースとして定着した**。学習率0.0001 / 200ステップ / CAMEという即席設定が共有され、三面図ベースのキャラLoRA学習に使われている。画像生成モデルとしてはdanbooruタグ制御の難しさや競合不出現によるオワコン視もあるが、学習ベースとしての価値が認められている。
