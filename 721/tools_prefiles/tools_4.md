# 生成AI関連「ツール」話題の抽出（モデル話題除く）

## 画像生成ツール・カスタムノード

### Snapref
- **SnaprefをAnimaのLoRA代替として評価する声（660）**：「Snaprefよいね もうAnimaにおいてはキャラLoRA、絵柄LoRAは不要では」
- **Snapref選定理由（663）**：「snaprefええけどリファレンス用意する手間ダルいで LoRAは作ってしまったら後はプロンプトだけでこねくり回せるからな」—Snaprefは参照画像準備の手間があるが、LoRA作成後の手軽さと対比される。
- **Snapref 1b vs 2 の比較（673）**：「snapref1bの方が2より微妙に性能がよかったりする」
- **Snaprefのstyle機能評価（676）**：「Snaprefのstyle触ったが凄い精度やな 絵柄は色が変わるから再現は出来てないがmossで失敗中の絵柄lora相当のポテンシャルを感じた」ただし「Node2.0用なのか知らんが数値いじるとSnaprefのレイアウト壊れてだるい」
- **Snaprefの破綻問題と線画参照の改善（679）**：「snaprefは前触ったら破綻多くてアレやったけど 参照に線画1枚混ぜるとデザインの認識が 良くなると聞いたんでもっかい試そうかな」
- **SnaprefをLoRA完全代替ではないとする否定的見解（685）**：「snaprefが称賛されてるけどワイの感想としては破綻多すぎるし技術デモレベルって所かな 少なくともloraの完全代替になるもんじゃない」
- **Snaprefの強みは絵柄維持（687）**：「snaprefのどこに驚くかの違いやないんかな キャラクターの特徴維持や編集は公式対応のQI-2.1やH3-Imageの方が上やろ けどこれまでどのモデルもできなかった絵柄の維持がかなり強いところに驚いてるんじゃないの？」

### Fizgig
- **FizgigのLoRA学習用途での評価（671）**：「fizgig1つのデータセットから色々ポチポチするだけで違ったlora作れるから楽しいわ グラボがもう一枚欲しい」
- **Fizgigでmoss_image_heal_bf16 + CAMEによる学習（761）**：「Fizgig で moss_image_heal_bf16 + CAME でやっとるけど 5000stepも回せば完全に過学習になるんで Strength:0.35とかで調整しとる 学習素材が30枚程度と少ないのが原因やろか」

### Strata / StratacomfyUI / dflash
- **dflashが拡散方式である言及（692）**：「dflashてのが拡散方式なんか strataやともうデフォで入っとるよな」
- **StratacomfyUIの交互ロードをチャッピーに実装依頼（832）**：「hermesハーネス下で StratacomfyUI の交互ロードを無料ちゃっぴーにお願いしてたらミリセカンドレベルでcomfyUI監視するadmission midddlewareを作るとか言い出して草もっと雑でええんよ 交互起動か同時共存してるニキ実装どうやっとるん？」
- **同時起動推奨の返答（838）**：「どっちもloadは生成処理するだけやしunloadはPOSTするだけ てか交互ロードするよりVRAM振り分けて同時起動すればええやろ」
- **strataアプリでcomfyui連携（839）**：「ワシはQwen3.8FNとgemma4使えるstrataアプリつくったから comfyuiのアドレスで生成検知したら自動でアンロードする設定作れってお願いしたらやってくれたで」

### ComfyUI-MossPanelDataset（カスタムノード）
- **チャッピー経由でカスタムノードを発見・改変（773）**：「チャッピーに相談したら ComfyUI-MossPanelDataset出てきたけど、『あれ？ このカスタムノード、BBOXへ直の高解像度設定出来なくね？』ってチャッピーに言ったら『この指示使ってDSH回せ♪』とか返してきたのでstrataへぶん投げてカスタムノード改変したの巻 チャッピーもう完全にDSHに面倒ごと投げ慣れてきてて草」

### NivisViewer（見開き画像ビューア）

## LoRA学習関連ツール・手法

### CAME（学習オプティマイザ）
- **mossのLoRA学習でCAME使用推奨（763）**：「CAME使うのと解像度を512にする、覚え方がなんかおかしいと感じたらキャプションファイル全消し状態の画像のみで学習を試す」

### base+dmd2（生成手法）
- **mossのLoRA代替としてbase+dmd2推奨（770）**：「まだmossのloraで苦労してるニキはsftじゃなくてbase+dmd2で生成したほうがええぞ あと1万step必要とか言い続けてる奴がおるが画風なら1000-2000stepで十分やで」

## LLM関連ツール

### vLLM / LLM方式画像生成
- **LLM方式画像生成への期待（680）**：「LLM方式の画像生成が出たんやって LLM方式やとvLLMみたいな仕組み使って多重生成させても速度落ちないとかっての期待してしまうな しかもMoEやからstrataみたいに動かせる可能性もありそうやし 拡散方式のLLMはdiffusion gemmaってのがもうでとるけど こっちはあまりぱっとせーへんのよな」

### DSH（DeepSeek関連ローカルツール）
- **DSHの危険性に関する議論（776-800）**：DSH（DeepSeek Harness）について、ローカルにインストールすると情報漏洩リスクがあるという警告が複数レスで展開。「deepseekをPCに入れるなんて 遅効性の毒料理パクパク食べるようなもんや（783）」「中華モデルをローカルに入れて全お漏らし確定ムーブはやめとけよ（800）」一方で「参照領域は限定してるが、気にしすぎたら負けかなと思っている（778）」とする利用者もいる。
