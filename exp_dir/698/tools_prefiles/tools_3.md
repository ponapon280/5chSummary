# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI / カスタムノード関連

### ComfyUIのブラウザワークフロー機能
- ブラウザのワークフローの右クリックで指定したtextノードに外部からプロンプトを送り、都度runできる。LLMとの連携が進むという（470）
- Codex（コーディングAI）にComfyUI内にカスタムノードを自動作成させたという報告あり（470）

### ComfyUI上でのLLM連携・プロンプト生成
ローカルLLMをプロンプト作成に利用する手法について複数の運用形が報告されている（579へのレス群）。

- **LAN内LLM専用マシン運用**: llmapa-swapをLAN内に立て、OpenAI互換接続でComfyUIサーバーから呼び出し。操作はLAN内のノートPC上でComfyUIのWebUIを開いて行っている（581）
- **OpenWebUI使用**: 画像・動画のプロンプトにOpenWebUIを使用。公式サイトの使い方を読ませて整理・スキル化し、エロ小説の途中でシーンを作らせている。LMStudioでも同じことができるとしている（582）
- **LM Studio Bionic使用**: LM Studio Bionicでワークフローを多数タブで開く運用。プロンプト管理アプリを自作し、フォルダ分けして保存・編集している（588）。ただしbionicは起動するだけでVRAM8GBくらい持っていくという指摘もあり（589）、環境次第でVRAM消費に差がある（592, 594）
- **ComfyUI内で完結させるツール**: クラウドAPI、LM Studioとの連携、スタンドアロン版も可能なツールを使用。システムプロンプトがしっかりしており生成プロンプトの出来が良い。弱点は生成プロンプトをそのまま流し込めずコピペが必要な点（598）
- **LlamaWebUI + カスタムノード**: LlamaWebUIを裏で立ち上げ、専用カスタムノードをCodexに作成させ、VRAM自動解放も実装（599）
- **llama-cpp-python使用**: llama-cpp-pythonを使ってカスタムノード化して処理。金があるならクラウド連携させた方が良いプロンプトが生成できるとしている（600）

### MiniMax H3関連のComfyUI拡張・ノード

#### Image-Studio
- MiniMax H3を一枚絵として使うComfyUI拡張「Image-Studio」。GitHubに専用ノードとワークフローが公開されている（567, 568）
- Image-Studioで参照画像を入れて「キャラクターシートを作って」とプロンプトを書けば3面図が作れる。これを動画の参照に使っている（540, 567）
- 裸のキャラクターシート作成のために切り貼りしたり、動画のキモのシーンを画像で作って動画の参照に使うなど、動画生成に重宝している（567）
- 導入方法: カスタムノードマネージャー（拡張機能の管理）で検索してインストール、ワークフローをダウンロード（564, 567）

#### RefMod（MiniMax H3の機能/ノード）
- RefModはt2v（テキストから動画）で使うもの。RefModノードで学習済みデータを参照させており、他に画像を参照させても良いことにはならない（566）
- 参照画像なしのt2vで参照画像なしでもキャラが似るため便利（549）
- ref2vとfl2vのどちらでも行ける。参照素材とRefModを併用も可能。エロ動画作成時に体位などの構図レイアウトを参照画像、キャラをRefModにすると調整しやすい（571）
- Fizgigで作成可能。キャプション等の用意が不要で、1分かからず学習（パッキング）でき、VRAMも全然必要ない。顔と画風はほぼそのままで出せるが、衣装の詳細は再現度低い。効きすぎ感があるため複数の角度やポーズを用意した方が良い（580）
- キャラの前後と顔アップでRefModを作り、カメラをキャラ中心に回転させるように動画生成させると衣装の再現性が良かった（583）
- 実際の使用モデル: `minimax_h3_ref2va_pruned_int8_convrot.safetensors`。高速化系と相性が悪いためSpectrum Apply MiniMax H3のみにして20step生成。VRAM16とメモリ64GBで生成可能（553）

#### MiniMax H3のその他ノード・機能
- H3のContextLoopで使う「ContextLoopのカルーセル」ノード。各画像にタグをつけて@タグで画像を指定できるようにし、プロンプトをカスタムノードに組み立てさせるWFを構築（512）
- H3のRef2VAとF2VAを組み合わせたいという要望。2つの要素を組み合わせたHybridモデルや2つを組み合わせるノードがある（541）
- AIにカスタムノードを作ってもらった方が早いというアドバイス（524）

### Wan2.2関連
- H3を動かせないためWAN2.2を始めたが、エッチなプロンプトに反応しない。テキストエンコーダーをnsfw_なんちゃらというものに変えたが他も探す必要がある（617）
- WANはLoRAを使わないと性知識が小学校低学年レベルとのスレ上の見解（626）

### YuE2（音楽生成）関連ツール
- YuE2の公式リポジトリと連携使用するやつが出た。GGUFで量子化モデルを使えば低スペックでも使える。cppのビルドは自分でやってねの鬼畜仕様（537）
- styleやartistでLoRA学習できるが全てVRAM24GB前提。現在のチェックポイントはバグっているためd8164a1を使うべき（537）

## WebUI / その他ツール

### Krea2
- Krea2でさくっと日本語が置けるのが良い（縦書きは怪しい）（469）
- Krea2で作ったどすけべセリフをanimaで生成した画像に合成しようという構想（475）
- 断捨離の結果Krea2とMiniMax H3しか残っていないというユーザーあり（573）

### Gemini
- Geminiに描かせた絵の報告。無理に完成品を目指した漫画より「存在しないヒトコマ」のような使い方の方が可能性があるというスレ上の感想（538）
- Geminiは背景の指示をしつこくしないと変になるが、望遠ショットも可能。エージェントで次のコマで時間を進める/進めない、アップにする等のスイッチでカットを作るツールにするとカメラで追うようなコマ割ができそう（606）
- プロンプト作りではGeminiが緩く、エロティックな演出指示にも平気で対応してくれるというスレ上の報告（601）

### その他ツール・サービス
- **wise folder**: wise folderで暗号化すればcodexに見られないというチャッピー（別AI）の発言の引用（433）
- **boinc**: 計算領域を貸す仕組み。現在も続いている。AIモデル学習でも同様の仕組みがあれば協力する人もいそうというスレ上の期待（590, 595, 620）
- **計算力売るサイト**: 5090で電気代差し引いても毎日1800円入るというスレ上の話題（578）

## ストレージ・ハードウェア関連（ツール利用環境）
- モデルやLoRAの断捨離でA1111系から続けているユーザーの場合2TBくらい空くというスレ上の試算（570）
- AIやってるとストレージがいくらあっても足りない。qwen入れた後はminimaxのためのストレージ容量が必要になる（569）
- 2TBのSSDがゲーム専用だったがゲームが減ってほぼAI関連だけになった（576）
- SteamでFF7リバースをやりたいがminimaxのせいで容量がない（577）

## 選定理由のまとめ
- **Image-Studio**: MiniMax H3でキャラクターシート（3面図）が簡単に作れ、動画生成の参照画像として使えるため重宝している（540, 567）
- **RefMod (t2v)**: 参照画像なしでキャラの再現が可能で、パッキングに1分未満、VRAM消費少なく、キャプション不要のため楽ちん（549, 580）
- **OpenWebUI / LM Studio**: モデル管理に特化しており使いやすい（587）
- **Krea2**: さくっと日本語が置けるため（469）
- **LAN内LLM構成**: ワークフローを多数タブで開く運用ではプロンプトノードでやってられず、ローカルエージェントなら履歴も残り整理しやすい（588）
