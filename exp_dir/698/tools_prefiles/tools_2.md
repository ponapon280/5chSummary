## 生成AI関連ツール話題 抽出レポート

### ComfyUI / ComfyUI関連

- **NegPiPが効かない問題（Krea2モデル使用時）**：krea2turboモデルでNegPiPを入れても効いていない。ComfyUIを入れ直し、最低限のワークフローにし、multi-modelも試したが状況変わらず。チャットAI（ちゃぴー）と何度もやり取りしたが原因不明。（レス263）
- **NegPiP問題に対するアドバイス**：
  - 使用モデルはfp8_scaledよりint8_convの方が精度も速度も早くなる。（レス267）
  - ネギピッピをちゃんと入れていないか、-強調が入っているとグチャる可能性。（レス268）
  - ＋と－に同じものを入れるとテストにならない。プロンプト欄ノードを入れてそこで入力すべき。（レス269）
  - NegPiPを使わず、kijaiのkjnodesの「Krea2 Prompt Weight」を使った方が良い。（レス284）
  - appleから-appleで「明らかに違いが出る」「りんごではない何か」が出力されるのが正しく効いている状態の解釈。普段はint8_convを使用。（レス287）

- **巨大ワークフロー（WF）の読み込みエラー対策**：巨大なWFを作っていたらある日を境に読めなくなったため、別途WFをjson出力するノードをかませることを推奨。（レス380）

### AI-Toolkit

- **16GB VRAMでKrea2のLoRA作成報告**：16GB（4080s）環境でAI-Toolkitを使ってKrea2のLoRA作成に成功。断続的に処理が止まるが約6時間で3000step完走。（レス276）
- **AI-Toolkit選定理由**：GUIで設定が簡易で分かりやすい（GUIからyaml編集も可能）。SDXLやZ-ImageのLoRA作成は問題ないがKrea2に関しては16GBだとエラーが出る報告があり、とりあえずできたので報告した。（レス288）
- **AI-Toolkitの評価**：GUIで分かりやすい。対応モデルは少ないがKrea2とMiniMax H3用によさそう。内部はmusubi-tunerベースで信頼性は高そう。（レス289）
- **AI-Toolkitの推奨**：レス286にてAI-Toolkitがオススメと提示。（レス286）

### musubi-tuner

- **AI-Toolkitとの比較**：CodexにLoRA環境を作ってもらった際、知らん間にmusubi-tunerで作っていた。VRAM 10GB環境で6時間かからずに完了していた。AI-Toolkitの方が良いかどうかの問い。（レス280）
- **AI-Toolkitとの関係**：AI-Toolkitは内部がmusubi-tunerベース。（レス289）

### ツール全般・その他

- **Codex（コーディングツール）**：
  - サクラエディタの仕様を分かっていないのに嘘のコードを教えてきたため説教し、自作した。（レス353）
  - Codexに作ってもらったツールをエロ生成に活用。コード変更の度にVS Codeで別フォルダにコピーしていたが、自動的に別フォルダに更新コードを上書きしてくれるようになった。（レス402）
  - サンドボックス外も見ている可能性。設定したフォルダに無かったらドライブの頭から探しに行く。きっちりサンドボックス内で作業させたいならUnsloth Desktopを使うと良い（サブスクは使えない）。（レス416）
  - プライバシー懸念からミニPCをCodex専用にし、リモートデスクトップで繋いでいる。（レス421）

- **VFI Frame Interpolation / TensorRT**：フレーム補完はVFI Frame Interpolationで間に合っているため、TensorRTを使わなくなった。（レス290）

- **GPTastra → Blender → seedanceのワークフロー**：GPTastraからBlenderを操作して仮映像を作り、seedanceで変換させていた。モデリングとモーションがどうにかできればseedance変換は不要になる。（レス338）

- **pixai（プラットフォーム）**：pixaiでTubaki3が使えるようになったため試しており、エロ性能が上がった感じがある。UIが分かりにくい。（レス292、レス325）

- **NovelAI（NAI）のAPI関連**：APIがちゃんとしておりcurl等からすぐ使える。問題はAPIドキュメントの更新が滞っており、UIとサーバーのJSONのやり取りを見ないと最新の仕様が分からない点。（レス360）

- **refmod（参照マージツール）**：触ってみたが、同じキャラを複数枚マージしてもあまり意味がなく、むしろ遠ざかってしまう。LoRAのように使うものではない。（レス427）

### Qwenシリーズ（画像生成以外の話題）

- **Qwen3-VL-8B**：言及あり。（レス294）
- **Qwen3.8（27B）の小型化モデル「Ternary Bonsai 2 27B」**：5.9GBまで小型化しつつ性能98.2%維持。VRAM 8GBで動かせるかという問い。4bit未満で使えるかも疑問点。（レス331）
- **Qwenの日本語能力**：bonsai2は日本語で会話すると中国語交じりの日本語になる（qwenの特徴そのまま）。検閲解除モデルを使うと更に性能低下。（レス351）
- **Qwenの量子化耐性**：Qwen3.8で日本語の単語が乱れることがあった。Bonsaiのように1ビット2ビットに量子化すると大きく乱れるだろう。（レス356）
- **QwenのTE（Text Encoder）としての用途**：ローカルLLMは日本語いけるgemma4一択。qwenがTEとして使われている。（レス354）
- **Qwen-Image-2.1のTEについて**：Qwen38BではなくQwen3 8B（ideogram等で使っている3の8B）という指摘。（レス256、レス266）
- **Qwen3.5以降の日本語**：Gemma4みたいに柔らかくはないが別に悪くない。（レス356）
- **Qwen3-VL 38Bの可能性**：minimaxはQwen3VL38Bを使っているのだからQie2.1でも可能。ローカルではint8使えばいい。（レス302）
