# 生成AIモデル関連話題抽出レポート

## NovelAI (NAI)
- **メンテ時期の批判**: シルバーウィーク丸々NAIメンテであるとの指摘（231, 333）。ただしメンテ中も使える部分があるとの訂正あり（335, 337）。
- **利用制限**: 1日11パーセント回復はきつく、せめて2倍欲しいとの不満（327）。opus利用上限80%にもかかわらず大量のanal消費が発生した事例（359, 370）。ステップ数28に設定したらanal消費が早まった（370）。
- **位置づけ・選ばれる理由**: NAI5の最大の利点は「ローカルへの投資なしで、日本語でアニメキャラのNSFWを生成できる」こと。APIもcurlからすぐ使える（360）。ただしAPIドキュメントの更新が滞っている問題がある（360）。
- **性能評価**: 基本性能は中間程度でエロもあるがLORAが無い。解像度もゴミとの評価（348, 340）。
- **利用シーン**: ローカルで動画生成しつつNAIでキーフレーム用の静画を作る贅沢な使い方（343）。Turbo込みの絵柄が好きならTurboを使う方が幸い（393）。
- **情報源**: NAIの情報はDiscordの方が圧倒的に多く、5chではネガキャンが多いとの指摘（339）。

## illustrious (リアス, ill, IL)
- **過去の評価**: 当時の基準で全てが上手く噛み合っていた「リアスNOOB時代」が異例だったとの回顧（348）。

- **Text Encoder**: 一部のfluxでQwen3の8Bを使っているとの指摘（266）。

## Wan

## Qwen-Image
- **Qwen-Image-2.1 / QI2.1**: 配布予定のQwen-Image-2.1のText EncoderにQwen38Bを使っているとの情報（260）。ただし「qwen38Bなんてモデルは無いからideogramや一部のfluxで使っとる3の8Bやろ」との反論（266）。minimaxはQwen3VL38Bを使っているのだからQie2.1でも可能、ローカルではint8使えばいいとの意見（302）。
- **現行QIとの比較**: 現行のQIが20Bなのに7Bなのか？かなりの小型化だが性能はどうかとの疑問（329）。
- **Text Encoderとしての評価**: qwen image 2.1はideogram4のTEと同じ。krea2よりも賢いのは間違いない、後はモデル次第（297）。qwenがTEとして使われているという文脈で、ローカルLLMとしては日本語いけるgemma4一選との見解（354）。

## Anima
- **アプデ状況**: Animaのアプデはまだ時間かかりそうとの問い（250）。開発終わっているのではとの返答（251）。
- **性能評価**: エロもLORAも有るが基本性能が低いとの評価。三すくみ状況の一端（348）。
- **anima2 9Bへの言及**: 「anima2の9B」と同じ流れを感じるとの指摘。オープンソースのTEで38Bのモデルを使うわけがないとの否定的見方（296）。
- **実用テスト**: 30stepが実用的な時間で処理できるようになりanima base（ターボ無し）を試したが、ほとんど酷い絵になる。FT+ターボの絵柄を再現したいがスタートラインまで残り10000歩位あるとの感想（357, 393）。
- **Turboの特性**: Turboは高速化ではなく低stepで崩れない画風LoRA。Turboを抜くとバタ臭い・チープになる。マスピLoRAとして機能している（363, 365, 371）。源流モデルが暴れ馬なのはanimaに限らない（366）。
- **学習用途**: PS2/PS3時代のリアル系3Dキャラ生成テストで、学習はanima base、出力はbotan最新を使用。3D成分が濃く出たが全体的に整って出てきたとの結果（398）。

# モデル関連話題抽出レポート

## 抽出対象モデル

### MiniMax H3
- **言及内容**: `minimax_h3_fastvideo_vsa_datafree_1300step_4step_int8_convrot`というモデルが言及され、より良いモデルを求める声がある（>>239）。H3環境整備のためFL2VAを触っていたが、Ref2VAを触って全てを理解したという報告がある（>>271）。H3でpruned fp8モデルを使用中、bf16モデルで劇的に良くなるか問う声がある（>>272）。静止画のMiniMaxでも32BのTEを使うのではないかという予想がある（>>298）。Qwen3VL38Bを使っているMiniMaxと同様にQie2.1でも可能ではないかとの指摘（>>302）。H3で四六時中動画のエロシチュを考えて生成しているという報告あり（>>258）。
- **選ばれている理由**: H3での動画生成においてエロ用途で没入感が高い（>>258）。

### Krea2 (krea2turbo)
- **言及内容**: 編集用途ではfluxとkleaより上という評価がある（>>232）。Krea2のLoRAを16GB(4080s)環境でAI-Toolkitを使って作成した報告あり（約6時間で3000step）（>>276）。SDXLやZ-ImageのLoRA作成は問題ないがKrea2は16GBだとエラーが出る報告があった（>>288）。AI-ToolkitはGUIで設定が分かりやすく、内部はmusubi-tunerベースで信頼性が高い（>>289）。NegPiPを入れても効いていないという報告に対し、kjnodesのKrea2 Prompt Weightを使うよう推奨される（>>284）。int8_convの方が精度も速度も早くなるとの指摘（>>267）。基本性能もLoRA品質も勝るがエロ(danbooru)が無いという評価（>>348）。
- **選ばれている理由**: 編集用途で性能が高い（>>232）。基本性能とLoRA品質に勝る（>>348）。

### Qwen3-VL-8B / Qwen3.8 / Qwen-Image-2.1
- **言及内容**: 配布予定のQwen-Image-2.1のText EncoderにQwen38Bを使っているという話題（>>260）。qwen38Bというモデルは存在しないためQwen3の8B（ideogram等で使用）ではないかという指摘（>>266）。Qwen3-VL-8Bをやっているという報告（>>294）。現行のQIが20BなのにQie2.1は7Bなのか、かなりの小型化で性能がどうかという疑問（>>329）。Qwen3.8で日本語の単語が乱れることがあり、Bonsaiみたいに1-2bit量子化すると大きく乱れるだろうとの指摘（>>356）。8Bだと量子化耐性があるためデザイン・編集用途以外ならガッツリ落としても違和感なく使えそう（>>300）。
- **選ばれている理由**: Text Encoderとしての用途が主。ローカルではint8使えば良い（>>302）。量子化耐性がある（>>300）。

### Gemma4 (Gemmi4 / gemma4)
- **言及内容**: プロンプト作成にGemmi4を使用しているという報告あり（>>229, >>230）。ローカルLLMで日本語がいけるのはgemma4一択との評価（>>354）。Qwen3.5以降の日本語はGemma4みたいに柔らかくはないが別に悪くないとの比較（>>356）。素の頭が悪い、油断すると頭同人ピンク化する、長文指示通りに書いてくれないとの指摘（>>371）。プロットまではもっと頭の良いローカルモデルを使った方が良いとの使い分け提案（>>371）。
- **選ばれている理由**: ローカルLLMで日本語能力が優れている（>>354）。

### Bonsai2 27B (Ternary Bonsai 2 27B)
- **言及内容**: PC Watchやgigazineで記事になったQwen3.8 27Bを5.9GBまで小型化しつつ性能98.2%維持したモデル。VRAM8GBで動かせるか問われる（>>331）。BF16比較でQ4_K_Mが96.2%、Q8_0で97.6%程度のため1.76bitで98.2%は凄い数字という評価（>>349）。bonsai2は日本語で会話すると中国語交じりの日本語になりqwenの特徴が出ている（>>351）。性能が良さそうなら3060をサブにして2枚差ししてみる、無検閲モデルも出るだろうとの期待（>>282）。量子化後のモデルサイズで任せられる作業を増やすのが最大の意義（>>371）。
- **選ばれている理由**: 5.9GBまで小型化されてVRAM8GBで動かせる可能性（>>331）。量子化後サイズで実用性を高める意義（>>371）。

### Jev
- **言及内容**: 自分のプロダクトに入れようとしたが小型ローカルモデルで同様のことが出来ないと意味がないことに気づいて停止した（>>285）。オープンで出たら驚く準備をして待つという声（>>377）。プロダクトに入れるならオープンが前提かつ小型化が必要、原稿は汎用性高いが用途応じてはまだ甘いところがある（>>378）。個人のシステムに入れるにはちょうど良い（>>378）。jevを凄いと言っている人は全員驚き屋だからブロックしろという批判（>>373）。過去の出力画像を自動選別する用途でJevを試したいが環境リスクが高いという声（>>428）。
- **選ばれている理由**: 個人システムにはちょうど良い（>>378）。汎用性が高い（>>378）。

### Tsubaki3 (Tubaki3)
- **言及内容**: pixaiでTubaki3が使えるようになり試しているが、だいぶエロ性能が上がった感じがするとの評価（>>292）。ログボで乞食生成できるためtsubakiの垢を作ったという報告（>>325）。
- **選ばれている理由**: エロ性能が上がっている（>>292）。

### YuE2 (yue2)
- **言及内容**: yue2で英語曲→中国語のAIカバー曲を作り直した報告（>>293）。hugにyue2のツールがあるが使っていない、より正確なカバーとアーティスト学習ができそうだがYuE2を消してしまった（>>295）。

### SD1.5
- **言及内容**: SD1.5時代からH3で四六時中動画生成するようなことはなかったとの回想（>>258）。SD1.5登場からまだ3年半しか経っていない（>>391）。

### Anima (anima base / FT+ターボ)
- **言及内容**: AnimaはエロもLORAもあるが基本性能が低いとの評価（>>348）。anima base ターボ無しを試しているが酷い絵になる、LoRA作るしかないかという報告（>>357）。Turbo抜くとバタ臭くなる、マスピみたいな効果がある（>>363, >>364）。Turboは高速化ではなく低stepで崩れない画風LoRAと覚えるべき（>>371）。源流モデルが暴れ馬なのはanimaに限らない（>>366）。PS2/PS3時代の3Dキャラ補正テストで学習はanima base、出力はbotan最新を使用した報告（>>398）。
- **選ばれている理由**: エロもLoRAもある（>>348）。3Dキャラ補正テストの学習用ベースとして使用（>>398）。

### Opus / GPT Astra / Codex / Gemini
- **言及内容**: Opusの利用上限80%なのに大量にanal消費し始めたという報告（>>359, >>367）。GPTastraからblender操作して仮映像を作りseedanceで変換させていた（>>338）。Codexにサクラエディタの仕様を知らないのに無理してウソコード教えるなと説教（>>353）。Codex君に作ってもらったツールをエロ生成に活用（>>402）。Codexは設定フォルダに無かったらドライブの頭から探す、Unsloth Desktopを使うとサブスクは使えんがサンドボックス内で作業してくれる（>>416）。Geminiが箸でシーフードヌードル食ってる画像を出してきて進化しているとの評価（>>409）。

### Ref2VA / FL2VA
- **言及内容**: H3環境整備のためFL2VAばかり触っていたがRef2VAを触って全てを理解した（>>271）。

### Refmod

### Seedance
- **言及内容**: GPTastraからblender操作で作った仮映像をseedanceで変換していたが、モデリングとモーションどうにかできればseedance変換不要（>>338）。
