## ツール関連話題 抽出レポート

### ComfyUI

- **基本操作・利便性**: ComfyUIの操作に馴染めないという声があり、画像サムネイル右クリックでエクスプローラーを開く機能が標準でないため、自作したとのこと（280）。この自作機能に対して「有能」との反応あり（282）。
- **モデル対応の速さが選ばれる理由**: Forge Neoのユーザーもいるが、多くはComfyUIのみ使用。理由として、Neoは最新モデル（Qwen-Image-2.1等）に未対応だが、ComfyUIはモデル公開前から対応済みであるため。新モデルをすぐ試したいならComfyUIを使わざるを得ない。WebUIから離れられない・ComfyUIの操作に馴染めない層がNeoを使用しているという分析（275）。
- **ノード・ワークフロー**:
  - WAS node suiteのImage Rembgを使用した背景透過。バックグラウンドは単色にしておく必要がある（320）。
  - アルファ背景はComfyUIのノードで幾らでも作れるとの指摘（300, 311）。
  - 公式テンプレートのQwen2.1ワークフローをそのまま使用（349）。Comfyのワークフローはstep20、公式資料ではstep40で記載されていた（289）。
  - H3のRefMod使用手順：Create H3 RefMod Masterで事前作成→Load H3 RefModsとApply H3 RefModで適用。デフォ値だとバケバケになるが、Componentsの指定をVisualにしたらマシになった（270）。
  - ComfyUI-Fantastic-MiniMaxH3-PromptBuilderのドキュメントがRefModの使い方の参考になる（281）。Fantasticの方ならDraft form Refmodボタンで参照関係が自動入力される（267）。
  - QI2.1専用としてBenjiニキのカスタムノードが便利。LLMというかTEはComfy謹製のものを使用。システムプロンプトはノードに内包されており、このノードとClip Loaderだけで済む（396）。ただしプロンプトが生成されない問題があり、max_length=24,000の処理に1時間近くかかる状態。1,024に変更しても何も生成されないという不具合報告あり（433）。
  - ComfyUIのテンプレにあるLLMのWFを流用してプロンプトエンハンサーを構築可能。上流のテキスト入力ノードにふんわり日本語で指示を書くと良い感じのプロンプトに仕上げてくれる（362）。
  - i2iの場合、resolutionが0だと入力画像のサイズをそのまま使うため、大きい画像を使うと遅くなる（352）。
  - 参照画像の数で一気に重くなる印象。参照画像をなくしたら20秒でいけたが、参照するだけで10倍以上時間を食う（358）。Kitchen attenをかませることを推奨する声あり（353）。
- **MiniMax-H3関連ノード**: ComfyUI-MiniMax-H3-W4A4-VSAは早く、12GB環境向けに適している可能性（437）。
- **自作ノード**: シチュエーション固定でカメラアングル10回ランダム生成→次のシチュなど、リストの順番指定や別リストのランダムシャッフルを選択可能にした自作ノード。wildcard系ノードとは異なり柔軟な指定が可能。自作ノードの良所はほしい機能をすぐ手に入れられること（330, 351）。

### Forge Neo (webUI系)

- WebUIから離れられない・ComfyUIの操作に馴染めないユーザーが使用している。ただし最新モデルへの対応が遅れている（275）。

### IOpaint

- 背景透過に使用していたが、Qwen-Image-2.1の透過性能の方が良いとの評価。IOpaintだと汚くなるためクリスタで手作業していた（299, 303, 315）。

### Krea2 (サービス/ツール)

- 複数人制御においてKrea2が独壇場との評価。Animaは動きをつけると3キャラで崩壊するがKrea2は強い（332）。
- プロンプト応答性が高く、プロンプトと構図がほぼ1:1でガッチリ繋がる。細かく指定できる反面、少し変えただけで他の部分まで変わってしまう難点がある（410）。
- NSFWは素の状態では弱く、乳首すら出せない仕掛けが入っている（LoRAで解決）（388）。
- 三次元実写系ではKrea2の方が好みという声が複数あり、肌の質感に生命感がある（377）。T2IではKrea2優位、QI2.1は軽くて早い立ち位置（292）。
- Turbo版あり（359）。

### Codex / Grok (プロンプト作成ツール)

- **Codex**: Krea2のプロンプト作成に任せると精度が高いが、エロ系には全く協力しない。ショタ・ロリ画像を投げると成人にするプロンプトなら出してくれるが、エロ構図は拒否する（350）。ゲームのプラグインや背景透過ソフトも作らせたことがあるが、既存のクリスタの方が性能が高い（240）。
- **Grok**: 参照画像を貼り付け「参照画像がこれ、Minimax公式のプロンプトガイドがこれ、それでこういう動きのプロンプト作って」でプロンプト完成。ショタ・ロリは100%拒否する（247, 350）。CodexのKrea2プロンプトの作り方をGrokに引き継がせる手法が紹介されている（350）。
- **選ばれる理由**: Codexはエロ全般ダメだがKrea2プロンプト精度が高い。Grokはショタ・ロリNGだがエロ構図は可能。この2つを組み合わせることで大抵の画像に対応できる（350）。

### MiniMax ImageStudio / MiniMax-H3 Edit

- 参照画像のおっぱいをそのまま出して馴染んでくれる。Qwen2.1だと参照画像と同じではなく微妙なものになる（422）。
- MiniMax-H3のEditがアップスケーラーとして有効可能性。プロンプト「upscale <image1>」のみで740x960から2倍にアップスケール可能。画像が結構変わるため低解像度向け（423）。
- チンポを深く入れたい・抜きたい等の表現はMiniMax-H3のEditが適している。元が動画モデルなので深く刺す・抜くのにちょうどいいコマ取り出し可能。代わりに画質は微妙（426）。
- 画像編集においてMiniMaxの方がプロンプト応答性が良い（380）。

### 自作画像ビューワ

- スレ住民が自作した画像ビューワのアップデート。機能追加・不具合修正・起動高速化。Viewerを閉じるキーの設定とアイコンサイズ変更に対応。右クリック↓のマウスジェスチャーで閉じることを推奨（381）。

### AMD環境のAIインストーラ

- RadeonのドライバアップデータにPyTorch・ComfyUI・LMStudio・Ollamaのインストーラが付いてくるため、初心者でも即ローカルAI環境が整う（244）。

### Qwen3-VL / Qwen3.5テキストエンコーダー (ComfyUI内)

- Qwen3-VL-4B-Instructでプロンプト作成を試したところ数秒で終わるが、アバウトな指示に対する想像力が全然だった（391）。
- ComfyUIのHFにプロンプトエンハンサー用のTE（qwen3.5テキストエンコーダー）が追加。i2iとt2i用がある（302, 360）。
- プロンプト作成用途の推奨モデル：Qwen3-VL-8Bの非検閲・NSFWキャプションモデル（qwen3-vl-8b-abliterated-caption-it、qwen3-vl-8b-nsfw-caption-v4.5）。プロンプト用なら高精度でなくてもいいが、システムプロンプトが重要（413）。
- QI2.1のローカルLLMでのプロンプト作成にはQwen3.8 27Bの非検閲かGemma4 31Bの非検閲が選択肢。ただしVRAM容量ゲーで16GVRAMでも物足りない。コスパ考えるとGrok最強（390）。

### その他ツール

- **W14Tagger**: LoRA学習のキャプション作成でタグ結果を参考にしつつ手書きで書き直す用途で使用（434）。
- **AIToolkit**: Qwen2.1のLoRA学習に使用。1024解像度で4.0s/it程度。オフロード機能100%設定でVRAM14GB・RAM60GB使用。RAMがあれば16GVRAMで可能（393）。
- **Kohya**: Qwen2.1のLoRA学習環境としてKohyaニキの対応を期待する声あり（392）。
- **EasyDiffusion系**: EasyQI2.1を求める声に対し、公式WFを開いて指定場所に落として入れるだけで十分簡単という反応。今はeasy～の時代より簡単（287, 288）。
