# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI (comfy)

### デフォルトワークフローの問題と対処
- Qwenのデフォルトワークフローではシードが固定されており、毎回手動で変更する必要がある。さらに設定変更も不可になっている（>>21）
- 解決法：デフォルトのqwenテンプレート→サブグラフ展開→Kサンプラーのシードを「randomize」に変更する必要がある（>>22）
- スレ上の感想として、デフォルトワークフローは「絶妙に嫌がらせみたいに使えない」（>>21）、「サブグラフの外に出しておくべき」（>>25）

### ComfyUIのアップデート問題
- ComfyUIをアップデートした際、MiniMax H3 Reference to Video等のノード入力要素追加がバグり散らかしている（>>42）
- minimax image studioがComfyUI更新でぶっ壊れたという報告（>>71）
- ComfyUIのバージョンがGithubの方もv0.37.0になった（>>212）
- ComfyUIを最新にしたらタブ移動時にFast Muter等がおかしくなる。フロントエンドを1.52.7に下げたら直った（>>149, >>163）

### ComfyUIの利点と選定理由
- 最近の画像生成モデルはComfyUIがサポートしているため、野良のエコシステムもそこまで需要がない（>>82）
- ComfyUIにはTextGenerateというノードでi2tが可能。QI2.1で画像からセリフを自動生成するWFを構築可能。TEは流用可能でWFはシンプル（>>204）

### ComfyUI以外のツール言及
- スレ上で「基本ComfyUIがいい」という話だったが、最近は「ForgeNeoがいい」という話も見かけるようになった。使用者のツール選択に関する質問（>>220）

### 8ヶ月ぶりの復帰時のワークフロー問題
- リアス系の過去のワークフローを読み込むと使えないノードが結構多い。代替探しが面倒（>>154）
- 解決法として、動かないWFをAIエージェント（Codexやチャット）に放り投げて同等機能のノードを作らせてWFを動かす方法が提示された（>>156, >>157, >>158）
- ただしComfyUIでCodex Astraを使うのは勿体ない。GPT Solで十分。たまにトークン消費するworkに誘導されるので注意が必要（>>160）

## AI Toolkit (LoRA学習ツール)

- AI Toolkitは相変わらず対応が早く、Qwen2.1のLoRAにもう対応している（>>196）

## musubi-tuner (LoRA学習ツール)

- musubi-tunerでminimax lora学習を行った際、1024画像を使うとメモリ溢れが発生。学習画像を400×400の9組18枚、blocks_to_swap:35にすることで4090でギリギリ動作した。max_train_epochs16で10分ちょい（>>108, >>109）
- 4090ですら512×512が無理なら大多数はminimax h3のlora学習は無理という見解。次世代モデルは内部構造が多層LLMや多層DiTで複雑化しておりオフロード処理が難しい（>>178）

## Antigravity (検閲回避ツール)

- Antigravityを使えばクラウドのLLMにもエロプロンプトを作ってもらえる（>>169）
- スレ上の知見として、検閲の手順が異なるのか、AIエージェントとの会話に書き出すのではなくローカル環境にtxt等で書き出してもらうとエロ系は緩くなる（>>171）

## Jev (動画生成高速化ツール)

- JevをMiniMax H3に組み込んで動画生成を高速化する試み。Attention処理のスパース化にJevを使用。層ごとにJevが重要度を判定し、スパース率1%, 3%, 5%, 10%を選択。RTX4070で6分7秒→3分34秒で41.7%短縮（>>221）
- 詳細はその人のnoteの記事に書かれている（>>239）

## RegexExtract node (LLM連携ツール)

- LLM経由でプロンプトを作成する際、RegexExtract node (All Matches)でプロンプトを抽出する手法が提示された。パターン: `&quotrewritten_prompt&quot\s*:\s*&quot((?:\\.|[^&quot\\])*)&quot`（>>116）
