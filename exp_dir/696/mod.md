# 🆕 新規トピック（前回からの差分）
### MiniMax H3 / MiniMax / MMH3（動画・音声生成）
- 選出理由：I2V動画生成の物理挙動が優秀で、Ref2Vでのエロ出力やirodori ttsを凌ぐ音声生成が可能。
- 設定・Tips：TEのint8 conv化で内容が変化し、sol-attn（品質）/sla（速度）/vsa（fastH3）を使い分ける。t2vの笑顔問題は「expressionless」指定で改善。空間イメージとVAE latentを1ファイル管理するカスタムノードを構想中。
- 懸念点：ステップ毎のVRAM消費増による停止、モデル容量60GB（確保100GB）の負荷、RAM64GB推奨。手指・腕の破綻や効果音の質に課題があり、器用貧乏との指摘。

### YuE2-3B / YuE2（音楽生成）
- 選出理由：ローカルでのabc譜出力が革命的でMiniMax-Music3を上回り、非CUDA環境でも動作可能。
- 設定・Tips：VRAM16MB環境ではGGUFを使用。fp8推論はCPU動作となるバグに注意。abc譜で確認後に本番生成する手法が効率的。sheetsage2で詳細編曲が可能。
- 懸念点：Flow-VAE非採用による音質低下とデジタルノイズ、Suno v3相当のメロディ・ボーカル品質と破綻の多さ。インスト作成が困難でスキャットが混入しやすく、非商用モデルである。

### Krea2（画像・動画生成）
- 選出理由：ローカルでの日本語・漢字描写が良好で、bboxによる位置指定が可能。
- 設定・Tips：全キャラLoRAとしてユニークタグで学習させ、複数人の混ざりを防止。素材は1枚で十分であり、着脱はLLMに任せられるが、難読漢字は化ける。
- 懸念点：画質の違和感はnvidea vsrが原因であった。

### GPT Image 2.5 / GPT-image（画像生成）
- 選出理由：参照画像＋棒人間以上の利便性で可愛い系の生成が速く、2.5では参照画像の位置固定が改善。
- 懸念点：プロンプト追随性や素材感に課題があり、ノイズや電子透かしが入る。学習素材の水増し利用時に個性が消される。

### NovelAI (NAI)（画像生成）
- 選出理由：エロへの寛容さと手軽さ、画質の良さ。
- 設定・Tips：CFG Scale 45付近でアニメ絵のジャギを抑制。インペイントの「cross-section」で膣内、「uvula」追加で口内を表現。V5は精密参照不可のためV4.5を併用。
- 懸念点：V5は参照画像が機能せず、V4にフォールバックしてゴミ画像が出る。

### Dasiwa / Wan / FLUX / LTX / illustrious（動画・画像生成）
- 選出理由：Dasiwaはref2vaにおいて高性能。Wanはsmoothmixによるピストン動作が有効。Illustriousは0.1派生への需要から寄付的に支払うユーザーが存在。

### 総評
- 動画生成：MiniMax H3がI2V/Ref2Vで他を圧倒するが、VRAMとストレージ消費の激しさが撤退レベルの課題。
- 音楽生成：YuE2-3Bのabc譜生成は新機軸でMiniMax-Music3を凌ぐが、音質・破綻面ではSunoに及ばず評価が二分。

# 元の本文
今回とくに盛んに議論された話題は、MiniMax H3による動画・音声生成、animaのLoRA学習検証、そしてYuE2-3Bを中心としたローカル音楽生成モデルの性能比較です。

※注記：本レポートに記載されるレス番号は、統合元パート内の通し番号であるため、元スレの通し番号とは限らない。

# 流行しているモデルの推測
ログの言及頻度と議論の深さから推測すると、動画生成および音声生成では「MiniMax H3（MMH3）」が、画像生成とLoRA学習では「anima」が、ローカルLLMでは「Gemma4」および「Qwen3.8」が、音楽生成では「YuE2-3B」がそれぞれ流行していると見られる。

## 1. MiniMax H3 / MiniMax / MMH3（動画・音声生成）
- **選ばれている理由**: I2V動画生成があっさり可能であり、公式モデルが優秀で風で翻る物理的挙動などがGeminiやGrokと比べても別物と評価されている。エロ出力もRef2Vで可能。音声生成においてはirodori ttsより圧倒的に良い声が出るとされる。
- **設定値・Tips**: テキストエンコーダー（TE）をnvfp4からint8 convにするだけで動画内容が変わる。model sparse attentionの設定では、sol-attnは品質寄り、slaは速度寄り、vsaはfastH3用と使い分ける。参照なしのt2vで勝手に笑顔になる問題は、プロンプトで「expressionless」等に指定すると改善する。5枚の空間イメージを読み込んだ際のデータとVAE latentを1ファイルで管理するカスタムノードが構想されている。
- **採用されなかった理由**: 1ステップごとにVRAM消費が多くなり止まる問題がある。モデルダウンロード容量が60GBに達し、100GBの容量確保と不要モデルの削除が必要。VRAM24GBで動くがRAMは64GB欲しい。手指が6本や腕が3本になる破綻が頻発し、効果音も「シュゴオォォォオー」のような音になりMMAudioよりマシ程度。GTAおばあちゃんのような長尺動画は作れるが、所詮ローカルモデルで器用貧乏との指摘。
（243, 263, 309, 312, 336, 390, 420, 430, 456, 464, 470, 472, 480, 580, 602, 848, 868, 914, 916, 929, 930, 938, 941）

## 2. anima / Anima（画像生成・LoRA学習）
- **選ばれている理由**: controlnetなしでも「そこそこの打率」で目的の構図が出る。自然言語で細かく指示でき、「clitoral hoodだけ見せる」ような表現が簡単。SDXL時代から破綻が減りインペを全然使わなくなった。
- **設定値・Tips**: LoRA学習のdim/alphaは32/32が圧倒的に再現力が高く、16/8だと衣服が別物になる。ファイルサイズと学習時間は微増。64/32は顔は原作に近づくが体型がふっくらする傾向。学習率は4e-05、エポック100から120に変更し、弱火でコトコト煮込むと変な学習をされず安定。学習素材は反転や加工ありで最低13枚、足りない場合はMiniMax等で増殖。3D素材（PS2のICOのヨルダ等）で学習させると3Dタグが雑味を吸い、立体的な情報量が増す。公式のTurboが一番安定。素のAnima 2Bと2.9B用LoRAを3.8Bで使うワークフローが提供されている。
- **採用されなかった理由**: 手指はIllustriousより崩れる。nightプロンプトを指定すると窓や星空が映し出される。Turboを使うとクオリティがダイレクトに落ちる。V1.0 2.9Bに替えたら絵が崩れ安っぽくなる。ComfyUIで生成中にDRAM消費がどんどん増加する現象がある。
（33, 42, 57, 75, 293, 389, 395, 433, 494, 495, 503, 507, 512, 513, 514, 629, 734, 796, 979）

## 3. YuE2-3B / YuE2（音楽生成）
- **選ばれている理由**: ローカルでabc譜が出せるのが革命的。MiniMax-Music3よりクオリティも音質も上。audio.cppのdevブランチでも動くため、非CUDA環境（RadeonやmacOS）でも利用可能。
- **設定値・Tips**: VRAM16MB（GBの記載ミスと思われる）環境ではGGUFを使用。fp8推論はバグ持ちでCPUで動くような状態になるためOOMに注意。ガチャ時にabc譜だけ出して確認後、本番生成すると効率が良い。同時リリースされたsheetsage2は譜面レベルで詳細編曲可能。
- **採用されなかった理由**: Flow-VAEでないため音質批判があり、Stage-2の復元が雑でデジタルノイズが発生。メロディやボーカルはSuno v3程度でBest-of-1の破綻が多く、溜め引き算が壊滅的。インスト曲が作りにくく勝手にスキャット風の声を入れてくる。遅くて曲も声も悪いとの意見。モデルは非商用。
（306, 308, 317, 328, 516, 534, 535, 536, 556, 625, 674, 675, 687, 691, 699, 701, 710, 711）

## 4. Gemma4 / Qwen3.8（ローカルLLM）
- **選ばれている理由**: Qwen3.8は5060tiのようなロースペックでも時間さえ許せばMV自動生成の推論に使え、意外とエロいける。Gemma4はMTPが動作し200tok/s越えを確認。
- **設定値・Tips**: コンテキストレングスは「VRAMの許す限り」確保し、プロンプト出力なら4096や8192、コーディングなら65536、可能なら131072。LM Studio環境で画像添付時のエラーは、Physical Batch Sizeをデフォルト512から2048に変更するか、評価バッチサイズを512に下げることで解消。
- **採用されなかった理由**: Gemma4はLM Studio 0.424 build1で確定クラッシュし、画像を読ませるとterminatedエラーで強制イジェクトされる。脱獄知っていればガバガバだが版権未成年キャラは検閲に引っかかる。多様なエロシチュ対応にはVRAMゲーとなり12GBだとつらく32GB必要。Qwenはトークン消費が激しく、3.5〜3.8では日英翻訳が上手くいってない単語が多い。
（137, 140, 184, 185, 189, 669, 670, 672, 678, 679, 682, 683, 726, 736, 827, 833, 834, 838, 839, 920, 942）

## 5. Krea2（画像・動画生成）
- **選ばれている理由**: ローカル環境で漢字含めた日本語描写がかなり良い線いっており、bboxで位置指定が可能。MiniMax-H3の面白さを半減させる重要な存在。
- **設定値・Tips**: キャラLoRA検証において、キャプションをタガー方式ですべてユニークタグにし全キャラLoRAとして学習させることで複数人の混ざりを防ぐ。学習素材は1キャラ画像でよく、服の着脱はLLMに任せられる。難しい漢字は化ける。
- **採用されなかった理由**: 画質が変だった原因はnvidea vsrのせいだった。
（36, 40, 41, 216, 229, 244, 604）

## 6. GPT Image 2.5 / GPT-image（画像生成）
- **選ばれている理由**: ナノバナナを超え、参照画像+棒人間以上に楽に描ける。可愛い子を出すのに適し、生成が早いためリアルタイムでSFWを出すのに重宝。2.5では参照画像の位置を変えない点が改善された。
- **採用されなかった理由**: プロンプト追随性に課題があり、ピチピチの素材感にならない。条件でノイズが入る。GPT image2.0時点でチャッピーで十分、バナナ側は進化なし。電子透かしが入る。学習素材の水増しに使うと固有の模様をいじると個性を消しに来る。
（24, 44, 57, 159, 165, 167, 170, 307, 311）

## 7. NovelAI (NAI)（画像生成）
- **選ばれている理由**: エロに寛容でお手軽。画質が良い。
- **設定値・Tips**: CFG Scaleを45ぐらいに落とすとアニメ絵のジャギが収まる。フェラシーンにインペイントで「cross-section」だけ入れると膣内になるが、「uvula」を追加すると口内になる。V5は精密参照が使えないためV4.5を使っている。
- **採用されなかった理由**: V5は参照画像ができず勝手にV4に選択されゴミ画像が出る。
（138, 150, 233, 237, 765, 767, 783）

## 8. Dasiwa / Wan / FLUX / LTX / illustrious（動画・画像生成）
- **選ばれている理由**: Dasiwaは現状のref2vaにおいて大正義でハイブリッドと言いつつref2vaの気配がある。Wanはsmoothmixが有効でピストンができる総合モデル。Illustriousは0.1の派生が今でも世話になっているため寄付的に支払うユーザーがいる。
- **採用されなかった理由**: MiniMaxを導入するとWanは過去のものになる。WanやLTXのエロモデル（10eros等）はピストン等はできるが汎用性がめっちゃ下がりエロ以外がまともに動かないため、個別に専用LoRAを使う選択となる。FLUX（fl2va向きモデル）は1フレーム目が参照画像そのままになる。Wan2.2はRAM32GB環境でVRAM50%しか使わないのにCドライブアクセスが止まらなくなる。Illustriousはcontrolnetなしだと2人構図が厳しく、謎の擬音語でしか出せない成分がある。
（245, 433, 786, 847, 848, 854, 863, 865, 883, 917, 981）

# 総評
1. 動画生成においてはMiniMax H3がI2VとRef2Vの性能で他モデル（Wan等）を過去のものにしたが、VRAMとストレージ容量の消費が激しく、環境によっては撤退を余儀なくされる重さが課題。
2. 画像生成のanimaでは、LoRA学習のdim/alphaを32/32に設定し小火で煮込む手法が「最初からここで開始して良いレベル」と高く評価され、学習パラメータのベストプラクティスが確立されつつある。
3. 音楽生成ではYuE2-3Bがローカルでのabc譜生成という新機軸を打ち立てMiniMax-Music3を凌ぐとされた一方、音質や破綻の多さから「Sunoの足元にも及ばない」と評価が完全に二分している。
4. ローカルLLMではGemma4とQwen3.8の動作検証が盛んで、特にLM Studioでのバッチサイズ調整がエラー回避の鍵となっているが、VRAM消費とトークン消費の激しさが利用の壁となっている。
