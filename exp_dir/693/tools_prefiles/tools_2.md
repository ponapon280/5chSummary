# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI (comfy, ComfyUI)

- **AIに導入支援させる使い方の普及**: ComfyUIが苦手・分からない時代は終わり、AIに導入してもらい自分用UIを作ってもらう時代になった。ComfyUIの画面を見ずに専用画面でプロンプト書いて生成ボタン押すだけの直感UIになり、参照画像やLoRAの付け足しもAIに言えばやってくれる。必要なのは最低限の言語能力とPCスペック（レス405）
- **存在価値への言及**: AIポン出しで中身がブラックボックスになると、ComfyUIの存在価値がない。AIにインターフェース含めて作ってもらえばいいというスレ上の見解（レス409）
- **カスタムワークフローの利点**: Comfy自体の自由配置で継ぎ足し自由のワイ専用ワークフローのように化すため、生成するのに不自由を感じたことはない（レス411）
- **動画生成での渋々使用**: 動画生成だけはどうしようもないからComfyを渋々使っている（レス415）
- **移行後の不便さ**: インペイントとi2i多用マンだったためComfyUI移行後は結構つらい思いをしている。ほんのちょっと直したい時はwebUIのほうがサクサク作業できて恋しい（レス422）

## krea2 (Krea2)

- **krea2生成の動作確認**: グラボ3つ繋ぎ環境でも遅くならずちゃんとkrea2生成できた（レス247）
- **漫画制作向けLoRA**: krea2は座標指定できるため漫画用LoRAを作ると結構行ける（レス275）
- **二次エロとLoRA**: Krea2は二次エロが相当厳しい。LoRA使えば出るが版権や画風制御は無理。素のRawでLoRAを作るとエロはダメンゴされる（レス283）
- **実写向けの位置づけ**: Krea2は実写向け。性能自体はいいがエロ無理、画風やキャラ再現が激弱、LoRA学習が激重で使い所がない。3ヶ月くらい触っていない（レス284, 288）
- **LoRA学習の特徴**: Krea2でLoRAを作り試しているがすごく素直に覚えるためLoRAは作りやすそう。ただDanbooruタグ未履修はきつい（レス290）
- **ケモFTへの期待**: krea2ケモFTには期待している（レス291）
- **公式プロンプトガイドとWF**: Krea2は公式がコピペするだけでいいシスプロを用意してくれており、公式WFにも組み込まれているため余計なことしなくていいレベル（レス319）
- **英語自然言語記述の難しさ**: kreaは多くの人にとって英語の自然言語記述が難関。英語がある程度理解できれば問題ないが1girl,nakedレベルで精一杯の人もいる（レス324）
- **シスプロの改変利用**: Krea2もよくわからんプロンプトガイドがあるが、ハグのコミュニティにシスプロを晒してくれてる人がいたのでそれを改変して使っている（レス317）
- **edit用途の期待**: kreaはエディット版が来ればH3の参照画像作成に活かせる。写実描写とプロンプト追従は強いが何かと歯痒い（レス294）
- **二次エロでの再現性**: 今のkreaでも二次エロめちゃくちゃいける。初期設定は性器出ずにプロンプト検閲もされているが、日本語入力も効くしloraの効きも良いからanimaより再現性高い（レス339）
- **h3fastとの比較**: h3fastはかなり早くなるがbaseと比べると落ちる。8stepぐらいでやると品質多少は維持できる（レス386）
- **H3系のVAE**: H3_VAE_TRTなかなかいいが、へっぽこマシンではコンパイルに3時間かかった（レス375）
- **H3系高速化の泥沼状況**: H3系高速化は種類多すぎ、いつどれがどういう更新されてるか把握しきれない、個々の環境・生成する物・クオリティ判断基準によって最適解や評価が変わるという泥沼感（レス387）
- **KitchenAttentionとSolAttention**: KitchenAttentionとSolAttentionはとりあえず入れ得感、そこからTurboLoRAを入れるかどうか（レス381）

## MiniMax H3 (MMH3, H3, h3, FastH3)

- **二次絵リップシンクの良さ**: MiniMax H3は二次絵のリップシンクがいい。WanもLTXも二次絵の場合ここまで自然なリップシンクにならなかった。人権ないPC環境でも普通に生成できるのはありがたい（レス277）
- **ローカル動画生成の確認**: VRAM16GB メモリ64GBでもMiniMax H3で0.5MP程度の動画なら15秒動画が問題なく生成できている。MMH3が出た時はメモリ64GBで無理なら増設しようかと思ったが動いた（レス352）
- **可能性の高さ**: Wanは即投げたがMiniMax H3は可能性を感じる（レス328）
- **ref2vの性能**: minimax h3のref2vはkrea2のeditすら超えている。画像生成モデルを出してくれたらキャラloraがオワコンになる。今はカスタムノードで疑似的に画像生成するぐらいしか手段がない（レス329）
- **画像Edit用途への活用**: MiniMaxを画像Edit用途に使う動きもある。QIEよりスジは良さそう（レス321）
- **公式の画像編集モデル**: MiniMaxH3は公式が画像編集モデルを出すと言っていた。待つのみ（レス327）
- **画質の課題**: minimaxは画質さえ良くなれば画像編集モデルとしてもスゴイ。画質マジでなんとかならんかな（レス325）
- **FastH3の確認**: FastH3試したが結構いい。Turbo系Loraと違って1itもバニラの10％以上は速い。プロンプトの大体の動き確認したい時に使えそう（レス353）
- **導入の難易度とkijai**: 現時点では導入が大変すぎる。kijai神ならいずれ簡単に導入できるようにしてくれるだろう（レス354）
- **kijaiのhfレポジトリ**: kijaiのhfレポジトリにモデルがある。特に何もしなくてもモデル差し替えるだけで行ける。unet unexpectedで結構羅列されるから完全対応ではないのかも知れない（レス369）
- **fastvideo**: fastvideoというやつ（レス377）
- **Fast H3の位置づけ**: 今後の高速化の本命はFast H3だがまだ情報が少なくてようわからん（レス384）
- **H3 Eros Max**: H3 Eros Maxのbeta4だいぶ良くなっていた（レス435）
- **10eros**: 10erosはkrea2も学習してるみたいだからちゃんとしたおpanties出るんやろか（レス436）
