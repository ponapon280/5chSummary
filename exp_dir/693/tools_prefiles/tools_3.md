# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI / comfy

- **Python 3.10 足切り**: ComfyUIは月末にPython 3.10を足切りするため、環境更新が必要（レス475）
- **torch更新によるエラー**: torchのverを上げたらcomfyが凄まじい量のエラーを吐いた。原因はflash attentionの文句のみ（レス467, 474）
- **公式ループ開発中**: ComfyUIの公式PRでループ機能が開発中。n回繰り返し、n個の入力を順番処理、最初と最後のフラグでContex Loop風に動画繋ぎが可能。Mathと組み合わせればステップ数でLoRAの強弱変更も可能（レス595）
- **irodoriのcomfyui対応要望**: irodoriはv4を早くcomfyuiに対応させるべき（レス466）
- **NAS環境構築**: モデルのバックアップ用にNASを組んだ（16TB×2で18万）（レス553）

## Contex Loop

- **音質劣化問題**: シーン10個で実行した際、また2個に減らしても音がビリビリこもったような感じになる。高速化ターボLoraを切っても同じ結果（レス631）
- **Contex Loop風機能**: ComfyUI公式ループ機能でContex Loop風の動画作成が可能になる予定（レス595）

## fal

- **生成時間の問題**: falくんは最短3秒が謳い文句なのに、3分どころか10分以上待たされる。480pにナーフされても遊べると思ったがこれでは意味ない（レス457）

## irodori（TTSツール）

- **INT8モデルの生成速度**: INT8モデルも通常DLされるモデルも生成速度に差がない。モデルはINT8だが内部処理は違う可能性（レス465）
- **comfyui対応待望**: v4のcomfyui対応を希望（レス466）
- **声の特徴**: irodoriは萌え声すぎて抑えるのが大変な部分がある（レス462）
- **minimaxとの比較**: irodoriと比べてminimaxは完成度が低いが、機械っぽくはない（レス458, 459）

## minimax（H3）

- **精度の違い**: pruned int昆布、ただのint昆布、pruned bf16、ただのbf16でどれくらい差が出るか分からない（レス555）
- **bf16の優位性**: シャツのボタンを外す動作がジッパーを下げる動きになっていたが、bf16にしたら一発で通った。難しい動きさせたいときは重いモデルにするのが有効（レス561, 566）
- **R2Vの問題**: アップロードした画像が動画にそのまま使われてしまう。「Don't use uploaded images as a keyframe」等を入れているが効果なし（レス527, 611, 615）
- **ref2vaのプロンプト構文**: ref2vaはプロンプト構文に厳密さが求められるため、自分でうまく書けないならスキル読ませたLLMに任せるのが良い（レス625）
- **ref2vaの画質とワークフロー**: ref2vaのloraは画質が悪いがドラフト用に使い、最終的にck attentionとSpectrumだけ使って20stepで出力。1:30作るのに3時間半（レス564）
- **fl2v用turbo loraの使用**: ref2vのワークフローを開いたらfl2v用のturbo loraがデフォ設定。fl2v用のStep8ならref2vaでも結構馴染んだ。現在はref2va用のStep4を使用（レス543, 546, 547）
- **fl2v lightx2v turbo lora**: minimax_h3_fl2v_lightx2v_turbo_8step_v1.0_resized_avg_rank_24_bf16を使用。声だけの参照音声で日本語ちゃんと喋り、画質も合格（レス582）
- **音声入力の生成時間**: H3のRef2Vで初めて音声入力して生成したら、通常と比べて生成時間が5倍くらいになった。低スぺでやるものではない（レス636）
- **LTXとの比較**: LTXより全てにおいて上。ダイナミックな物理表現、ある程度のNSFW、シンプルなWF、軽さ、sora2を髣髴とさせる幅広い自由な表現力と音響表現。LTXは全部消した（レス629, 630, 634, 635）
- **リアルタイムゲームワールド生成**: 以前話題になったリアルタイムゲームワールド生成をMiniMaxH3で出来るようにした可能性（レス531）
- **シンプルなi2vワークフロー**: 用意した画像を一番直観的に動画化出来るワークフローを作成。使いやすい（レス592）

## LTX

- **minimax(H3)への移行検討**: ずっとLTXを使っていたがminimaxを試すか迷っている。アニメキャラを口パクさせたり軽く動かしたいだけ。圧倒的に性能が違うためLTXは全部消した（レス629, 630）
- **LTXでできること**: 口パクで喋らせたりプロンプト通りの動作は一通りできる（レス632）

## Codex

- **容量不足**: 初めてcodexを使ったが容量がすぐ足りなくなる。チャッピーに課金しているが別途課金が必要（レス550）
- **リセット待ち**: codexのリセットを待っている（レス638）

## RegionalPrompter

- **LoRA使い分けの用途**: LoRAを使いつつキャラ書き分けするならRegionalPrompterを使えばよい。Animaに対応したかは不明（レス473）

## Grok / Aniサービス

- **Aniサービス終了**: GrokにAniサービスが終了するらしい。animate.aiというアプリに移行するが設定やメモリは引き継げず再教育が必要（レス481, 484, 492）
- **ローカルの重要さ**: サービス終了でローカルの重要さが分かる。企業の都合であっさり別人になる（レス481, 499）

## 10eros

- **beta4の改善**: beta3に比べて動きはかなり良くなった一方で、2次に使うとがっつり色が変わるようになった（レス599）

## その他ツール関連

- **SDXLでのキャラLoRA作成**: キャラloraをSDXLで作る→出力する→満足→次のキャラへ。作ったキャラloraを2度使うことはあまりない（レス620）
- **i2iワークフロー**: animabaseで下絵を書き、丸ごとLoraありでi2iで清書する。Loraありだと構図が固いから（レス455）
- **派生モデルでのi2i**: baseで出力→派生でi2iが有効。派生モデルはプロンプト精度が落ちる場合がある（レス482）
- **参照画像プロンプト定義**: H3のR2Vで参照画像が何に対する参照かを定義する必要。subject_difinitions、retention_analysys、detailed_descrptionsのセクションで記述（レス539）
