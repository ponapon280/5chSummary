# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI (comfy, comfyui)

- **comfy kitchenの改善**: comfy kitchenが早くなり、静止画モデルでもsageより僅かに早い。約1ヶ月前にあった構図が変わる問題も修正済み（552）
- **Codexでcomfy管理**: comfy丸ごとCodexで管理しており、Codex依存になっている（555）
- **comfyuiのクラッシュ問題**: disable-comfy-compilerを設定してもOOM等でクラッシュし始めた（470）
- **block sparse attentionのバグ**: block sparse attention使用中、生成中に時々comfyuiごと落ちる。古いノードを新しいノードに入れ替える必要がある（586, 589）
- **ノード更新時の入力値ズレ**: comfyui更新後にノードも更新があり、項目に対する入力値がズレる現象が発生。ノードを設置し直すことで対応（592）
- **comfyui終了後のCPU負荷残留**: comfy終了してもCPUに負荷が残り、PC再起動しないと直らない。pythonプロセスが残っている可能性あり、タスクマネージャからpythonを終了すれば良い（612, 620, 627）
- **Fast VAE Comfyの不具合**: Fast VAE Comfy V0.31では爆速で問題なく動いていたが、最新版に更新したら生成物がやたら暗くなる（594）
- **comfyuiのlora入力ノード**: comfyuiでpower lora loaderではなく、webuiのようにtext入力でloraを使うカスタムノードについての質問。impact packのimpact wildcard encodeに該当機能がある。animaのLoRAもロード可能だが動画系では未検証（494, 495）

## Forge (webui系)

- **Forgeでの3.8B利用とLoRA remap**: Forgeで3.8Bを使おうとしたが、comfyuiと違ってloraをremapする拡張機能が見当たらない。しばらくは2.9bを使い続ける必要がある（621）
- **Forge Neoの対応**: Forge Neoなら3.8BでもLoRA修正してくれる可能性がある。数日前に更新したため、以降に対応されたかもしれない（622, 629）

## Krea2 (krea2)

- **Krea2の実写に関する特徴**: krea2の実写は足が太くなりがち。もっと薄細にしたいが肉付きが良くなってしまう（478）
- **Krea2の推奨設定**: int8のエセターボのため、ステップ8~12、CFG１でOK。0時まで利用可能。Krea2の仲間が増えると嬉しいというスレ上の声（625）
- **Krea2 Megaの問題**: Megaは無理やりデスクトップアプリを入れさせられるため面倒くさい（631）

## Animerge

- **Animerge更新**: Animergeが更新され、学習機能は各バージョンに対応。不具合報告待ち。問題はマージ機能で、異なるバージョンのマージが上手くいかない。互換マージが上手くいかないだけで同バージョンのマージは可能。仕様が酷過ぎるためAnima3.8Bは広まらないかもしれないという懸念（610）

## その他ツール関連

- **CapCutでのAI画質調整**: 画質が悪い動画をCapCutでAIに聞いた調整数値でかなり画質が良くなる。アップスケーラーなしでも対応可能（596）
- **AIツールによるwebp対応**: AIが作るツールは指示しなくてもwebpにすべて対応しているため楽ちんという感想（598）
- **複数AI環境の管理問題**: 様々なAIをインストールしていると、どこに何が入っているか、インストールしたディレクトリにどうやってアクセスするか迷子になる。outputする画像や映像もAIによって場所が異なり管理が混乱する。WSLのホーム直下に起動スクリプトを置く方法や、エクスプローラーのショートカットにフォルダを登録する方法が挙げられている（515, 517, 521, 522）
- **dasiwa（動画生成ツール）**: fl2vaとref2vaのハイブリッドモデル。dasiwaもハイブリッドモデル。一部プロンプトが効きにくく局部が変わったり胸が露出されやすい傾向。実写は横顔を参照しないと微妙、アニメキャラの方が得意という印象。t2vaは全然あかんかった（602, 603, 605, 607）
