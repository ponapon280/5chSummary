# 生成AI関連ツール レポート（ログ要約）

今回とくに盛んに議論された話題は、ComfyUIの生成・保存速度の高速化（kitchen/高速化Lora/NVENCノード/AI生成カスタムノード）と、Codexをはじめとするコーディングエージェントの運用・権限・リスクである。

※以下のレス番号は統合元パート内の通し番号であり、元スレの通し番号とは限らない。

## 1. ComfyUI（実行・加工の主戦場）

- **速度検証**：minimaxh3のi2v同一ワークフローで「公式のままだと500秒、高速化Lora8stepで180秒、さらにkitchen入れて130秒。高速化Lora8stepだけ入れて445秒、さらにkitchen入れて309秒」と報告。「comfy UI本体のVUしたせいかも」（>>187）。別検証ではMATLOWAI 6stepで6000が280〜290秒、5090が300〜310秒、どちらも保存のCPUエンコがネックでざっくり5分（>>514）
- **保存ノード改善**：video saveノードが遅すぎるためOpus5.5にNVENC版を作らせ保存が40秒→6秒（>>538）。生成ログをAIに解析させ改善用カスタムノードを作ったら「20秒の動画が300秒以上かかってたのが220秒に縮まった」（>>698）。遅いカスタムノードをCPU処理からGPU処理に変更してもらい爆速化した例も（>>968）
- **VRAM対策**：モニタ出力をiGPUに切り替えてVRAM800MB〜1GB節約する手法が複数報告（>>441、>>448、>>479、>>500）。AMDはヘッドレス非想定でVRAMアンロード失敗等の不具合、ダミーHDMIプラグは1GB持って行かれる（>>460）
- **長尺動画の繋ぎ**：ContexLoopで1分超にすると20秒あたりで「再放送」（動きの重複）が入りノイズ化。使わず生成→編集で繋げた方がいい（>>859）。1シーン5秒にして「前のシーンを続けろ」プロンプトで繋ぐ運用（>>851）。FLで繋げて1分が一番破綻なし（>>856）。ContexLoopは動画延長の現状FA（>>891、>>896）
- **Extenderの発見**：Clip毎にValidatedすると次のClipで参照画像を変えられる。画像18個でClip6個の動画が問題なく完成（>>370、>>372）
- **不具合**：inputフォルダ画像のプレビューが表示されなくなった（>>703）。nvidiaドライバをstudio→game ready 596.49に変えたらPython固まりが直ったがまた固まる（>>880、>>882）。wsl操作ミスでsafetensors約800GB全消去の事故報告（>>930）

## 2. エージェント運用（Codex / Claude / ローカルLLM）

- **Codexの権限とリスク**：デフォルトで書き込みはサンドボックス内だが読み取りは「PC内ほぼ全て可能」。VSCodeなら低リスク、Computer Useだと高リスク（>>270）。エロ用途ならDGXsparkやM5 Ultraでローカル動かしたほうがいいというスレ上の見解（>>255）
- **Codexの不具合と対処**：アップデート後コマンド実行のたびにターミナルが一瞬出る（>>868）。書き込み権限不具合は.codexフォルダと作業フォルダのCodexSandboxUserパーミッションをフルコントロにして解消（>>954〜962）。電話番号要求が開始（>>948）。Plus民はAstraでトークンが止まる（>>914）
- **コスト意識**：「Codexは麻薬や」（>>147、>>299）。マウスの取り合いに注意（>>153）。作業が自分で勉強すれば簡単だったと気づく日が来るかもというスレ上の見解（>>292）。環境はまっさら再構築・引き継ぎ方式が良い（>>302）
- **Claude code**：Krea2のlora作りを手伝わせたら実写系画像を見られて未成年判定で拒否された。「comfyuiがどういうものか理解してるので手伝えません、2次絵ならいくらでも手伝える」（>>245、>>250）
- **活用例**：MMDでモデルを踊らせたが下地知識がない分はcodexにやらせてトークン消費（>>228）。ロゴ・装飾除去カスタムノード作成（>>320文脈）、生成ログ解析（>>698）、3Dゲームは最上位モデルで鬼トークン消費かつ演出はファミコン以下（>>571）。LM Studio Bionicは「Codexみたいになっててめっちゃ楽しい」でGemma/Qwen 20B前後が実用、無限試行錯誓できるから用途次第でローカルが強い分野あり（>>782、>>785）
- **選択理由**：業務はClaude一択。ちゃっぴー/codex/claudeなら一発で改修まで終わるがGoogle系は「かなり終わってる」から（>>755、>>765）。カスタムビューワ作者は「ソース公開しとるからChatGPTで勝手に機能追加してくれてええで」（>>364）

## 3. 動画・音声ツール

- **Viggle.ai**：動画の人物だけ置き換える用途で「手軽で覇権」。淫夢リメイク動画の多くがこれ（>>83、>>177）。選ばれる理由は手軽さ（>>177）
- **Seedance**：オリジナルINMU KINGはSeedance説。理由は有料で高め（>>84、>>166）
- **Ref2VA音声参照**：15秒長だと空白で謎言語・セリフ潰れ・飛ばし問題（>>669、>>678）。対策は英語テンプレでsubject/retention指定（>>695）、台詞をプロンプトにそのまま書く（>>672）
- **セリフとturbo**：turboで劣化キツいのはセリフ。minimaxでは喋らせずirodoriで作って最後合成が結論。リップシンク課題あり（>>933）

## 4. ペイント・素材管理ツール

- **クリスタ騒動**：AI搭載できないため新機能がadobeの劣化コピーと批判（>>130）、クリスタMCP対応は夢のまた夢（>>184）。ただしAI補助でブラシは作れる（>>219）
- **krita移行派の理由**：AI使えるしadobeより良い（>>138）、無料（>>133、>>155）。リアルタイムi2i機能が気になる（>>162）。ただし「コマ割とテキスト入れがクリスタよりやりにくい、でも愛してる」（>>158）
- **NivisViewer**：タグはEXIFでなくファイル名埋め込み。Zipplaからの移行がそのままできる利点があるからこの方式（>>433、>>594）。PSD/Clip対応を実装、クリスタで開けること確認（>>596、>>694、>>699）。作者は機能追加要望にChatGPTでの自作改修を歓迎（>>364）

## 5. その他の選択理由が語られたもの

- **DanbooruTagger**：半脱ぎのタグがそのまま出てエロ用途ではLLMキャプションより手間が減る（>>291）
- **krea2**：エロ表現なら部族語理解のほうが上だが、動画素材として使うなら圧倒的背景力で選ぶ（>>325、>>363）。版権キャラ未学習でwildcard運用が困難（>>911）
- **MATLOWAI**：公式fl2vよりモデルサイズ小さいのに生成時間は公式+高速化Loraよりだいぶ遅い（>>419）。6bit/8bitの方が変換処理をスキップできて速いというスレ上の説明（>>421）
- **Grok W6A8量子化**：INT8の2割減のサイズで誤差3分の1、5090だとINT8より速い（>>418）。RTX 50はFP4対応・INT4非対応、20系は逆というスレ上の説明（>>421、>>423）
- **ローカルLLMキャプション**：VRAM16GBなら総パラメータより量子化精度が効く。12B@Q8のほうが13B@Q3より精度も速度も上（>>803）
- **ComfyUIマルチGPU**：「5090で火事チキンレースするくらいなら5080か5070Tiデュアルの方が速くて安全」が選択理由（>>631）

## 総評

1. 生成速度の改善はComfyUI本体・ノード・LoRA・量子化の積み重ねで実測値がログ内で繰り返し検証されており（500秒→309秒、40秒→6秒、300秒→220秒等）、AIエージェントを使ったカスタムノード自作・改修が定着しつつある（>>187、>>538、>>698、>>968）。
2. エージェント運用ではCodexの権限設計（読み取りはPC全体、書き込みはサンドボックス）とトークンコストへの意識が高く、画像を見たことでの拒否事例から「2次元素材かつローカル処理」方向の工夫が示された（>>245、>>255、>>270）。
3. 動画長尺化はContexLoopの「再放送」問題により、生成→編集での繋ぎ運用へ収束しつつある（>>859、>>891）。
4. クリスタのAI不搭載を機にkrita/affinityへの移行が具体化し、ビューワ・素材管理は有志ツール（NivisViewer等）がChatGPT併用開発で急速に機能拡張している（>>138、>>155、>>364、>>596）。
