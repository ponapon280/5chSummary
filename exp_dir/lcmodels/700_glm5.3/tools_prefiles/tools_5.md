# レポート：ツール関連話題の抽出（828〜1000）

## 1. 動画生成の長尺化・接続手法（ComfyUI系）
- 5090で1MP/20秒動画、参照4枚重ねでOOM。回避策はあるがモデルをメモリに逃がすため遅くなるとチャッピーに言われた（842）
- 回避策としてrefmodsを使う（843）、Context Loopで2つの動画をつなげる（844）
- 1シーン5秒程度にしてプロンプトで「前のカメラ、シーンを続けろ」と書き繋げる運用。20秒1発は歩くだけなど失敗の恐れがない場所でしか使わない（851）。15秒繋げてClip毎にガチャ回すと時間がかかる（854）
- ContexLoopで1分超動画を作ると20秒あたりで「再放送」（動きの重複生成）が入りノイズになるため、ContexLoopを使わず生成→編集で繋げた方がいい（859）
- FLで繋げて1分ぐらいにしている。自分の環境ではこれが一番破綻なく綺麗。qie2.1でF画像が完璧になった（856）
- 動画延長には現状ContexLoopがFA。既に作った動画も延長可能（891）。ContexLoopのWFをベース生成フローにして、ガチャで良いのが引けたら即延長という運用も提案される（896）

## 2. メモリ・スペック関連
- 尼で64GBメモリが安くなっている。前回は1日で値段が戻ったためチャンス（837）
- グラボそのままでメモリ96まで上げればいける（861）
- 4090＋RAM128Gの環境で、`--fast-disk`（場合により`--disable-pinned-memory`）を付けるとメインメモリ少なくても済む。モデルはbf16よりint8_convrot推奨（898）
- メインメモリは「魔法の呪文」書き足すだけで余るようになったがVRAMは常にカツカツ（863）
- 最近のComfyアプデでモデルデータ置き場がNVMeか自動判定するようになり、`--fast-disk`は「古の呪文」に。逆に環境次第では`--disable-fast-disk`が魔法の呪文になる（901, 903）

## 3. minimax H3の高速化・LoRA
- minimaxH3のLoRAは絵柄に影響し3D寄りになる。0.3ぐらいで2Dアニメ化、乳揺れとのトレードオフ（864）。あり3なし3程度の検証で、プロンプト追従性もありだと落ちる（866）
- minimaxH3のLoRAはピンポイントかつ強烈に働き悪影響もデカい。ローカルLoRA学習は知見不足で、素材・学習方法・epoch・強度が手探り。DGX Sparkが欲しいが金額が厳しい（875）。Baseが蒸留状態で通常のLoRA学習より難しいらしい（876）。Google AI ProでA100が使えるらしいという情報あり（877）
- minimaxの高速化：Attention Backendとブロックスパースアテンションで0.9MP/15sが90秒くらい（881）。別名が60秒ちょいと主張（883）、グラボ・VRAM表記なしでの比較は無意味という批判（884）。リポジトリにPro6000のサンプルがあるためそれ前提と推察される（885）
- 4060Ti(16GB)で、Comfy-kitchen Attention / Block Sparse Attention / Spectrum / Model Shift(ModelSamplingMiniMaxH3)の4つを使い、0.6MP/30steps/12s/24→48fps化が18分（888）
- 64GBクラスの使用例：kitchen attentionとsol attnのtau1.00だけでステ25メガピ0.9の15秒が13分弱（907）
- 高速化したものとそうでないものの差が分からなかったが、Spectrumはダメだった（899）
- turboで一番劣化がキツいのはセリフ。minimaxでは喋らせずirodoriで作って最後に合成という結論。リップシンクの課題あり（933）

## 4. ComfyUI・カスタムノード・環境
- Pythonが固まって生成できなくなる問題がnvidiaドライバをstudio最新からgame readyの596.49に変えたら直った（880）。その後また固まる（882）
- qiのtinyVaeが出たがKJのModel Preview Overrideで見るには修正が必要。チャッピーと壁打ちして見えるようにした（906）
- 使っていたカスタムノードが遅く、チャッピーに頼んでCPU処理からGPU処理に変更してもらい爆速化（968）
- wslの操作ミスでmodelsフォルダ以下のsafetensors800GB位を全消去。find一括処理への注意喚起（930）
- forge neoでspectrum integratedをオンにすると生成途中で画像が壊れる問題（915）。原因は部族語の補足に使った適当な自然言語で、ちゃんとした文章にしたら解消（978）
