- H3は3Dアニメ感が強く、WANよりアニメ動画の実用性が高い（874, 872）

- 公開Baseが蒸留状態のため学習が困難で、kohya氏も苦慮（876）
- 素材に近い参照画像しか利用できず、fl2vaはモーションが遅くなる（587）
- 効果音の生成も可能（658）

### 環境・速度検証
- PRO6000 vs 5090：T2V(1MP20s)ではPRO6000が僅かに速く、実用上は不要（514）。ただし1.2MPで5090はOOMとなり、学習にはVRAM32GBでも不足との反論あり（518）
- 5080＋RAM128：1mp/10秒（808）。スペック以上の差が出るとされる（811）
- Attention Backend＋ブロックスパースアテンション：0.9MP 15sが90秒前後（881-883）
- 4060Ti(16GB)：特定設定（kitchen/Block Sparse等）で0.6MP/30steps/12s/24→48fpsが18分（888）。ただし高速化設定は環境依存（886, 900）
- kitchen attention＋sol attn tau1.00：0.9MP 15sで13分弱（907）
- 5060ti+RAM32：0.5MPx2が250秒（967）
- H3対応エロモデル：MATLOWAIは実写の動きと忠実度が◎だが生成が遅い。Dasiwaは一貫性とアニメ表現が〇だが指示への忠実度が低い（324, 419）

### 弱点

- 巨乳寄りの傾向があり、小胸Loraでも谷間が出るため参照画像での修正が必要（673）
- 高解像度・LoRA・あり3なし3等の条件で3D寄りになり、プロンプト追従性が低下（864, 866, 867）

### Tips・欠点

# 生成AIモデル関連レポート（なんｊログ統合）

## 総括（冒頭まとめ）
本ログ群で最も話題量が多く、実用面で中心的に扱われているのは**MiniMax H3（動画）**と**Qwen-Image 2.1 / QIE2.1（静止画・編集）**。二次元静止画では**anima**が依然定番であり、実写・背景では**Krea2**が使われている。流行の推測（スレ上の評価に基づく）：
- 動画：MiniMax H3が実質の主流（872, 874, 324, 514, 881）
- 静止画I2I/編集：QwenImage2.1（189, 320, 677, 679, 692）

## 1. MiniMax H3（MMH3）— 最も活発な議論対象

**選ばれる理由**
- アニメ動画で実用性が高い。「WANはリアル三次が混ざる感じ、H3は3Dアニメが混ざる感じ。アニメが行けるのはWANより比べ物にならない」（874）。三次に引き寄せられがちな絵柄がむしろ二次で破綻しないという評価（872）
- Ref2Iの強さ：「スレ見てる感じRef2IはMM-H3のImageStudioの方が強い印象」（217）

**採用を見送る・苦労する理由**
- 途中から映り出す情報に弱い。背面パン生成でパンツが紐になり局部に腫瘍が出る破綻（221）
- H3 Maxの出るタイミングを待って動画生成の意欲が減退（52）
- 動画Lora利用時の課金の負担感：制作労力を考えれば160円は安いが課金は躊躇（94）
- 生成速度低下の報告：公式i2v 500秒→高速化Lora8step 180秒→kitchen追加で130秒だったのが、445秒／309秒に悪化。投稿者自身「comfyUI本体のVUしたせいかも」（187）

**LoRA学習のTips（詳細記載のまま）**
- ref2va 1f学習：Loraは画像・人物・背景・モーション全てに影響。参照画像との相性が超重要で近いほど効果高い。動きが重くなりがち。最初は学習jsonl方式がお勧め（249）
- V3焼成報告：学習Promptに背景と構図の説明を追加、Epoch 1.0前後から調整。参照画像との相性問題は未解決で、Lora使用時は学習素材に近い参照画像を引っ張ってくる（521, 700）
- 公開Baseが蒸留状態のため通常より学習が難しい。kohya氏も対応に苦労（876）
- 学習素材に近い参照画像しか引っ張れない性質、fl2vaは動くがモーションが遅くなる（587）
- 効果音も作れる（658）

**環境・速度検証**
- PRO6000 vs 5090：1MP20秒のT2Vで6000が280-290秒、5090が300-310秒。「MiniMax-H3で実用的に遊ぶならPRO6000はいらん」（514）。ただし1.2MPで5090はOOM（514）、学習にはVRAM32でも足りないという反論（518）
- 5080＋RAM128で1mp/10秒（808）。ただし「スペック以上に差がつく」（811）
- Attention Backend＋ブロックスパースアテンションで0.9MP 15sが90秒前後（881-883）
- 4060Ti(16GB)で0.6MP/30steps/12s/24→48fpsが18分。Comfy-kitchen Attention / Block Sparse Attention / Spectrum / Model Shift使用（888）。ただし「高速化設定は環境で変わり魔法ではない」（886, 900）
- kitchen attention＋sol attn tau1.00、ステ25メガピ0.9の15秒で13分弱（907）
- 5060ti+RAM32で0.5MPx2が250秒（967）
- H3対応エロ動画モデル比較：「MATLOWAI 実写神動き◎ アニメ△ 言う事も忠実／Dasiwa 素材の一貫性神 アニメ〇 言う事あんま聞いてくれない」（324）。MATLOWAIは公式fl2vよりサイズ小さいのに生成遅い（419）

**弱点**
- 物理的な関係を認識せず突っ込む先がズレる事例多発（700）
- 巨乳寄りの傾向。小さい胸のLoraでもかがむと谷間を作り参照画像で修正（673）
- 3D寄り化は高解像度・LoRA・あり3なし3程度でプロンプト追従性が落ちる（864, 866, 867）
- turboで最も劣化がキツいのはセリフ。喋らせずirodoriで作り合成が現時点の結論（933）
- 生成中に画像が突如崩れる現象の報告（878）

## 2. Qwen-Image 2.1 / QIE2.1

**選ばれる理由**
- I2I主体にはゲームエンドレベル。GPT Image画像→三面図化、マスクやマークアップ指示でI2I・Ref2I自由自在。GPTで20回近くお断りされたプロンプトが1発で通った（189）
- 5070tiで十分、15秒で差分生成。「2511時代は5090欲しかったけどもうええわ」（101）
- バッチ500枚で変な絵0枚（QIE2511時代は2割）（320）
- QIE2.1は「QIE2511の正統進化版」（679, 681）。「Qwen-Image2.1のi2iが実質QIEやで」（692）
- 2.1のターボloraが良い（92）

**Tips・欠点**
- Qwen Multiangle Cameraのlora抜きで方角指示プロンプトのみでもぐりぐり回せる。qwen image editは容量の邪魔（238）
- 肌のプラスチック感が欠点として指摘（319）
- プロンプトの効きは2511の方が良かったという個人評価（267）
- 公式プロンプトガイドはhgのQI公式・QwenLMにある（354, 396, 402）
- LoRAは80MB程度で軽い。前のQIは1GB超えもあった（599）
- 派生「Noct Q」は本家よりプロンプトがよく効く（613）。日本人サンプル不在への懸念には「参照画像使えるから極論なんでも出せる」（619, 625）
- 二次エロFTを待つ声（410）。ただしanima同等の版権&絵柄ありFTは「絶対来ないから諦めた方がええ」（411）
- 評価：「ZimageもQwenimageも軽くマスピ絵出せるチューン止まりで覇権二次モデルは来ない」（918、スレ上の評価）

## 3. anima

- wan2.2の方がプロンプト自由度・追随性が良い（i2v）（338）
