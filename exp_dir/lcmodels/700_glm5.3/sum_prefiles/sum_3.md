# レポート：なんJスレッドログ要約（427-627）

## 1. ハードウェア・環境

### GPU運用・ケース
- ミニタワーに5070tiでも問題なく動作。動画の「10連ガチャ」をしない限りは平気という報告（427）
- マルチGPU環境ではフルタワー＋140mm×3枚吸気で温度管理が楽になった。旧来の120mm×1枚吸気＋GPU1枚運用より快適（438）
- フロントファン交換・回転数アップで排熱改善した報告（430）
- 動画生成中に画面とGPUだけ落ちる症状の原因は、AfterburnerのFAN回転設定が固定になっていたことだった。自動設定に戻して解消（429）
- GPU真上のSSDが熱で識別できなくなることがあり、5分放置で復旧（563）

### iGPU併用・ヘッドレス運用
- 液タブをマザボ（iGPU出力）に接続しドライバとBIOS更新した結果、VRAM1GBほど浮いた（441）
- 生成専用モニタはマザボ側出力が推奨。ゲーム等GPUを使う時だけグラボに切り替え（448、454）
- iGPU＋RTX切替運用でVRAM800MB節約、OOMギリギリ時に助かるという報告（479）
- VRAM16GB環境では「800MB空けてOOM解決」する状況がまずなく、iGPU併用は面倒でやめたという反論（500）
- ブラウザはiGPU処理にしているユーザー（504）
- iGPU併用はCPU買い替え不要のケース（AM5持ち）に限るという見解（502）
- スレ上の注意：グラボのHDMI/DPに何も接続しないヘッドレス運用はNVIDIAはドライバで想定しているがAMDは想定しておらず、VRAMアンロード不全やドライバクラッシュが起こりうる。ダミーHDMIプラグで回避できるが1GBほどVRAMを消費（460）
- AMD→Intelという「変体」構成の両環境で問題が出まくっているとの報告（440）

### 熱・電力
- 「温度が80度以下ならPL100%で回し続けても平気か」という問いに対し、5090は16ピンコネクタの温度がソフトで計測できず、フル稼働時に600Wオーバー・90℃超えが確認されたという回答（623、627）

### VRAM自慢
- 「VRAM使用量の少なさで俺に勝てるやつはおるか！」に対し画像未添付で「俺の負けだ」（495、496）、「お前パラメータ数0.1Bなんか？」というツッコミ（497）

## 3. 動画生成・LLM

### MiniMax-H3ベンチマーク（スレ上の検証報告）
- TEやDiTが個別にVRAMに乗り切るならPRO6000とRTX5090の速度差は大差ない（514）
  - 1MP：20秒、MATLOWAIモデル6step、SLA0.85、T2VでPRO6000が280-290秒、5090が300-310秒。どちらもざっくり5分
  - この設定で1.2MPに上げると5090はSLA処理中にOOM
  - 結論：MiniMax-H3で遊ぶならPRO6000は不要
- 反論：大きい画像や動画で学習するにはVRAM32GBでも足りずレイヤーオフローディングが必要で、遅くなるためPro6000が欲しい（518）
- 5090はこれからの動画AIやLLMを考えると先が見えており、次は6000クラスという見解（516）。YouTubeのAI動画生成チャンネルでもPro6000が増えている（566）
- スレ上の見解：「Pro6000買えるくらい稼げるにはPro6000が必要。初手Pro6000が最適解」（589）

### LoRA学習
- minimax h3 ref2va 1f学習で成人向けLoRA V3を焼成。背景・構図の説明をPromptに入れ、Epochを落として過学習回避。参照画像との相性問題は改善せず。lora倉庫リンク共有（521、537）
- ref2vaが基本。fl2vaは動くが動画のモーションがめっちゃ遅くなる。kohyaのDocによると学習の流れが双方で異なる（587）
- MMH3の精液LoRA希望。素だとサラサラで少なく、エロチューンモデルだと過剰（602）。プロンプトで濃度調整可、civitaiでcumshotが上手い勢力が存在（606、617、624）

### ワークフロー・ツール
- comfyのvideo saveノードが遅すぎるため、CPUに処理を戻さないNVENC版save videoノードをCodexに作らせた結果、40秒→6秒（538）
- 3ヶ月ぶりにローカルAI環境を触ったら壊れており2時間かけて修復（493）
- LLMはVRAMに乗り切らないと遅いままかという質問に対し、「全部載せは毎回転送不要で速いが、一部転送でもそこそこ速度が出るようになった。但し最低限必要な容量はある」（509）
- 旧来の「VRAMにモデル全部収めなあかん」は情報が古いという指摘（506、507）

### ローカル vs クラウド
- ローカルはランニングコストで圧倒的。クラウドは動画生成の勉強だけで結構持っていかれる（529、532、534）
- パーツが去年の8倍高騰しているものもあり、ローカルがコスパいいかは疑問という反論（531）
- 現状、抜ける実用性のある動画生成は無理。動画は画像より要求される一貫性の高さがレベル違い（530）
- ローカル勢は超少数派。一般人にとってのAIはクラウドサービス。SD1.5からSDXL、ComfyUI、Animaと来た感覚はここ特有（525）
- NSFWだけがローカルの意義という意見（527）
- 「計算資源を貸すクラウド＋自前のNSFWモデル」の建前の案（533）に対し、モデルアップロードした奴がしょっ引かれそうという反応（535）

## 4. AIサービス・ツール

### Gemini / Codex / チャッピー
- Geminiの音声生成（TTS）が「エロ音声を作るハードルが地面に埋まったレベルで下がった」（485）。ただしエロ利用はチキンレースになり、大手TTSで素材を作りローカルで処理するのが最善という意見（588、590）
- Geminiで生成したものが健全なら外部ツールで参照利用可で、学習利用がNGという規約解釈（591）
- GoogleはYouTubeから学習し放題で音声が強い（501）
- チャッピー全体的にダウン、Codexも死んでいた（577-583）。OpenAI障害はお環ではなく復旧（582）

- Proプランはすぐ枯渇して5時間制限で止まらない点だけでアップグレードの意味がある（511）

### ゲーム制作AI
- 素人でもunity等でオリジナル3Dアクションゲームが作れるかという議論（512）。Benderでメジャー3Dゲームの雰囲気は即作れるが最上位モデルで鬼トークン消費、動かすとファミコン以下（571）。実装出来るとゲームが作れたは別物で、AIに脳みその中を見てもらえる時代までは無理という意見（573）。ゲームの面白さはテンプレ化できず学習困難という意見（574、575）

### 画像加工サービスの使用感
- Gemini：無料で100枚くらい加工できるが記憶力がなくアホ
- ChatGPT：無料23枚、GOプランで1日50枚くらい、品質はいい
- Grok：学習が2D/2.5D/3Dでごちゃまぜで指示が難しいが、課金すると動画も20-30とか通る
- 高画質化のローカル一括ソフトとしてTopaz PhotoAI（553、610）

### NivisViewer移行
- NivisViewerのタグはレート同様、ファイルに埋め込まずファイル名に埋め込まれる。ファイル読み込み不要、Zipplaのレート・タグ移行可能（433）
- タグ管理から同名を登録すればファイル名タグも認識される（594）
