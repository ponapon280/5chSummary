# 生成AIモデルに関するレポート

## 話題の中心・流行の推測

ログ内で**特に存在感が強いのは、画像編集・参照画像からの生成で評価されるQwen-Image 2.1系、アニメ画像生成のAnima、そしてNovelAI（NAI）**です。動画生成では**MiniMax H3**が繰り返し話題になり、Krea 2やWan 2.2も用途ごとの比較対象になっています。

ただし、これはログ内の言及の反復と具体的な使用報告からみた推測です。ログは話題を抜き出した断片の集合で、番号も投稿番号とみられるため、**モデルの一般的な人気や利用者数を示す定量ランキングではありません**。また、LLMやコーディング用途ではClaude／Opus、Gemini、Qwen系も話題に上りますが、画像・動画生成の話題とは別の傾向として捉えるのが適切です。

## 1. 画像生成：用途と安定性を重視

### Qwen-Image 2.1／Qwen-Image Edit系
ログでは、I2I・Ref2I、画像内の部分修正、ポーズ変更、差分生成など、**画像を編集・加工する用途**で高く評価されています。なかでも「大量の画像をまとめて処理しても失敗が少なかった」「5070 Tiで十分」「短時間で差分生成できる」といった報告から、品質だけでなく、安定性や処理効率も選ばれる理由になっています。

一方、別の比較では、画質はきれいでも、プロンプトの効きや目的の実現しやすさは旧版の方がよかったという声があります。肌の質感などへの疑問もあり、評価は用途や比較対象によって異なります。ログでは「Qwen-Image 2.1」と「QIE 2.1」の呼び分けに揺れがありますが、現行の公式説明ではQwen-Image-2.1は生成と編集を統合したモデルです。([qwen.ai](https://qwen.ai/blog?id=qwen-image-2.1&utm_source=openai))

### Anima
Animaは、**Baseモデルのまま使えること、絵柄の安定性、LoRAの作りやすさ**が選ばれる理由として挙がっています。NAIで絵柄が安定しなかったためAnimaに戻ったという比較や、好みの画風を派生モデルと画風LoRAで調整しているという例もあり、日常的なアニメ画像生成の選択肢として定着している様子がうかがえます。

ただし、指示への追随性ではWan 2.2に及ばないという比較や、三コマ構図など苦手な用途の報告もあります。2.9B・3.8Bをめぐっては、性能向上への期待と、モデルサイズ・生成速度・LoRA互換性への懸念が並行しています。したがって、ログ上では「有力な定番候補」ではあるものの、モデル更新や派生版を含めて選択が揺れている段階とみられます。

### NovelAI（NAI）
NAIは「強さを感じる」「良い」といった肯定的な評価に加え、**日本語と独自のタグ表現を混ぜやすいこと、位置指定のしやすさ、インペイント**が利点として挙がっています。Krea 2で仕上げると高解像度でも塗りの潰れが減ったという併用例もあります。

一方で、枚数制限、位置指定のばらつき、絵柄の安定性、小物描写などには不満や課題もあります。NAIだけで完結させるというより、用途に応じて他モデルやインペイントと組み合わせる使い方も見られます。

### Illustrious
「リアス」の略称で話題になり、使用例やLoRA互換性の議論があります。生成結果がプロンプトだけでなく**解像度・アスペクト比にも左右されやすい**という評価や、Animaに比べて自然言語での表現幅が限られるという比較もあります。ログからは、強い支持理由が明確に語られているというより、既存の選択肢として使われている印象です。

### Krea 2、FLUX、Z-Image／Ming-Image
- **Krea 2**は、スタイルや背景の表現、スライダーによる調整が評価されています。実写系・動画素材向けに使う例がある一方、編集で狙った部分以外も変化する、版権キャラクター用LoRAの扱いが手軽でない、という課題も挙がっています。
- **FLUX**は、ログでは容量やVRAMの質問が中心で、性能評価や回答はありません。14GBという数字だけではモデルの種類や量子化方式を特定できず、12GB VRAMでの可否もログからは判断できません。
- **Z-Image互換とされるMing-Image**は、LoRAが動くことやデザイン能力への期待が話題です。ただし、Z-Imageの派生・ファインチューンであるという点はログ中の推測で、確定情報として扱うべきではありません。

## 2. 動画生成：制御性とワークフローが評価軸

### MiniMax H3
動画生成では、H3への言及が多く、**画像参照からの動画化、LoRA、高速化設定、アニメ表現**などが議論されています。画像を作ってからH3で動画化する手順や、用途を絞ったLoRAで特定の問題を解決する考え方が紹介されています。

一方、カメラが回り込んだ際に新しく見える情報、人物同士の位置関係、衣服や身体の描写には破綻の報告があります。LoRAの効きが強く、画風や動きも変わるため、意図どおりに制御するには設定や素材の調整が必要という評価です。音声・セリフについては別のTTSモデルと組み合わせる案も出ています。

### Wan 2.2
Wan 2.2は、**プロンプトの自由度や指示への追随性**がAnimaより高いという使用感が示されています。静止画からの動画化でAnimaでは難しかった動きを実現できた、という比較もあります。一方、アニメ表現ではリアルな三次元寄りになりやすく、不気味の谷に入るという報告もあり、表現スタイルが選択理由に影響しています。

### Seedance、Viggle AI、MATLOWAIなど
SeedanceとViggle AIは用途の違いが語られ、**オリジナル人物・動画にはSeedance、既存動画の人物置き換えにはViggleが手軽**という使い分けが紹介されています。価格が利用の障壁になりうるという見方もあります。MATLOWAIは実写の動きや指示追随性が評価される一方、生成速度への不満もあります。

## 3. LLM・作業支援モデル

画像・動画生成とは別に、コーディングや日常作業では以下の傾向があります。

- **Claude／Opus**：仕様書からのコーディング、複雑な改修、業務文書などに高い期待が寄せられています。Opus 5.5については、ログ中ではX上の評判が言及されており、具体的な利用体験は限定的です。
- **Gemini**：会話や指示文の整理、簡単な質問、TTSなどで使いやすさが語られています。一方、プログラミングや大規模改修ではClaude／Codexより弱いという比較があります。
- **Qwen系LLM**：ローカル運用によって、費用を抑えながら試行錯誤しやすい点が利点として挙がっています。ただし、モデルサイズによる速度やVRAMの要求が導入上の課題です。
- **Gemma 4**：画像キャプション用途では、パラメータ数だけでなく量子化精度も実用上の重要な要素だという報告があります。ログ内では、高精度量子化した12Bが低精度量子化の26Bより有用だった例が紹介されています。
- **Codex**：強い利便性が評価される一方、リモート操作中のマウス競合など、作業環境との相性が課題として挙がっています。

## 4. 選ばれる理由の共通パターン

ログ全体からは、モデル選択が単純な「画質の高さ」だけでは決まらず、次のような実務的な条件に左右されていることが読み取れます。

1. **目的に合うか**：画像編集・参照画像活用ならQwen-Image系、アニメ画像ならAnimaやNAI、動画ならH3やWanなど。
2. **出力が安定するか**：大量処理での失敗の少なさ、絵柄の一貫性、ポーズや編集範囲の維持。
3. **環境内で動かせるか**：VRAM、モデル容量、生成時間、手元のGPUでの実用性。
4. **調整しやすいか**：LoRA、インペイント、マスク、参照画像、スライダーなどの支援機能。
5. **利用上の負担が許容できるか**：サブスクリプション、生成枚数制限、料金、ワークフロー構築の手間。
