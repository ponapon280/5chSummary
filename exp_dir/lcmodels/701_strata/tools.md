## 1. ComfyUI（ワークフロー運用・カスタムノード・VRAM管理）

### 1-1. カスタムノードの自作とAIエージェントへの依頼

スレでは「comfyuiで使うカスタムノードは有名どこ以外はたいてい自作ノードに切り替えてる」「ちょっとした機能追加ならどんぴしゃなの探しにいく手間もはぶけるし一度作れば作ったもの同士で連携も楽」という運用が報告されている（>>619）。CodexやClaude Codeに「使えるようにカスタムノード作って！」と依頼する流れが複数箇所で見られる（>>637, >>633, >>655）。>>633では「claude codeなりcodexなりに繋がってる以上 欲しい拡張は自分で作るし、他から輸入してくる時もURL投げて『やれ』やね」と、外部ノードの導入すらAIに委ねる運用が語られている。

>>673では「違うワークフロー用意して呼べばいいだけ。大半はAIが要求満たすワークフローを作ってくれる。必要な入力部分やワークフローごとに大差なく、大半はスイッチのON/OFFでしかない。AIからしたらお手の物」と、ワークフローの差分が本質的に小さいことが指摘されている。

>>390では、Claudeに作ってもらったsave videoノードが「1MP20秒の動画」の保存処理で「38秒かかってた変換保存の処理が6秒になった」と報告されている。comfy公式のsave videoノード（MiniMax-H3テンプレに入っているもの）は「色んな変換を全部CPUでやってるから遅い」ことが原因とされている。VHS（Video Combine）のNVENC変換項目も「処理のごく一部しかGPUに渡してない」ため「ごくわずかしか速くならん」と評価されている（>>390）。

>>614では「ComfyUI的な部分全部自作してるな 生成部分はDockerで環境隔離したPythonで、WebUIはTypeScript＋Reactで作って、認証つけたうえでCloudflare tunnelで公開して外スマホからでも好きな音声やら画像やら生成できるようにしてる」「機能追加は『新しく出た◯◯のモデルのダウンロードと新規のワークフロー良い感じに作って』とか言うだけだからむしろ楽だ」と、ComfyUI自体を置き換える方向の事例も報告されている。>>622では「AIにwebuiを自作させられるならエンジン部分も簡単に自作できるで Comfyを起動する必要がなくなる」と補足されている。

### 1-2. ComfyUIをLLM/AIに操作させる運用

>>621「最近面倒で全部LLM にComfyui とか操作させてるわ」、>>616「ComfyのAPI叩かせる感じでLLMから操作できるUI用意してるし、Viewerも自前で用意したりで楽しくやれてる」、>>617「irodori使ってLLM自作webuiでロールプレイで喋らせるのが最高 comfyuiは立ち上げてるだけ」と、ComfyUIを「エンジンとして起動しておくだけ」で操作はLLM側で行う運用が複数報告されている。>>625では「色々組み合わせるならComfyUIを基盤にするのが正解やな」と基盤としての位置づけが確認されている一方、>>626では「ComfyUIをWebUI化しとるニキらはWF変更したい時とかどうしてんの？」とワークフロー変更の運用面での課題が投げかけられ、>>627「AIに依頼するんやないか」、>>629「大半はWF固定なんやないか ワイはWFに合わせて柔軟に変えてたけど少数派だと思う」と応答が分かれている。

### 1-3. VRAM・メモリ管理と動画生成の制約

>>359では「動画生成が2時間経っても終わらない。タスクマネージャーでPythonがGPU99%使ってるのに電力消費は非常に低いで温度も50℃未満」と報告され、>>360「スワップ見た？多分メモリから漏れてSSDまで使ってるぞそれ」、>>379「モデルウェイトをVRAMに転送（スラッシング）してるときでも99%行く。繰り返しの生成によるVRAM領域の確保と解放の繰り返しでVRAMの連続した空きが分断されて実際に使える領域が小さくなってたんちゃうか。そうなったらあきらめて再起動せい」と原因の推測がなされている。>>380では「高速化してStep数下げたら同じ解像度フレーム数で20個くらい連続でやってもその現象起きなくなった（Step下げる前は5個くらいで発生してた）。素直に設定下げる方法探したほうがいい」と対策が示されている。

>>366では「ComfyUIがRAMを節約して使うようになってから、35個動画作るたびにブラウザリロードしないと生成進まなくなった（VRAM100% RAM60%で動かない）」とRAM節約モード自体が問題を引き起こしている事例がある。>>388では「VRAM節約系カスタムノード使ってモニタ出力を別の駄グラボに任せたらなんとかなった。16GB勢やけどVRAM削りに削って1MP15秒までは滞らないようになった。1.1MPはダメ」と、補助GPUへのモニタ出力オフロードが有効だったと報告されている。

>>345では「動画生成に参照画像増えるとめっちゃ時間伸びる。4個まではそうでもなかったけど7個でやったら終わらん」と参照画像数と生成時間の関係が報告されている。

>>384では「VeteranAIのFastH3 WF」について「つなぐだけで同じ設定で1stepあたり60秒から40～50まで減った。多分Step下げるよりこっちのほうが効いてると思う」とワークフロー移植による高速化が報告されている。>>386では「5070tiだから高速化が40番台で機能するかはわからん」とGPU世代による制約が指摘されている。

>>383では「4070Tisで0.6MP 15秒で結構頻繁にこうなってた。MPはこれ以上下げたくないし短くして繋げるしかない」と解像度と生成時間のトレードオフが語られている。

### 1-4. フロントエンド・ノードのバージョン問題

>>708ではComfyUI 0.38更新後に「ブラウザにwebpをドロップしても『ワークフローが見つかりません』となり、画像に保存されているワークフローが読み込めなくなった」と報告され、>>714で「原因はフロントエンドと特定。ComfyUI_frontend v1.53.6 → v1.52.7にダウングレードすれば読み込める」と特定されている。>>874では「frontendは相変わらず1.52.7使い続けてるわ 1.53.6はFast Groups Muter/Bypasser (rgthree)でtoggleRestrictionをalways oneまたはmax oneにしても効かないのよね いろいろ切り替えて遊びたいワイには致命的」とrgthreeノードとの不整合が報告され、>>944で確認されている。

>>208では「ComfyUI を 0.35→0.37 に上げたら minimax の ref が 100秒くらい遅くなった」とバージョン更新による性能劣化が報告され、>>212で「何かしらの高速化ノードが足を引っ張ってそう」と推測されている。

>>337では「`nodes/sampler.py` の `if self.has_prompt_changed(text):` でプロンプトの更新がかかるようになってたからここを消し飛ばしたら動くようになった」と内部コードの修正で動作が回復した事例がある。

>>568では「V4だとComfyUIのIrodori Model Loaderでエラー出たから 標準のはv3、VoiceDesignとCharacter Voiceはv2にしたらうまくいった」とモデルバージョンとノードの互換性問題が報告されている。
