# 掲示板ログレポート（レス435〜639）

## 1. Irodori TTS の実用状況とモデル選定

- **v4 small が実用レベルで安定**しているとの報告が複数。工夫なしで「毛根基準」で出力可能（598）。画像生成と比べて導入が軽く一瞬で生成できる（564）。
- **VRAM12GB環境での推奨**：irodori-tts v4 small（557）。VRAM10GBでもSmall+Large両方をint8で導入可能（559）。
- **Largeの位置づけ**：参照音声少なくても再現性が高いが、結局参照音声を増やせばSmallで足りる（559）。
- **参照音声の重要性**：v4以降長く参照を突っ込めるようになり、ASMRから喘ぎ・囁き・チュパ音等を切り取って渡すと演技の幅が広がる（593）。10秒程度の色んなパターンを大量に繋げるのが良さそう（605）。
- **参照音声の音質が命**：irodori単体では音質が気になるため、Gemini TTSで参照音声を作りirodoriに参照させる方法が有効（558, 576）。
- **ComfyUIでのv4導入エラー**：Irodori Model Loaderでエラーが出る。標準はv3、VoiceDesignとCharacter Voiceはv2にすると動く（568, 604）。
- **絵文字TTS**：このスレのニキが公開したirodoriTTSのフォーク版で、感情表現を絵文字で出せるようにしたもの（565）。元からある機能との指摘もある（575）。
- **クラウド型TTS品質向上によりIrodoriの重要度が下がっている可能性**（435）。

## 4. ComfyUI / 画像生成ワークフローの技術話題

- **アスペクト比問題**：ComfyUIテンプレのワークフローで縦横ピクセル数が32の倍数に調整されアスペクト比がおかしくなる。入力画像を32の倍数にクロップするか、出力を入力と同じサイズにリサイズすれば正しくなる（448）。
- 入出力完全に一致させても微妙にずれる（言われんと気づかんレベル）。DiT変えても結果は変わらんかった（482）。
- 解像度を変えてタイルの数が増えると生成時間が延びる（471）。
- **QIE2.1**：背景だけ編集はまだ苦手。服装を変えるのはなかなか良い（454）。ピクセルシフト対策版（QIE2511）を取っておいた方が良さげ（609）。ピクセルシフト修正LoRAあり（613）。
- **Qwen Image 2.1 アニメ特化版**：Anime-Uncensored-Qwen-Image-2.1、Qwen2.1_Anime_consistency（LoRA、実験段階）（628）。Noct-Q-Anime-Uncensored-Qwen-Image-2.1（アニメ特化NSFW学習版）（632）。
- **Minimax H3**：H3 Eros Max + Mystic XXXでそこそこ出来ている（536）。糞出せるか不明（520）。
- **Wan2.2**：smoothMix vs Remix_NSFWの比較中（488）。DaSiWaかブチギレが正解との指摘（537）。
- **Anima**：Animerge更新、Anima2.9B完全対応。AnimaBase v1.0で気に入ったモデルを2.9B/3.8Bへマージ可能（509）。Krea2リアル系からH3より、Animaアニメからreal-life付けたH3の方が出来が良い（579）。
- **Krea2**：乳七段活用（minute, tiny, very small, small, medium, large, huge）（529）。gitantic忘れとる（530）。hug, gigantic, enormousにincredibly付けるとめちゃくちゃデカくなるモデルもある（540）。
- **量子化済みモデル**：Qwen3.8 104GB + PLE27GB、VRAM128GBで動かす話。5090では不可能なレベル（570）。Flash Nextなら5090で余裕（574）。
- **forge-neo**：Resolution Stepデフォルト64 vs 8刻みの比較（538）。
