なんJ風スレ（おおよそ >>842–>>1000）の要約レポートです。主題はローカル動画生成（MiniMax H3 / WAN / Context Loop 周辺）で、途中からツール不具合・モデル比較・雑談に散らばっています。

## 全体像

長尺・高解像度の動画生成でVRAM/RAMが足りない、品質を落とさず速くしたい、シーンをどう繋ぐか、という実務話が中心です。スペック自慢と「数字だけ速くしても品質が落ちたら意味がない」という対立が繰り返し出ます。エロ生成が前提の書き込みも多く、技術話と用途話が混線しています。

## 1. 長尺生成とOOM

- 起点は「5090で1MP・20秒、参照画像4枚を重ねるとOOM。回避するとメインメモリに逃げて激遅」という相談。
- 対処として挙がったのは次のとおり。
  - **refmods** を使う
  - **Context Loop / Extender** で短い動画を繋ぐ
  - 1シーンは **5秒前後** にし、プロンプトで「前のカメラ／シーンを続けろ」と書いてガチャを回す
  - 20秒を一発生成するのは、歩くだけなど失敗しにくい動きに限る、という意見
- 長尺そのものに必要なスペックは「15秒以下を1本出せる分」で足り、あとは繋ぐだけ、という整理も出ています。
- 反対意見として、Context Loopで1分超にすると **20秒付近で動きの再放送（ループノイズ）** が出るので、結局バラ生成して編集で繋いだ方がきれい、という報告あり。
- メモリ増設（グラボ据え置きでRAM 96GBなど）や、`--fast-disk` / `--disable-pinned-memory`、モデルはbf16より **int8** 寄り、という節約策も共有されています。
- 補足として、最近のComfyUIはモデル置き場がNVMeかを自動判定するようになり、`--fast-disk` は古い呪文になった、という指摘あり。環境によっては `--disable-fast-disk` 側が効く、とも。

## 2. MiniMax H3 の速度と品質

速度報告は環境差が大きく、比較になっていない、という不満が目立ちます。

| 報告例 | 条件の目安 | 時間の目安 |
|---|---|---|
| 高速設定寄り | 0.9MP / 15秒 | 約90秒、別報告では約60秒 |
| 品質優先 | 4060 Ti 16GB、0.6MP / 30steps / 12秒 / 24→48fps | 約18分 |
| 中間 | kitchen attention + sol attn、25step / 0.9MP / 15秒 | 約13分 |
| 低VRAM | 5060 Ti + RAM 32GB、0.5MP×2の10秒 | 約250秒 |

品質を落とさない前提で挙げられていた設定要素は、Comfy-kitchen Attention、Block Sparse Attention、Spectrum、Model Shift（ModelSamplingMiniMaxH3）。一方で「Spectrumはダメだった」「高速化の差が体感できない」という声もあります。Turboはセリフ劣化がきつい、という評価が複数あります。

延長は現状 **Context Loop が事実上の答え**、既製動画も延ばせる、という整理。一気に90秒級を出したい派とは温度差があります。

## 3. 画風・LoRA

- H3のLoRAはピンポイントで強く、悪影響も大きい、という感触。公開Baseが蒸留済みで通常LoRAより難しい、kohya氏も対応に苦労している様子、という情報。
- 強度を下げると（例: 0.3付近）急に2Dアニメ寄りになり、乳揺れなどとのトレードオフ、という報告。
- 高解像度にすると3D寄りになるのは学習データ（トゥーンレンダのゲーム動画など）の影響では、という推測。
- WANはリアル3Dが混ざる、H3は3Dアニメが混ざるが、アニメ適性はWANより明確に上、という比較。
- ローカルLoRAは素材・epoch・強度とも手探りで、学習の試行錯誤自体がPC性能と素材の壁になる、という総括。クラウド（Google AI ProのA100）を試す案も出ています。
- 別件で「上の画像が2–3秒後に突然崩れる」症状の情報募集あり。解決報告はこの範囲では見当たりません。

## 4. モデル比較（画像側）

- **Krea2**: 画は良いが版権キャラを学習していないのが弱点。wildcardで版権シチュを量産できない。キャラLoRAもAnimaほど手軽ではない。
- **Anima**: 最初から版権対応している点が優位。ユーザー側のガッツリFTで覇権二次モデルを作る時代はSDXLで終わった、という見方。
- Z-Image / Qwen-Image 系は「軽くマスピ絵を出せるチューン」止まり、という評価。
- Grok Imagine が少し上がったのでは、という比較投稿（対 Qwen-Image-2.1、動画は対 MiniMax H3）あり。エロ動画を再び解禁してほしい、という要望も。
- プロンプト作成は Codex → 制約回避のため Grok に渡す、という運用が推奨されています。Codexはエロにうるさい、という前提です。

## 5. 環境トラブルと回避

- **Pythonが固まる**: NVIDIAドライバをStudio最新から Game Ready 596.49 に変えたら直った、という報告。その後再発し、再解決には至っていません。
- **Forge Neo + Spectrum integrated**: 生成途中で画像が壊れる。原因は適当な自然言語の補足プロンプトで、文章を整えたら直った、という自己解決。
- **Codex**: コマンドのたびにターミナルが一瞬出る不具合（ダウングレードしても直らず）。許可確認がうるさい問題は、起動オプション（`--ask-for-approval on-request --sandbox workspace-write`）、プロジェクト単位のフォルダ許可、sandboxユーザーの権限戻しで緩和、という手順共有。`.codex` と作業フォルダの CodexSandboxUser をフルコントロールにしたら自動承認のブロックが消えた、というWindows報告あり。電話番号要求で入れなかった、という遅参者も。
- **WSL操作ミスで safetensors 約800GB 削除**。バックアップがなければ復旧不能、カスタムノード自動取得分は中身すら不明、という事故報告。`find` の一括処理への注意。
- カスタムノードの遅い処理をCPUからGPUに移して高速化した、という成功例。

## 6. ビューア開発のやりとり

SVGサムネイルが出ない不具合の切り分けが続いています。

- 原因例: 宣言のない `inkscape:` 属性で、描画前のXML解析が止まる。
- Illustrator出力SVGはサムネイル可、Inkscape製は不可、という切り分け。
- ブラウザで開かず「リンク先を保存」しないと壊れる、というアップロード側の注意。
- 要望: 設定文言を「AI画像」ではなく「Illustrator(.ai)」と明示、Escでビューアを閉じる、フルパスのコピー。
- 開発側の返答: 新ビルドでサムネイル改善。閉じるは Ctrl+Q/W（Escはフィルタ解除に使用済み）。フルパスは Shift+C。マウスジェスチャ（右クリック+下で閉じる、上で全画面）を推奨。不具合はリポジトリの issue / discuss へ、という案内。

## 7. スレの空気

- スペックを書かない速度報告は参考にならない、PRO 6000×2 + DDR5 512GB 前提で読む、という皮肉が定番化。
- 「成果は動画を貼れ」「見かけの秒数は品質を犠牲にすればいくらでも縮む」という品質派が優勢。
- 用途は抜き用途の短尺（10–15秒で足りる）と、シーンを盛りたくなる長尺欲の両論。セリフは別ツール（irodori等）で作って合成、リップシンクは未解決、という暫定結論。
- 終盤は障害者向けクーポン（高額PCの割引）への反応で脱線し、障害や生活保護めいた境遇への侮蔑が目立ちます。技術情報はほぼありません。

## 実務メモ（この範囲から言えること）

1. 20秒・1MP・参照複数は、ハイエンドでも一発生成より **短シーン分割＋接続** が現実的。
2. 接続は Context Loop が有力だが、長尺だとループノイズが出るので、編集接続と使い分ける。
3. H3の高速化は環境依存。秒数だけを比較せず、解像度・steps・最終画をセットで見る。
4. H3 LoRAは効果が強く副作用も大きい。蒸留Base前提で、強度と画風（2D/3D）のトレードオフを小さく試す。
5. VRAM不足時は量子化とディスク／ピンメモリ系オプション、RAM増設が先。呪文の有効無効はComfyUI版で変わる。
