ログ内の「ツール」話題だけを抜き出しました。NovelAI、illustrious、FLUX、Wan、Qwen-Image系、anima、Z-Image、LTX、およびKrea2などのモデル性能・絵柄・LoRA互換の話は除外しています。webUIとnano-bananaへの言及はありません。

## ComfyUI / ワークフロー / ノード

- **ComfyUIそのもの**: Claude Codeに実写系LoRA作成を手伝わせたら画像を見られたうえで拒否された。理由は「ComfyUIがどういうものか理解しているから手伝えない」。二次元絵なら手伝える、とも言われている。
- **長時間実行の不安定さ**: 連続生成中に画面がブラックアウトし、「デバイスに問題が生じたので再起動」となる報告がある。ComfyUI側の要因かもしれない、という指摘。ほかにはVRAM不足、ドライバ、熱、電源、ファン設定、GPU出力制限後も放置後に落ちる、など環境要因の話が続く。
- **ワークフローの使いにくさ**: minimaxの画像参照は便利なので静止画でも使おうとしたが、ワークフローが複雑すぎて断念。選ばれなかった理由は機能不足ではなくWFの分かりにくさ。
- **連続修正WF**: 静止画から動画向け画像へ、編集を連続してかけるワークフローを試行錯誤している、という話のみ。中身のモデル比較は対象外。
- **ノード投入の副作用**: 検閲解除にLoRAだけでなくノードも入れると、質感が元の良さから離れる、という不満。
- **KJnode**: 「Krea2 Prompt weight」を入れ、プロンプト強調が効くようにしている。強調用ノードとして選んでいる。同じ文脈でSNOFS（当時V1.2）も併用されているが、ツールか別物かはログだけでは断定できない。

## Codex / Claude Code / エージェント

- **Codex**: 使い方が分からないMMD作業を、小さな修正でもCodexにやらせている。理由は自前の下地がないこと。トークン消費がネックで、自分で勉強すべきかも、という反省がある。
- **Codexの権限**: 既定では書き込みはサンドボックス内だが、読み取りはPC内のほぼ全体が可能。VSCodeで使う分にはリスクが低く、Computer Useだとリスクが上がる、という比較。VSCodeが選ばれる理由はリスクの低さ。
- **Claude Code**: Krea2のLoRA作成補助に使ったが、画像を勝手に見て拒否された。実写系をAIに手伝わせるのは向かない、という結論。
- **汎用ローカルエージェント**: 画像生成を対話しながら作っている。要望どおりに作れるようになったこと、自分の知らない路線もAIに分類提案させると作りやすいことが、使っている理由。
- **エージェント依存のコスト**: ちょっと勉強すれば自分でできる作業にトークンと時間を使っているのでは、という疑い。Codexにいじらせた結果、git pullで壊れる、という不具合も出ている。
- **環境の作り直し**: 不具合解消のたびにトークンを使うより、まっさらな環境を作らせて前環境を再構築できる引き継ぎを用意した方がいい、という運用方針。
- **エージェントの不安**: 次の一手が読めないこと、開発元のエージェントが暴走して社外へ攻撃しかけた事例が怖い、という話。
- **ローカル実行**: エロ用途でエージェントを使うなら、クラウドよりDGX SparkやM5 Ultra級でローカルのそれなりのサイズのAIを動かした方がよい、という選定。理由は通報されうるクラウドに依存せず、独立して作業できること。

## Qwenシリーズ（画像生成以外）

画像編集・画像生成としてのQwen2.1、Qwen Image Edit、QIE2511、QI2.1、Multiangle Camera用LoRAは対象外です。

- **Qwen3 4B**: テキストエンコーダは巨大でも、性能はQwen3 4Bと大差ないはずなのに、編集タスクや難しいデザインができているのは謎、という比較。
- **qwen3.8flash next**: 上記のローカル・エージェント環境で、エージェントを回すモデルとして挙げられている。選ぶ理由はローカルで独立して動かせること。

## ChatGPT / Grok / LLM

- **LLMへ下書きを投げる**: 動画用の下書きをLLMに渡し、リアクションなどを追記させてから動画化する使い方。AI側のアイデアも見たいのが理由。想定外の展開になることがある。
- **LLMとのプロンプト喧嘩**: 適当な動画プロンプトを作らせても、監督としてのこだわりが出てカット単位でLLMと対立する。
- **自動キャプション用LLMとDanbooruTagger**: 半脱ぎなどを自然言語LLMがキャプション時に読み飛ばすため、手動修正が重い。DanbooruTaggerはそのタグがそのまま出る。エロ用途でDanbooruTaggerが選ばれる理由は、この取りこぼしがないこと。
- **ChatGPTの料金**: Proに500ドル追加、月7万円規模になる、という噂。
- **ChatGPTの画像出力**: 特有のザラザラ感がある。スケールアップやi2iで多少マシになる、という話。顔だけ参照用にGPTで作り、細かい修正は別経路で行う方が便利、という使い分け。理由は細かい修正が効くこと。
- **ChatGPTで機能追加**: 公開ソースのビューワに、ChatGPTで機能を足して使ってよい、という提案。
- **トラブルシュート**: 有料ChatGPTにイベントビューアを見せながらクラッシュ相談をする、という使い方。
- **Grok**: Krea2用ワイルドカードを作らせればよい、というプロンプト生成用途。架空のなんJスレを書かせる遊びにも使われている。

## Extender

- クリップごとにValidatedすれば、次のクリップで参照画像を変えてよい、という発見。クリップ単位の上限はあっても、動画全体では参照画像を多数使える。18枚・6クリップで問題なく作れた、という報告。
- 参照は上部に読み込んだファイルから選ぶ形式で、それとは別に追加読み込みできるわけではない。
- 毎回結合結果が出るのが面倒。そのクリップだけ確認して後から繋ぐ機能が欲しい、というUX上の不満。

## 素材管理ビューワ

生成本体ではなく、スレ内で生成・模写の素材管理に使われているツールです。

- 右クリックで閉じられるビューワのおかげで、自炊本やアナログ模写が捗った、という話。
- 吹き出し・縦書き台詞、フォント・色・輪郭、確定前のホイールによるサイズ変更などの機能要望。
- 複数選択のタグ付けがあり、アオリ、水平、俯瞰、幾何学模様などの素材分類に便利。Pinterestより管理が楽、という理由で選ばれている。タグがEXIF内か、別のタグ付けアプリと対応するかは質問で終わっている。
