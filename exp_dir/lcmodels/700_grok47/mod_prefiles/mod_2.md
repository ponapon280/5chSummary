## NovelAI（NAI / V5）

- **揺れ表現**: afterimage と motion blur を入れれば自然に揺れる、という助言。
- **V5の評価**: パンツ描写のレベルは高い、という短評。一方で小物描写にはまだ課題がある、という指摘。
- **胸サイズ**: large breast では物足りず、huge にすると急に大きすぎる。中間が出しにくい。
- **構図・サイズの一貫性**: 通常生成だと指定サイズに断面図側が勝手に合わせてしまう、という不満。inpaintで調整している。
- **絵柄の安定性**: 1ヶ月試したが絵柄が安定せず、最終的に anima に戻った、という離脱理由。
- **熱量の低下**: 以前の驚き勢が消えた、という観測。使ってみると期待と現実の差を理解する、という見方。
- **V5の陰毛**: pubic hair が VIO 扱いになりやすい、という不具合談。
- **選ばれている／残している理由**:
  - 日本語と Danbooru 系タグ（「部族語」）を混ぜられる。
  - 位置指定が簡単（ただしガチャ要素あり）。
  - Opus なら inpaint が無料。
- **不満で放置されがちな点**: 枚数制限がきつい。ポーション（生成枠）と参照機能が来ていない、という待ちの空気。ポーションが来るまで放置でよい、という意見。

## illustrious（リアス）

- **エロでの制約**: タグ縛りだとできることが限られすぎる、という否定的比較。突破して話題になったのは anima 側、という位置づけ。
- **LoRA互換**: Illustrious 製 LoRA は 0.12.0 で互換がある。理由は「全バージョンを公式が出しているから」。anima の 1.0 / 2.9B / 3.8B 非互換と対比されている。
- 直接の「今これを選ぶ」理由はほぼなく、比較対象としての登場が中心。

## Wan（wan2.2）

## Qwen-Image（Qwen2.1 / QI2.1 / Qwen Image Edit / QIE2511）

- **Qwen2.1の画質**: 綺麗。ただし「やりたいこと」は 2511 の方がプロンプトが効いていた、という逆転評価もある。公式プロンプト術を見ていないのでは、という反論。

- **パイプライン**: anima-edit → qwen-image-edit → minimax h3-edit の連続修正に組み込まれている。編集段として採用。
- **TEの話（>>233）**: TE は巨大なのに性能は Qwen3 4B と大差ないはずなのに、編集も難デザインもできる、という謎、として Qwen 系が引き合いに出されている。

## anima（公式Base / 2.9B / 3.8B / 各種FT）

話題の中心。選ばれる理由と、版の分裂が両方ある。

**選ばれている理由**
- 普段使いの定番になっており、新しく語ることが少ない＝空気のように使われている。
- 公式 Base が強く、SD時代のような「新版が出た」盛り上がりが起きない。LoRA が作りやすく、新キャラは自作した方が早い。
- タグ縛り（リアス的制約）を突破したモデル、という位置づけ。
- NAI で絵柄が安定せず戻ってきた先。
- 画風が気に入ったFTでなければ Base で十分、という結論が多い。hakushimix 系で画風がほぼ完結、という個人例。botan_anima でローカル環境が一段落、という例。
- 動画向け静止画の前段として anima-edit がパイプラインに入っている。

**不満・比較で負けている点**
- ガチエロでは Anima も H3 も微妙。
- wan2.2 の方がプロンプト自由度・追随性が上で、i2v では anima が再現できないことをやられる。
- 公式が動かないことには先がない、という待ち。

**2.9B / 3.8B**
- 3.8B はモデルも TE も生成速度も重く、普及は見込めない、という見方。
- 2.9B が主流になりそう、という意見と、すでに完成しているのでその可能性はほぼない、という反論が併存。
- 2.9B のメリットが体感できない、という声。製作者が移行しているなら効果はあるのでは、という推測。
- 2.9B は P1 プレビューで、完成すれば「最新知識＋タグ＋自然言語」の立ち位置を取る予定、という説明。2026年中にカットオフ更新が期待できる数少ない枠、という期待。
- 評価いまいちで終わった 2.9B の話題が再燃している、というメタコメント。
- Base 製 LoRA が 2.9B で使えないなら移行は面倒、という実用上の障害。使いたければ Base で使えばよい、対応スクリプトもある、という反論。
- 1.0 / 2.9B / 3.8B は階層数・対応層・規格が違い互換がない。非公式版を公式っぽい番号で出していることが混乱と「ブランド乗っ取り」批判の原因。公式 anima2 が出せなくなる、という指摘。
- 「背乗りanima（TE増量）」は情弱、という強い否定。公式自身が TE 巨大化はあまり効かなかったと言っている、という伝聞。
- 試されたFT: AnimaYume 1.5（大規模FT）、Kirazuri Animav4（高解像度・画質/スタイル）、Light Lavender（自然言語理解）。変化は分かりにくいが地道に進化している、という感想。
- 援助がなければ次は作らない、と公式が言っている、という伝聞。次が別ベースなら LoRA は作り直し、という見方。

## Krea2（Krea）
このログで最も具体的に「使い分け理由」が出ているモデルです。

- **選ぶ理由**: 動画の素材にするなら背景力が圧倒的（325）。サイズ系はプロンプトのニュアンスよりスライダーの方が確実で、スライダー自体も優秀（385, 387）。エロを弱めにしたいなら公式のまま二次絵と実写の混合も出せ、そこにMystic等のエロLoRAを足す、という使い方（326）。
- **選ばない／限界**: エロ表現だけなら部族語モデルの方が上、という対比（325）。Danbooru語は効かず自然文必須で、clothes lift・skirt lift・panties pullの同時指定は失敗（278）。プロンプト追従が強すぎて、一語直すと他の細部まで変わり、大量生成のポーズガチャもできない（363）。貧乳が出にくくDカップ寄り（384）。アニメ調はバイパスで胸を大きくしやすいが、実写はエンハンスしても大きくなりにくい（389）。乳首つまみはプッシュになりやすく、Prompt weightやSNOFSを入れても打率は低い（391, 408）。
- **質感を理由に素のモデルを残す**: 検閲解除はできるが、そのLoRAやノードを入れるとバリエーションが減り、再蒸留のようなプラスチック質感になって元の良さが消える（373）。
- **周辺**: qwen2.1との優劣を聞く投稿がある（239）。GrokにKrea2用ワイルドカードを作らせる、という使い方（334）。LLMが状況文を書くと「warm lighting bedroom」のような無難な描写になり、迸りに欠ける（361）。

## Minimax H3（minmax / minimax）
- **選ぶ理由**: 画像参照が便利（243）。LoRAは狭い範囲のピンポイント対策に効き、ニッチ需要を満たせる（249）。静止画から動画向け画像への連続修正ワークフローの最終段に `minmaxh3-edit` を置いている（341）。
- **性質**: LoRAは画像・人物・背景・モーションの全てに影響する。ref2vaの参照画像は学習素材に近いほど効果が高い。相性が良くても動きは重くなりがち。汎用性は課題（249）。
- **学習の入り方**: 最初はref2vaの1フレーム学習（jsonl）が作業が単純で推奨（249）。
- **選ばない理由**: ガチエロだとH3も微妙（306）。静止画モデルとして使おうとするとワークフローが煩雑（243）。
- **関連する方式**: Ref2VAは内容が想像できてしまうので嫌で、T2VAでAI側のアイデアを出してほしい、という好み（227, 232）。H3向けにエロに強い動画モデルが出たか、という問い（298）への答えが次の二つ。
