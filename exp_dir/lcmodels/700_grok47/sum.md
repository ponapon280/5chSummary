### 長尺・速度・接続
- 起点は、5090で1MP・20秒・参照4枚がOOMし、回避するとメインメモリに逃げて激遅、という相談。

- Context Loop / Extenderで短い動画を繋ぐ。

- 20秒の一発生成は、失敗しにくい動きに限る。
- 長尺に必要なスペックは15秒以下を1本出せる分で、あとは繋ぐだけ。

- H3の速度は環境差が大きく比較不能。自己申告は高速で数十〜90秒、品質優先で十数分、低VRAMで数分。品質維持で名前が挙がったのはComfy-kitchen Attention、Block Sparse Attention、Spectrum、Model Shift。Spectrum無効や体感差なしの声もあり、Turboはセリフ劣化がきつい。

### ハードウェアとVRAM
- 5090は安くならず、次はPro 6000。最初から次世代6000級とマザー・RAM・SSDを揃えるべき、という意見。QI2.1以降は5090必須感が薄れた、という対比も。
- AM4からAM5よりGPU優先。iGPU併用はAM5持ち向け。
- サブモニタをiGPU出力にするとVRAMが約0.8–1GB浮く実測。16GBでは800MB空けても変わらない、切り替えが面倒、という反対。
- AMDはヘッドレス非想定。ダミープラグで回避できるがVRAMを食う。
- 5090のPL100%常用は、計測に出にくい16ピン側の温度・電力が問題になり得る。5080の低温運用や5070 Tiデュアルの方が安全で速いのでは、という比較。
- H3では5090とPRO 6000の速度差は実用設定で小さい（約5分前後）。1.2MPでは5090がOOMしやすい。学習や大容量オフロードなら32GBでも足りずPRO 6000が欲しい、という反対。
- 節約策はRAM増設（据え置きで96GBなど）、`--fast-disk` / `--disable-pinned-memory`、bf16よりint8。最近のComfyUIはNVMeを自動判定し`--fast-disk`は古い呪文。環境によっては`--disable-fast-disk`が効く。
- 量子化はW6A8がサイズ・誤差・速度の折衷。INT4とFP4の対応差（50系とそれ以前）を混同しない訂正あり。
- 長時間生成のブラックアウト候補はVRAM、ドライバ、熱、電源、ファン固定ミス。電源交換・電力制限・ファン交換で収まった例と、放置後に突然落ちる例が混在。
- GPU-Z 2.71.0でRTX 5000のホットスポット温度を見る話題。

## スレの位置

なんJNVA部のAI画像・動画生成スレ。シリーズは700目前で、深夜帯は書き込みが薄い。質問はAIアシスタントやnoteに流れ、「ここにあるのは温もりだけ」という自己評価が出ている。

実用の関心は画質そのものより、指示が通るか、既存ワークフローを壊さずに乗れるか、参照の効き、長尺の繋がり、音と動作の同期、VRAMと速度の折り合い、に寄っている。新モデルが出るたびに話題が移動し、検証投稿とネタが同じ速度で流れる。

## コミュニティ

- 以前は不明点をスレで聞いていたが、今はAIや検索で足りる、という意見が多い。
- noteは有用記事もある一方、マネタイズ目的で外れが増えた、という不満。特定著者だけブロックする案も出た。qiitaも昔より外れが増えた、という対比。
- 情報を一括遮断するのは老害化の危険信号、という反論あり。
- 速度報告は条件がバラバラで比較にならない、という不満が繰り返される。スペックを書かない報告や、秒数だけを縮めた報告は品質派から却下されやすい。
- 終盤は高額PCの割引制度への反応で脱線し、個人への侮蔑が目立つ。この部分に技術情報はほぼない。

## モデルの分業

スレ内の読みに近い整理は、二次元の常用は Anima、編集と実写寄りは Qwen / Krea、動画は MiniMax H3 と Wan、という分業です。盛り上がりは新モデル側に移動している。

### 画像

Anima の大規模FT（AnimaYume、Kirazuri、Light Lavender 等）は試しても差が分かりにくい、という感想。非公式ナンバリングは混乱のもとで、公式が後続版を出しにくい、というブランド上の懸念も出ている。

Noct Q はプロンプト追従が良いが、サンプルが欧米・アジア寄りで日本人の出やすさは未確認、というやり取り。Qwen 系の軽量 LoRA（数十MB級）は評価される一方、まとめ記事の「VRAMに全部載せろ」は古い、という批判がある。

### 動画

- **MiniMax H3** が中心。大型更新が止まり平常運転、という空気と、H3 Max 待ちで意欲が落ちる、という声。速度低下の報告あり（公式ワークフローが数百秒、高速化 LoRA や kitchen で短縮、本体更新後に再悪化した例）。
- 公式のタスク分けは、テキスト／首尾フレームの **FL2VA（T2VA を含む）** と、画像・動画・音声参照の **Ref2VA**。Ref2VA は参照が強すぎて中身が読めてしまう、という不満があり、T2VA 側に展開を期待する声がある。
- Extender / Context Loop では、クリップごとに参照を切り替えて全体の参照枚数を増やせる、という使い方が共有されている。
- **Wan 2.2** はプロンプト自由度と追随で Anima より上、という比較。リアル3Dが混ざる。H3 は3Dアニメが混ざるが、アニメ適性は Wan より明確に上、という整理。
- スレ内で名前だけ挙がった **MATLOWAI**（動きと指示は忠実、アニメは弱い、遅い）と **Dasiwa**（一貫性は強いが指示は弱め）は、公開の主要モデル名としては確認できなかった。
- クラウド動画は Seedance が高い。人物差し替えは Viggle.ai が手軽、という整理。Grok Imagine が少し上がったのでは、という比較（画像は Qwen-Image-2.1、動画は H3）もある。

## 長尺・速度・接続

起点は「5090で1MP・20秒、参照4枚で OOM。回避するとメインメモリに逃げて激遅」という相談。

共有された対処は次のとおり。

- refmods を使う
- Context Loop / Extender で短い動画を繋ぐ
- 1シーンは5秒前後にし、プロンプトで前シーンの継続を書いてガチャを回す
- 20秒の一発生成は、失敗しにくい動きに限る
- 長尺に必要なスペックは「15秒以下を1本出せる分」で、あとは繋ぐだけ、という整理

反対意見として、Context Loop で1分超にすると20秒付近で動きの再放送（ループノイズ）が出るので、バラ生成して編集で繋いだ方がきれい、という報告がある。延長の現実解は Context Loop だが、一気に90秒級を出したい派とは温度差がある。

H3 の速度報告は環境差が大きく、比較になっていない。スレ内の自己申告の幅は、高速設定で数十〜90秒、品質優先で十数分、低VRAMで数分、というオーダー。品質を落とさない前提で名前が挙がったのは Comfy-kitchen Attention、Block Sparse Attention、Spectrum、Model Shift。一方で「Spectrumはダメだった」「高速化の差が体感できない」という声もある。Turbo はセリフ劣化がきつい、という評価が複数ある。

その他の速度談義として、Comfy の video save が遅いので NVENC 版に置き換え、40秒が6秒になった、という報告。ボトルネック判定ノードで20秒動画が300秒超から220秒に縮んだ、という報告。カスタムノードの遅い処理を CPU から GPU に移した、という成功例。

## LoRA・参照・ワークフロー

成人向けの具体的な書き方は省く。技術談義として残る点は次のとおり。

- キャラ参照は複数枚より三面図・キャラクターシートの方が安定する、という同意が多い。帽子など形状が崩れやすい。構造が不明な背面は推測になるので、三面図か具体指定が必要。
- 同じ参照シートでもセルアニメ風と3D質感が混ざる。style参照や解像度アップ（Singularity）で質感が変わる、という共有。スタイル例として、2D anime、digital drawing、チェンソーマン風、水彩が挙がった。
- 高解像度にすると3D寄りになるのは、学習データ（トゥーンレンダのゲーム動画など）の影響では、という推測。
- H3 の LoRA は人物・背景・動きすべてに効く一方、悪影響も大きい。参照画像との相性が悪いと動きが重く、汎用よりピンポイント対策向き。公開 Base が蒸留済みで通常 LoRA より難しく、kohya 氏も対応に苦労している、という情報。強度を下げると急に2Dアニメ寄りになり、別の効果とのトレードオフ、という報告。学習の入り口としては 1f の jsonl が簡単、という意見。参照画像側でカバーした方がよい、という結論も出ている。
- ローカル LoRA は素材・epoch・強度とも手探りで、試行錯誤自体が PC 性能と素材の壁になる。クラウド（Google AI Pro の A100）を試す案も出た。
- 失敗例として、dim/alpha、学習率、枚数、ステップを振っても教師画像の細部（糸の編み方など）が再現されない。キャプションにアーティストタグを入れると次元を余分に食うのでは、という仮説が出たが結論は出ていない。
- 自然文キャプションが飛ばしやすい概念は、Danbooru 系タグの方が扱いやすい、という実務寄りの対比。
- LoRA 管理が面倒になり、i2i と軽いプロンプトに寄る人もいる。昔の画像は LoRA 消失で再現不能、というあるある。
- カスタムテンプレを消したら安定した、という報告。背景固定＋ポーズ変更は難しい、という前提で QI2.1 が評価されている。
- 構図は開始フレームで固定する運用がある。髪型・髪色で目の形が変わるのは、学習データ上のキャラ傾向では、という推測。
- 動画の音は、リアルすぎるより既知の物理音に寄せた方が安定する、という意見が優勢。動作と音を同一文で縛る、参照音声の声質と台詞をプロンプト側でも明示する、という運用。空白時間に意図しない言語が出る、指定台詞が飛ぶ、音が潰れる、といった長尺の不具合が共有されている。対処案は、参照の役割をタグで補足する、台詞をプロンプトに書く、外部 TTS を使う。セリフは別ツールで作って合成し、リップシンクは未解決、という暫定結論。
- 特定の成人向け動作は、素材不足とモデルの物理誤認識で不安定、という認識がある。手順はここでは書かない。
- 実写は需要が大きいが、ディープフェイク懸念でアニメに限る、という流れもある。実写は顔の特徴を書かないと同じ顔になる、という感想。実写側の常用として MATLOWAI が挙がり、アニメ側の常用は問いのまま。
- 別件で「上の画像が2–3秒後に突然崩れる」症状の情報募集があったが、この範囲では解決報告はない。

## ハードウェアとVRAM

- 5090 は安くならない。次に買うなら Pro 6000。最初から次世代6000級とマザーボード、RAM、SSD を揃えるべき、という意見。QI2.1 以降、5090 必須感は薄れた、という対比もある。
- AM4 から AM5 への買い替えより GPU 優先、という空気。iGPU 併用は AM5 持ち向け、という整理。
- サブモニタをマザーボード（iGPU）出力にすると VRAM がおおよそ 0.8–1GB 浮く、という実測談義。反対は「16GB では 800MB 空けても状況が変わらない」「切り替えが面倒」。
- AMD はヘッドレスを想定していない、という話。ダミープラグで回避できるが VRAM を食う、という指摘。
- 5090 の PL100% 常用は、計測に出にくい 16ピン側の温度・電力が問題になり得る、という慎重論。5080 の低温運用や、5070 Ti デュアルの方が安全で速いのでは、という比較も出た。
- H3 では、5090 と PRO 6000 の速度差は実用設定では小さい（おおよそ5分前後）という検証投稿。1.2MP では 5090 が OOM しやすい。学習や大容量オフロードまでやるなら 32GB でも足りず PRO 6000 が欲しい、という反対意見。
- メモリ増設（グラボ据え置きで RAM 96GB など）、`--fast-disk` / `--disable-pinned-memory`、bf16 より int8、が節約策として共有されている。最近の ComfyUI はモデル置き場が NVMe かを自動判定するようになり、`--fast-disk` は古い呪文になった、という指摘。環境によっては `--disable-fast-disk` 側が効く、とも。
- 量子化では W6A8 が、サイズと誤差と速度の折衷として話題。INT4 と FP4 の対応差（50系とそれ以前）を混同しないよう訂正も入っている。
- 長時間生成のブラックアウトは、VRAM、ドライバ、熱、電源、ファン固定のミスが候補。電源交換、電力制限、ファン交換で収まった例と、放置後に突然落ちる例が混在。
- GPU-Z 2.71.0 で RTX 5000 のホットスポット温度を見る、という話題。

## ローカルLLMとクラウドAI

- 16GB VRAM のキャプション比較では、総パラメータより量子化精度が効いた例（12B の高ビットが、26B の低ビットより良かった）が共有されている。
- LM Studio 上の 20B 前後は、フロンティア並みではないが、試行回数を稼げる用途では実用域、という評価。コンテキストを伸ばすならメモリ積みが前提。
- Codex / agent 依存は、知識がなくても完成物は出るが、微修正のたびにトークンを溶かし、権限範囲（特に Computer Use）のリスクがある、という両面評価。環境が壊れたら都度直すより、まっさらな環境を再構築できる引き継ぎを用意した方がトークン効率がいい、という運用論。
- クラウド側は、ChatGPT / Codex 系のリセット、Gemini の業務適性、Claude の実装完遂力の比較。フラッグシップ以外をどこで使うかが難しい、ハルシネーションはモデルだけでなく指示側の問題でもある、という論。
- 「AI」を「SI」と呼ぶ、という業界話は、定着しないだろうという見方が多数。
- 有料プランの値上げ噂と、「できる」が「金を払えばできる」に縮んだ、という倦怠。
- 高画質化のローカル一括希望に Topaz Photo AI が挙がる。クラウド加工では Gemini / ChatGPT / Grok の枚数と品質が比較されている。
- 音声は Gemini TTS の品質評価が高い一方、成人向けは規約上のチキンレース。健全な生成物を外部ツールの参照に使うのは可、学習利用は不可、という確認投稿がある。
- コストは「電気代 vs サブスク」だけならローカルが安いが、パーツ高騰とリセールを入れると単純ではない、で終わっている。NSFW は今後もクラウドが厳しく、実用の逃げ場はローカル、という見方が優勢。「計算資源だけ貸すクラウド＋自前モデル」という建前には、アップロード側が責任を問われそう、という冷やかし。
- AI で本格的なオリジナルゲームは、見た目の模倣はできても面白さは学習されていない、という懐疑が優勢。
- 素材収集（古本・裁断・スキャン）が PC 並みに高くつく、というボヤキ。AI 生成素材は量産感とマイナー作品の欠落が問題、という反論。

## 環境トラブル

いずれもスレ内の自己解決・未解決で、公式の既知不具合とは限らない。

- Python が固まる。NVIDIA ドライバを Studio 最新から Game Ready 596.49 に変えたら直った、という報告。その後再発し、再解決には至っていない。
- Forge Neo + Spectrum integrated で生成途中の画像が壊れる。原因は適当な自然言語の補足プロンプトで、文章を整えたら直った、という自己解決。
- Codex はコマンドのたびにターミナルが一瞬出る不具合（ダウングレードしても直らず）。許可確認は、起動オプション、プロジェクト単位のフォルダ許可、sandbox ユーザーの権限戻しで緩和、という手順共有。`.codex` と作業フォルダの権限を広げたら自動承認のブロックが消えた、という Windows 報告。電話番号要求で入れなかった、という遅参者も。
- WSL 操作ミスで safetensors 約800GB を削除。バックアップがなければ復旧不能。カスタムノード自動取得分は中身すら不明、という事故。`find` の一括処理への注意。

## ビューア（NivisViewer）

自作ビューアの更新告知と、作者とのやり取りが続いている。

- 評価やタグはファイル本体ではなくファイル名に埋め込む方式。読み込みやメタデータ追跡が不要で、旧ソフト（Zippla）からの移行がしやすい、という説明。デメリットはファイル名が変わることと、文字数上限。
- 同じ書式でも、アプリ側でタグ登録していない名前は認識されない。タグ管理か config の編集が必要。
- 移行希望は、Pinterest ノートの自動DL、PSD / Clip Studio / SAI を画像として開けること、「規定のアプリで開く」。対応は「制作ファイルを画像として開ければ十分」で一旦まとまっている。
- ComfyUI 側では、入力プレビュー非表示、PSD / CLIP / SVG サムネイル、Dropbox 上の未ダウンロードファイルを勝手に取得して固まる問題が、ツール作者とのやり取りで進んでいる。
- SVG サムネイル不出の切り分け。宣言のない `inkscape:` 属性で、描画前の XML 解析が止まる例。Illustrator 出力は可、Inkscape 製は不可。ブラウザで開かず「リンク先を保存」しないと壊れる、というアップロード側の注意。
- 要望は、設定文言を「AI画像」ではなく「Illustrator(.ai)」と明示、Esc で閉じる、フルパスのコピー。開発側の返答は、新ビルドでサムネイル改善。閉じるは Ctrl+Q/W（Esc はフィルタ解除に使用済み）。フルパスは Shift+C。マウスジェスチャを推奨。不具合はリポジトリの issue / discuss へ、という案内。

## CLIP STUDIO PAINT

素材の非公開化（成人向けブラシ、文字ペン、ポーズ参照などが巻き込まれた、という体感）が大きな話題。

- 強みだった素材エコシステムを自分で潰した、という見方が優勢。Civitai 削除騒動の連想。
- 背景に、英国 NASMA（学生200万人規模）との公式パートナー発表（2026-08-31 の IR）を挙げる書き込みがある。海外展開のための成人向け切り、という推測。公式がそう説明した、という話ではない。
- 吹き出しとモザイク用途なら残る、Affinity が無料、Krita や Photoshop へ、という移行論。反面、Krita はコマ割りとテキストがクリスタよりやりにくい、操作の敷居が高い、という声。リアルタイム i2i は過去に話題になった程度。
- クリッピー（金で直接買えないポイント）、UI の九龍城化、AI 機能が Adobe の劣化コピー、という既存不満とセットで語られている。
- 日本のプラットフォームが成人向け表現や反AIで研究連携しにくい、という周辺論も出た。

## 決済・規制

スレ内で感情が一番強い話題で、事実関係は投稿者間でも割れている。一次情報は少なく、体験談と憤りが混ざっている。

- pixiv FANBOX などがカード会社や決済代行の圧力で成人向け表現を絞られている、という不満が中心。
- 「Visa / Mastercard 本体はポルノ全面NGを出していない。先に動いたのは決済代行」という記事紹介と、「結局どこかに思想の強い人がいる」という見方が併存。
- JCB を国内の逃げ先にする案と、「外国人の逃げ先になった瞬間に規制される」という反論。
- 仮想通貨決済は、複数サービスを跨がないと完了せず、普及させる気が見えない、という体験談。
- 規制の中身としては、非同意・暴力・排泄などが海外基準で外れやすい。日本ではそれらがメインストリーム寄りだったため反発が大きい、という整理。
- Civitai では無修正が多数派なのに、日本側はバーセブンを入れざるを得ない、という不満。
- 年齢表現の線引きでは罵倒合戦になったが、根拠の提示はほぼなく、感情論で終わっている。

## この範囲から言えること

1. 20秒・1MP・参照複数は、ハイエンドでも一発生成より短シーン分割と接続が現実的、という空気。
2. 接続は Context Loop が有力だが、長尺だとループノイズが出るので、編集接続と使い分ける。
3. H3 の高速化は環境依存。秒数だけを比較せず、解像度・steps・最終画をセットで見る。
4. H3 LoRA は効果が強く副作用も大きい。蒸留 Base 前提で、強度と画風（2D/3D）のトレードオフを小さく試す。
5. VRAM 不足時は量子化、ディスク／ピンメモリ系オプション、RAM 増設が先。オプションの有効無効は ComfyUI の版で変わる。
6. 二次元の常用（Anima）と、編集・実写・動画（Qwen / Krea / H3）の分業が、この時点のスレの落としどころに近い。
