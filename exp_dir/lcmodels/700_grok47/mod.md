## 動画モデル

### MiniMax H3（H3 / MM-H3 / Hailuo 3）

このログの動画本命です。選ばれている理由は、アニメ適性が実用域にあること、参照画像・参照動画が便利なこと、LoRA が狭い範囲に強く効くこと、効果音を含めた一本化、5090 クラスでも速度目的なら実用になることです。ワークフローの最終段（`minmaxh3-edit` / ref2v / ref2va）に置かれています。

同時に不満もセットです。公開 Base は蒸留済みで LoRA 学習が難しい、延長で絵が急変する、途中から映る面の構造が崩れやすい、成人向けの物理は静止画 LoRA だけでは足りない、Turbo はセリフが劣化しやすい、巨乳寄りで体型制御が難しい、という指摘があります。運用の結論は「一気に長尺」ではなく、5〜15秒を作って繋ぐ、です。H3 Max は「もうすぐ出る」前提で現行に手が止まる名前として出ますが、このログ内では未リリース扱いです。

公式の **FL2VA**（ログの fl2v）は、参照より動きが重くなりやすい比較対象です。Ref2VA は参照が学習素材に近いほど効く、一方で中身が想像しやすく、テキストからアイデアを出してほしい人は嫌う、という分かれ方です。

### Wan 2.2

選ばれる理由は、anima よりプロンプトの自由度と追随性が高く、i2v で anima が再現できないことをやる、という一点です。逆に、リアル寄りの三次へ引き寄せられて不気味の谷で安定する、精液色などの色指定を毎回書かないと崩れる、という弱点も書かれています。アニメ適性では H3 の方が上、という比較です。

### Krea 側の動画ではなく、動画の脇役

- **Seedance**: 有料で高め、利用者は少数。作り込む系の本編に使われているのでは、という推測。人物差し替えでは Viggle に負けている、という役割分担。
- **Viggle**: 動画の人物差し替えは手軽さでその界隈の多数派。本編は Seedance、差し替えは Viggle、という書き方。
- **DaSiWa**: コミュニティの動画ファインチューン。素材の一貫性が高くアニメも使えるが、指示はあまり聞かない、という評価。
- **MATLOWAI**: ログ前半では「実写勢が使っているもの」としか書かれておらず、モデル名か常連名か断定されていません。後半では実写の動きと指示追従がよい、アニメは弱い、公式＋高速化 LoRA より遅い、という動画モデル比較に出ます。

## ローカル画像モデル

### Qwen-Image-2.1（QI2.1 / QwenImage2.1。ログの「Qwen2.1」は LLM の Qwen 2.1 ではない）

最初の区間で言及が最も多いです。選ばれている理由は次のとおりです。

- 背景を固定したままポーズを変えられる
- 形状が比較的安定する（自転車などの構造物）
- 5070 Ti で差分生成が約15秒。前世代（2511 前後）は 5090 が欲しかったが、もう不要
- I2I・参照編集の自由度が高い。マスクやマークアップ指示が通る
- 編集の信頼性が段違い。ロゴや装飾消しで、旧 Edit（QIE2511）は約2割破綻、2.1 は500枚バッチで破綻0、という報告
- 方角指示だけでもカメラを回せるので、容量の大きい旧 Edit を消したい、という乗り換え
- LoRA が約80MBと軽い（前の QI は LoRA だけで 1GB 超もあった）

留保もあります。Ref2I 単体では H3 の ImageStudio の方が強い、という見方。やりたいことによっては 2511 の方がプロンプトが効いていた、という逆転。肌のプラスチック感は質問だけで結論なし。二次向けの本格ファインチューンは「anima 級は来ない」という見立て。後半では「Edit 側が本命で、ベースの i2i は実質 Edit」「話題になっていないのが不思議」という温度です。派生の **Noct Q** は、本家よりプロンプトが効き、使い込むと Krea 2 よりベンチ上のモデルに感じる、ただし直球の成人向けは出にくい、という理由で選ばれています。

テキストエンコーダ（Qwen3-VL 系）が本体より大きい、という構造の話も繰り返し出ます。

### anima（CircleStone Labs の公式 Base / Turbo。2.9B・3.8B は別物）

静止画の二次絵では、このログの定番です。選ばれる理由は、公式 Base が強くて新版騒ぎが起きないこと、LoRA が作りやすく新キャラは自作した方が早いこと、タグ縛りを突破していること、画風が気に入った派生がなければ Base で足りること、NovelAI で絵柄が安定せず戻る先になっていることです。動画の前段（anima-edit）にも入っています。

負けている点は、ガチの成人向け動画では H3 と並んで微妙なこと、プロンプト追従と i2v では Wan 2.2 に負けること、3コマ構図が苦手なことです。

版の分裂が大きな話題です。2.9B はコミュニティによる層拡張で、公式ではありません。3.8B はモデルもエンコーダも重く普及しない、という見方。2.9B は知識カットオフ更新への期待がある一方、Base の LoRA が使えず移行が面倒、非公式版が公式っぽい番号で混乱を招いている、という批判が併存します。軽さ優先なら int8 の anima turbo でよい、という結論もあります。

### NovelAI Diffusion V5（NAI5）

選ばれている、または残している理由は、日本語と Danbooru 系タグを混ぜられること、位置指定が比較的簡単であること、上位プランでは inpaint が使いやすいこと、文字品質の比較基準になること、高解像度でも塗りが潰れにくい上流として Krea 2 に渡せることです。揺れ表現は afterimage と motion blur で自然になる、という助言もあります。

不満は、小物、胸サイズの中間が出にくい、断面図が指定サイズに引っ張られる、絵柄が安定せず anima に戻った、枚数制限がきつい、生成枠や参照機能待ち、です。熱量は下がった、という観測です。

### Illustrious（ログの「リアス」）

今これを選ぶ積極理由はほぼありません。タグ縛りだとできることが限られる、という否定的比較の相手です。一方で、公式が版を出しているので LoRA 互換が保たれている、という対比材料にはなっています。EasyReforge 運用では、タグを減らしアスペクト比を変えると目的の絵が出始めた、プロンプトより解像度で絵が決まる、という特性が語られています。

### Z-Image と周辺

評価は「LoRA が動く」「デザイン力を足せば最強になり得る」程度で、実際の覇権にはなっていません。後半では Qwen-Image とまとめて、軽い二次絵チューン止まり、と総括されています。ログの **ming-image** は、新モデルに見えて Z-Image のファインチューンではないか、という推測として出ています。Z-Image Turbo / ZIT / ZIE という呼び方そのものはほとんど出ていません。

## クラウドの画像・動画

### Krea 2

使い分け理由が最も具体的な画像モデルの一つです。選ぶ理由は、動画素材にするなら背景力が強いこと、サイズ系はプロンプトよりスライダーが確実なこと、公式のまま二次絵と実写の混合が出せること、実写寄りに寄れたこと、塗りや体格をプロンプトでかなり変えられること、遅れて「二次キャラもそれなりに描ける」と評価されたことです。NAI5 からのアップスケールでは、大きい解像度でも塗りの潰れが減り、inpaint 性能が重要、とされています。

選ばれない理由は、成人向けの語彙ではタグ系モデルの方が上、Danbooru 語が効かず自然文必須、一語直すと他の細部まで変わるので大量のポーズガチャができない、体型が偏る、版権キャラを学習していないのでワイルドカード運用ができない、文字が弱く NAI5 に届かない、検閲解除 LoRA を足すとプラスチック質感になって元の良さが消える、です。krea3 は「今は NAI が強いターンだから待つ」という待ちの名前です。

### GPT Image / ChatGPT

選ばれる理由は、キャラ画像を渡して 3×3 のカットを一発で切り、それを H3 の参照動画に入れられることです。他では拒否された指示が 3×3 だと通った、という比較もありますが、細部は崩れる、見た目がギトギトする、フィルタは通るまで繰り返す、という留保つきです。画像加工の品質比較では Gemini より上、枚数は Gemini の無料枠より少ない、という位置づけです。

### Grok / Grok Imagine

課金すると短い動画が通る、という実用理由。画像は 2D / 2.5D / 3D が混ざり指示が難しい。文章側の規制は厳しくなった、効果音品質では H3 に負ける、Codex が成人向けプロンプトを拒否するので書き換え役に使われる、という位置です。

### Claude（コーディング側を含む）

カスタムテンプレを消したら動くようになったので再課金を検討、という復帰話。業務では仕様書を渡すと案件ごと終わる、Comfy の遅い処理をコードで置き換えられる、という理由で選ばれています。ログの **opus5.5** は「タイムラインがそればかり」という言及だけで、選定理由はありません。

## 音声・周辺ツール

- **Gemini TTS**: 新しい TTS の質が高く、ローカル音声とは桁が違う、AI Studio で試せる、通常の Gemini に降りてきたら利用者は増える、という評価。成人向け利用は規約リスク、という留保。画像加工は枚数が多いが指示が甘い。
- **Irodori**: H3 に喋らせず、セリフは別で作って最後に合成する、という現時点の結論。リップシンクは未解決。
- **Singularity**: 生成モデルではなく解像度上げ。上げると 3D 感が強く出る。
- **SAM3**: 検出モデル。生成モデルの選定からは外れている。

## プロンプト用・業務用 LLM

画像モデルとは別に、選定理由が読めます。

- **Gemma 4 26B / 12B**: あらすじから動画プロンプトを書く用途。VRAM 16GB のキャプション比較では、26B の低ビットより 12B の高精度の方が誤認が少なく速い、という結論。
- **Qwen3 系のローカル LLM**（Qwen-Image とは別）: クラウドのエージェントに依存せず、回数無制限で回せるから選ぶ。コーディングはコンテキストがすぐ埋まる。RAM があるなら Flash 系、というメモリ話。
- **Claude / ChatGPT・Codex**: プログラミングと Comfy ノードはこちら。Gemini は業務では戦力外、日常の軽い質問と指示文の固め、安い／無料の Flash が理由。信頼が要る作業はフラッグシップ以外をいつ使うか分からない、という反対意見もある。
- **Codex**: 完成物は出せるが、少し直すにもトークンを使う。読み取り範囲が広く、Computer Use だとリスクが上がる、という運用上の不満。モデル性能より、障害・残量・許可プロンプトの話が多い。

## ログ上、選定理由がほぼ無いもの

FLUX、LTX / LTX-2.3、Z-Image Turbo という呼び方、WAN を「選ぶ」積極理由（追従以外）、Illustrious を新規に選ぶ理由、は実質ありません。前半の抜粋では Wan と LTX が明示的に不在、後半の抜粋では Illustrious / FLUX / Z-Image / LTX が不在、と区間によって穴が違います。通して読むと、穴が大きいのは **LTX-2.3 と FLUX** です。
