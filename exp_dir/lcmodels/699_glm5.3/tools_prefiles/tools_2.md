# ツール関連話題の抽出（根拠レス番付き）

## ComfyUI
- レス番280：ComfyUIの操作に馴染めないと投稿者が明言。「画像サムネイル右クリックでエクスプローラーを開く」機能が標準であってほしい→自作して「今ちょっと便利になってうれしい」（282で「有能」の反応）。
- レス番275：Forge Neoは最新モデル（Qwen-Image-2.1）に未対応だがComfyUIはモデル公開前に対応済み。「新モデルをすぐ試したいならComfyUIを使わざるを得ない」のが選定理由。WebUIから離れられない・ComfyUIになじめない層がNeoを使うという（スレ上の推測）。
- レス番344/349：ComfyのテンプレートにあるQwen2.1ワークフローを使ったら1枚4分かかるとの報告（5070ti、RAM32GB）。347では3060 12gbで1024正方形が1分か40秒程度という比較報告。353：参照画像の数で重くなるという指摘。358：参照画像なしでは20秒程度だったと報告。
- レス番289：Comfyのワークフローはstep20、公式資料ではstep40だったという記憶（スレ上）。
- レス番437：ComfyUI-MiniMax-H3-W4A4-VSAが早い。「12GB民はこれで決まりかも」。

## REFMOD（ComfyUI-Fantastic-MiniMaxH3-PromptBuilder）
- レス番270：Create H3 RefMod Master→Load H3 RefMods→Apply H3 RefModの流れで試したがデフォ値ではバケバケになり、ComponentsをVisualにしたらマシになったが再現度はいまいちとの報告。
- レス番267：Fantastic系の「Draft form Refmod」ボタンで参照関係が自動入力されるという情報。
- レス番271：subject_definitionsで`<Subject 1>`にアンカーなしで定義付けする使い方の解説。VLMでプロンプトを作らせ`<Picture 1>`を手動書き換える方法も提示。
- レス番281：refModの使い方はComfyUI-Fantastic-MiniMaxH3-PromptBuilderのドキュメントが参考になるとの紹介。
- レス番259：VLMでキャプション生成→メタデータ化すればRefMod単体でプロンプト自動作成ができるのではという質問。
- レス番260：RefModでもキャラ情報をプロンプトに書く必要はあるが、含まれる画像のポーズに寄せられるとRefMod側に引きずられるので切って使うのをやめた、という使用感報告。
- レス番427：RefModは顔アップ・三面図などを一つにまとめられる感じで便利そうという評価。

## プロンプト作成支援ツール（VLM/LLM、Grok、Codex、GPT等）
- レス番247：GrokにRef用画像＋Minimax公式プロンプトガイドを貼ってプロンプトを作らせる方法。理由：「画像読み込みアリでプロンプト作成もローカル完結やろうとするとかなりのVRAM容量が必要」だから。
- レス番252：上記の方法だとREFMODの意味が薄れるという反応。
- レス番242/259：REFMODでプロンプト自動化にはVLMでキャプション化してメタデータに含める必要があるという見解。
- レス番386：qi2.1で画像入力＋適当なプロンプトからローカルLLMでプロンプト作成したい、どのモデルとノードがいいかという質問。
- レス番390：Qwen3.8 27Bの非検閲かGemma4 31Bの非検閲の選択。VRAM容量ゲーでこのクラスは16GVRAMでも物足りない、コスパではGrok最強、MoEでFree TokenすればVRAMなくてもいけるらしいがエロ性能評価が出回ってない（スレ上の見解）。
- レス番391：Qwen3-VL-4B-Instructを試したが数秒で終わるがアバウトな指示への想像力は全然だったという報告。
- レス番413：qwen3-vl-8b-abliterated-caption-it@q6_k / q8_0、qwen3-vl-8b-nsfw-caption-v4.5@q6_k / q8_0 の紹介。「プロンプト用だとそんなに高精度じゃなくてもいい」、システムプロンプト命との感想。
- レス番421：システムプロンプトはモデルの説明書をChatGPTに投げて作らせコピペしているという方法の確認。
- レス番362：ComfyUIテンプレにLLMのWFを流用し、上流のテキスト入力ノードに日本語で指示を書くとプロンプトに仕上げてくれるという使い方。
- レス番405/406：Claudeで全送信拒否された原因が古い時に導入した「クロードの性能が上がる」カスタムプロンプトだったという報告。空にしたら動いた。
- レス番326：H3プロンプト生成でgeminiは放屁・母乳等もノリノリでやってくれる、チャッピーはどうかという質問。
- レス番330：チャッピーにリストからランダムにプロンプト入力する自作ノードを作らせたという報告。336の質問（既存wildcardノードを使わず自作するメリット）に対し351：「シチュエーション固定でカメラアングル10回ランダム」等、リストごとに順番/ランダム/シャッフルを選べるようにしたかった、「自分がほしい機能はすぐ手に入る」が自作の利点。
- レス番350：CodexはKrea2のプロンプト作成精度が高いがエロ系に非協力。Codexに引継書を作らせメモ帳保管→Grokの新チャットごとに貼って運用する手法の詳細説明。GrokはロリショタNG、Codexはエロ全般ダメだが大人Verのプロンプトは出す、という使い分け（ツール選定理由を含む）。
- レス番357：ローカルLLMで画像からプロンプトを出させる案。
- レス番361：Krea2起動しながらだとGPU24GB超えでローカルLLM併用はダメだったという報告。
- レス番435：LoRA作成→生成→キャプション再検討のループでCodexが超頼りになる。トークン消費がエグいので手動の一次厳選が最重要。
- レス番356：スパグロ契約で一番世話になってるのはローカルMMH3向けプロンプト作成という報告。
