# 生成AI関連「ツール」話題抽出レポート

## 1. ComfyUI
- H3生成が異常に遅くなる現象の報告：3060 12GBで「10秒生成に90分」「12秒だと20分」。再現性あり(470)。別報告も「途中stepから1分→40分に伸びる」「ソフト立ち上げ直すと普通の時間」(479)。「--reserve-vramで0.6GB余裕を取っても、キュー中にブラウザ切替するとCUDAでなく3Dに負荷がかかる」(487)、「10.7GBあたりで推移、14秒以上だと11.8GBで張り付く」(496)。対処として「comfyuiのバージョン最新にしたら緩和される」(514)、「解像度欲張ると電力が全然使われずファンが静かになる、キャンセルも反応しないので再起動」(516,529)。
- VRAM節約術：「--listen 0.0.0.0にして別端末からcomfyuiを操作すれば多少VRAM節約できる」(497)。
- T2Iテンプレでノード追加、画像生成込み「120秒程度」（デフォルト設定）(463)。I2I用だと4070Tiで「3分半かかった…常用はちときつい」(490)。

## 2. Qwen-Image-2.1用ワークフロー／ノード
- Prompt Enhancer組み込みWFを共有：「基本ComfyUI本体のノードだけで動く、Lora Managerは推奨」「緑色のテキスト入力ノードに日本語でおｋ。T2I/Edit切り替え可能」(474)。「システムプロンプトはQwen公式のを無検閲化してある」(477)。メタデータ消滅のため再アップ(491,493)。
- 使用者報告：「30秒くらいでプロンプト生成、常用範囲内。生成プロンプトが中国語になるが気にしない」(503)。
- 「JSONから文字列を抽出＝Extract Text from JSONか？」という質問(490)。
- QI2.1のEDITで裸にさせても肝心なとこ描かれない、チクビのディテール指定するのか？という質問(481)。
- QI2.1でポーズスワップ：「OpenPoseノード挟めば完璧にできた。Minimax ImageStudioでもたぶん同じようにやればできそう」(630)。

## 3. Lora Manager
- 「バチクソ便利なのにいまいち浸透しないLora ManagerのLora Loader」(593)。「LoRA Stackerもあるんやね、今度使ってみよう」(595)。

## 4. Minimax H3（動画ツール周り）
- 高速化オプションが多すぎて「SageAttention、Kitchen、SolAttn、Spectrum、Sparse……何が併用できてできないのかもよくわからん」(461)。「高速化は品質が劣化するから、使わないのが正解や」（スレ上の見解）(469)。
- ref2va 1f Lora学習の実践共有：dataset.toml＋jsonl、パスは「/」を使うこと、references/Image/英語説明で構成、ファイル名は全て別名、4090で400サイズSWAP35でギリギリ、素材10組20枚 epoch160、4090で150分、Lora効果は動作の補助と上書き(540)。試作Loraの実証依頼(513)。検証結果：「棒がうまい棒じゃなくなってる！良い感じ。fl2vaだと全体的に凄いスローモーションになる」(601)、「効果の出るものと動画崩壊レベルで悪化するものがある」「正常位が壊れやすい」(628)。
- H3用lora：「動画や音声を素材に含めなければvram8GでもFizgigで2時間ぐらいで作れる。局部修正loraぐらいなら誰でも作れそう」(527)。
- FL2VAとRef2VAのモデル切替：「Ref2VA用のWFのモデル部分をIf/Else Switchノードで切替式に、大体はFL2VAの方を使う」(586)。「fl2vaにref2vaモデルパッチ当てる仕組みが色々模索されてる」(582)、「公式側が解決策出してなかったっけ？」(585)。hybrid loaderについて：「ハイブリッドのsafetensors使ったがint8のせいか普通のref2vaの方がええ感じ」(589)、「メモリ使用量は普通のモデルローダーとほぼ同じだったと思う」(592)。

## 5. Kohyaスクリプト
- 「danbooru＋自然言語」キャプショニング用のOpenAI互換APIサーバ＋VLMスクリプト紹介、「体感的には9095％はそのまま使えるのでたたき台に良い。ただし手動見直し必要」(442)。採用は見送り報告「danbooru語だけで学習させたloraで問題なく使えている」(573)。

## 8. AIアシスタント／コーディングツール（Codex・Astra・Luna等）
- Codexリセット運用：Proの残量「今日リセットの噂あるのにまだ88％」(472)、「リセット権はプラン変えても持ちこせる」(557)、「tiboさんはcodexの開発者、xのポストで情報得られる」(551)、監視サイトの存在(554)。
- Pro契約の消費：「Astra使っててもほんと減らん。個人で20倍とか何してるか気になる」(561)→「20倍で常に23個のプロダクト、OpenClawもこの枠から毎日50万トークンくらいと1000回程度の呼び出し」(568)。AstraのBlenderリモートモデリングで「10分ちょいで100%から0」(611)。
- Luna/Solの使い分け：「Astra中レビュー＋LunaXhigh実装は5.6lunaは安いがポンコツでバグ産む。時間効率悪い」(600)、「普通の作業はsol、コードレビューはastra」(606)。
- Chat側Proモードで設計→Codexに渡す運用の共有(602,603)。
