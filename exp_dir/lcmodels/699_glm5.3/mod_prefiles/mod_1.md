# レポート：なんｊスレログから見た生成AIモデル話題の抽出

## 1. Qwen-Image / Qwen-Image-2.1 / Qwen2.1 (QI2.1) / QIE2.1

**動作環境・速度**
- レス12：新しいQwenを4070・VRAM12GB・メモリ16GBのPCでもデフォルト設定で70秒で完了
- レス45：ローカル主流が8GBなのでqwenもVRAM要件を下げてくれた、実力と比較を知りたい
- レス72：Qwen21は軽くて良い。拡散モデルとTEをbf16に上げても5070Tiの16GVRAMで画像編集2MPで21秒。2511のbf16(40GB)の頃は1分以上かかっていた記憶
- レス74：軽いから足切りラインかなり低くint8昆布で7GB台、12GB勢でも余裕
- レス103・115：なお本スレでは「12GB民」の言及あり（レス95）

**選定理由（スレ上の評価）**
- レス26：Qwen21はMinimax Image Studioで上手くいかなかった服装・髪型スワップが上手くいった。厳密な参照画像の当てはめはMinimaxが強く、Qwenは「似たような感じにするだけ」
- レス74：QI2.1は性能高くて使いやすい。t2iは衣装が強くkrea2と使い分け。加工系はH3より性能が良い。透過画像作る能力が高く、キャラと背景を別モデルで作る自動化がやりやすくなる
- レス77：モデル自体の性能はいい。ただライセンスのせいでLoRAやFTモデルのエコシステム発展は望めない
- レス117：日本語による編集能力はFlux2kleinの方が高い。TEは同じ8Bなのに差がある（無印とVLの差か）
- レス155：QI2.1のEditでキャラシート作成、Krea2より使いやすい
- レス205：パチスロ学習してなさそう。ベース筐体はKrea2-turboで出して参照させるのがええか
- レス211：現状のQwen2.1の利点は「軽めなEditモデル」という位置。驚きは少ないが、LoRAが16GVRAMでも作れるかもというのは今後大きい
- レス98：縄・緊縛系をQwen21で試した結果、バニラでそこそこ出る。SNOFSに期待

**ComfyUIワークフロー問題**
- レス21：comfyのデフォルトのワークフローではシード固定で手動で変えなければならず設定変更不可
- レス22：解決法＝デフォルトのqwenテンプレート→サブグラフ展開→Kサンプラーのシードを「randomize」に変更
- レス25（スレ上の意見）：seedのランダム化はサブグラフの外に出しとけ
- レス32：QIE2.1はAVIF保存はまだできないかも。「PyAV's SVT-AV1 encoder does not support alpha」エラー

**ライセンス問題**
- レス79：QI2.1はlora作れるらしいが、ライセンス的に配布が無理そうということか
- レス81：生成物もチューンモデルもLoRAも金のやり取りがダメ（個別にライセンス取得必要）。趣味の無償公開は問題ない。Animaの後継になりうる二次エロ大型ファインチューンは金集めしないと無理で来ないだろう
- レス80：xで有名人が公式にライセンス緩和を要望して緩い返事が返ってきたらしい
- レス182：公式声明「出力はライセンス対象のマテリアルには含まれません。生成した画像等の権利はユーザーが保持」
- レス187：これでQwen-Image-2.1をレギュラー布陣に加えられる
- レス184：編集データセット作って公開しても許されることが確定したのはローカルにとって良いこと
- レス206：生成物まで商用禁止は疑いの魔狩り。novelaiやpixaiみたいなサービスのタダ乗り禁止の文言
- レス202：この手のライセンスが出るたび生成物の扱いは問題になる。企業でやってるなら意識して書け
- レス213：anima初期のライセンスとqwen image 2.1のライセンスはよく似てる。既視感ありあり

**その他**
- レス196：AI ToolkitがQwen21のLoRAにもう対応
- レス204：ComfyUI本体のTextGenerateノードでi2tを挟みセリフ自動生成。8bだと性能足らん感、Qwen3.8 27Bを持ってくるべきだがVRAM容量ゲーになる

- レス214：プロンプト生成向けに調整されたLLMも公開されている。日本語で入れられるから楽

# 生成AIモデル関連話題の抽出（除外：Qwen/NAI/illustrious/FLUX/Wan/Z-Image/anima等）

## MiniMax（H3 / Image Studio / Singularity / FastH3）

- MinimaxのImage Studioはアイコラ的な編集でQwenより上という評価（>>14, 15）
- ただしQwenでは成功した服装・髪型スワップがMinimaxでは失敗するなど一長一短。厳密な参照画像の当てはめはMinimaxが強く、Qwenは「似たような感じにするだけ」（>>26）
- ポーズスワップはMinimax/Qwenどちらもうまくいかない（>>26）
- 画像編集モデルは特定タスク想定の堅いデータセットで訓練されているだろうというスレ上の推測。MMH3の訓練と能力の論文化を望む声（>>28）
- 女性視点のクンニなどは学習データ自体がなさそうで、悪夢的な生成物しか出ないという報告（>>43）
- Minimax H3 Reference to VideoがComfyUIアプデでノード入力のバグに悩む（>>42）
- MiniMax SingularityはXで凄いと言われているが、実際触るとイマイチという評価（>>90）。Seedanceの生成データで学習してそうというスレ上の感想（>>91）。エロのアピールがないので触る気にならない（>>91）。スレでリンクを貼られても無反応だった（>>95）
- Singularityは動きは良くなるが3次寄りでシネマティックになり、2Dアニメしか出さない人には無用（>>201）
- Singularityはアニメの画風が繊細、バニラ/FastH3のアニメはコミカルでポップという印象（>>96）
- FastH3はクオリティが今一で使い込まない（>>95）。1MP・高速化LoRA不使用・25stepが答えを出し済みというスレ上の見解（>>95）
- MiniMax H3のLoRA学習報告：musubi-tunerで1024画像だとメモリ溢れ、学習画像400×400で9組18枚、blocks_to_swap:35で4090でギリギリ、max_train_epoch16で10分（>>108, 109）。4090ですら512×512が無理なら大多数はH3のLoRA学習は無理という指摘（>>178）
- ref2va_1f LoRA学習の焼き上がり報告：学習2時間で効果は出るが変化量は小さい。1f学習の弊害か動きは固くなり、代わりに学習素材のブラ質感改善が出た（>>208）
- 次世代モデルは内部構造が多層LLM/多層DiTでSDXLの二層処理を超える複雑さになりオフロード処理が難しいというモデル解析に基づくスレ上の話。H3はまだマシだがYuE2 3Bは難しい部類（>>178）
- Jev（スパース化Attention）をMiniMax H3に組み込み、4step・49層、スパース率1〜10%でRTX4070が6分7秒→3分34秒、41.7%短縮というX投稿の紹介（>>221）
- minimax高速化バージョンのfal公開を望む声（>>107）
- 二次はr2vだと似た絵柄に変換され、Xで流れるwanやseedance製と比べ差をつけられているがローカルでここまでできるのは凄い（>>118）
- 盛り上がりが去り、先月勢いで5090のPCを買った人はどうしてるんだろうというスレ上の疑問（>>102, 104）
- 視点移動系はまだ2511のほうが強いかも、まあminimaxでええんやけど（>>63）
