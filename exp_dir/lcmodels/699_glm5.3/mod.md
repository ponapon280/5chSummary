- ライセンス：緩和によりレギュラー採用へ（レス182, 184, 187）。ただし商用利用の解釈は混迷（レス206, 607, 609）。
- 不採用理由：複雑なポーズやエロ描写の人体崩れが激しく（レス403, 507）、Krea2向けデータセットでのLoRA学習も崩れる（レス383, 392）。

### Krea2
- 選定理由：T2I品質、複数人制御、指の強さでQI2.1より優位（レス292, 332, 388）。エロはLoRAで解決（レス388）。
- 使い分け：t2i衣装はKrea2、透過・EditはQI2.1（レス74, 155）。パチスロベース出しはKrea2-turbo（レス205）。
- 不満：プロンプトと構図が密接すぎて放置生成不可（レス410）、Danbooru概念（wariza等）が通じない（レス456）。
- Krea3：公式発表後動きなし。オープン化は緩やかに来るとの見立て（レス293, 298）。

### MiniMax（H3 / Image Studio / Singularity / RefMod）
- 選定理由：厳密な参照画像当てはめとプロンプト応答性が強い（レス26, 380）。Editは深い変更に有効（レス426）。H3-W4A4-VSAは12GB民向けに高速（レス437）。

- 高速化：Jev組み込みでRTX4070の生成時間を41.7%短縮（レス221）。
- RefMod：`<video N>`指定で動画扱いとなるが、ポーズに強く引っ張られる（レス226, 229, 238）。
- FL2VA vs Ref2VA：FL2VAの方が動きとクオリティに優れ、パッチ当てが模索中（レス581, 582, 586）。
- 制限：1.2MP/20秒動画は5090でもOOM。公式最大尺は15秒（レス731, 742）。

### NovelAI (NAI)
- 選定理由：日本語プロンプトの正確な反映（目頭のシワ等）や、W-sittingでのwariza再現、描き文字の指示が可能（レス190, 456, 457, 688）。
- 規約変更：定期購入クレジットの失効報告あり（レス115）。残高削除は過去分に未適用（レス604, 608）。

### FLUX / Wan / Z-Image / LTX
- FLUX：QI2.1より日本語編集能力（Flux2klein）や肌の質感・産毛の描写に優れる（レス117, 701）。

### LLM（Codex / Grok / Gemma4 等、補助用途）
- Codex：Krea2プロンプト作成やLoRAキャプション再検討に有用だが、エロは非協力的なためGrokと使い分け（レス350, 435）。
- 消費：Astraはリモート操作で短時間に消費（レス600, 611）。GPT-6-Sol Maxは継続作業でも消費が緩やか（レス927）。

### Tips（モデル横断）
- キャラ書き分け：完全文に近い自然言語や、DiT系のcharacter1/2記法が有効（レス910, 913）。
- 動画精度：公式システムプロンプトより「必要指示＋日本語ストーリーのLLM英訳」が有効（レス847）。
- 高速化：VAE int8＋--fast fp16_accumulationでデコード爆速だが、プロンプト無視バグあり。KJ Nodesでの個別設定が安全（レス747, 814, 824）。

### 総評（このログ固有の結論）

## 今回とくに盛んに議論された話題
Qwen-Image-2.1（QI2.1）の性能・軽量性・ライセンス問題と、MiniMax H3のLoRA学習・高速化、Krea2/QI2.1/animaの使い分け。

## 冒頭まとめ：どのモデルが流行しているか（スレ上の状況から）
- **Qwen-Image-2.1（QI2.1）が最も話題量が多く、実用投入が進んでいる**。「軽めなEditモデル」という位置づけで選ばれ、参照編集・背景透過・キャラシート作成で採用報告が多い（レス74, 155, 211, 299, 699, 755, 831）。ComfyUIがモデル公開前に対応済み（レス275）。
- **Krea2**はT2I品質・複数人制御・指の強さで使い分け対象として定着（レス292, 332, 388）。
- **MiniMax H3**は動画・参照編集勢の中心。ただし「盛り上がりが去った」という声も（レス102）。
- **anima / SDXL（リアス）**は二次エロの実用の柱として継続（レス193, 846, 886）。
- NAI V5は「画像はNAI5ぐらいのがローカルに来たらゲームセット」との期待付きで高評価（レス183, 190）。

## 1. Qwen-Image-2.1 / QI2.1

**選定理由**
- 軽量・高速：4070・VRAM12GB・メモリ16GBでデフォルト設定70秒（レス12）。5070Ti 16GVRAMで2MP画像編集21秒（レス72）。int8昆布でVRAM7GB台、12GB勢でも余裕（レス74）。
- 性能：Minimax Image Studioで失敗した服装・髪型スワップが成功（レス26）。加工系はH3より良い。透過画像作成能力が高く、キャラと背景を別モデルで作る自動化がしやすい（レス74）。Editのキャラシート作成はKrea2より使いやすい（レス155）。背景透過はIOpaintより良い（レス299）。
- ライセンス緩和後、レギュラー布陣に加える判断（レス182, 184, 187）。ただし生成物の商用は不可との解釈もありカオスな状況（レス206, 607, 609）。
- 採用しなかった側の理由：複雑なポーズの描画能力が低い「Krea2どころかZ-Image以下」（レス403）。エロは人体が崩れやすい（レス507）。LoRA学習がkrea2で上手くいったデータセットでも崩れる（レス383, 392）。

**Tips（ログ表記のまま）**
- ComfyUIデフォルトWFでシード固定問題 → サブグラフ展開→Kサンプラーのシードを「randomize」（レス21, 22）。
- QIE2.1の一番楽な使い方は爆速を活かした細かい編集の連打（レス755）。
- AIToolkit学習：1024解像度で4.0s/it、オフロード100%でVRAM14GB・RAM60GB、RAMがあれば16GVRAMで可能（レス393）。AI ToolkitがQwen21 LoRAに対応（レス196）。
- musubi-tuner対応待ちの声（レス660, 661）。
- TEをQwen3.5 0.8Bに交換したモデルが出た。多言語不可・テキスト品質低下はあるが生成・編集は機能（レス821）。
- OpenPoseノードを挟むとポーズスワップが完璧（レス630）。
- プロンプト生成用LLM：Qwen3.8 27B非検閲かGemma4 31B非検閲推奨、16GVRAMでも物足りない（レス390, 413）。

## 2. Krea2
- 選定理由：T2I品質でQI2.1より優位、複数人制御の独壇場、指が圧倒的に強い（レス292, 332, 388）。ただし素の状態はエロフィルターで乳首すら出ずLoRAで解決（レス388）。
- 使い分け：t2i衣装はKrea2、透過・EditはQI2.1（レス74, 155）。パチスロはKrea2-turboでベース出し（レス205）。
- 不満：プロンプトと構図が1:1で繋がりすぎて放置生成ができない（レス410）。wariza等のDanbooru概念が通じない（レス456）。
- Krea3は公式アナウンス後動きなし。オープン化はゆっくり来るだろう（スレ上の見立て、レス293, 298）。

## 3. MiniMax（H3 / Image Studio / Singularity / RefMod）
- 選定理由：厳密な参照画像の当てはめはMinimaxが強い（レス26）。プロンプト応答性が良い（レス380）。Editは「もっと深く入れたい」系に有効、元が動画モデルでコマ取りが良いが画質微妙（レス426）。H3-W4A4-VSAは速く12GB民向け（レス437）。
- 不採用側：Singularityは実際使うとイマイチ、3次寄りで2D勢には無用（レス90, 201）。FastH3はクオリティが今一、1MP・高速化LoRA不使用・25stepが答え（レス95）。
- LoRA学習：musubi-tunerで1024画像はメモリ溢れ、400×400で9組18枚、blocks_to_swap:35で4090ギリギリ、max_train_epochsで10分ちょい（レス108）。4090ですら512×512が無理なら大多数は無理という指摘（レス178）。ref2va 1f LoRA学習：素材10組20枚、epoch160、4090で150分、400サイズSWAP35（レス540）。VRAM8GでもFizgigで2時間程度（レス527）。
- 高速化：Jev組み込みでRTX4070が6分7秒→3分34秒、41.7%短縮（レス221）。
- RefMod：動画扱いで`<video N>`指定。ポーズに引っ張られまくる（レス226, 229, 238）。
- FL2VA vs Ref2VA：FL2VAの方が動き・クオリティが良いとされ、パッチ当てが模索されている（レス581, 582, 586）。
- 1.2MPで20秒動画は5090でもOOM、H3の公式最大尺は15秒（レス731, 742）。

## 4. anima
- 選定理由：Comfy.orgが予算を持って作り込んだ「奇跡の存在」。絵師タグ・版権キャラの履修済みで実用圏内（レス193）。FANZAに採用（レス868）。キャラLoRAはAnimaの方が作りやすい（レス857）。
- 制約：多人数で崩壊、3キャラでダメ（レス332, 763, 787）。danbooru自体は非対応で部族語が自然言語に引っ張られる（レス448, 449）。LLM産クソ長プロンプトで発狂破綻（レス762）。
- 運用例：animaで構図出し→リアスでi2i（レス886）。

## 5. illustrious / SDXL（リアス）
- 選定理由：「相変わらずリアスが一番合ってる」（レス328）。抜きゲー、animaは普通のエロゲという評（レス846）。タグに直結するU-NET特性で絵師タグ大量並べが効くSDXLの到達点（スレ上の見立て、レス844, 854）。モデル進化停滞のおかげでFT・マージ・LoRA資産が豊富（レス856）。
- NAI・Flux等をベースに含むとするFTモデル一覧の引用（レス877）。

## 6. NovelAI (NAI)
- 選定理由：NAI5は日本語プロンプトを正確に反映。「目頭の下にシワの線がある」の直書きで再現（レス190）。warizaは「W-sitting」で一発（レス456, 457）。描き文字のテキスト・色も指示可能（レス688）。
- V5規約変更で定期購入クレジットが失効、9100クレジットを消費した報告（レス115）。残高削除は過去分に適用されず（レス604, 608）。

## 7. FLUX / Wan / Z-Image / LTX
- FLUX：QI2.1の日本語編集能力はFlux2kleinの方が高い。TEは同じ8Bなのに差がある（レス117）。肌の質感・産毛はfluxに軍配（レス701）。
- Wan：エッチな動きは強いが精液は飛ばせない（レス379, 185）。
- Z-Image：複雑なポーズが苦手という比較言及（レス403）。オフィシャルのアニメモデルは学習ツールのみ配布で終わったとの情報（レス199）。
- LTX：nvfp4は「クッソ速いけど順当に劣化」からアップデートできていない（スレ上の感想、レス773）。

## 8. LLM（Codex / Grok / Gemma4 等、補助用途）
- 選定理由：Gemma4-31Bは意図の汲み取り力がQwen3.8-27Bとは比較にならず（レス489）。ただしプロンプトにないものまで描く副作用（レス492）。
- Codex：Krea2プロンプト作成は精度高いがエロ非協力。引継書でGrokに受け渡し、Grokと使い分け（レス350）。LoRAキャプション再検討に超頼りになる（レス435）。
- 消費：Astraはリモート操作で10分ちょいで100%→0%（レス600, 611）。20xでGPT-6-Sol Max継続作業でも残り97%の報告（レス927）。

## Tips（モデル横断）
- キャプション：SDXLまではDanbooruタグのみ有効。Krea2は自然言語キャプションで柄を詰め込める。LLMキャプション＋手動修正が鉄則（レス398, 434）。
- キャラ書き分け：自然言語の完全文に近いほど制御が効く（レス910）。DiT系はcharacter1/character2記法（レス913）。
- 公式システムプロンプトより「必要指示＋日本語ストーリーのLLM英訳」が動画精度高い（レス847）。
- VAEをint8に＋--fast fp16_accumulationでデコード爆速、ただしプロンプトガン無視バグ報告あり。KJ NodesのModel Patch Torch Settingsで個別設定が安牌（レス747, 814, 824）。
- Qwen参照生成：3060環境で2枚7分 → AIに頼んで全体7分→2分に短縮（レス443, 504）。

## 総評（このログ固有の結論）
1. **QI2.1の公式声明（出力権利はユーザー保持）を受け、レギュラー布陣に加える判断がスレ内で確定した**。ただし生成物商用の扱いでは異論が残る（レス182, 187, 206）。
2. **実用布陣は使い分け型に収束**：T2I・複数人はKrea2、透過・軽量Edit・キャラシートはQI2.1、構図出しはanima、仕上げ・実写质感はFLUX/flux2klein、動画・参照はMiniMax H3（レス74, 155, 292, 332, 701）。
3. **MiniMax H3のLoRA学習は4090でも400×400・SWAP35が限界**で、大多数に無理という認識が共有された（レス108, 178）。
4. **QI2.1の運命はエロチューン（二次エロ大型FT）の出現有無で決まる**という見立てがスレ上で繰り返し述べられた（レス617, 81）。
