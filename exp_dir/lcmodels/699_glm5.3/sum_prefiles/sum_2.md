# ログ要約レポート（なんJ／画像・動画生成AIスレ）

## 1. Qwen-Image 2.1（QI2.1）関連

### 1.1 速度・動作環境
- QI2.1はデフォルト25stepでもkrea2の同step比でおよそ1/2の時間で済むとスレ上で語られる（>>261）。
- 別のレスではComfyワークフローはstep20、公式資料ではstep40と書かれていたとの指摘（>>289）。
- 5070ti・RAM32GB環境でQI2.1の1枚生成に4分かかるという報告（>>344）。参照画像なしのt2iなら1分もかからないとの助言（>>347, >>353）。参照画像ありだと20秒→参照ありで10倍以上の時間という本人検証（>>358）。
- i2iでresolutionが0だと入力画像サイズをそのまま使うため大きい画像は遅くなる（>>352）。
- 3060 12GBで1024正方形t2iが約1分/40秒、cfg1 step30という報告（>>347）。

### 1.2 背景透過・編集
- 編集で背景透過が一発で抜けるのを「ちゃんと凄い」と評価（>>292）。IOpaintより良く、VRAM10・メモリ32でも動作（>>299）。
- 比較検証ではqwen image 2.1で透過すると細部のレベルが違う（生成し直し分）との報告（>>315）。
- 透過の仕組み：生成時に背景を作らない方式と、人物検出で背景を消す方式の差と説明（>>318）。
- 透明背景が普通に出せるようになったとの気づき（>>436）。Outpaintingも「いい感じ」（>>268）。丸を書いて「これ直して（消して）」ができる（>>266）。
- Qwen2.1Editをアップスケーラーとして使用、「upscale <image1>」のプロンプトのみで740x960から2倍化を試験した報告。ただし画像が結構変わるため低解像度向けと評（>>423）。

### 1.3 Krea2との比較
- T2Iはkrea2＞QI2.1傾向、人物系はkrea2優位。QI2.1の強みは軽くて早い、編集性能。使えるツールが増えた程度という評価（>>292）。
- ベンチマークでNanoBanana超えと報告（>>273）。
- t2iの所感で三次はKrea2好みという比較画像投稿（Krea2-turbo vs Qwen-Image-2.1）（>>359）。
- 表現力は圧倒的にKrea2という意見も（>>367）。実写専の比較ではQI2.1は「顔マスピ寄り・スリム・CG感」、Krea2は「肉付き・肌質に生命感・グラビア未加工」の生写真（>>377）。
- QI2.1は画像参照がKrea2より強く軽いが、エロ性能は素のKrea2並みでlora学習環境が当時はまだ無いという評価（>>378）。
- QI2.1は2次元イラストの指の溶け率が気になる。Krea2は指が圧倒的に強い（>>388）。
- QI2.1は複雑なポーズの描画能力が低く「Krea2どころかZ-Image以下」との意見（>>403）。
- QI2.1はまだアウトな絵は作れずKrea2で足りるが、編集能力が高くQIEより軽い点は良い（>>373）。
- 「クウェンが全てを過去にした。重みも一番多い8vram対応サイズ」とのスレ上の主張（>>343）。

### 1.4 アーキテクチャ・学習
- アーキテクチャがcross attn方式やMMDiTよりパラメータ効率が高くmulti-turn editingに自然に適合しそうとスレ上で評価（>>253）。
- 本体はQwen3-VL。attention maskがblock-causal maskになっているのが証左で、DiT部分はLLM/VLMのworld cognitionを画像化する部品というスレ上の分析（>>432）。
- AIToolkitでの1024解像度学習は4.0s/it、Animaより遅くKrea2より速い。オフロード機能100%でVRAM14GB・RAM60GB使用、RAMがあれば16GVRAMでいける（>>393）。
- Krea2で成功したデータセットでLoRA学習したがぐちゃった画像しか出なかった報告（>>383）。Kohya対応を待つ声（>>392）。

### 1.5 周辺ツール
- EasyQI2.1への要望に対し、公式WFを開いて入れれば済むので「easy～の時代より簡単」との反論（>>287, 288）。
- Comfy HFにプロンプトエンハンサー用のTE（qwen3.5テキストエンコーダー、i2iとt2i用）が追加（>>302, 360）。上流のテキスト入力ノードに日本語で指示を書くとプロンプトに仕上げてくれる（>>362）。
- turbo lora等の低step化技術が待たれる（>>261）。
- Qwen-Image-2.1-Uncensored-GGUFが来たとの報告（>>295）。ただし「画像で追加学習してない非検閲版に意味あるのか、そもそもがっかり描写なだけでエロ出る」という疑問も（>>408, >>372）。

## 2. Krea2
- T2Iではkrea2＞QI2.1傾向、krea2は品質出しやすい（>>292）。
- 複数人制御は以前からKrea2の独壇場。Animaは動きつけると3キャラで崩壊（>>332）。
- Krea2はLoRAで解決するものの乳首すら出せないフィルターがある（>>388）。指が圧倒的に強く腕は増えても指は増えない（>>388）。
- 欠点として構図とプロンプトがほぼ1:1で繋がりすぎ、変えただけで良かった部分まで変わる。タグ連記して放置生成という使い方ができない（>>410）。
- Krea3は公式発表以降動きがない。krea2はサービスモデルの一部オープン化なので3はクローズのみの可能性もというスレ上の見立て（>>293, 298）。
- Qwen2.1の台頭で「krea2の時代が終わるの早かった」とのスレ上の感想（>>290）。

## 3. MiniMax H3 / RefMod
- H3ではキャラ情報をプロンプトに含めないとまともな動画生成がされない。REFMODでも参照画像が違えば都度キャラ情報が要る、という指摘（>>242）。実際RefModでもキャラ情報は必要との確認（>>248, >>260）。
- RefModに画像のポーズに寄せると覿面にRefMod側へ引きずられるため切って使うのをやめたという報告（>>260）。
- Fantasticの方ならDraft form Refmodボタンで参照関係が自動入力（>>267）。
- Create H3 RefMod Master→Load H3 RefMods→Apply H3 RefModという手順で試したがデフォ値だと崩れ、ComponentsをVisualにしたらマシになったが再現度はいまいちという報告（>>270）。
- subject_definitionsで<Subject 1>にアンカーなしで定義付けする使い方、VLMに立ち絵を渡してプロンプトを作らせ<Picture 1>を手動修正する例の紹介（>>271）。
- ComfyUI-Fantastic-MiniMax-H3-PromptBuilderのドキュメントが参考になるとの情報（>>281）。
- Edit用途：元が動画モデルなので「深く入れたい」「抜きたい」のコマ取りがちょうど良いが画質が微妙（>>426）。画像編集のプロンプト応答性はminimaxのほうがいい気がするという印象（>>380）。
- H3の画像生成はアニメ絵を一貫性保ったまま動かすのに良い部分がある（>>292）。
- ComfyUI-MiniMax-H3-W4A4-VSAが早く「12GB民はこれで決まりかも」（>>437）。

## 4. プロンプト作成の自動化・LLM連携
- GrokにRef用画像＋Minimax公式プロンプトガイドを貼ってプロンプト作成させる方法の共有（>>247）。ローカル完結だと画像読み込みでVRAMが必要になる（>>247）。
- 参照画像のキャプションをVLMで生成しRefModのメタデータに含めれば単体でプロンプト自動作成ができるのでは、という質問（>>259）。REFMOD自動化はVLMで元画像をキャプション化→メタデータ→VLMでプロンプト作成という構想（>>242）。
- ローカルLLMでのプロンプト作成の推奨：Qwen3.8 27B非検閲かGemma4 31B非検閲。ただし16GVRAMでも物足りない世界でコスパではGrok最強との評価（>>390）。Qwen3-VL-4B-Instructは速いが想像力不足（>>391）。qwen3-vl-8b-abliterated/nsfw-caption系の量子化モデルの使用例（>>413）。
- BenjiニキのQI2.1専用カスタムノード＋Comfy謹製TEでシステムプロンプト内包という紹介（>>396）。ただし生成が失敗する、max_length関連の動作を疑うレス（>>433）。
- Grok／Codexの使い分け：CodexはKrea2プロンプト作成精度が高いがエロ非協力。Codexに引継書を作らせてGrokに貼り付ける運用、ロリショタはGrok 100%拒否、Codexはエロ全般ダメだが大人Verのプロンプトは出す、という詳細な手順報告（>>350）。
- Krea2起動中だとローカルLLMでGPU24GB超え（>>361）。
- スパグロ契約がローカルMMH3向けprompt作成で一番役立っているという皮肉（>>356）。

## 5. LoRA学習・キャプション
- Animaでキャラ・画風LoRAに自然言語キャプションかDanbooruタグかという質問（>>369）。LLMが「テッペイ」という誤ったキャラ名でキャプション付けした例。
- 機種別の性格のまとめ：SDXLまで→Danbooruタグのみ有効／Anima→自然言語反応するがTE弱い／Krea2→TE強く数百文字使っても生成に影響なし。LLMキャプション全任せは無理で「LLMキャプション+手動確認・修正」（>>398）。
- Anima学習の具体的作法：Danbooruと短い自然言語の両方で精度を出す、学習Promptと画像内容の一致が大事、模様は安定せん、W14Tagger結果を参考に全部手書き（>>434）。
- Animaで自作LoRA使用時に頭が大きくなる問題→学習不足の可能性、ステップ上げて段階保存で確認を勧める助言（>>429, 430）。
- QI2.1のLoRA学習はAIToolkitで4.0s/it（>>393）。Kohya対応の要望（>>392）。「学習環境はもうあるが」（>>382）。
- キャプション再検討ループでCodexが超頼りになるがトークン消費がエグいので一次厳選が最重要（>>435）。
- Krea2は衣装模様など自然言語キャプションで詰めきれる（>>398, >>439）。模様の再現例あり（>>439）。
