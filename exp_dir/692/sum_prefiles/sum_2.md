## MiniMax H3 関連

### Context Loopの長さ設定
- Ref2V Tagged Planのdefault duration secondsがあっても動画が10秒になる件について、各シーンのExact frames（もしくはSeconds）を足した数値が関係する。Plan defaultにするとdefault値が有効になり、Review Gateの数値はReroll時に使うシードと長さと推測される（>>233, >>238, >>242）
- Scene Lora routeでシーンごとにLoraを選ぶ項目があるが、lora_Aやlora_Bの設定場所に関する質問が挙がった（>>251）

### Scene LoRAの読み込み方法
- MiniMax H3 Scene LoRA SchedulerノードをPatchAttention系ノードの前に差し込む
- 入力のstateにMinimax H3 Contex Loop Startの出力のstateを繋ぐ
- 入力のlora_Aやlora_Bに使うLoRAを繋ぐ（>>263）

### LoRA構成と改善報告
- 本体: minimax_h3_ref2va_pruned_int8_convrot.safetensors
- 叡智LoRA: MysticXXX_MMH3-V3.safetensors
- 8step LoRA: MiniMax-H3-Ref2VA-Acc-8Step.safetensors
- LoRA読み込みには専用カスタムノードが必要、LoRAはComfyUI/models/pdd_acc/に配置。だいぶ改善したとの報告（>>249）

### サンプラー
- 新しく追加されたcfgpp_ud10_abサンプラーは815stepぐらいで使うのが良さそうというスレ上の見解（>>236）

### H3 Maxの速度について
- スレ上の触れ込みとしてH3 MaxはH3 baseモデルの30～50倍早い。falでは35倍、kijaiでは4ステップ・int8・attention(CK/sage)の場合で既に25倍という報告（>>244, >>245）
- AI界隈のn倍の実態は条件次第であるとの指摘（>>247）
- つよつよサーバー内での速度ではないかという疑義（>>252）

## ダウンロード関連

### 大容量ファイルのダウンロード問題
- 10GB以上のファイルをChromeで落とすと完了付近でやり直しになる。FireFoxを使っている（>>235）
- HuggingFaceは大容量ファイルで失敗するようになった。コマンドプロンプトでhuggingface-cli downloadを使用し、--local-dirを指定して直ダウンロードすると失敗しない。ただし指定先にフォルダが作られて保存されるため、本来の階層に移動が必要（>>239）
- ダウンローダー（aria2c）を使用すると中断再開や分割DLが可能で軽量。鯖の孵化が少ない（>>240, >>241）
- 公式cliを使うべきとの複数の指摘（>>243）

### Civitai / ハゲフェイス
- Civitaiはダウンロードで苦労した記憶がない（>>237, >>239）
- ハゲフェイスはダウンロード完了後にエラーで一からやり直しになる問題。Codex先生に相談しキャッシュを用意して失敗時に途中から再開する仕組みを作成、作業フォルダを提示して解決。原理は不明（>>237）

- lodestonesニキがKrea2のFTをやっておりエロもぼちぼち出せる、まだWIPっぽい（>>394）

- animaのint8は露骨に劣化して使い物にならなかったが、50GBもあるならint8が欲しくなるという意見（>>402）

## エージェントAI / Codex 関連

- ツクールやコイカツのプラグインはCodexが簡単に作ってくれる。ログ読み込みでのエラーチェックも速攻で終わる（>>329）
- Codexに投げてもできないことは結構ある。蓄積がないとCodexに「何を指示するか」で躓く。自分の作りたいものを明確にして、他者のWFやLoRAがどう合致するかは泥臭い試行錯誤するしかない。この構図は5年・10年後も変わらないという見解（>>275）
- 凝ったことをしようとするとCodexにぶん投げようが結局人間の知識や経験が必要。人間が手綱を握って方向性を指し示さないと、AIが安全と言いながら無限にいらんことばっかやって極小リスクを延々潰す状態になり、トークンと金と時間を溶かす（>>283）
- まだCodexに触れていないが、動画作業量が多くそろそろ触るべきかという相談。映像の創作とは感覚が異なる世界なので一度は触れることを推奨。分からなければChatGPTで相談するのも良し（>>280, >>281）

### 3DCG / Live2D
- 海外ニキ達はエージェントAI使ってblenderで3DCGモデル作らせたりUE5やUnityでゲーム作らせている（>>300）
- AIに3Dモデルを作らせると造形がぐにゃぐにゃで頂点が物凄く多い激重の全く使えないモデルになる（>>313）
- 現状ではある程度blenderや3DCGの知識がないと無理。動かしても破綻の無い高品質モデルのポン出しはまだ無理（>>307）
- クラウドAIを使って1枚絵からlive2dを作ることについて、live2d社のプロプライエタリなソフトを使う必要があるためクラウドAIのサポートには限界がある（>>288, >>292）
- inochi2dを使ってGPTでレイヤー分けしてから再結合させようとしたができなかった。sonnetでは荷が重く、Fableやcodexならできるか気になる（>>328）

## サンクコスト / AI学習の陳腐化議論

- 進化がすごいので覚えたことがすぐ役に立たなくなるから常に最新についていく必要性はない。どうしてもやりたくなったら3日もあれば取り戻せる程度の難度（>>257）
- むしろ生成AIは後進ほど有利。LLMのように先人が必死になって築いたプロンプトエンジニアリングの大半がモデルの進化とともに滅び去った。サンクコストを踏まえると後から触る方が得、FOMOに陥らない方がよい（>>259）
- ただし機材の高騰やファンダムを意識する場合は早くから手をつけた方がいい。枯れた技術を使いこなせる点や習慣化の観点からもアーリーアダプターは有利（>>265）
- AIのサンクコストはAIの進化でかなり頭がよくなったおかげで年々少なくなっており、共通項の使い方が多いから先行者優位になりつつある。ローカルなら最大の先行者優位がハード投資。待ち自体にコストが掛かるようになった（>>274）
- アングラなものは何時消されるか分からないし後から情報掘るのもやり辛い。大手LLMがどんなに高性能になってもスケベなテクニックは教えてくれない（>>277）
- 磨くべきは「頭の中のアイデアを言語化する能力」この一点（>>273）
- LLMの進化による下駄が高くなってるからNAIリーク時代に比べれば明らかに差は縮まっている（>>306）

## GPU / ハードウェア情勢

- スレ上で5090が人権ラインになりつつあるという指摘（>>413）
- このスレは日本の特異点、変人が集まると自分たちが平均だと思ってしまうとの指摘（>>418, >>419）
- 個人でGPUが買えなくなるという煽りについて、現状はGDDR7投入遅れやDDR5生産関係の調整で不足感が厳しいだけ。来年には均衡にもっていける分野も増える見込み。データセンターは電力インフラ構築が足引っ張っており、変圧器や電源設備の不足で接続まで10年かかるとの予想もある（>>420）
- LLMだと電気代だけでAPIより高くつく。ゲーム用ならともかくAI用を個人持ちは一般的には意味不明（>>405）
- GPUとNPUが分かれる時代になってほしい、個人用ならメモリ帯域はメインメモリでも十分という意見（>>412）
