# 元の本文
今回とくに盛んに議論された話題は、ComfyUIの起動オプションや最適化機能によるVRAM・RAM削減と、ローカルLLM推論ツール（LM Studio・freetoken等）の実行環境ごとの使い分けである。

# ComfyUI（comfy）

- **起動オプションによるメモリ最適化と運用制約**
  - `--fast-disk`はデフォルトのRAMにモデルデータを詰め込む挙動を切り、RAM64GBでの問題を解消しSSDの寿命延長にも有効。`--disable-pinned-memory`はVRAM転送用の固定領域を解除しRAMを空けるが生成中のストリーミングが遅くなるため非推奨とされる（レス704）。
  - `--disable-pinned-memory`の追加で使用メモリが減る一方、生成時間が1,2割増えるとの指摘あり。`--fast-disk`併用時はSSDからVRAMへロードするため生成時間が変わらない可能性がある（レス259, 297, 302, 304）。生成でメモリ限界近くまで消費する場合はpinned memoryを切った方が良いがSSDの寿命には変えられない（レス305）。
  - `--reserve-vram` / `--vram-headroom`は他アプリによるOOMを防ぐためのVRAM管理オプション（レス704）。
- **H3 optimizationsによる高速化と省メモリ**
  - SageAttention環境でLimiter・Memory Optimization・Sparse Attentionをデフォルト設定でつなげると、SageAttentionオンリーより生成時間が半分になりVRAMが5GB空く。Sparse Attentionは劣化を伴うがVRAMカツカツ環境ではLimiterとMemory Optimizationの適用が推奨される（レス94, 243）。
  - デフォルト値での速度はSol attn + SLAと同程度との報告あり（レス250）。
- **運用方針とアップデート対応**
  - 最新版へのアップデートで使えなくなるカスタムノードは切り捨て、codex等を使って対応する割り切りが主流（レス621, 622）。PDD LoRA対応がコミットログに確認されたがバージョンタグ付まで待つ判断がある（レス914）。標準LoraLoaderでAcc-Loraを動かすため`git fetch origin pull/15908/head:pdd-fix && git checkout pdd-fix`を実行し動作した（レス278）。
- **環境構築上の注意**
  - 検索上位の害悪note鵜呑みによる古い環境（Python3.9, Pytorch2.6等）構築の連鎖が問題視されている（レス624）。初心者はdasiwaワークフロー丸パクリではなく公式テンプレ推奨（レス934, 935, 936）。
- **選定理由**
  - モデルデータのVRAM載せを蹴る機能、メモリ最適化、SparseAttention等でVRAM削減と高速化を両立できる点（レス94）。APIを叩いてフロントを作りLLMに処理を投げるシステム構築など拡張性が高い点（レス728, 763）。

# LM Studio

- **VRAM合算によるマルチGPU運用**
  - GPU2枚構成（5080+3080）でVRAMを合算して扱えるため、Gemma4の31BやQwen3.8の27Bが3040tosで実用的に動く（レス917）。
- **プロンプト推敲用途**
  - ComfyUIでの生成作業と並行してLLMでプロンプトの推敲・壁打ちができる点が選定理由（レス889, 890）。freetokenがGGUF対応したらLMStudioを使わなくなりそうとの予想もある（レス843）。
- **RAM消費の課題**
  - ComfyUIやForgeと同時起動でRAMを大きく消費するためメモリ容量が課題（レス660）。

# freetoken（LLM推論ソフト）

- **動作制約と適合モデル**
  - 3060環境では31Bの一番小さいモデルすら動作せず、llamaで設定を弄り回して4.5t/sが限界。MoEモデル専らに早くなるツールであり26B-A4Bのようなモデルを選ぶべき（レス293, 312）。
- **NVFP4/MXFP4での動作**
  - aabbas/Huihui-Ornith-1.5-35B-A3B-abliterated-NVFP4-freetokenが動作し調子が良い。MoEモデルが速く動きメモリカツカツでも動く点が評価されている（レス843, 854, 856）。

# beellama（LLM推論エンジン）

- **選定理由と使い分け**
  - Denseモデル使用時にfreetokenより適しており、kvキャッシュ量子化をkvarn4にするとかなり良い結果が得られるためfreetokenの代替として選定される（レス312）。

# Codex / Codex Pets

- **環境構築の自動化**
  - H3環境の構築やワークフロー作成を自動化でき、GitHubリポジトリやHuggingFaceモデルを指定してインストールからワークフロー作成までこなす（レス761, 765, 770）。ComfyUIの機能スクショを渡して自分専用のUI作成を期待する用法がある（レス763）。
- **運用上の注意**
  - 推論レベルを「高」にすると一生終わらなくなる（レス725）。「Codex Pets」デスクトップ常駐アプリはクリックしても会話できずほぼ意味を為さない（レス781）。
- **選定理由**
  - 画像選別・整理のシステムやエロプロンプト生成の意図設計にローカルLLM併用前提で使える点（レス674）。古いノートPCのメモリ・ストレージ交換やデータ復旧等の外部作業にもフル回転させている（レス166, 172）。

# H3 optimizations（高速化ツール）

- **選定理由**
  - 生成時間を半分にしVRAMを5GB空けられるため。VRAMカツカツ環境で有効（レス243）。

# nano-banana（チビタイ）

- **エコシステムとしての位置づけ**
  - 単なるアップローダではなく、ソフト側がnano-banana前提でモデルデータをダウンロード・探索するディレクトリ構造を持つエコシステムとして機能している（レス150）。広告もなく毎日世界中に無料DLを提供しており買収されるためにやっているのではというスレ上の見解がある（レス177, 182）。
- **容量制限と課金騒動**
  - 以前は全モデルバックアップできたが容量制限で不可となった（レス171）。課金騒動時にオープンソース側でコピーサイトができたがわからせられて勝ちきった経緯がある（レス185）。Diffusersライブラリの提供元でもあるとの言及（レス125）。

# Krea2 / Krea3

- **用途と制約**
  - LLMが考えたプロンプトを受け取り参照画像を作成するシステムのパーツとして使用される（レス696, 697）。版権・画風なしなら公開エロLoRAやエロチューンを使えば良いが素のKrea2ではエロが壊滅状態（レス823）。DLSS5のON/OFF指示テストが行われた（レス837）。360ERP機能でパノラマ風動画が作れる（レス561）。Krea3は企業向け秘密保持契約と思われる非公開発表会であり一般公開されるか不明（レス606, 609, 612, 614）。
- **選定理由**
  - 夕闇通り探検隊のようなパノラマ動画やERP動画が作れる点（レス561）。

# WAN2.2（VACE）

- **動画結合機能**
  - 動画同士の結合において10erosよりもWAN2.2のVACE結合の方が良いという評価（レス184）。選定理由もこの結合品質の優位性による。

# 画像編集ツール（Photoshop / Affinity）

- **透過背景処理**
  - NAI5の透過背景は輪郭がグズグズになるため使わなくなった。Photoshopなら超簡単にでき、月額が嫌ならAffinityでも良い（レス192, 194）。選定理由は透過背景の輪郭処理が超簡単にできる点。

# VRM変換ツール・モーション作成ツール

- 3Dモデル自体は転がっているがお手軽なVRM形式への変換ツールがないため面倒（レス175）。モデリング・アニメーション製作ツールの有名企業は有料提供であり一般人向けは期待できない（レス74）。

# 総評

1. ComfyUIは`--fast-disk`や`--disable-pinned-memory`等の起動オプション、H3 optimizationsのLimiter・Memory Optimization・SparseAttentionの組み合わせで、VRAM5GB削減と生成時間半減を同時に実現できるとの実証報告が複数あり、VRAMカツカツ環境での実行基盤として選定されている。
2. ローカルLLM推論ツールは明確な使い分けが議論されており、freetokenはMoEモデル専ら・NVFP4/MXFP4対応で速く動くが3060クラスでは4.5t/sが限界、Denseモデルならbeellamaでkvキャッシュ量子化kvarn4が良く、LM StudioはマルチGPUのVRAM合算で31B・27Bが実用速度で動く点が選定理由となっている。
3. CodexはH3環境構築・ワークフロー作成の自動化からPCハードウェア作業の補助まで幅広くフル回転しており、ComfyUIのスクショを渡して専用UIを作らせる拡張性が期待されている一方、推論レベル「高」設定や無意味なPetsアプリへの注意喚起がある。
4. nano-bananaは単なるアップローダではなくソフト側が前提とするディレクトリ構造を持つエコシステムとして機能しており、無料DL提供の維持コストと容量制限・過去の課金騒動対処が運営上の制約として認識されている。
