## ComfyUI

### 省メモリ・高速化設定

- **SageAttention環境での最適化**: Limiter・Memory Optimization・Sparse Attentionをデフォルト設定で適用した結果、SageAttentionオンリーより生成時間が半分になりVRAMが5GB空いた。Sparse Attentionには劣化が伴うが、VRAMカツカツ勢ならLimiterとMemory Optimizationは入れておくべきとの推奨（>>243）
- **--disable-pinned-memory**: VRAMへの転送用領域の固定確保を無効化しRAMが空くが生成中のストリーミングが遅くなる。`--fast-disk`で空きができた場合は非推奨（>>704）
- **--reserve-vram**: ブラウザ切り替え等でOOMする環境向けに、Comfyが使うVRAM上限を減らす（>>704）
- **--vram-headroom**: VRAM消費見積もりに余裕を持たせる。見積もりが変で生成途中にOOMする環境向け（>>704）
- **--fast と --fast-disk は別物**: ずっと`--fast`を使っていたユーザーが別物と認識（>>772）
- ** SparseAttention等の適用について**: 全適用すればVRAMが5GB近く空いた上に2倍速になるとの主張。サードパーティー省メモリ高速化の決定版のようなパックと評価されるが、劣化の程度次第（>>94）

### アップデート・互換性

- **デスクトップ版アップデート**: H3ワークフローにTurboが標準で組み込まれ、ノイズシードが外に出る等の改善（>>619）
- **アップデートに対する姿勢の変化**: 以前は環境壊しを惧れてアップデートを躊躇していたが、性能向上・信頼性向上でカスタムノードの切り捨ても割り切って更新するようになった（>>621-622）
- **最新版でのノード互換性**: 最新化で使えなくなるノードが出るかの懸念（>>234）
- **0.34.0でContexLoopのNative対応**が入ったという情報（>>740）

### LoRAロード・カスタムノード

- **LoRAロード問題**: 標準LoraLoaderで`lora key not loaded: diffusion_model.final_layer.audio_out.set_bias`のエラーが出てロードできずカスタムノードが必要な状態。`git fetch origin pull/15908/head:pdd-fix && git checkout pdd-fix`で標準LoraLoaderでAcc-Loraが動くようになった（>>269, >>271, >>278）
- **PDD LoRA対応**: comfyuiのコミットログでPDD LoRA対応を確認。ただし中途半端なタイミングでpullするとトラブルになるためバージョンタグが付くまで待つべきとの見解（>>914）
- **PDD Acc**: カスタムノードを入れて使用。音やプロンプトの忠実度は他のターボより良いが映像がグチャる。幾何学模様が崩れるのは致命的との評価（>>916）

### 8step LoRA

- **minimax_h3_fl2v_turbo_8step**: 4stepでは微妙なものが多かったため8stepのものが欲しかった（>>186, >>190）
- **kijai版Turbo LoRA**: アリババがminimax用に出したターボローラをkijaiがcomfy用に調整したものが公開された（>>593）。ただしComfyUI対応がまだ未対応の様子とも（>>188）

### ワークフロー・運用

- **ComfyUI公式テンプレ**: 生成しかできないとの指摘あり（>>936）。初心者がdasiwaのワークフローを丸パクリするか公式テンプレを使うべきかの議論（>>934-935）
- **T2VA/I2VAでのループGIF生成**: ループGIFを生成するワークフローを提示。動画生成ワークフローの強みが輝くとの感想（>>849, >>858）。背景透過してデスクトップに表示させれば癒しになり、electron等で作ればよいとの提案（>>859, >>861）
- **Qwen-image-editのポーズ置換**: 公式テンプレワークフローで試したがポーズも人物も別人になった（>>784, >>787）
- **APIを叩いて動かせるため**、フロントを作ってLLMに投げる一連のシステムをAIに作らせることが可能（>>728）
- **JXL保存対応**をデフォルトで希望する声（>>797）
- **ROCm 10.0がComfyUI最適化を拡張**。Wan2.2、FLUX.2 KLEIN、SD3.5 Medium等のパフォーマンスを最適化（>>818）

### 選定理由

- アップデートで性能向上・信頼性向上が進み更新しない理由が減った。動画生成やローカルLLM同時使用でForge等より拡張性が高い（>>621-622, >>728, >>763）

## 総評

1. **ComfyUIの省メモリ最適化が実用的レベルに到達**: Limiter・Memory Optimization・Sparse Attentionの全適用でVRAM 5GB節約＋2倍速が実現し、起動オプション（`--disable-pinned-memory`, `--reserve-vram`, `--vram-headroom`等）と組み合わせてVRAMカツカツ環境でも実用可能との報告が複数ある。ただしSparse Attentionの劣化やストリーミング遅延にはトレードオフが存在する。

2. **ローカルLLM×動画生成の連携が「3台分散」に収束**: 1台で全てを同時実行するとRAM 128GBでも足りずモデルロード/アンロードの繰り返しでやる気を失うため、GPUごとに役割を分ける3台分散構成（画像生成機＋動画生成機＋LLM機）が現実解として機能している。LM StudioのVRAM合算がGPU2枚挿しの最大メリットと認識されている。

3. **Codexが環境構築・ワークフロー自動構築を実用的にこなす**: H3の環境構築からワークフロー作成まで一括指示で対応可能。GitHubリポジトリを渡すことで余計な検索を減らせる。実作業をcodex・思考をchatgptで分離して自動化するツールも既に存在する。Codex Petsのデスクトップ常駐アイコンは機能せずほぼ意味がないとの報告。

4. **動画結合・参照ツールでWAN2.2 VACE結合が優位**: 10erosよりWAN2.2 VACE結合の方が品質が良いと判定。ref2v/i2vでは動画参照が一番クオリティ高いが時間がかかるというトレードオフがあり、MysticXXXのようにリファレンス不要で楽なツールも選ばれている。
