# 生成AI関連「ツール」話題抽出レポート

## 1. ComfyUI (comfy)
- **環境構築とシステム構成**
  - Python3.9やPytorch2.6を用いたインストールに関する話題が出ている (641)。
  - 動画生成やローカルLLMを同時使用するようになるとRAM消費が激しくなり、comfyを3つ同時に開く猛者もおり、RAM64gbでは天元突破してフリーズするケースがある (646, 660, 673)。
  - ComfyUI0.34.0でContexLoopのNative対応が入ったという報告がある (740)。
  - コンソールのログメッセージに時刻をつける方法についての問い合わせがある (764)。

- **起動オプションに関する解説**
  - `--fast-disk`：デフォルトの「RAMにモデルデータを詰め込む」狂った制御を切り、RAM64GBでの問題を解消する。SSDの寿命延長にも有効 (704, 772)。
  - `--disable-pinned-memory`：VRAM転送用の固定領域を解除しRAMを空けるが、生成中のストリーミングが遅くなるため非推奨 (704)。
  - `--reserve-vram` / `--vram-headroom`：画面表示や他アプリによるOOMを防ぐためのVRAM管理オプション (704)。

- **選ばれている理由と運用**
  - H3等の動画生成モデルを動かす環境として「ComfyUI入れるだけ」で標準的だが、A1111ライクなUIを好む層には不満がある。しかし、APIを叩いてフロントを作りLLMに処理を投げる一連のシステムをAI(Codex等)に作らせるなど拡張性が高い (728, 763)。
  - MiniMax-H3等を動かすためにComfyUIを使用し、VRAM16G環境でもint8版モデル等で運用している (737, 832)。
  - ComfyがデフォルトでJXLで保存できるようになることへの期待がある (797)。
  - ROCm 10.0でComfyUIの最適化が拡大され、Wan2.2等のモデルでパフォーマンス向上が図られている (818)。

## 2. Image-studio
- 画像のポーズだけを変えたい用途で使用されるが、reference editワークフローで画像2枚を入れてもポーズ反映されず、どちらかの画像が出力されるだけという不具合が報告されている (655)。

## 3. Krea2
- LLMが考えたエロプロンプトを受け取り参照画像を作成するシステムのパーツとして使用されている (696, 697)。
- 版権・画風なしなら公開されているエロLoRAやエロチューンを使えばOKだが、素のKrea2だとエロが壊滅しており使い物にならないという指摘がある (823)。

## 4. LM Studio
- ローカルLLM（Qwen3.8-27B等）を動かすために使用されている (660, 737, 832)。
- ComfyUIやForgeと同時に起動して運用されるが、RAMを大きく消費するためメモリ容量が課題となる (660)。

## 5. Codex / Codex Pets
- ローカルLLMを併用前提にし、画像選別や整理のシステム、エロプロンプト生成の意図を設計させる用途で使われる (674)。
- H3環境の構築やワークフロー作成を自動化でき、GitHubのリポジトリやHuggingFaceのモデルを指定してインストールからワークフロー作成までこなす (761, 765, 770)。
- A1111ライクなUIが欲しい場合、ComfyUIの機能スクショを渡して「何が欲しいか」を入力すれば自分専用のUIを作ってくれるという期待がある (763)。
- 推論レベルを「高」にしてしまうと一生終わらなくなるという注意点がある (725)。
- 「Codex Pets」というデスクトップ常駐アイコンアプリはクリックしても会話できずほぼ意味を為さないと評価されている (781)。

## 6. EasyWan / aitag.win
- 1年前にZuntanニキが提供したEasyWanを使用していたという過去の振り返りがある (832)。
- aitag.winというツール（サイト）が復活したという報告がある (800)。

## 7. その他関連ツール・環境
- **SDXLベンチマーク / int8 convrot**：5060Ti等のGPU性能比較に使用される (645)。
- **OpenClaw / AIライザ**：PC処理を何でもやってくれるソフトとして期待されている (690)。
