# 生成AI関連「ツール」話題抽出レポート

## ComfyUI

### 基本動作・環境構築

- **最新版でのノード互換性**: ComfyUIを最新にした際、使えなくなるノードが出るかどうかの懸念が提示された（>>234）

- **起動オプションによるメモリ削減**: `--disable-pinned-memory`を起動オプションに追加することで、使用メモリが減り生成時間も変わらないという報告。ただし生成時間は1〜2割増えるとの指摘もあり、`--fastdisk`を付けている場合はメモリを使わずSSDからVRAMへロードするため、`--disable-pinned-memory`の有無で生成時間が変わらない可能性がある。生成でメモリ限界近くまで消費する場合はpinned memoryを切った方が良いとの見解（>>259, >>297, >>302, >>304, >>305）

- **SageAttention環境での最適化**: SageAttention環境でLimiterとMemory OptimizationとSparse Attentionをデフォルト設定のままつなげたところ、SageAttentionオンリーより生成時間が半分になりVRAMが5GB空いた。Sparse Attentionは劣化を伴うが、VRAMカツカツ勢ならLimiterとMemory Optimizationは入れておくべきとの推奨（>>243）

- **ComfyUI上でのLoRAロード問題**: 標準のComfyUIのUNet/DiT構造に合わせた`末尾_comfy版`は使える可能性があるとの指摘（>>258）。実際に試したが`lora key not loaded: diffusion_model.final_layer.audio_out.set_bias`のエラーが出てロードできず、カスタムノードが必要な状態。最終的に`git fetch origin pull/15908/head:pdd-fix && git checkout pdd-fix`で標準LoraLoaderでAcc-Loraが動くようになった（>>269, >>271, >>278）

- **H3 optimizationsの検証**: デフォルト値で実行したところ、速度はSol attn + SLAと同程度だったとの報告（>>250）

- **解像度の設定**: SDXL時代からAnimaを使用しており832x1216のような1024^2の解像度で作成しているが、pixivの投稿では1024x1536のような1536^2の解像度を使うユーザーが多く不安になったという声。こだわりがない時は1536x1152を使用。hakushiMixでは2048x1024も使用するという報告もあり。同じプロンプトでも解像度によってポージングが異なるため、縦長・横長・標準など数種類出している（>>283, >>285, >>291, >>350）

- **Krea2でのキャラLoRA作成**: Krea2でキャラLoRAを作成中。ahogeなどの要素は元が覚えてくれていないため精度が下がり、データセットの見直しが必要との報告（>>327）

## Discord

- **AI成果物の共有場所としてのDiscord**: DiscordサーバーでのAI成果物の貼り合いはイマイチ流行らない。反応が見たいならSNSや掲示板に貼って大勢に見てもらった方が良いとの指摘。閉じたコミュニティのチャットツールでは身内の反応しか返ってこないため。ただしエロ絵の貼り合いが盛んなのはエロDiscordが存在するとの話（>>409, >>412, >>414）

## 選定理由の推測・背景

- ComfyUIはカスタムノードの制約や最新版への追従で互換性問題が度々発生するが、標準LoraLoader等で対応可能なケースがある（>>269, >>278）
- `--disable-pinned-memory`はメモリ消費を抑えつつ生成時間への影響を最小限にできるため、VRAMカツカツ環境で有用（>>259, >>304, >>305）
- フリートークンは3060/16GB RAMでは31Bモデルすら動かず、llamaエンジンで4.5t/sが限界というハードウェア制約が選定に関与（>>293）
