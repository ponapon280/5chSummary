# なんJ掲示板ログ要約レポート

## 1. ハードウェア・パフォーマンスに関する議論

### GPU・VRAM構成
- **5060Ti 16GBへの乗り換え**: 3060 12GBから5060Ti 16GBへの変更でAnimaの生成速度は変わるかという疑問に対し、Animaはbf16かint8 convrotを使用するため、ちもろぐのSDXLベンチマーク性能比とほぼ同じで「5060Tiが3060の1.5倍程度」との見方がある（レス645）。5000番台はfp8とint8両方に対応しているため、int8 convrotの性能はきっちり出るとされる（レス640, 645）。
- **2GPU運用のメリット**: フルタワーPCで電源1000W以上を積めるなら、5060Tiを買い増しして2GPU運用にすれば、gemma4-31BやQwen3.8-27Bも実用的な速度とコンテキスト量で使えるとの報告がある（レス783）。ただし、5090等をフルで回す際の排熱やケースの対応能力が懸念される（レス723）。
- **MacのRAM拡張**: Macの512GB購入に悩む声がある。1〜2年のうちに凄いAIモデルが出ると予想され、買えない価格になりそうとの理由（レス699）。

### メモリ（RAM）要件と起動オプション
- **RAM容量の目安**: 64GBで足りないという声（レス648）がある一方、LMStudioとForge×2、ComfyUIと多数のタブを開くと64GBでフリーズするという運用実態が報告されている（レス660）。動画生成やMiniMaxを動かす場合は64GBでは少ないとの意見（レス665, 689）。
- **ComfyUI起動引数のまとめ**: RAM不足に対する有効な対策として以下の起動オプションが提示された（レス704, 732）。
  - `--fast-disk`: ComfyUIのデフォルトの「なるべくRAMにモデルデータを詰め込む」という制御を切り、HDD発狂を防ぐ。RAM64GBで問題なくなるとのこと。
  - `--disable-pinned-memory`: VRAMへの転送用領域の固定確保を解除し、RAMを空ける。ただし生成速度は遅くなるため、fast-diskで空きができた場合は非推奨。
  - `--reserve-vram`: 画面表示の消費分としてVRAMの上限を減らす。ブラウザ切り替え等でOOMする環境向け。
  - `--vram-headroom`: VRAM消費量の見積もりに余裕を持たせる。
- **pinned memoryについて**: Windowsではメモリの40%を固定確保する仕様であり、96GBや128GBあれば問題ないが、32GBだと命取りになる。メモリ価格が暴騰しているのが問題点と指摘されている（レス691, 695）。

## 2. ローカルLLMの比較と用途

### Qwen 3.8 27B と Gemma 4 31B
- **Qwen 3.8 27B**: 
  - コーディング用途や指示遵守に優れるが、日本語やサブカル系の知識が壊滅的でクリエイティブ用途には不向きという評価（レス708, 760）。長文出力させると後半で英語になる不具合（レス759）。推論レベルをmediumにしないと長考する（レス755）。VRAM16GB環境では、推論時に延々と考え込む事象が発生している（レス758）。速度は「80トークン秒」（レス724）。
- **Gemma 4 31B**: 
  - エロチャットやエロプロンプト作成に適し、ユーザーの意図を汲んでくれるとの評価（レス724, 726, 739, 742）。ただし「35トークン秒」と遅く、画像生成との併用は難しい（レス724, 756）。
- **スレ上の評価のまとめ**: 「Qwenは理系・事務・指示を守る、Gemmaは文系・営業・意図を読む」との比喩で説明されている（レス751, 756, 776）。両方入れて用途で使い分けるのが推奨される（レス751）。

### API vs ローカル
- プロンプト生成をローカルLLMにやらせるより、負荷分散の観点からクラウドAPIに任せる方が良いとの意見（レス728）。ただし、西洋の基準に抵触してIDやアカウントがBANされるリスク（デジタルタトゥー）を避けるため、エロ系のプロンプトや性癖を投げる場合はローカルLLMが選ばれる（レス741, 754, 788）。

## 3. 画像・動画生成モデルとツール

### NAI (NovelAI) v5
- 日本語で指示してセリフも日本語で出せる点が進歩と評価されている（レス715）。スレ上ではV5は「Qwen 3.5」を利用しているという噂がある（レス719）。絵師タグを使わずとも塗りや顔の形状を力業でプロンプト指定して出せる点が驚かれている（レス830）。また、NAIのプロンプトがリークされた画像が貼られ、プロンプトに「sample」と入力すれば無修正画像が出せるという悪用手法が話題に上がった（レス813, 816）。

### Anima / Krea2 / anytest
- **Anima**: プロンプトが独自の方言（anima語）のようになっており、自分で書くのが一番とされる（レス775）。Anima3.8Bをsd-scriptに組み込むと要求スペックが上がりVRAM16GBからRAMに溢れるため、量子化やBlock to swapが必須。構造的にLoRAがほぼ非互換となり、苦労するならKrea2の方がマシかもしれないとの見解（レス798）。
- **Krea2**: 版権・画風なしなら公開されているエロLoRA等で対応可能だが、素のKrea2ではエロが壊滅的。学習コスト面からRawとTurboがセットで公開される見込みは薄いとされている（レス823）。
- **anytest**: AnimaではanytestのためにILを続けている声がある一方（レス686）、AnimaのanytestはILほど効かないとの指摘もある（レス684）。

### MiniMax H3
- **H3 Eros Max beta3**: 試用結果として、特に2次エロでグロい結果が出にくくなった印象との報告（レス768）。
- **H3 Max**: 別会社のファインチューンモデル。Grokの情報によるとAPIのみの提供で、速度が売りだが768pxまでとの制限がある（レス807）。1stepで生成される可能性が示唆されている（レス737）。
- **VRAM16GB環境での運用**: LM StudioでQwen3.8にプロンプトを生成させ、ComfyUIでH3チェックポイント（int8, 8step）を使用して10秒動画生成を行い、高いクオリティが実現できている事例（レス737）。

### その他のツール・技術
- **DLSS5**: 特定のゲームからリークしたDLLファイルで映像の次元が変わるとの話題。AI生成への応用が期待されている（レス814）。
- **JPEG XL**: 2026年内に主要ブラウザが正式採用予定。ComfyUIでのデフォルト保存対応が望まれている（レス797）。
- **aitag.win**: 復旧したとの報告（レス800, 808）。
- **Qwen-image-edit**: ComfyUIのワークフローで、画像1の人物のポーズを画像2に合わせる手法としてプロンプト指示が提案された（レス662）。ただし別人になる不具合報告あり（レス784）。

## 4. その他の話題・スレ動向
- **髪の毛（剛毛）**: 2次画像で剛毛にすると毎回同じ形になる問題が指摘され、様々な毛を学習させたモデルが出るべきとの意見。スレ上では「sparse pubic hair」推奨派が多い（レス659, 675, 676, 678）。
- **エージェントAIの活用**: PCを遊ばせておくのが勿体ないため、画像選別をローカルLLMに補助させる、または自分の分身として掲示板等で活動させるアイデアが議論された（レス668, 670, 674）。OpenClawやAIライザのようなソフトへの関心（レス690）。
- **GPUの寿命と電気代**: 画像生成を常時回しているとグラボが3年持たない懸念。PL70設定で24時間回し、暖房代の節約兼用とする運用実態（レス661, 690）。
- **不和・荒らし**: ロリ画像を貼るレスに対し、唐突に激昂するユーザーが存在し、スレが険悪になる事象が発生（レス786, 790, 791）。
