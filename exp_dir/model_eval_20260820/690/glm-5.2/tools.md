# 生成AI関連ツールに関するレポート

## 1. 画像・動画生成環境（ComfyUI / WebUI / Forge）

### ComfyUI
ComfyUIは画像・動画生成の基盤として多くのユーザーに利用されており、様々な目的で選択されています。

*   **公式テンプレートの利用とワークフローの扱い**（>>161, 163, 166, 175, 180-183）
    MiniMax H3 Remix等の動画生成において、専用ワークフローや謎のカスタムノードを導入するのは複雑で分かりにくいため、「ComfyUI公式テンプレでいい」と選ばれる傾向にあります。また、Context Loopという機能については、ComfyUIのNative対応を待たないとフルセットで使えないため、現状は専用ワークフローを探してもヒットしない状況とされています。
*   **kijaiのcomfy-kitchenによる高速化**（>>161, 163, 166, 175, 180-183, 189, 190, 192-194, 210, 213, 215, 219-221, 224, 225, 359）
    動画生成の高速化のため、kijaiの作成したcomfy-kitchenが「神がかっているため」利用されています。pr117更新で処理が速くなり、Sol-Atten（Sparse Attention等の高速化機能）のノード（`sol_attn_minimax_v3.py`など）を追加で利用することで、モデルや解像度を落とさずに劇的に生成時間を短縮できると評価されています。ただし、RTX 50xx系の環境ではSage Attentionと比較して恩恵をあまり感じられないケースもあるという報告もあります。初期状態に入っている「Comfy Kitchen Attention」ノードと「Patch Sol-Attn(Minimax)」を組み合わせる手法が紹介されています。
*   **メモリ速度と動画生成の関係**（>>195, 197, 198, 217）
    メモリを4枚刺し（192GB）に増設して動作周波数が低下（5600MT/S→3600MT/S）した場合の影響について検証したユーザーからは、「ComfyUIでの生成速度は誤差の数秒程度しか変わらない」「モデルオフロード用途ならPCIeがボトルネックになるから気にしなくていい」との報告があり、ComfyUIで動かす場合にはメモリ速度の低下による影響は少ないとされています。
*   **VRAM不足の解消・LLM連携**（>>229, 245, 251, 316, 627）
    グラボのVRAMが不足している場合、ComfyUI上でLLMのモデル即時解放を行うためにノードが探されます。OllamaのモデルはComfyUIを終了しても解放されないため、カスタムノードで`keep_alive="0s"`の引数を追加することでVRAMを解放できるという知見が共有されています。また、「Deno Local LLM Loader」ノードを使ってローカルLLMをロードし、日本語の指示を英語プロンプトに整形させて動画生成モデルに直接繋げるワークフローを構築するためにも選ばれています。一方で、ワークフロー内でOllamaを用いてプロンプトを生成しようとするとハングアップして異常なループプロンプトを返す不具合に悩まされる報告もあります。
*   **API・NAIノードの利用**（>>305, 別ログ）
    自前でバックエンドとしてComfyUIを叩き、チャットで会話しながら生成できる自作ツールを作って利用している事例や、NAIのAPIを使って重めのローカルLLMと同時進行で画像生成を行うためにComfyUIにNAIノードを導入する事例があります。
*   **超解像拡大とトラブル**（>>932, 935）
    一般的なグラボがあれば、ComfyUI上で3ノード程度の簡単な構成で超解像拡大が可能です。ただし、BIOSでグラフィック設定をいじった後に画像生成しようとすると、ハードフォールトを起こして灰色の画像しか生成されなくなるトラブル事例も報告されています。

### SD WebUI (A1111)
*   **未だに使い続ける理由と自動化**（>>304, 別ログ）
    「未だにSDwebuiから逃れられない」という感想が挙がっており、ComfyUIなどへ移行できずに使い続けているユーザーが一定数いることが示唆されています。また、A1111のダイナミックプロンプトやChromeの拡張機能で.txtからワイルドカードを呼び出し、無限生成を行う目的で使われています。API経由で利用することで、WebUI上でダイナミックプロンプトを使ったランダム性を持たせた無限生成が可能になるため選ばれています。

### Forge (forge neo)
*   **モデル利用とトラブルシューティング**（別ログ>>445, 458）
    Forge上で特定モデルを使用しようとした際、真っ黒な画面しか出てこない不具合が相談されました。Forge neoがサイレントでアップデートされており、対応する拡張機能をGitHubから導入する必要があることや、TE（Text Encoder）やVAEの設定、アダプターの配置に関する技術的ノウハウが語られています。

### Stabilitymatrix
*   **環境管理ツールとしての利用**（>>935）
    ComfyUIでエラーが起きた際に、Stabilitymatrixのコンソールを確認することでVRAM/RAMの状態やPytorchのバージョンなどのログをチェックする目的で使われています。

## 2. 動画生成AI・関連機能

### MiniMax / MinimaxH3
*   **選ばれている理由**（>>112, 113, 118, 133, 135, 143, 151, 156, 160, 196, 203, 209, 216, 573, 574, 575, 別ログ）
    動画生成において「seedance2.5は頭一つ抜きん出ている」ものの、中国系サービスで信用性に懸念があるため、MiniMaxが選ばれる傾向にあります。MiniMaxは「リップシンクがすごい」「3DCG風が得意」「原神などの中国系版権物の再現度が高い」「実写だと手ブレ等の指示でリアルになる」などと評価されています。プロンプトの指示追従性が高く、コントロールネットが追加されたというアップデート話題も報告されています。
*   **プロンプトの工夫**（>>112, 113, 118, 133, 135, 143, 151, 156, 160, 196, 203, 209, 216, 573, 575）
    性器がグロテスクになる問題に対し、直接的な単語を使わず「股の間」などに誤魔化してR2Vを活用することで改善が見られるなど、ツールの仕様に合わせたプロンプトの工夫が盛んです。GrokなどのLLMにプロンプトを作成させても微妙な指示を出すため、別途最適化する必要があるという課題や、LTXでアップスケールする際に漢字を読めない不具合があるためH3の音声出力をそのまま使用した方が良いという知見も語られています。

### MiniMax R2V (Reference to Video)
*   **選ばれている理由**（>>54, 132, 145, 149, 196, 209, 216）
    アニメ生成時にキャラクターを参照画像にして生成する機能です。デフォルトで参照画像に合わせたスタイルで動画を作る仕様になっているため、画風やキャラの維持に利用されています。また、下半身のリファレンス画像を渡すことで、局部的な描写崩れを防ぐ用途にも使われています。

## 3. ローカルLLM・プロンプト生成ツール

### FreeToken (FreeTalk / freetorkun)
*   **選ばれている理由**（>>504, 507, 522, 525, 554, 565, 891, 別ログ）
    VRAMが不足していても、SSDからストリーミングするよりも圧倒的に高速な25 tok/sでDRAMからストリーミング生成できるため、ローカルLLMのハードルが大幅に下がる注目の技術として頻繁に言及されています。MoEのexpert部分を選択的に動的にVRAMに配置する仕組みを入れた点が画期的であり、計算効率が良いと評価されています。RTX 5090一枚で120Bモデルが実用的な速さで動かせる点や、もう1台の5090をプロンプト生成用として有効的に動かせるためリソースの有効活用に繋がるから選ばれています。一方で、ロード時にattention/dense部分を一度VRAMに展開する必要があるためVRAMを消費する点や、現在は非検閲の巨大モデルを使いたい層向けであるといった課題も指摘されています。

### llama.cpp
*   **選ばれている理由**（>>516, 512, 554）
    ComfyUIで画像生成を行っている合間に、ローカルLLMを動かし、100 tok/s越えの速度でthinking処理を行わせる用途で使われています。VRAMに収まるモデルであればFreeTokenより速いと評されています。将来的にllama.cpp側でもexpertの動的VRAMロードが実装される可能性が語られています。

### Ollama
*   **選ばれている理由・課題**（>>627, 229）
    ComfyUIのワークフロー内でプロンプトを生成するために利用されていますが、ハングアップして異常なループプロンプトを返す不具合に悩まされる報告があり、Ollama optionsのノードで制限をかけても改善しないという問題があります。

### DeepSeek API
*   **選ばれている理由**（>>124）
    画像が読めるようになったため、プロンプト作りがはかどるツールとして利用されています。

### Qwenシリーズ / JoyCaption / Florence2
*   **選ばれている理由**（別ログ, >>931）
    ローカル環境でエロシチューションの自然言語を英語のプロンプトに変換して渡すためにQwenシリーズが使用されています。ただし、システムプロンプトが長いとループにハマる問題が発生しやすく、運用上の工夫が必要です。画像認識やTaggerとしてはJoyCaptionやFlorence2で十分という意見もあります。また、「MiniMax H3のプロンプト作成をより簡単にするため」のノードとしてQwen 3.8ベースのプロンプターノードが使われています。

### Codex / 無料GPT
*   **選ばれている理由**（>>25, 別ログ）
    ローカルAPIを使えるハーネスの話をするだけであれば、Codexを使わなくても無料のGPTで十分であるため選ばれています。また、ローカル環境構築が苦手な人でも、Codexを使えば簡単にNSFWできるローカル環境が作れるため利用されています。

## 4. 学習・専用ツール・編集ソフト

### sd-scripts (kohya)
*   **選ばれている理由**（>>90, 98, 212）
    LoRAを作成・学習させるためのツールとして利用されています。層の数（num_blocks）を自動検出にするか指定すれば、新しいモデルでもLoRA学習ができるため重宝されています。プルリクエストにモデル対応のコードが上がっていることもあり、情報参照先として使われています。

### Mystic LoRA / Turbo LoRA / 4step LoRA
*   **選ばれている理由**（>>145, 147, 209）
    動画生成・画像生成の高速化や補助に用いられています。i2vaで局部を描かせる際にはMystic LoRAを強度0.6でぶち込む手法が紹介されています。

### AviUtl / x264guiEx
*   **選ばれている理由**（>>153, 165）
    動画にモザイクをかけるために使用されます。アップロード先の弾き（ファイルサイズ・形式対策）を回避するため、AviUtlのプラグイン出力（x264guiEx）で「ニコ動設定（30分以下）」を用いてH264圧縮のmp4を作成する手法が紹介されています。動画配信では一般的な手法であるため選ばれています。

### Autodepth Image Viewer
*   **選ばれている理由**（>>424）
    1枚絵から擬似的に立体視（深度マップ）を作成するためのツールとして愛用されています。「コイカツVR」などの3Dソフトよりも手軽であり、生成したエロ画像との相性が良いため選ばれています。

### Krea2 (Krea)
*   **選ばれている理由**（>>441, 478, 499）
    マッサージ台の女性に性的な行為をさせる実写画像生成や、アニメモデルのリリース待ち、RTX 5090環境でKrea2のLoRAを作成する運用のために利用されています。

### アップスケーラー（超解像拡大ツール全般 / Topaz）
*   **選ばれている理由・課題**（>>961, 949, 962, 985）
    「Topaz」が映像やCG系でそこそこ知られているツールとして挙げられています。AIを使った単純な超解率拡大は、元データが無い場合に「引き延ばして滑らかにする」手段として全然使えるという意見がある一方で、アプスケモデルが「勝手に解釈して描いてしまう（影や唇の表現を消したり、勝手に光源を設定して影を描いたりする）」ため、細部の表現が破綻するという批判的な意見もあります。

### クリスタ (CLIP STUDIO PAINT) / Affinity
*   **選ばれている理由**（別ログ）
    おっさんが手動でフキダシや文字入れをすると絵と文字が「浮いて」しまうため、AIの機能に任せる方が自然で早いという理由で使われます。クリスタやAffinityにはマクロ機能があり、単純作業を登録すれば一瞬で終わるため、AI生成後にこちらで編集する手段も選ばれています。

## 5. 企業・一般利用向けAIツール
*   **Copilot / ChatGPT / Gemini / Claude / チャッピー**
    企業的なセキュリティや情報漏洩リスクを考慮し、フィルタリング機能があるCopilotが許可・推奨されています。用途に応じて「アレはアイツでコレはコイツ」と複数のAIツールを使い分けるのが仕事ができる人の特徴とされています。VS2017のトラブルシューティングでは、ChatGPTやGeminiでは解決できなかった問題がClaudeによって解決されたというエピソードもあります。大学などで提供されるGeminiは使い物にならないと不評の声があります。
