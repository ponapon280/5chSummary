# 生成AI関連ツールに関するレポート

スレッドにて議論された生成AI関連ツールについて、各ツールの選定理由や評価、活用方法を取りまとめた。

## 1. 画像・動画生成環境・フロントエンド

### ComfyUI
ComfyUIは新しいモデルやLoRAを動かすためのハブとして機能しており、多くのユーザーに利用されている（レス188, 186）。選ばれている理由として、VRAM消費の最適化や細かな制御を行う上で必須のツールとなっている点が挙げられる（レス94）。VRAMがカツカツな環境でも生成を安定させるため、起動オプションでメモリ削減の設定が使われている（レス259）。例えば、「`--disable-pinned-memory`」を入れることで使用メモリが減り生成時間も変わらないという報告がある（レス259）。「`--fast-disk`」を用いればデフォルトの「RAMにモデルデータを詰め込む」制御を切りRAM消費を抑えられるが、「`--disable-pinned-memory`」と組み合わせると生成速度が遅くなるため非推奨とされている（レス704, 732, 772）。

また、標準機能では対応できない新しいモデルを動かすためにカスタムノードやワークフローが利用されている（レス258, 266, 271）。一方で、ComfyUIのアップデートに追従できないカスタムノードは切り捨てるかCodex等で対応する割り切った運用がなされている（レス621, 622）。ComfyUIのノード式UIを嫌う一定数のユーザーからは「A1111ライクのUIじゃないとダ目」との声もあり（レス763）、AI（Codex等）にUIスクショを渡して自分専用のUIを作らせる活用法も提案された（レス763）。

### WebUI / Stability matrix
Stability matrixを用いてLaunchし画像生成をすると、SSDにsystemとchrome.exeの読み書きが発生する挙動について疑問が提示され、解説がなされた（レス503, 511, 514, 521）。

### Image-studio
画像のポーズだけを変える用途で「reference editワークフロー」が試されているが、意図通りにポーズが反映されないという課題が挙げられている（レス655）。

## 2. 動画編集・生成支援ツール

### 動画結合機能（10eros / WAN2.2のVACE結合 / T2VA・I2VA）
動画同士の結合において、「WAN2.2のVACE結合」の方が「10eros」よりも普通に良いと評価されている（レス184）。また、T2VA／I2VAでループGIFを生成するワークフローは面白く、動画生成においてワークフローの強みが輝くとの報告があった（レス849, 858）。

### EasyWan (Zuntan)
1年前にWanの環境構築に利用されていたツールとして言及された（レス832）。

## 3. 画像編集・加工ツール

### フォトショップ / Affinity
AI生成画像の透過背景処理などで輪郭が崩れる問題がある際、「フォトショップ」を使えば超簡単に処理できると評価されている（レス194）。月額料金が嫌な場合は「Affinity」でも良いという提案がなされた（レス194）。AI画像生成では苦手なレタッチ作業をツール側で手軽かつ高精度に補正できるため選ばれている。

## 4. 3Dモデル変換ツール

### VRM形式への変換ツール
3Dモデル自体はネット上に転がっているものの、お手軽なVRM形式などへの変換ツールがないため、準備がわりと面倒になっているという課題が挙げられている（レス175）。3DモデルをAIチャット等で使いやすい形に落とし込むために不可欠だが、お手軽なツールが存在しないことが問題点として指摘された。

## 5. LLM・テキスト生成ツール・エンジン

### LM Studio
ローカルLLMを動かし、画像・動画生成用のプロンプトを生成させるために使われている（レス737, 754）。ComfyUIで生成中にLM Studioを使ってプロンプトの推敲ができるというメリットがあり（レス889, 890）、VRAM16GB環境でもiq4_xs量子化モデルを動かせる（レス832）。また、GPUを2枚挿しにすることでVRAMが合算され、Gemma4の31BやQwen3.8の27Bが実用的な速度で動くという報告があった（レス917）。一方でfreetokenのGGUF対応が来たらLMStudioを使わなくなりそうだという予測もある（レス843）。

### フリートークン (freetoken)
メモリがカツカツでもMoEモデルが速く動いてくれるため助かるという評価がある（レス843）。safetensors形式であることへの言及や（レス854）、NVFP4とMXFP4のモデルを動かした際に調子が良いという報告があった（レス856）。

### llama.cpp / beellama
ローカルのVRAM環境（3060など）に合わせて最適なエンジンや設定を選び、推論速度を稼ぐために利用されている（レス293）。MoEモデル以外の場合は別のエンジンを使ったほうが良く、「beellamaでkvキャッシュ量子化をkvarn4にするとかなり良い」という報告があった（レス312）。

## 6. プログラミング・エージェントツール

### Codex
プログラミングや環境構築、ハードウェアのデータ復旧といった複雑なタスクを自動化・代行してくれるほどの圧倒的な性能を備えているため選ばれている。ユーザーの父親の古いノートPCのデータ復旧やメモリ・ストレージの交換作業をフル回転で行い、「凄すぎて怖いレベルで何でもやってくれる」と評価されている（レス166）。また、LoRA作成時のエラー解消や（レス39）、ComfyUIのインストールやモデルのダウンロード、ワークフローの作成を自動で行わせる「エージェント」としての利用が期待されている（レス761, 765, 770）。ただし「推論レベルを高にすると一生終わらなくなる」といったクセの強さも語られている（レス725）。デスクトップ常駐版はただの常駐アイコンで会話もできずほぼ意味がないという厳しい評価もあった（レス781）。

### OpenClaw
PC処理を何でもかんでもやってくれるソフトとして関心が寄せられていた（レス690）。

## 7. AIチャット・LLMサービス

### Krea (Krea2 / Krea3)
Krea2は細部描画とパース理解、背景力が高く評価されているため選ばれている（レス339）。360ERPを用いることで360度パノラマ視点の映像やERP動画を作成できるという活用法があり（レス561, 604, 628）、LLMでエロプロンプトを出力させ、Krea2で参照画像を作るという自動生成ループの中に組み込まれている（レス696）。一方で、素の状態ではエロが壊滅的であるという評価もあった（レス823）。Krea3については非公開の発表会となっており、オープンソースと期待するとがっかりする雰囲気があるとされている（レス609, 612, 614）。

### Claude / Grok
精度が高く、エロ系やクリエイティブなプロンプト生成において理解力が高いため選ばれている（レス677, 690, 711等）。ローカルLLMでは限界があるため、APIや無料枠を利用する動機となっている。一方で、西洋の基準に抵触してBANされるリスクや、プロンプトが弾かれることが課題として挙げられている。また、Xのポストで何もしなくてもAI作成と全部自動でつけてくれていたが最近外れるようになり、grokで作ったものはちゃんとgrok表記されるとの報告があった（レス848）。

### ChatGPT / Copilot等の業務用AIツール
職場の業務環境において、ChatGPT/CodexやClaude Codeを直接使わせてもらっているという声がある（レス534）。Geminiは主にNotebookLMやAPIを叩くチャットボット、CopilotやCopilot StudioにPower Automateを組み合わせるなど、ツールごとの特徴に合わせて用途を使い分けているため選ばれている（レス534）。一方、鉄鋼メーカーなどで使えるAIツールが「ChatGPTもどきとCopilotのみ」に制限されており不便という声や（レス513）、社内開発のクオリティが低いAIソフトの利用を強いられるという苦情もあった（レス522）。

### その他LLMモデルの用途比較
スレッド内ではローカルLLMの特徴に応じた使い分けが語られている。Qwenはコーディングや指示を守る事務的な用途に優秀で「理系」と例えられる一方、日本語が弱くサブカル系の知識が壊滅的でクリエイティブ用途には不向きと評価されている（レス751, 752, 757, 760）。Gemmaはエロチャットやエロプロンプトの作成において意図を読み取って良い感じに考えてくれるため「文系」「営業」のようにクリエイティブ用途に相性が良いと評価されている（レス739, 752, 757）。

## 8. 検索・翻訳・その他ツール

### llmfit系のサイト
自分のPCスペックに合った量子化モデルや適切なエンジンを検索・選定するために利用されている。ただし「llmfit系のサイトは多すぎてどれがいいのかよく分からんな」との指摘もあった（レス238）。

### DeepL
LLMに書かせるほどではない程度のプロンプトを作る際にDeepLが使用されている。「POV」を「ハメ撮り」と訳したり、「吹く仕事」を「oral sex」と訳したりするなど、ツールとしての翻訳の面白さ・クセについて言及された（レス497）。

### Diffusers ライブラリ
Huggingfaceが出しているライブラリであり、Python環境等でモデルを直接扱う際の基盤となっているが、「古の動画モデルをいじった時に触った程度」「このスレではあまり馴染みがない」という声がある（レス131, 125）。

### Antigravity
裏で50MB/秒で書き込みを行っている正体として言及された（レス753）。

### aitag.win
復活したツール（タグ生成等）として喜びの声が挙がっている（レス800）。一方で、pixivに投稿しても消えないAI生成画像のメタデータを自動転載する時限爆弾のようなサイトであるという指摘や、規約的に自動で内容を取得するのは駄目っぽいとの見解も示された（レス949, 978）。
