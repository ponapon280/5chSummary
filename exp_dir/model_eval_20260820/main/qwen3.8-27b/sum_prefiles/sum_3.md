# 5ch「AI生成（画像・動画）」スレ レポート

## 1. 概要
本スレは、最新のAI動画生成技術（特にMiniMax H3）、画像生成（Anima、Krea等）、ローカルLLM（Qwen 3.8, Gemma 4, DeepSeek等）の運用環境や、その制作手法・倫理面について議論が行われている。
最近のMiniMax H3やQwen 3.8などの登場により、生成クオリティが劇的に向上し、ローカル環境でのVRAM負荷やコスト、プロンプトエンジニアリングの必要性、さらにはクラウドAIとローカルAIの優劣、そして「生成できること」と「評価・指示できる能力」の重要性が焦点となっている。

---

## 2. 主要トピックと議論の要点

### 2-1. 生成AI（動画・画像）の現状とMiniMax H3の評価
*   **MiniMax H3の圧倒的性能**: MiniMax H3が非常に高クオリティな動画を生成できることで話題。特に「細かな所作の要求」に応え、プロンプトの意図を正確に具現化できる点が評価されている。
*   **ワークフローと制御**:
    *   ComfyUI上でH3を使う場合、`int8`や`BF16`などの量子化/精度設定の議論がある。GPUが暇になる場合はint8推奨の声も。
    *   参照動画を入れると生成時間が2.5倍になるなどコストは高いが、一貫性のために利用するユーザーもいる。
    *   「部分修正（ガチャ直）」が難しいのが課題。そのため、ControlNet等で3Dプリビズを作成し、そこからv2v（Video to Video）で生成する手法が「最も手間がかからない」と指摘されている。
*   **アニメ vs フォトリアル**: フォトリアルは勝手に動いてしまう感があるが、アニメスタイル（Anima等）は指示しない限り動かないため、むしろ制御しやすいという意見。
*   **画像生成**: Anima, Krea, Qwenが混在し、出力フォルダの整理やLoRAの互換性（システム違いによる不可）が問題視されている。Save Image Extendノードによるフォルダ分類機能が活用されている。

### 2-2. ローカルLLMの動向とVRAM問題
*   **Qwen 3.8 (27B) の話題**:
    *   公開直後から海外で注目を集め、Opus 4.6並みのコーディング能力やエージェント能力を示したとされる。
    *   24GB VRAM（7900XTX）で60tok/s、または16GB VRAMカード単騎で動作する量子化版（11.7GB）が公開され、ローカル勢に大きなインパクト。
    *   日本語精度が保たれたまま軽量なため、画像キャプション生成やプロンプト作成に適しているとの見解。
*   **Gemma 4**:
    *   幅広い言語や文化的知識への理解で優位だが、日常使いには軽めの12BがVRAM的に快適。
    *   フリーダム（規制が緩い）なため、エロ用途のプロンプト作成にも活用可能。
*   **VRAMの壁**:
    *   高性能LLMをローカルで動かすにはVRAM24GB以上、理想は32GB以上が目安になりつつある。
    *   12GB〜16GBでは小規模なモデルになり、性能面でクラウドAI（Grok, Claude等）との差を感じやすい。
    *   「VRAMがないならRAMを積めばいいのでは？」という意見に対し、「統合メモリ（Unified Memory）のMacが売れている理由」や、「GPUのVRAM専用設計ゆえの制約」について議論。
*   **ローカル vs クラウド**:
    *   ローカルの利点は「プライバシー」と「大手の規制・価格改定に左右されない」点。
    *   だが、新モデル出現時の環境構築の煩雑さや、性能差から「結局クラウドを使う方が楽」という意見も多い。
    *   エロ用途では、クラウドAI（Grok, ChatGPT等）は検閲が厳しく、ローカルLLMや無検閲モデルが需要あり。ただし、ローカルLLMでのプロンプト生成は「イマイチ」で、結局Grok等で生成したものをローカルで補正するハイブリッド手法が主流。

### 2-3. プロンプトエンジニアリングと「センス」の再定義
*   **LLMによるプロンプト生成の普及**:
    *   Sora 2やGrokなどが「意図以上の動画」を作る裏側は、LLMが自動的に詳細なプロンプトを作成しているからだと指摘。
    *   ローカル環境でも同様に、画像や短い指示から詳細なプロンプトをLLMに生成させるワークフローが定着しつつある。
*   **「作れる」から「わかる」へ**:
    *   AIが誰でも生成物を出力できるようになった今、**「出力結果を評価し、改善させるための指示を出す能力（センス・言語化能力）」**が最も重要になるという結論。
    *   「正直飽きた」という荒らしコメントへの対応、あるいはAIへの指示が不正確な場合の結果として、生成物の質は利用者の実力に比例し続ける。
    *   車運転の比喩：「細かい構造（ワークフローの内部）を知らなくても乗れる（AIに任せている）」が、カスタマイズやトラブルシューティングには理解が必要。

### 2-4. 倫理・権利・文化論
*   **声・キャラの二次創作**: 声優やキャラクターの声丸々参照させて二次創作で収益化する行為への指摘。リスペクトの度合いや権利問題が議論される。
*   **DLsite等のAI作品**: 以前は手描き中心だったが、現在は高クオリティのAI動画・イラストが増加。購入者は「自分の生成より上手くて心折れる」ことも。
*   **ローカル環境の文化**:
    *   100万円超えのPCを当たり前のように購入する富裕層の流入が見られ、従来の5chスレとは異なるコミュニティの形成。
    *   「化石」的なSD1.5使用層と、最先端を追い続ける層との格差。
    *   エロ用途におけるローカル環境の「匿名性」と「自由度」は依然として価値があるが、クラウドの利便性との板挟み。

## 3. 技術的Tips・共有情報まとめ

| 項目 | 共有された情報 |
| :--- | :--- |
| **MiniMax H3** | 速度優先なら特定ワークフロー使用。参照動画で生成時間増。服の指定をプロンプトで変えると反映される（編集能力の高さ）。 |
| **Qwen 3.8 (27B)** | 16GB VRAMで動作する量子化版あり。日本語精度高。コーディング・エージェント能力はOpus級。 |
| **Gemma 4** | 言語理解に強い。12B推奨（VRAM節約）。フリーダムでエロプロンプト作成に使える。 |
| **ComfyUI** | `Save Image Extend`でフォルダ分類可能。`DynamicVRAM`は推奨オンだが環境依存でオフにする場合も。 |
| **ワークフロー** | 部分修正は困難。ControlNet等でプリビズを作りv2vするのが王道。 |
| **LLM活用** | 画像キャプション生成、プロンプト作成はローカルLLM（Qwen/Gemma）でも十分。複雑な指示はGrok等クラウド併用が現実的。 |
| **音声生成** | 参照音声を入れると効果音が消えるバグ/仕様あり。英語特化モデルだとカタカナ英語の発音が面白い。 |

## 4. 総括

本スレは、AI生成技術の爆発的な進化に伴い、**「ハードウェアの制約（VRAM）」**と**「ソフトウェアの進化（モデル性能）」**、そして**「人間の役割の変化（生成から評価・指示へ）」**という三つの軸で議論が進んでいる。

1.  **技術面**: MiniMax H3やQwen 3.8の登場により、ローカル環境での高性能生成がより現実的なものになっているが、依然としてVRAM24GB以上が「快適圏」の下限になりつつある。
2.  **ワークフロー**: 単純なガチャではなく、**「プリビズ作成 → v2vによる修正」**や**「LLMによるプロンプト自動生成」**といった、人間とAIの役割分担を明確にした手法がベストプラクティスとして定着している。
3.  **文化的・社会的影響**: AIが「誰でも作品を作れる」ことを実現したことで、作品の価値は「作ること」ではなく「選別し、方向性を決定づけるセンス」にシフトしつつある。また、ローカル環境が持つ「匿名性・自由度」は、特に成人向けコンテンツ制作において、クラウドの規制が強まる中でますます重要視されている。

今後、LLMの自律性がさらに高まれば、人間の役割は「監督・プロデューサー」側に完全に移る可能性があり、そのための「言語化能力」や「AIとの対話スキル」が新たな必須スキルとして注目されている。
