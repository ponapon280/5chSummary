### Wan

### Qwen-Image / Qwen3.8
- **話題**: 
  - 画像生成AIのキャプション作成用LLMとしてQwen3.8が候補に挙がっている（>>466）。
  - ローカルLLMとしてQwen3.8 27Bが海外で祭り状態になっており、公開1日でDL数ランキング4位を記録。27Bでありながら「Opus 4.6レベル」のコーディング能力・エージェント能力を持ち、ゲームを作れるほどの性能だと評価されている（>>456, >>460, >>522, >>546）。
  - 一方で、推論時の「thinking」がバチクソ長く、コンテキストを初手で40%近く消費してしまうという欠点も指摘されている（>>522, >>523）。
  - 27Bの無検閲・日本語精度改善・11.7GB量子化版モデルが公開され、VRAM16GB環境（5090Ti 16gbや3070 8gbなど）でも最高39tok/sで動作すると報告されている（>>508）。
  - 24GBの7900XTX環境でQwen3.8 27B Q4 MTPが60tok/sで動くという報告もある（>>507）。
  - gemma4と比較され、日常使いや幅広い言語・文化的知識の理解はgemma4が優れるが、コーディングやエージェント能力はqwenが優れるという認識が示されている（>>458, >>464）。
- **選ばれている理由**: 
  - Opus4.6レベルのコーディング・エージェント能力を持つため（>>456）。
  - エロ用プロンプトや画像キャプションなど、クラウドだと都合の悪いセンシティブな用途をローカルでこなすため（>>466, >>508）。

### 抽出されたモデルと関連話題

**1. MiniMax (H3)**
- **概要:** 動画生成モデルとして話題に上がっており、スレ民の多くが1週間ほど没頭して生成を試している。
- **選ばれている理由・特徴:**
  - 細かな所作をプロンプトで要求する必要がある生成AIであり、プロンプトに高性能なLLMを要する（>>536）。
  - プロンプトで指示していない服でもキャラ参照に従って動画出力をするなど、編集能力が非常に高い（>>603）。
  - 進化が激しすぎて、昔のモデル（アビスオレンジミックス等）で止まっていたユーザーには難易度が高く感じられる（>>455）。
  - H3を転用して静止画生成や画像編集（参照画像を最大9枚まで入れるアイコン等）に使う実験ノードも開発されている（>>624）。
  - VRAM環境に合わせて、ベースモデルはBF16、H3 Extender等を使う場合はINT8を使うかどうか検討されている（>>475）。

**2. Gemma (gemma4 / Gemma-4-12B / gemma-4-31b-it-heretic-ara-GGUF)**
- **概要:** ローカルLLMとして、Qwenと比較される形で頻繁に話題に上がっている。
- **選ばれている理由・特徴:**
  - Qwenと比較して、幅広い言語や文化的知識への理解に優れており、日常使いに利があるとされる（>>458, >>464）。
  - フリーダム（検閲が緩い）なため、クラウドAIの検閲強化に振り回されずにエロ系のプロンプト生成等に使いやすい（>>528）。
  - スレ民の評価を見て `gemma-4-31b-it-heretic-ara-GGUF` を試す声もあり、VRAM12GB環境では重く、24GB環境でギリギリ実用レベル。12GB環境なら `Gemma-4-12B` が推奨されている（>>492, >>498）。

**3. Qwen (Qwen 3.8 27B)**
- **概要:** ローカルLLMとして非常に高い評価を得ており、画像のキャプション用途やコーディング用途で検討されている。
- **選ばれている理由・特徴:**
  - 公開1日でDL数ランキング4位になるほどの人気。27BでありながらOpus 4.6レベルのコーディング能力を持つと海外で話題になっている（>>456, >>522）。
  - エージェント能力やコーディングに特化しており、ゲームを作れるレベルの作例が多く投稿されている（>>464, >>546）。
  - 日本語の精度を残しつつ11.7GBまで量子化した無検閲版モデルが公開されており、VRAM16GB環境で最高39tok/sと軽量高速で動作する（>>508）。
  - 一方で、素の状態だとthinking（思考プロセス）がバチクソ長くなるため、設定を変更しないとコンテキストをすぐに消費してしまう欠点がある（>>522, >>523）。

**4. 10eros (10eros-max / 10eros beta2 / ltx-10eros)**
- **概要:** エロ描写を目的としたモデル（MiniMax版など）。
- **選ばれている理由・特徴:**
  - MiniMax版の10erosが話題になっており、beta2が出たばかり（>>534, >>540）。
  - 10eros-maxは色んなモデルから特性を移植するハックな方法で実際にエッチな描写をできるようにしており評価が高い（>>537）。
  - 以前はメインで使う必要がないレベルだったが、H3のエロ規制の影響で「確保しておいた方が良い」という理由で落とすユーザーがいる（>>557）。

**5. DeepSeek (deepseek-v4)**
- **概要:** クラウド/API系のLLMとして使用されている。
- **選ばれている理由・特徴:** エロ用途で使い勝手が良かったが、値上がりしてしまったため嘆く声が上がっている（>>518）。

**6. SDXL**
- **概要:** 画像生成モデル。除外対象のanimaやIllustrious等ではなく、汎用的なベースモデルとして言及。
- **選ばれている理由・特徴:** 最新のモデル進化が激しい中でも、絵柄などの事情から未だにSDXLを使い続けているユーザーが一定数いる（>>559, >>571）。

**7. SD 1.5**
- **概要:** 旧世代の画像生成モデル。
- **選ばれている理由・特徴:** 図形描画等の超特殊な事情がある場合を除いて推奨されないが、ごく一部のユーザーは今でも普通に出力したくなることがある（>>558, >>566）。

**8. AOM (AbyssOrangeMix) / AnythingMix**
- **概要:** 過去の画像生成モデル。
- **選ばれている理由・特徴:** 昔のユーザーが時が止まっているほど古いモデルとして言及されており、最新モデル（MiniMax H3等）の進化の速さを強調するための比較対象として挙げられている（>>455）。

**9. Sora2**
- **概要:** 動画生成AI。
- **選ばれている理由・特徴:** 簡単なプロンプトでも意図以上の動画を作ってくれるが、それは裏でLLMがプロンプトを作ってくれているからだと分析されている（>>459）。

**10. Seedance**
- **概要:** MiniMax H3と共に言及される動画生成モデル。
- **選ばれている理由・特徴:** MiniMax H3と同様に、短いプロンプトをいい感じにするのではなく、プロンプトに起こしたものをそのまま具現化するコンセプトであるため、明確なイメージを持っているユーザーに有効（>>632）。

**11. OpenClaw / Hermes Agent**
- **概要:** ComfyUIの競合となる可能性のあるツール・環境。
- **選ばれている理由・特徴:** 業界標準であり続けるComfyUIに対する競争環境として期待されている（>>621）。
