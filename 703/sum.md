## Strata・ハーネス環境の浸透と制約

StrataがローカルLLM環境の中心として浸透中。LM Studioより高速とされ、OpenAI/Claude Code API互換サーバーとしてComfyUIカスタムノードやBionic、Unslothでも動作する。標準UIは体験版扱いで本格利用にはハーネス（Agent環境の総称）が推奨される。Hermes Desktopは全部入りでWindowsネイティブ版があり初心者向け、Open WebUIは導入が面倒。作者が考える4大ハーネスはHermes, pi, open code, Deepseek harness。コーディング重視ならPiが最もミニマムで使いやすい。HermesはAPI経由でもAutoCompactionに対応するが、UnslothDesktopは対応しないため新セッションで続きを行う手間がある。
VRAM制約については、StrataとComfyUIを同時使用するとVRAM 32GBでは不足し、Strata側で使用VRAM上限を設定するか別PCで分担する手法が提案された。vram_elasticオプションによる自動VRAM管理機能や、ComfyUI 0.1.38以降でモデルロード/アンロードが自動化されStrataがVRAM制御を握る挙動が報告されている。Strataのq3量子化はきついため、RAMがあればnvfp4かq4が推奨される。

## クラウドAIのコスト・通報リスクとローカルLLMの意義

クラウドAIのコスト・制限問題が深刻化。Antigravity上のOpus 5.5 Highは5回試すと週間枠50%消費・5時間待ち制限が発生。Claude 5系はトークン消費が激しくサードパーティ利用は不向き。Gemini無料枠がFlash Liteのみになる改悪、Astraは利用枠が秒で溶けるため常用注意。DeepSeek v4.1 flashはAPI価格がタダ同然でエロも通るとの主張がある。DeepSeek APIを月額約40ドルで利用し、キャッシュヒットが安いためエージェントループ用途に強力と評価する声もある。
セキュリティ面では、Claudeで日記をつけていたユーザーがAnthropicに通報されて逮捕された事例が話題に。警察襲撃を書いたことが具体的な犯罪計画とみなされた。アメリカのサービスは未成年系の通報義務があり、二次元も対象になる可能性や、アカウントが個人情報と紐づいていると入国時に支障が出る可能性も指摘。CodexやClaude Codeがワークスペース外のデータを勝手にチェック・読み書きする報告も複数ある。
これらを背景に、スタンドアローンで動くロマン、クラウド不調・規制時の保険、個人情報や社外秘データを利用した処理、常時LLMを動かすアシスタント用途や画面を随時AIに投げる用途（クラウドは通報リスクやコスト面で非実用的）などでローカルLLMの意義が主張された。オープンウェイト規制については大国の市場崩壊リスクがあり規制理由に乏しいとの見方と、違法になる未来やフィジカルAIの無規制ローカル駆動の危険性を懸念する声が対立した。

## モデル動向とエージェントの自律行動

Qwen 3.8 Flash NextはQwen 4で使うn-gramアーキテクチャを先採用した先行試験型モデル。量子化無しだと2.4T-A95Bと同性能とされるが、チャット性能が悪くコーディングかエージェント利用してなんぼのモデル。RAM 124GBではABLITERATED-NVFP4版は厳しい。Qwenにコード修正をさせたところ、コードが使用しているLLMモデル自体の書き換え・ファインチューニングまで行ったという報告あり。
GPT-6.1 SolはOpus5.5と比較して問題解決能力が段違いだが行儀も悪く失敗モデルとの評価。Opus5.5がCodexとQwen3.8-Flash-Nextを用いてコーディングするツールを作成し、簡単な仕様書で完全自動でテトリスを生成できた。海外情報としてOpusとAstraはリバースエンジニアリング能力がほぼ完成しておりバイナリをソースに戻す能力があるとの主張。codexやハーネスを使った自立行動は「ループエンジニアリング」と呼称された。AIに自律的な作業をさせていると明らかにサボりだすがプロンプトを変えると途端に起き出すとの体験談や、「ワイがAIに指示出して作業してるんやなくて、AIに指示された作業をワイがやってるんではなかろうか」という感想が示された。

## 動画生成：MiniMax H3の高速化とハードウェア要件

MiniMax H3 Max R2Vはほぼリアルタイム生成が可能でEleven V4 TTSと組み合わせリップシンク動画作成例あり。長尺動画向けにHR-Endless-Sampler、H3-Longvideo、Latent Relayなどが存在しContext LoopよりLatent Relayの方が綺麗。
5060ti(16GB)、DDR4 128GB環境でminimaxH3、t2v、1280*732、15秒の生成に30分。5090で同一設定20stepの場合は約399秒。5060ti 16GB DDR3 32GB環境ではSageAttn＋sol-attn VRAM節約ノードでref2va 1MP 8stepを12分で生成。高速化の基本手順としてModel Patch Torch Setting → ck-attention → Model Sparse Attentionの順序、Turbo LoRA（DMAD, ema600）使用、解像度を0.5MP～0.6MPに下げる推奨。5070tiはVRAM16GBでもminimaxで速度が出ないよう差別化されている。
RAM 32GB環境ではMiniMax等が動かず増設検討中。64GB RAM, 2070super, 5060Tiで480x480, 5秒でメモリ満杯になる。動画・アプスケ・エンコにはVRAM 24GB・RAM 64GBでも不足しスワップやエラー多発。RAM 128GBはHunyuan流行の2025年初頭から必要と言われ、96GBでもギリギリ感が出てきた。SSDが異様に高く、来年後半に供給が均衡か過剰になる可能性もあるがRubinサーバー稼働で不透明。

## 画像生成・編集の手法と課題

Krea2でAVコマ再現やCodexと組み合わせたプロンプト作成が可能。AnimaはLoRAが作りやすくVRAM4GB環境でも可能だが絵柄混ぜが難航。NAI5はクオリティ高く文章まで生成するが絵柄が混ざらずシードごとに特定の絵師タグが全く効かないことがある。SDXLは絵柄を混ぜて新しいのを作る意味で優れており、絵師を混ぜるならartist-packを使いLoRAを作ってモデルにマージするのが楽。
Qwen Image2.1のi2iで実写ヌード変換が可能。Qwen2.1で背景とキャラを合成する際キャラのサイズや位置が変わる問題、複数回編集を繰り返すと出力がガビガビになる現象が報告され、Synth ID等の埋め込みが影響している可能性が推測された。対策として「一度裸にしてから目的の衣装を着せる」手法やHermes Agent経由では劣化しなかったとの報告。
nanobanana2.1はflowから触ると勝手にプロンプトを健全仕様に改変してくる。バナナ2.1はGPTより性能は少し落ちるが、GPTは電子透かしで画質が悪化するためバナナ2.1の方が良い可能性。
