以下に、提供ログから抽出した「ツール」に関する話題をまとめる。モデル単体の話題・感想は除外した。

---

## ComfyUI (comfy / comfyui)

- **VRAM不足問題**：strataとComfyUIをフル稼働したところVRAM32GBでは足りなくなったとの報告あり。5090環境ではstrata側でVRAM使用量上限を16GBに設定し、残りをComfyUIに割り当てる運用が提案された(442)。
- **vram_elasticオプション**：最近のアップデートでvram_elasticというオプションが追加され、VRAMを他システムに渡したり再取得できるようになった(462)。
- **StrataによるVRAM制御**：ComfyUI 0.1.30→0.1.38アップデート後、i2t→画像生成の流れでモデルのロード/アンロードが自動処理されるようになった。StrataがVRAMを制御し、設定通り空き700Mを確保する。ComfyUIのモデルもStrataが制御してしまうという驚きの報告(508)。
- **ワークフロー破損問題（フロントエンド）**：ComfyUI 0.38以降、生成画像をドラッグ＆ドロップするとワークフローが壊れる問題が発生。起動オプション`--front-end-version Comfy-Org/ComfyUI_frontend@v1.52.7`で解決する(574, 598, 604)。ComfyUI 0.39ではv1.52.7で正常読み込み可能、v1.54.13とv1.56.2では位置等が壊れることを確認(605)。JSONで読み込む場合は正常にできるとの報告もあるが、メニューからJSONを開いても全く読み込めないケースもある(607, 608)。
- **Comfy MCPによる自動化**：HermesとComfy MCPを使えば生成コマンドの自動化が可能。StrataとComfyUIはPCを分け、Strata内蔵のWebUIのみで試した例あり(495)。

## nanobanana

- **VRChatモデル用イメージ画像の生成手順**：イラストを用意→nanobananaに「フィギュア化して」と依頼→「この画像をVRChat風の3D画像風にして」と依頼、という手法を試したが微妙な出来になる。回答として、VRChatの画面写真や3Dモデル販売サイトの三面図を参考画像として提示する方法が推奨された(431, 434, 437)。

## Open WebUI

- **ComfyUI連携での画像編集問題**：Open WebUIにComfyUIを連携させ、Qwen-Image-2.1で画像編集を行うと、2回目の編集で出力がおかしくなる（ガビガビになる）問題が発生(485)。Open WebUI側で出力された画像をDLして手動で同じプロンプトを使ってもガビガビ出力になる(504)。繰り返し編集するとガビる・幾何学模様になる現象はチャッピー（ChatGPT）でも報告されており、synth ID等の埋め込みが影響している可能性が指摘されている(507)。
- **Hermesとの比較**：OpenWebUIは導入がやや面倒で最初はチャットしかできない。ファイル操作やターミナル実行は増築が必要（黒い画面で設定）。ネット検索やファイル操作・ターミナル実行が最初から揃っているHermesの方が導入が楽(513)。
- **MCPによる環境構築**：OpenWebUIとMCPで環境構築していたが、Hermesの方が楽だったとの報告(561)。
- **ツール作成事例**：OpenWebUIで1日かけてKrea2→Qwen-image-2.1→MiniMax-H3をチャット内で生成できるツールをChatGPTに作ってもらった事例あり(515)。

## Hermes (Hermes desktop / Hermes Agent)

- **選ばれている理由**：導入が圧倒的に楽で、最初からネット検索・ファイル操作・ターミナル実行の機能が揃っている。OpenWebUIと比較して増築の手間が不要(513, 515)。アイコン（クジラ）が可愛いという理由で選ぶ声もある(470, 581)。
- **注意点**：ちゃんと指示しないと余計なことをするため、言語力が重要(514)。
- **Strataとの併用**：Hermes desktopとStrataをChatGPTと一緒に動作確認したところ、特定ファイルの削除指示時に確認なしで削除（rmコマンド実行）される問題あり。rmコマンドを承認必要にする方法が課題(487)。
- **画像編集での優位性**：Open WebUIのComfyUI連携でガビる問題に対し、Hermes Agentの方で画像編集を試したところガビらずに生成できた(512)。
- **バグフィックス状況**：ずっとバグフィックスばかりでいつ安定するか様子見している声あり(576)。
- **セキュリティソフトの誤検知**：インストール時にセキュリティソフトがTrojanとしてブロックする事例あり(458)。
- **覇権性**：今のハッキングブームにもhermesが使われているという指摘(537)。ただし、VPSやホームサーバーを建てない・cronもkanbanもゲートウェイも使わない用途なら、JANやpiを使った方がシンプルでHermesを選ぶ意味がないという見解もある(575)。

## Strata

- **VRAM制御機能**：使用VRAMの上限を設定できる。5090環境でstrata 16GB・残りComfyUIという運用が提案された(442)。
- **回答表示の変更**：回答までにかかった時間の表示がなくなったとの報告(445)。
- **Hermesによるファイル削除問題**：Hermes desktopとStrataを同時に動かした際、ファイル削除指示で確認なくrmコマンドが実行される問題が報告された(487)。
- **ComfyUIのVRAM制御**：StrataがComfyUIのモデルのVRAMも制御するようになり、設定通り空き700Mを確保する(508)。
- **非検閲モデルの動作確認**：StrataでHuihui-Qwen3.8-Flash-Next-abliterated-GGUFを起動し、ロリ官能小説生成→セックスシーン記述→Anima用プロンプト化の3ターンを試した例あり。今回はStrataとComfyUIはPCを分け、Strata内蔵のWebUIのみで試行(495)。

## Bionic

- **セキュリティ面での利点**：最初のプロジェクト設定で指定したフォルダ（およびサブフォルダ）しかエージェントが見られないため、隠したいファイルがある場合に適している(583)。

## ハーネス（全般・自作）

- **自作の推奨**：OSSのハーネスが多数あるため、それらを参考にしつつ自分が使う機能に特化して拡張するのが良い。あるユーザーはgooseの改良から始めたが、一から自作した方が結果的に良かった(456)。
- **モデルの学習状態が重要**：ハーネスの設計以上に、モデルがagentとして使われるように学習されているかどうかの影響が大きい(579)。
- **次のトレンド予想**：ビューワーの自作が盛んになってきたので、次はハーネス自作が流行るのではないかという期待。セッションをブランチした際の関係性を示すツリーが欲しいというニーズあり(579)。
- **隔離の重要性**：アホモデルにハーネスをくっつけて広範な権限を与えると、CodexやClaude Codeの2倍でPCを壊しにくるため隔離が大事(535)。

## Codex (Claude Code含む)

- **PCファイルアクセスへの懸念**：PC内のファイルを全部見られるのが嫌で導入を躊躇する声あり。クラウド版の利用価値についての問い(480)。
- **長時間作業の傾向**：6時間PCを拘束し続けることがあり、サブPCで動かす判断が正解だったとの報告(477)。延々と3Dモデルをこね繰り回すが成果物が未だ0(477)。頻繁に長時間作業したがる傾向がある(478)。
- **監査AIの存在**：Codex自体はチクっているわけではないが、さらに上位の監査AIがCodexの取得したユーザーPCデータログをチェックしてBANしてくるという指摘(493)。
- **PC破壊リスク**：ハーネス経由でアホモデルに広範な権限を与えると、CodexやClaude Codeの2倍増しでPCを壊しにくる(535)。
- **リセット頻度**：頻繁なリセットでお得感を出しているが、朝三暮四のようだという感想(589)。

## DeepSeek Harness / DeepSeek API

- **DeepSeek Harnessの利用**：問題なく利用できた。アイコンのクジラが可愛いとの感想(470)。
- **API利用のコスト感**：毎月40ドル程度使用。価格の割に性能が良く、ローカル代替として何でもできる。キャッシュヒットが安くキャッシュ保持時間が長いため、大量のコンテキストを積むエージェントループ用途で強力(586, 593)。実際の使用実績：Cost $37.82USD / API requests 22,959 / Tokens 4,331,404,431(596)。
- **用途別の適性**：MiniMax用プロンプト作成に使用したところ、ローカルLLMより賢い。エロ用途ではガードレールが厳しめなため他のプロバイダ推奨。翻訳だけならgemma4でも大差ない可能性(594)。

## Unsloth

- **Hermesとの比較**：Unslothを使っているが、Hermesへの乗り換え価値があるか問い合わせあり。回答として、やれることを調べて使い道を把握し、必要でなければ乗り換える必要はない。ほとんど知識がない段階では導入してはいけないという見解(564, 566)。

## LMStudio

- **量子化モデル検索のしやすさ**：量子化モデルの検索のしやすさではLMStudioが良いとの評価(569)。

## Opencode

- **無料モデル利用の選択肢**：Opencodeで無料モデルを使うのもありという意見(577)。

## Mac用AI高速化ツール（iPhone外付けGPU）

- **概要**：MacのAI処理を高速化するツール。iPhoneを外付けGPU代わりに使えるというもの。Windowsでもできれば神だとの感想(467)。
