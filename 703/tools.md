## ComfyUI：実行・加工・エージェント連携

### ワークフロー破損とフロントエンド回避
ComfyUI 0.38以降、生成画像をドラッグ＆ドロップするとワークフローが壊れる問題が発生。起動オプション`--front-end-version Comfy-Org/ComfyUI_frontend@v1.52.7`で解決する。0.39ではv1.52.7で正常読み込み可能、v1.54.13とv1.56.2では位置等が壊れることを確認。JSONで読み込む場合は正常にできるとの報告もあるが、メニューからJSONを開いても全く読み込めないケースもある（>>574, >>598, >>604, >>605, >>607, >>608）。

### VRAM制御と自動アンロード
ComfyUI 0.1.30→0.1.38アップデート後、i2t→画像生成の流れでモデルのロード/アンロードが自動処理されるようになった。StrataがVRAMを制御し、設定通り空き700Mを確保する。ComfyUIのモデルもStrataが制御してしまうという報告がある（>>508）。`vram_elastic`オプションが追加され、VRAMを他システムに渡したり再取得できるようになった（>>462）。5090環境ではStrata側でVRAM使用量上限を16GBに設定し、残りをComfyUIに割り当てる運用が提案された（>>442）。メモリ不足時に捨てSSDに大容量の仮想メモリを当ててOOM防ぐ方法があったが「今じゃComfyui自体が賢くなってやる必要性すらなくなった」という報告もある（>>355）。

### Comfy MCP経由の自動化・エージェント連携
HermesとComfy MCPを使えば生成コマンドの自動化が可能。StrataとComfyUIはPCを分け、Strata内蔵のWebUIのみで試した例あり（>>495）。`Bionic ⇔ Comfy MCP ⇔ ComfyUI ⇔ Strata`の経路で連携可能になった（>>88）。CodexにKrea2のプロンプト作成をさせ、生成画像を放り込んで修正箇所を比較・改善させる運用。髪色・髪型・目の色はワイルドカードでランダム性を出させている（>>101）。CodexにKrea2のプロンプト作成引き継ぎメモを作らせ、Grokにドロップして教えればGrokでも良いプロンプトが作れる（>>105）。

### Open WebUI連携の制約
Open WebUIにComfyUIを連携させ、Qwen-Image-2.1で画像編集を行うと、2回目の編集で出力がガビガビになる問題が発生。Open WebUI側で出力された画像をDLして手動で同じプロンプトを使ってもガビガビ出力になる。繰り返し編集するとガビる・幾何学模様になる現象はチャッピーでも報告されており、synth ID等の埋め込みが影響している可能性が指摘されている（>>485, >>504, >>507）。Hermes Agentの方で画像編集を試したところガビずに生成できた（>>512）。

### プロンプト重み変更の仕様
`from_side`のような2語の単語でctrl+↑/↓で重みを変更すると、単語全体を選択しない限り`(from:1.05)_side,`のように部分的にしか変わらない。カスタムノードを作って解決した（>>106）。

### 動画生成の高速化ノード構成
`Model Patch Torch Setting (true)` → `ck-attention` → `Model Sparse Attention (sla)` の順序で接続が推奨。プロンプト構築中はウェイトをw4a8にし、comfyの`turbo_4step`を使用。Turbo LoRA不使用時はSpectrumを使用、Turbo LoRA使用時はDMADやema600が定番品（>>750, >>697, >>699）。5060ti(16GB)＋DDR4 128GB環境で、t2v 1280*732 15秒を20stepで約30分（399秒）で生成している事例あり（>>684, >>803）。

## Strata：ローカルLLM実行エンジン

### 選ばれている理由
LM Studioよりもだいぶ早い（>>193）。codex無料で使い放題相当と評価（>>232）。codexを使ったことがない層がStrataで初めてAIエージェント的なことができたという報告（>>233）。更新速いから頻繁に驚ける、利用者も増えてきて情報も充実してきた（>>318）。Irodori-TTSのエロセリフ自作が難しかったのが解決した（>>108）。成年向けSkillsを作りたい用途にも関心（>>42）。

### VRAM制御と動作要件
使用VRAMの上限を設定可能。StrataがComfyUIのモデルのVRAMも制御し、設定通り空き700Mを確保する（>>508）。ローカルLLM用途でStrataを使用する場合、VRAM12GB以上、RAM64GB以上が必要。動画生成勢と同等以上の要求値で、高騰前にRAMをガン積みした人なら試せる（>>770）。Strataのq3は量子化きついからRAMがあるならnvfp4とかq4がええよという助言（>>390）。

### 動作実績
RTX3080でStrataを動かしRTX5080で画像生成する2GPU構成（>>199）。RTX4070ti 12GB + RAM96GBでもMMH3もStrataも使える（>>206）。RAM192GB環境にUD-Q4_K_XLを入れた結果、GPU使用量15.4GB、共有GPU使用量68GB、RAM使用量121GB、平均3338tok/s（64Kコンテキスト）。IQ3_Sが6377tok/sだから速度は遅い。規制解除できず画像も読めないため削除検討（>>150）。

### UIと運用上の注意
標準WebUIで新しいチャットを開始するには入力欄左下のボタンをクリック。過去のチャットは保存されず破棄。会話を残したければアプリやハーネスにAPI経由で接続。標準WebUIは体験版みたいなものなのでハーネスを使った方が良い（>>195, >>202）。System Prompt入力欄はないがAPI経由なら送れる（>>226）。`START-HERE.bat --setup --host 0.0.0.0 --api-key <secret>`でスマホや他PCから開ける（>>90）。優秀だが気を抜くと「お前」呼びになり一人称が「俺」になる（>>123）。回答までにかかった時間の表示がなくなったとの報告（>>445）。Strataがcodex対応したとの報告（>>424）。

### Strataによるツール作成・キャプション作業
複数の画像からグリッド画像作るツールをQwen3.8 IQ2-XS Strata Unslothで作らせたらサクッと良いものができた。chatGPTに頼んだ場合は完成前に無料枠終了した（>>225）。以前はi2tでLLMに英語プロンプト出力させて修正は手動だったが、今はStrataに「キャミソールやで」みたいな修正指示を出すだけ。対話型は楽（>>870）。非検閲モデルの動作確認として、StrataでHuihui-Qwen3.8-Flash-Next-abliterated-GGUFを起動し、ロリ官能小説生成→セックスシーン記述→Anima用プロンプト化の3ターンを試した例あり（>>495）。

## ハーネス全般とエージェント環境

### ハーネスの定義と分類
「Harness」という名前のソフトが一つあるわけではなく、AIエージェント環境の種類。Agent Harnessという種類があり、DeepSeek Harness、Hermes、Codex、Claude Code等がある（>>214, >>215）。Strata作者の考える4大ハーネスはHermes, pi, open code, DeepSeek harness（>>239）。Qwenに手足を付けるAgent環境で、ComfyUIはその手足で操作する画像生成環境（>>214）。

### 用途別の選定
- **Pi**: コーディング重視ならPiをハーネスにするのが一番ミニマムで使いやすい。Pi2が出たばかり。Strataの推奨もPi（>>263）。
- **OpenCode**: デスクトップアプリとの連携ができるかという質問。オープンソースで揃えたい場合の候補。無料モデルを使うのもあり（>>234, >>238, >>577）。
- **DeepSeek Harness**: all of pluginみたいな思想。難易度高め（>>238）。アイコンのクジラが可愛い（>>470）。
- **Claude Code**: codexみたいにしたいならClaude Codeのバックエンド変えるのが一番簡単。コーディング用途以外なら自分に合わせた機能とUIをClaudeCodeに伝えて半日で作ったほうが満足度高い（>>238, >>262）。

### 自作と隔離の重要性
OSSのハーネスが多数あるため、それらを参考にしつつ自分が使う機能に特化して拡張するのが良い。あるユーザーはgooseの改良から始めたが、一から自作した方が結果的に良かった（>>456）。アホモデルにハーネスをくっつけて広範な権限を与えると、CodexやClaude Codeの2倍でPCを壊しにくるため隔離が大事（>>535）。ビューワーの自作が盛んになってきたので、次はハーネス自作が流行るのではないかという期待。セッションをブランチした際の関係性を示すツリーが欲しいというニーズあり（>>579）。ハーネスの設計以上に、モデルがagentとして使われるように学習されているかどうかの影響が大きい（>>579）。

### Codex / Claude Codeのリスク
PC内のファイルを全部見られるのが嫌で導入を躊躇する声あり（>>480）。6時間PCを拘束し続けることがあり、サブPCで動かす判断が正解だったとの報告（>>477）。config.tomlで特定範囲の読み取り禁止しても実態としては読み取れてしまう既知の不具合。エロフォルダがいつ読まれるかヒヤヒヤする（>>899）。Codex自体はチクっているわけではないが、さらに上位の監査AIがCodexの取得したユーザーPCデータログをチェックしてBANしてくるという指摘（>>493）。

## Open WebUI

### 選定と制約
オンライン・ローカル共用のLM Studio的なUIを提供（>>209）。ComfyUI連携機能で対話型画像生成が可能。OpenTerminal入れればOpenWebUIと連携してCodexみたいにファイル操作やコーディングができる。VRAMのアンロードをワークフローや連携処理に噛ませればメモリの天元突破を防げる（>>201）。スマホでチャットする用途に対し推奨（>>338）。OpenWebUIで1日かけてKrea2→Qwen-image-2.1→MiniMax-H3をチャット内で生成できるツールをChatGPTに作ってもらった事例あり（>>515）。

### 導入難易度とHermesとの比較
環境構築がめんどい。初心者ならWSLから始めてDockerコース（>>203）。OpenWebUIは導入がやや面倒で最初はチャットしかできない。ファイル操作やターミナル実行は増築が必要（黒い画面で設定）。ネット検索やファイル操作・ターミナル実行が最初から揃っているHermesの方が導入が楽（>>513）。OpenWebUI + OpenTerminalの面倒な環境構築が終わった後にHermes Desktopという導入簡単なオールインワンがあることを知ったという報告（>>250）。OpenWebUIとMCPで環境構築していたが、Hermesの方が楽だったとの報告（>>561）。

根拠：>>201, >>203, >>209, >>250, >>338, >>513, >>515, >>561

## Bionic / Unsloth Desktop

### Bionic
Bionicを使ってAIエージェントごっこしたい（>>80）。Bionic(Gemma4 E2B)とComfy MCP経由で画像作成が実現（>>178）。最初のプロジェクト設定で指定したフォルダ（およびサブフォルダ）しかエージェントが見られないため、隠したいファイルがある場合に適している（>>583）。API経由でローカルLLM動かせないはずという指摘（>>245）。OpenAI互換APIの設定がないことを確認。LM StudioでDLしたモデルを優先的に使う思想かと推測（>>247）。Sandboxフォルダにhtmlファイルをポン出ししてくれる機能。LM Studio bionicでも同じことができたがStrataとの連携ができなかった（>>237）。avif形式はBionic側が未対応、comfy-cliからの実行はextra_pnginfoが取得できずPowerPuterノードがエラーを出す（>>178）。

### Unsloth Desktop
API経由だとAutoCompactionしてくれない仕様。コンテキスト足りなくなったら引き継ぎ書作成させて新しいセッションで続きやる使い方をしているが「くっそめんどい」（>>243）。UnslothでStrataを使っている（>>224）。Qwen3.8 IQ2-XS Strata Unslothでツールを作成（>>225）。Unslothを使っているがHermesへの乗り換え価値があるか問い合わせに対し、やれることを調べて使い道を把握し、必要でなければ乗り換える必要はない。ほとんど知識がない段階では導入してはいけないという見解（>>564, >>566）。

## FreeToken：LLM推論ツール

ローカルLLMをVRAM載せきらずに早く動かす目的（>>908）。4080s/192GB環境で規制解除版が動いたのはGemma4 26B A4B BF16だけ。16tok/sで遅くて実用厳しい。VRAMが2.7GB足りなくて動かなかったが24GBならQwen3.8-Flash-Next-ABLITERATED-NVFP4が動く可能性高い（>>906）。Qwen3.8-Flash-Next-ABLITERATED-NVFP4は125GBあるのでRAM124GBだときついかも（>>911）。FreeToken試したが遅いため「おとなしくStrataきゅんに戻ります」（>>906）。

## DeepSeek API / Harness

### 選ばれている理由
問題なく利用できた。アイコンのクジラが可愛い（>>470）。価格の割に性能が良く、ローカル代替として何でもできる。キャッシュヒットが安くキャッシュ保持時間が長いため、大量のコンテキストを積むエージェントループ用途で強力（>>586, >>593）。実際の使用実績：Cost $37.82USD / API requests 22,959 / Tokens 4,331,404,431（>>596）。MiniMax用プロンプト作成に使用したところ、ローカルLLMより賢い（>>594）。

## 画像編集・ペイント・3D関連ツール

### nano-banana
nano-banana 2.1が出た。GPTより性能は少し落ちるが、GPTは変な電子透かしで画質が悪くなるため、nano-bananaの方が良い可能性があるという評価。選定理由として「GPTの電子透かしによる画質低下を回避できる点」が挙げられている（>>818）。flowから触る2.1は「勝手にプロンプトを健全仕様に改変してくる」。studioやapiからなら違うのかという問い（>>840, >>914）。VRChatモデル用イメージ画像の生成手順として、イラストを用意→nanobananaに「フィギュア化して」と依頼→「この画像をVRChat風の3D画像風にして」と依頼する手法を試したが微妙な出来。VRChatの画面写真や3Dモデル販売サイトの三面図を参考画像として提示する方法が推奨された（>>431, >>434, >>437）。

### GIMP / Krita
GIMP3は「圧倒的に高機能やし使いやすい」けど、GIMP2.10が3秒で立ち上がるため使い続けている。GIMP3は閉じる癖があると立ち上げ直しに20秒かかる（>>937）。LLMとのやりとりで生成された画像ファイルをGIMP等で普通に読める（>>181）。kritaで頑張っているという声もある（>>909）。gimpは操作性カス、すアフィ死ねニティは文字の縦型対応していないとの指摘（>>898）。

### Tripo / Meshy
astra&tripoほんま覇権という評価（>>882）。Comfy公式テンプレートの3DタブにTripoとかMeshyのワークフローがあるが、使えそうなのはAPI。無料の3Dモデル化ワークフローを探している（>>953）。Microsoftのオープンウェイトの3Dモデル化ワークフローがある（>>955）。3D編集ソフト（blender等）もAIに食われるかという議論。フリーウェアなblenderは死なんがmayaやzblushは死ぬと思う（>>932）。

### AIによる既存ソフト再構築
AIを使ってphotoshopやillustratorをオープンソースで再構築・公開するのが流行り始めている。まだオリジナルには及ばないが、AIの進化と共にいずれ超えるとの見方（>>821）。類似品をCodexに作らせることができ、win32アプリも余裕で作れる。試しに作らせたらクソ軽かった（>>823, >>825）。リビルト品を使う理由がないこと、何が仕込まれているか分からないことが懸念（>>824）。OSSの画像編集ソフトをopusで自己改造している例もある（>>878）。

## 総評

1. **StrataがComfyUIのVRAMまで制御する統合的エージェント環境の中核として機能している**：`vram_elastic`オプションやComfyUI 0.1.38以降の自動アンロード処理により、StrataとComfyUIの同時起動時のVRAM競合が構造的に解決されつつある。ただしHermes経由でrmコマンドが確認なしで実行される問題など、権限管理の課題は残存している。

2. **ハーネス選定が用途に応じて分化している**：コーディング用途にはPi、ルーティン自動化にはHermes、オープンソース志向にはOpenCodeという使い分けが明確化している。導入の容易さでHermesが優位だが、VPS未構築の軽量用途ではJANやPiの方がシンプルという見方もある。

3. **ComfyUIのフロントエンド破損問題が実運用に支障を出している**：0.38以降のドラッグ＆ドロップでのワークフロー破損は`--front-end-version Comfy-Org/ComfyUI_frontend@v1.52.7`で回避可能だが、新バージョンでは再発しており、JSON経由でも読み込めないケースがあり、安定化には至っていない。

4. **DeepSeek APIがエージェントループ用途でコスト優位性を発揮している**：キャッシュヒットの安さとキャッシュ保持時間の長さにより、大量コンテキストを積む用途で強力。実際の使用実績として月額$37.82で43億トークンを消費しており、ローカル代替として機能している。エロ用途ではガードレールが厳しめという制約がある。
