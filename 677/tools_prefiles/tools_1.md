**ComfyUI関連のツール話題抽出（モデル言及は除外）**

### 1. ComfyUIの導入・環境構築に関する話題
- **ポータブル版 vs デスクトップ版**  
  ポータブル版の方がCドライブを圧迫しない、Dドライブに入れやすいという理由で選んでいる人が複数。デスクトップ版はインスタンス分けがしやすいという声も。
- **Stability Matrixの評価**  
  「ComfyUIの導入は結局Stability Matrixでいいのでは？」という意見。環境分けやカスタムノード導入が簡単という理由で推されている。
- **WSL + git clone**  
  「wslにgit cloneが一番」という意見あり。ポータブル版より安定して管理できるという理由。
- **Agent AI（Codex、Claude、Grokなど）の活用**  
  ComfyUIのインストール・ワークフロー構築・カスタムノード導入をAIに任せる手法が複数言及。  
  理由：「自分で調べるよりAIにやらせた方が速い」「昔は自分で全部やっていたが今はAI任せで問題なく動く」「エージェントに環境構築を任せられるようになった」。

### 2. ComfyUIの運用・最適化に関する話題
- **Coreノードの充実**  
  「ComfyUIのCoreノードが充実してるおかげで公式テンプレがどシンプルでいい」という評価。昔はカスタムノードを大量に必要だったのが改善された点が理由。
- **--disable-pinned-memory**  
  メモリ使用量が大幅に減るが「ちょっと怖い」という声あり。
- **SageAttention / KJnodesのMiniMax用ノード**  
  「KJnodesに新しく追加されたminimax用のsageattentionノード」を入れてVRAM16GB/RAM64GBでも溢れにくくなったという報告。  
  理由：低スペック環境でも安定して動くようになった。
- **RAMの積極活用**  
  「VRAM容量だけ気にしろ」は昔の話で、今はRAM128GB積むのが普通という流れ。モデルがVRAMに収まらなくてもRAMで動くようになった点を評価。

### 3. ワークフロー・操作性に関する話題
- **公式ワークフローのシンプルさ**  
  Minimax H3の公式ワークフローが「格納部分含めてもかなりシンプル」と評価。モデル性能だけでなく「指示のおかげでちゃんと良いサンプルが出る」点も含めてツール体験が良いとされている。
- **カスタムノードの管理**  
  ComfyUI Managerの更新が遅いという不満と、手動で最新ノードを入れる必要性についての言及。

### 4. その他のツール言及
- **easyWan / easyAnima**  
  過去にこれらのお世話になった人が「結局ComfyUIの理解度が低いままだった」と振り返っている。
- **forgeNEO**  
  「forgeNEOのぬるま湯に浸かりすぎてComfyの操作を思い出すところから始めなあかんな」という声あり。ComfyUIへの移行のハードルとして言及。
