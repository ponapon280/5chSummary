**抽出結果（ツール関連のみ）**

### 1. **ComfyUI**（最も多く言及）
- **導入のしやすさ**：公式GitHubに推奨バージョンの組み合わせが載っているので、それを揃えるだけで済む。今は導入がバチクソ簡単になった。
- **理由**：SD1.5時代の古いモデルはもう使わない前提で全消し推奨。軽量化ノードを公式WFにぶち込んでエージェントに使い方を聞ける。
- **高速化関連のノード組み合わせ**（理由付き）：
  - **Sage Attention + Sol-Attn**：共存可能になり、倍プッシュできる。Sol-AttnはKijaiのアプデでSageと共存可能になった。
  - **MiniMax H3 Mem Eff Sage Attention Patch → Patch Sol-Attn → Spectrum Apply MiniMax H3**：16:9(0.4mp)の15秒動画が約5分30秒（RTX5080+DDR4 128GB）。
  - **EasyCache / Spectrum**：変化が少ない部分を飛ばす高速化。Spectrumの方が品質劣化がマシだが、モデル本来のクセが出る可能性あり。
  - **H3Cache**：Spectrumと排他。Spectrumで色がおかしくなるケースがあったためH3Cacheを採用。
  - **Model Preview override + taeh3.safetensors**：生成中のリアルタイムプレビューが可能になり、ガチャ効率が大幅向上。
- **その他の利点**：WF共有が活発、ノード更新でさらに高速化。低スペックでもrunpodでA100（$1.5程度）を使って試せるテンプレートあり。

### 2. **nano-banana（ナノバナナ）**
- **言及**：NAIや昔のGrok imagineと比べて、元の絵柄をあまり変えずに動かしてくれる点が大きい。
- **理由**：画像生成後のアニメーション（I2V的な用途）で画風を維持したい場合に優位。

### 3. **runpod**
- **言及**：低スペック民がMiniMaxを試すのに最適。ワンクリックでモデルダウンロードまでしてくれるテンプレートあり。
- **理由**：ローカル環境が貧弱でもA100などで快適に動かせる（$1.5程度）。

### 4. **Forge**
- **言及**：Forgeリアスで止まっていた人が、codexに全ツッパしてMiniMaxの導入・運用最適化まで困らなくなった。
- **理由**：ComfyUI移行後の運用で特に困らなくなった点が評価されている。

### 除外したもの
- NovelAI(NAI)、illustrious、FLUX、Wan、Qwen、anima、Z-Image、LTXなどの**モデル名**に関する話題はすべて除外。
- Qwenシリーズの画像生成以外の話題はログ内に該当なし。

主に**ComfyUI**の導入容易さ・ノードによる高速化・WF共有の活発さが選ばれる理由として繰り返し挙げられています。
