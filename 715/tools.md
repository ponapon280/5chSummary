# 生成AI関連ツール話題 抽出レポート

※本レポートのレス番号は統合元パート内の通し番号であり、元スレの通し番号とは限らない。

今回とくに盛んに議論された話題は、ComfyUIの運用・連携と、野良exe・カスタムノードのセキュリティリスクである。

## ComfyUI（comfy / comfyui）

**実行・起動・運用**
- デスクトップ版はモデル読み込みが遅く、モデルjsonと同じフォルダのbat経由でターミナル起動した方が早い。bat起動では起動前処理も仕込める。デスクトップアプリはモデル管理・アプデ管理に用い、ターミナル版はアプデ不具合回避用途で使い分ける（>>53）。
- Windows 26H2環境でDLLブロックされる報告があるが再現性に個人差がある（>>42, >>43, >>44）。Smart App Controlをオフにすれば回避できる（>>47）。
- 新モデル対応が最も早く、動画生成ではComfyUI一択。バックエンドとしては優秀でフロントエンド不要の時代との指摘（>>394, >>398, >>408, >>411）。
- 新環境作成時は用途ごとにデスクトップ環境を使い分け、前環境をすぐ消さないのが推奨される（>>752）。
- ワークフロー画像（jsonメタデータ埋め込み済み）をドラッグ＆ドロップしても画像しか表示されない不具合報告あり。ワークフローjsonの直接提供で解決（>>628, >>630, >>631）。imgbb.comをアップロード先に使うとメタデータが消えない（>>637）。

**VRAM割り当て・連携**
- VRAM 16GB環境で8GBをStrata、8GBをComfyUIに割り振ることで画像ロスほぼ無しで�用動作可能（>>212）。strata+comfy想定ならVRAM 16/24よりも12+12の2GPU構成が良いとのスレ上の見解（>>202）。
- Strataを入れてComfyUI連携でハーネスも入れたいという需要あり。HermesやOpenCode等の選択肢がある（>>811）。

**AIによる操作・ワークフロー作成**
- AIにComfyUIを操作させて線を繋がせたりWFを作らせたりする使い方。AI生成WFを微調整するフローもある（>>360, >>364, >>406）。
- OS再インストール後、チャッピーにComfyUI設定と環境を教え、必要ファイルの場所を全部教えろと指示したらすんなり環境復帰でき、不要環境の掃除もできた（>>792）。
- LLMに「ComfyUIで導入して」と依頼すると基本的にComfyUIでインストールされる（>>751）。

**プロンプト制御・ノード活用**
- プロンプトの重みを変えられるノードを入れ、`(small and very tiny nipples:50).` のように極端な強度を指定すると効果が出る。環境によりweight:4くらいから崩壊するため `(small and tiny nipples:3.0),` 等の調整が必要（>>655, >>761）。
- テンプレートWFが複雑怪奇で何も分からない状態になる。NSFW生成時に規約画面へ飛ばされ戻し方が分からない事態が発生、原因は `prompt enhancer` がオンだったため（>>366, >>369, >>370）。
- MOSSのテンプレートWFネガティブプロンプトにnsfwが入っており気づいていないユーザーがいる模様（>>246）。

**Viggle-Remakeの導入と使い方**
- `viggle_remake_edit_comfyui.safetensors` と `viggle_remake_swap_comfyui.safetensors` をlorasフォルダに格納し、GitHub上の `ComfyUI-Viggle-Remake` の `__init__.py` と `nodes.py` をcustom_nodesフォルダに格納する。WFはGitHubのものをDLするか自作。プロンプトガイドはMiniMax-H3のRef2va用を使う（>>872）。
- `swap` は人物・キャラクター入れ替え専用、`edit` は物体追加・削除・背景・天気・光の変更等を担う（>>873）。3Dアニメーションを元に参照画像を与えて身体の比率や整合性を保ったままアニメを作れるツールとのスレ上の見解（>>893）。
- オプションの `pins` でソース動画の特定フレームに対応した書き換えフレームを用意するとswap精度が爆上がりする（>>912, >>917）。公式に `COMFYUI.md`、ノードパック、WF、int8/GGUFファイルが用意されている（>>868）。

**保存フォーマット**
- AVIF品質90で保存する運用。非可逆だがWebpやJPEGより段違いに綺麗で、ComfyUI自体がJpegXL対応するまでAVIFでいく（>>877）。BMP（>>879）やMAG（>>880）を推す声も。png 1MPよりwebp95 8MP(4K)の方が容量が軽くRTXVSRで移行した報告（>>754）。JXLのWeb標準化が進んでおり今後はJXLも（>>782）。webpは対応していないアプリがあるのが面倒（>>757）、Googleが開発を止めたらゴム化リスクとの懸念（>>777）。

**スレ上の対立構造**
- ComfyUI推しが定期的に湧くが、ComfyUIでしかできない事をしている人は大していない。A1111系の話をすると必ずComfyUI推しが現れると指摘（>>352, >>367, >>385, >>400）。

## rusting strata

**選ばれている理由・強み**
- 軽くてクソ速い。64GB環境でもツール複数立ち上げられる。環境構築は大変だがstrataよりかなり快適。strata+dsh完全依存になったという声があり、AIの方が画風制御確実に上手い（>>272, >>284, >>406）。
- strataで使うモデルならどのモデルでもいける。モデルや環境によって調整がかなり難しい。リファレンスマシンはRTX3060/12GB、RAM32GB（>>284, >>301）。
- 純正Strataは使用せず、もっと軽くて速いものをビルドして使う選択肢もある（>>196）。strata16または12でも十分動く（>>199）。

**導入時の注意**
- Windowsの場合「install the Visual Studio C++ Build Tools first」と書いてある。自分でRustを使ってビルドする必要がある。合わなかったという報告もあるが生成以外の用途には使う可能性（>>284, >>424）。

**規制挙動**
- 特定プロンプト（金髪ショタと版権キャラのセックス）を依頼したら拒否された。基準は変わっていないが前セッションでの適用失敗だったと回答（>>643）。規制解除モードは「成人同士の同意の元」という条件を満たさないと拒否される（>>644）。セルフチェックしろと指示するとほぼ毎回修正してしまい無能（>>724）。espオンでもたまに逸らされるため無検閲モデルを探す旅に出る報告（>>781）。

**8GB対応・連携**
- 8GB対応でVRAM 16GB環境でのStrata / ComfyUIへの8GBずつの割り当て併用動作が可能になった（>>212）。Echo Show改造でオカズ絵生成を声でStrataに依頼し結果を表示できるようにした報告（>>46）。

## ForgeNeo / Forge系

**選ばれている理由**
- 生成速度がForgeの方が早い。プロンプト以外のことで頭を使いたくないためForge Neo派がいる。枯れたモデルで新しいWFが出ない場合は画面に余計なものがないForge Neoが効率的。新しい事を覚えるのがしんどいという理由は「ただの老化」とスレ上で指摘（>>353, >>359, >>394, >>399）。
- MOSSを動かすために使用可能。anima以降のモデルならforge neoが出ているためそれを使う案内がある。ただし「もう使いにくいまである」との声（>>334, >>335, >>336）。
- VRAM12GBでP-H3 Imageを動かした際、ForgeNEOが整備されていたため動作自体はしたが8枚参照RefができずWFを探す流れになった（>>740）。

**Anima RGBA対応**
- ForgeNeoのコミット情報で「Anima RGBA」対応（元々ComfyUI用）が確認された。背景透過画像が作りやすくなるVAEとLoRAのような仕様で素材用途に良い可能性（>>203）。

## redrayzニキのGUI / sd-scripts / Fizgig

**LoRA学習の効率化**

- トレーニング中にその場で生成してチェックできるのが便利。sd-scriptsにはプレビュー生成オプション（`sample_every_n_epochs`）があるがその場で確認出来ないと嫌だという声（>>287, >>302, >>317）。
- fizgig automagic3について「暴れ馬過ぎて全く使いこなせない」不満報告（>>598）。マムーコ素材100枚ほどをfizgigで作成した言及（>>642）。

## セキュリティ：野良exe・カスタムノードのリスク

- 自動モザイクソフトのexeが公開された。局部のみモザイクがかかるよう中身を変更しEXE化したが、スレ上では野良exeの危険性が指摘（>>918）。
- ComfyUIのカスタムノードにすらウイルスが仕込まれる時代であり、得体の知れんexeを踏むのは危険（>>941）。過去にNIKKEのPC版アップデートexeがノートンに無条件削除されるほどの悪意あるファイルであった件、ブラウザパスワード窃取からSSH秘密鍵奪取、リモートでの任意コマンド実行まで可能な被害内容（>>943, >>946, >>952）。
- 野良exeの代わりにGitHubを使うべき。カスタムノード導入時に `requirements.txt` と `__init__.py` を読むことは必須、ComfyUI Managerの一発導入は危ない（>>937, >>945, >>949）。依存関係や怪しいコードの確認をLLMにさせる運用の声（>>974）。

## Claude / チャッピー / minimax / open code

- **Claude**: コスパがアホみたいに悪い。Freeで慣らし運転がてら質疑応答させたら「5時まで待て」と言われた。使用量少なすぎとの不満（>>257, >>323）。
- **minimax**: 動画はいいが声が言うことを聞いてくれない。呼吸音だけだと言ってるのに笑い出したり謎の言語を話す、叫びすぎる。解決できているかスレ上で不明（>>368）。
- **open code**: デフォルトで思考を展開するようになった。エージェントのコマンドを見直し・眺めしている。主な注意箇所はshellコマンドで変な事されてないか見ること、絶対パス表示で対象プロジェクトと関係ない場所を触ってないか確認（>>435）。
- **LM studio**: 元動画を2fps化したフレーム画像をLM studioでgemma4 31Bに渡してプロンプトを作らせる用途で使用（>>849）。LLMのおかげでインストールの手間がほぼ無になったとの声（>>856, >>910）。

# 総評

1. **ComfyUIは新モデル対応の速さと動画生成用途で圧倒的優位だが、テンプレートWFの複雑化やNSFW規制画面の罠など運用面の敷居は上がっている**。bat起動による前処理仕込みや用途ごとのデスクトップ環境使い分けなど、実行手法の最適化が議論の中心。
2. **野良exeとカスタムノードのセキュリティリスクが強く認識されており**、ComfyUI Managerの一発導入を危険視し `requirements.txt` と `__init__.py` の確認を必須とする意見が主流。LLMに依存関係や怪しいコードの確認を任せる運用も出ている。
3. **rusting strataは軽量・高速で64GB環境でも複数ツール同時立ち上がる強みがあるが**、Rustビルドが必要な導入の敷居とモデル・環境ごとの調整難易度が課題。VRAM 8GBずつの割り当てによるComfyUI併用が実用レベルで成立している。
4. **LLMを活用した環境構築・復元・インストールの簡略化が浸透しており**、チャッピーやClaudeに指示してComfyUI環境を復元したりモデル導入を自動化するフローが実用化されている。
