**抽出結果（ツール関連のみ）**

### ComfyUI（comfy）関連
- **対応の速さ**：新しいモデルや機能へのゼロデイ対応が早い（Codexリセット対応、MiniMax H3対応など）。Forge neoより根回しが早いと評価（633, 661）。
- **推奨理由**：画像生成以外（LLM・動画・音声など）はComfyUI一択になりつつある。LLMにカスタムノードを作らせやすい（656）。
- **ワークフロー・カスタムノード**：
  - Anima 2.9B用LoRAを3.8Bで使うためのworkflow＋カスタムノード（629）。
  - MV自動生成カスタムノード（歌詞同期SRT字幕対応、Context Loop使用）（682）。
  - comfyui-image-saverノード（メタデータ埋め込み）（706）。
  - AVIF対応のカスタムJS（666）。
  - Context Loop / Contex Loop関連ノード（MV生成、歌詞同期、日本語→英語コンパイラなど）（682, 716, 724, 728）。
- **UI・運用**：
  - ブラウザで動くが「webUIみたいなもの」との指摘（657）。
  - Desktop版（Comfy Desktop）の評価：インスタンス複数管理、スナップショット機能、モデルフォルダ管理がしやすい（746, 769）。
  - APIを叩く自作UI作成（655）。
  - kjnodes＋本体だけで大抵のことが済むようになった（753）。

### webUI / Forge関連
- ComfyUIと比較して「画像生成だけはA1111（Forge neo）を使いたい」という声（656）。
- Forge neoは頑張っているが、ComfyUIほどの新モデル対応速度はない（661）。

### その他のツール
- **LM Studio**：Gemmaモデル使用時のクラッシュ報告と対処（Physical Batch Size変更で回避）（669, 678, 726, 736, 822）。
- **audio.cpp**：Yue2-3BやIrodori-TTSをLinux+RadeonやmacOSで動かすためのCLIツールとして紹介（674）。
- **Claude**：UI作成やカスタムノード作成の相談先として推奨（629, 664）。

### 抽出されなかったもの
- Anima（モデル指定のため除外）
- Qwen（画像生成関連は除外、非画像生成話題は該当なし）
- その他モデル名（Wan, FLUXなど）は一切抽出せず

主な選定理由として繰り返し挙げられているのは「**新機能への対応速度**」と「**カスタムノード・ワークフローの柔軟性**」です。
