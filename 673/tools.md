# 元の本文
**ComfyUI / webUI系ツールに関するレポート**

以下は、提供されたテキストから抽出されたComfyUIおよびwebUI系ツールに焦点を当てたまとめです。ツールの言及内容、選定理由（手軽さ・軽さ・機能差・運用効率など）を中心に整理しました。モデル名（Animaなど）は除外し、ツール/UI/運用環境に限定しています。

### 1. ComfyUI
- **主な言及内容**: 
  - 動画生成後のWebPフレーム抽出（専用機能はあるが手軽さに欠けるため、batファイルやPython+tkinter GUIの代替検討）。
  - ForgeNeoとの比較で「高解像度時の軽さ」が優位と評価され、乗り換え検討の文脈で登場。
  - 用途（モデル/LoRA組み合わせ）ごとにポータブル版を複数分離運用（例: Anima用、エロLoRA用、Detailer用）。更新（v0.29.0など）による速度向上や新機能対応を期待しつつ、破壊的変更回避のため安定版を残す運用も。
  - Florence-2が標準搭載で、専用検知モデルの作成不要。
  - ワークフロー管理（LTX Video生成時のVAE切替など）で利用されるが、カスタムノードのエラー発生例も。
- **選ばれている（または検討される）理由**: 軽量性・リソース効率の高さ、既存機能（Florence-2）による手間削減、用途ごとの環境分離による干渉回避。シンプル作業や高解像度生成に向く点が評価される一方、手軽さ不足の指摘あり。デスクトップ版はプロファイル切り替えのしやすさが利点だが利用は少ない。

### 2. ForgeNeo（SD-WebUI-Forge-Neo / webUI系）
- **主な言及内容**: 高解像度（1536x1536）生成時のメモリ使用量・安定性に関する議論。ComfyUIとの軽さ比較で言及され、「Comfyのほうが軽いなら乗り換えも」との声。
- **選ばれている（または検討される）理由**: 現在使用中の環境として挙がるが、メモリ消費が厳しい場合の代替としてComfyUIが検討される。軽さが判断基準。

### 3. Krea2（Krea 2）
- **主な言及内容**: 画像生成ツール/インターフェースとして複数登場。LoRA学習実験（Animaと同一条件比較）、壁紙生成、衣装再現などで使用。torch更新（cu128→cu130）でINT8変換が約3倍高速化した事例あり。
- **選ばれている理由**: 衣装再現度の高さ、プロンプト追従性・細部学習の強み（Animaより優位な用途あり）。用途による使い分けが可能。

### 4. その他の関連ツール・プラットフォーム
- **Civitai**: LoRA公開・共有プラットフォーム。新規LoRAや実験的使い方の情報収集・検証場として活用。反応が早く集まりやすい点が利点。
- **MosaicTool**（GitHub: kidonaru/MosaicTool）: YOLO自動検出付きの静止画モザイク処理ツール。複数対象検出の漏れが課題だが、静止画用途で簡易性が評価。動画モザイクは性能不満が多く、理想ツール（ドラッグ範囲指定即出力）が求められている。
- **Codex**: GUIアプリ自作（コマ配置・キャラ指定アプリ、Zippla風画像ビューアなど）に活用。短期間（1週間程度）で実用レベルのツールを作成可能で、既存ツールの表示速度限界を解消。
- **Chappy（チャッピー）**: 日本語指示のみで高性能出力（キャラ指定・コマ配置・エロ表現・ラフ追従）。GUI不要の手軽さと柔軟性が強みで、ポン出し漫画の上位互換として位置づけ。
- **その他運用関連**: 
  - ローカルオフラインWindowsツール全般（ブラウザベースオンライン工具に対するプライバシー・データ送信回避）。
  - iPhoneでのローカルwebサーバー運用例。
  - runpod（クラウドGPU環境）。
  - 自作Prompt管理ソフトウェア（Codex/ClaudeCode組み合わせ）。

**選定理由の傾向**: 軽さ・リソース効率、手軽さ・GUIの有無/簡易性、特定タスク（デザイン維持・検出・モザイク・自作アプリ）での機能優位性、プライバシー（ローカル/オフライン）、運用効率（環境分離・更新管理）が主な判断基準。
