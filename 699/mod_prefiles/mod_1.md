## Qwen-Image（Qwen21 / QI2.1 / QIE2.1 / Qwen-Image-2.1）

このログの中心です。選ばれている／外されている理由はかなり具体的です。

**選ぶ理由**
- 軽い。4070・VRAM12GB・メモリ16GBでもデフォルトで約70秒。int8は7GB台で、12GB帯でも編集に使える、という評価。
- 速い。5070Ti 16GBで拡散モデルとTEをbf16に上げても、2MP編集が約21秒。旧2511のbf16（約40GB）は1分超だった、との比較。
- 編集が実用的。衣装・髪型スワップはMinimax Image Studioより上手くいった例あり。キャラや衣装の変更が簡単、という驚きもある。
- t2iは衣装が強いのでKrea2と使い分け、加工はH3と得意分野が違うので使い分け、という位置づけ。
- 透過画像が作りやすい。軽いことと合わせて、別モデルでキャラと背景を作る自動化がやりやすくなる、が採用理由。
- 日本語入力が楽（プロンプト生成用LLMも同梱）。日本語文字の表示も良い、という比較あり。
- 公式が「出力はライセンス対象外。生成物の権利はユーザー」と明言。これでレギュラー投入してよい、編集データセットの公開も問題ない、という判断。
- AI ToolkitがすでにQwen21 LoRA対応。16GBでもLoRAが作れるかも、が今後の利点として挙がっている。
- 生成・編集とも「他ではできない部分がある」という評価。

**選ばない／様子見の理由**
- ポーズは弱い。参照画像を厳密に当てるのはMinimaxの方が強い。Qwenは「似た感じ」にするだけ。
- t2i自体は高くない、という見方。物体の崩れ、手前を別物体が横切ると一貫性が崩れる。公式WFのstep25は少なく40〜50、cfg4でネガが使える、という運用話。
- 緊縛は縄が破綻しがちで、Krea2から積極的に乗り換える理由はない、という感想。Ideogram 4.0に戻った人あり。
- 日本語での編集はFlux2 Kleinの方が高い、という比較（TEは同じ8Bでも差がある。無印とVLの差では、という推測）。
- 二次エロ用途ではAnimaから移行する段階ではない。絵師タグ・版権・タグを履修しきったFTが来ない見込み。
- ライセンスがエコシステムを止める、が最大の不採用理由。生成物・チューンモデル・LoRAの金のやり取りは個別ライセンスが必要。無償公開は可だが、Anima後継のような大型二次エロFTは資金が要るので来ない。商用で小銭を稼ぐ人には使いにくい。
- 8Bでは画像からのセリフ自動生成は性能不足。パチスロは学習していなさそう。性器描写は期待薄。
- 運用上の不満: ComfyデフォルトWFはシード固定でサブグラフ展開しないとrandomizeにできない。AVIFのアルファ保存は非対応。

## NovelAI（NAI / NAI5）

- ログインできない、という不具合報告。
- V5規約変更で、残っている定期購入分のAnlasが失効する話が中心。契約日で期限は違う、放置分が一律削除されるのではとログインした、今のうちに消費する、V4移行時と違い今は消費できる、という実務話。
- **NAI5が基準として選ばれている理由**: 全体のバランスが良い。このくらいがローカルに来たら「ゲームセット」。日本語プロンプトを正確に反映する（「目頭の下にシワ」のような直接指定が通る）。以前のモデルは英語でも反映しないかガチャだった。
- Qwenのライセンス文言は、NovelAIやPixAIのようなサービスがタダ乗りするのを禁じるものだ、という解釈。

## illustrious（リアス）

- 8か月ぶりに復帰した人が、リアス系の過去ワークフローを読むと使えないノードが多く、代替探しが面倒、という環境話のみ。
- 画風や性能を理由に選んでいる記述はない。

## FLUX

- QI2.1の日本語編集はFlux2 Kleinの方が高い、という比較。TEは同じ8Bなのに差があり、無印とVLの差では、という見方。
- この種のライセンスが出るたびに生成物の扱いが問題になる、という前例としてFluxが挙げられている。性能面で積極採用する話はない。

## Wan

- 品質の比較対象。Xで流れるWanやSeedance製に比べ、ローカルのMinimax二次はまだ差をつけられている、という文脈。
- 精液の飛沫が難しい。顔射でも先端から飛ばず、先端を顔にくっつけて溢れる表現になる、という不採用に近い不満。
- これを理由にWanを選んでいる、という記述はない。

## anima（Anima / waiANIMA）

**まだ選ばれ続けている理由**
- 二次エロの実用基準。Qwenからの移行はまだ、という結論。
- Comfy.orgが予算を入れて作り込んだ「奇跡」。絵師タグ・版権キャラ・タグをきっちり履修している点が、Z-Image・旧Qwen-Image・Krea2との差。
- 特定の出方はAnimaなら大丈夫で、Qwen用にプロンプトを作り直さないと出過ぎる、という制御のしやすさ。
- タグ方式がまだ有効。自然言語キャプションはエロで弱いので、Animaは強調数値を大きく上げる、という運用。
- waiANIMA実使用例あり。ペニスサイズを強く書くと全体を描こうとして挟まない。サイズ指定を消すと挟む、というプロンプト調整。

**関連する不採用・懸念**
- 初期ライセンスが微妙で、改訂を経て今がある。Qwen-Image-2.1のライセンスは初期Animaと似ていて既視感がある、という話。
- Qwen側のライセンスと資金の問題で、Anima後継の大型FTは来ない、という見立て。

## Z-Image（z-image / Zimage）

- 緊縛が弱い。Krea2と同様、縄が破綻してイマイチ、が不採用理由。Qwen21はどうか、と比較対象にされている。
- 公式アニメモデルは実在するが、学習ツールだけ配布されて終わった。オープンソース継続で揉めていた時期に論文が出たので、時期がずれていれば正式リリースされていたかも、という経緯。
- マス向け二次エロはあるが、絵師タグ・版権・タグの履修が不十分で実用圏外、というAnimaとの比較。積極的に選ぶ理由はこのログにはない。

## MiniMax（Image Studio / H3 / FastH3 / Singularity）

このログで除外対象以外として最も厚い。用途で使い分けられており、全面採用ではない。

選ばれる理由:
- 参照画像を厳密に当てはめる編集は、比較対象より強い、という評価。
- 顔差し替えに近い編集では Image Studio の方が上、という報告。
- 動画は、外部サービス製には及ばないものの、ローカルでこの水準まで来る点は評価されている。r2vよりi2vの方が絵柄の崩れがマシ、という使い分け。
- FastH3は、スマホやFHDモニタなら合格、という実用判断。引きの低解像度では顔が溶けるので、4K前提では別評価。
- 編集は得意分野が違うので、他モデルと併用する、という位置づけ。

選ばれない・冷める理由:
- SingularityはXでは持ち上げられるが、このスレではほぼ不評。サンプルがSeedanceの生成物で学習したように見える、エロ用途の訴求がない、3D・シネマ寄りで2Dアニメ専門には無用、という理由で触られない。画風は繊細になるが、バニラやFastH3の方がコミカルでポップ、という対比。
- 初期は革命的と盛り上がったが、いまは勢いも話題もほぼない、という総括。
- 商用不可で使いにくい。
- ComfyUI更新で Image Studio や H3 の Reference to Video ノードが壊れる、という運用上の障害。
- LoRA学習は重い。1024は溢れる。400×400・少数ペア・block swap多用で4090がギリギリ、という報告があり、大多数には非現実的、という見方。できたLoRAも変化量は小さく、動きは固くなる一方、質感改善は出る、という初期結果。
- 特定の主観アングルや行為は学習データが薄く、工夫しても破綻しやすい、という指摘。性器をLoRAなしで安定して出せるモデルはまだ出ていないのでは、という疑問も出ている。
- 速度面では、falの高速化版を望む声と、Attentionを疎にする手法で4070上およそ4割短縮したという報告があるが、後者は意味が疑問視されている。

## Krea2 / Krea2-turbo

選ばれる理由:
- 特定の実物（パチスロ筐体など）のベース形状を出す用途では Krea2-turbo が使われている。
- キャラの好みとして、他モデルよりKrea2、という個人評価がある。

選ばれない理由:
- 拘束・緊縛は縄が破綻してイマイチ。ここから積極的に乗り換える理由はない、という見方。
- キャラクターシート作成は、比較した編集モデルの方が使いやすい。
- 衣装の強さでは差別化の相手にされる側で、衣装用途の第一候補ではない。
- 量産的な二次エロはあるが、絵師タグや版権キャラを十分履修しておらず、その用途では実用圏外、という評価。

## Ideogram 4.0

- Krea2から乗り換える積極理由が見えないため、使い慣れた Ideogram 4.0 に戻った、という報告。選定理由の詳細はない。
- ライセンスが厳しいモデルは、Ideogram 4程度の限定的なエコシステムにしかならない、という比較の物差しとして出ている。

## Seedance

- モデル自体をローカル採用した話ではなく、X上の動画品質の上位比較対象。ローカルのMiniMaxより上、という見方。
- Singularityの学習元がSeedance生成データではないか、という推測もある。

## その他

- **Deepseek**: ChatGPTとGeminiが拒否したプロンプト作成の代替として試されている。結果の安定には追加指定が必要、という評価で、採用理由は「拒否されにくい場合がある」程度。
- **Pixai / tsubaki**: tsubakiはエロで拒否された、という報告。18禁タグ自体はあるはず、という返答のみで、選定理由は出ていない。
- **YuE2-3B**: 採用話ではなく、LoRA学習が24GB前提でMiniMax H3より難しい、という難易度比較。
- **SD1.5 / SDXL**: 選定理由はなく、昔の基準や、次世代の多層構造がSDXLの二段処理よりオフロードしにくい、という比較だけ。
