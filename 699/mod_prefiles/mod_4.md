## illustrious（イラストリアス / リアス）
選ばれる／残る理由が一番はっきりしている。

- **841 / 842 / 846 / 857 / 859**: 漫画制作より「抜ける絵」向き。ランダム性が自分の妄想の先まで行くので、狙わず手軽にエロ絵が出る。線・塗りはイラストリアスの方が良い、という評価。対比として「リアスは抜きゲー、Animaは普通のエロゲ」。
- **844**: 絵師タグを大量に並べて品質を上げられたのは、生成がタグに直結するU-Netの特性。DiT主流になった今、SDXLのリアスは「ある意味の到達点」。弱点はほくろの左右すら分からないこと。
- **768**: 人数の描き分けは2人が限界（Animaは条件付きで4人程度、という対比）。
- **854 / 856**: animaやKrea登場でSDXLは古扱いだが、絵柄は今もトップ。絡み・背景を見るなら一線級。進化が止まった分、ユーザー製FT・マージ・LoRAが豊富なのが強み。
- **859**: キャラLoRAで小物再現を詰める用途ではリアス ＜ Anima ＜ Krea2。ただし「エロければ細部はいい」ならリアスで足りる、という使い分け。

## FLUX
- **695**: イラストの画風指定では、minimaxより flux2 klein の方が強い面がある（使い方が悪い可能性も自分で疑っている）。本命候補は洗練後のQI。

## Qwen-Image（QI / QI2.1 / QIE2.1 / Qwen2.1 / Qwen image）
このログの中心。選ばれる理由は速さ・同一性保持・編集のしやすさ。

- **652 / 655**: QI2.1は爆速。作例がなければ驚き屋、という突っ込み付き。
- **693 / 694 / 704 / 717 / 722 / 736**: 顔の維持・同一性保持は他よりかなり良い、が選好理由。弱点は色が薄い、中華顔／アジア顔が強い、綺麗すぎて人工感、デフォがGPT Imageの量産顔っぽい。チューニングモデルが出れば化ける、という期待。
- **699 / 755**: QIE2.1は生成が速く元画像保持が良いので、ゲーム向けのリアルタイム人物加工に使っている。QIE2511は遅い。AnimaやKrea2のEditは元画像が微妙に変わって違和感が大きい、という比較でQIE2.1が選ばれている。楽な使い方は、一発に詰め込まず細かい編集を連打すること。
- **701 / 702 / 707**: ポーズや形の整形役。Krea2-turboとの接写比較あり（4MPはKrea非対応なので2.3MPで比較）。
- **713 / 739**: デフォ絵柄はGPT Image量産風。二次元の三次元化はポン出しでも良く、プロンプトを詰めればさらに良くなる見込み。
- **724 / 727 / 728**: 二次元なら編集以外の出番は薄い（エロを拒否しないGPT Image 2.0くらいの位置）。三次はコツがないと似た顔ばかり。チューンモデルが来れば別、ただし来ないだろう、という見方。
- **745**: 参照画像だけ渡してその子とエロRPしたい、という用途の質問。評価は出ていない。
- **757 / 758**: TEはH3並みに賢い印象。Krea2＋QI2.1でnanobananaは超えたが、GPT-Image 2.0までは届かない。
- **660 / 661 / 826**: AI Toolkitでの画風LoRAは破綻しやすい。強度を下げると画風が乗らない。Musubi tuner対応待ち。kohyaは対応優先度低め。civitaiの「アニメ→リアル」LoRAは消えた模様。
- **771 / 828**: 複数人の参照画像だと崩れて、公式のような記念写真風にならない。結局、参照画像を渡して指示するのが一番、という結論（Minimax ImageStudioも同様）。
- **831 / 832**: 背景透過は強い。少し粗いが、自然言語で簡単に透明にできる点が評価理由。
- **821**: TEをQwen3.5 0.8Bに差し替えた版が出ている。多言語不可・テキスト品質低下は当然として、生成・編集自体は動く。2Bくらいなら大半の用途で劣化を感じずに動かせるのでは、という見立て。
- **814**: `--fast fp16_accumulation` ＋ Kitchen Attention 有効だと、Krea2やQI2.1がプロンプトを無視する不具合報告。

## anima
選ばれる理由は「狙った絵」と「キャラLoRAの作りやすさ」。弱点はTEと多人数。

- **699**: Edit用途では元画像が微妙に変わるため、同一性保持ではQIE2.1に負ける。
- **762 / 763 / 766 / 768 / 787 / 801**: 長文LLMプロンプトで破綻しやすい。人数がプロンプトに従わず、解像度・アスペクトで変わる。原因候補はTEの弱さとDanbooru寄せチューン。軽量級なのでQI/Kreaと単純比較できない、という意見も。多人数は苦手だが、SDXL（リアス）よりは強く、長文でなければ4人程度は描き分けられる、という主張と、女3人の複雑ポーズでは崩壊したという反論が並立。
- **838**: 2.5D寄りのアニメ調素材として使われている（参照画像用）。
- **846 / 857 / 859**: 狙った絵はLLMと相談すれば大体出せる。キャラLoRAはリアスより作りやすい。小物再現を詰めるならリアスより上、Krea2より下。一方、抜きやすさ・ランダム性ではリアスに負ける。

### Minimax（H3／mmH3／ImageStudio）
動画・画像の実用モデルとして繰り返し話題になっている。

- イラストの画風指定は弱く、そこは他モデルに劣る、という評価。
- それでも「めっちゃ強い」側。とくに **Grok Imagine が規制で意図どおり出ない** のに対し、mmH3 のほうが狙ったものが作れる、という理由で選ばれている。
- **Seed 固定で詰められる** 点も採用理由。
- ImageStudio は、プロンプト単体より **参照画像＋指示** が確実、という使い方。
- H3 の I2V は、公式最大がおおよそ 15 秒、という話。音声参照・リップシンクは、台詞をプロンプトに書いたうえで音声を参照させると通り、テキストエンコーダが賢い、という評価。FL2V 入力だけでは MP3 参照は通らない／無視される、という制約も出ている。
- 旧 Grok 動画のような「抜ける祭り」感は薄く、お淑やかで抜き用途には弱い、という対比もある。
- 初動の it/s が極端に遅く見えて止めがちだが、放置すると通常速度に収束する、という運用メモ。

### Krea2／Krea2-turbo
- 編集で元画像が微妙に変わり、違和感が出る、という欠点が明示されている（同一性維持目的では選ばれにくい）。
- 一方、キャラ LoRA で **小物まで再現したい** ときは、細かい再現の上限として Krea2 が上に置かれている。抜き専用なら細部は不要、という切り分け。
- 最終仕上げ枠としても名前が出る。Krea2-turbo は同一プロンプトの接写比較（2.3MP）の比較相手。
- LLM が書いた長いプロンプトを食わせる前提のモデル、という位置づけ。
- 起動オプション `--fast fp16_accumulation` と Kitchen Attention 併用で、プロンプトを無視する、という不具合報告がある。

### SDXL
新しいモデルが出て「おじいちゃん扱い」されつつ、まだ現役という話題。

- **絵柄は今もトップ**、絡みや背景も一線級、という理由で残っている。
- 進化が止まった分、FT・マージ・LoRA 資産が厚い。
- 複数人は位置がランダムで混ざる、という弱点も併記されている（背後の男性と女性が融合する、など）。

### Ming-Image
- Kijai が着手しはじめた、という速報。
- デザイン特化で、この板の需要（抜き・既存パイプライン）とはずれている。
- ただしアニメ化のベース候補としては、画面の AI っぽい煩さが出にくい。リアリティは低いが、アニメ用途なら問題にならない、という見方。

### Grok／Grok Imagine
- 「新しい Grok どうなん？」は投げっぱなし。
- 昔の Grok 動画は 10 秒程度で強いものが量産できた「祭り」だった、という回顧。
- 現行の Grok Imagine は **規制が強く、意図したものが作りにくい**。その反動で mmH3 に流れている。

### GPT-Image／GPT-Image 2.0
単体の作例議論は薄く、ベンチマークとして出る。
