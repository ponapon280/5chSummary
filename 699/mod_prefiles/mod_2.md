## Qwen-Image（QI2.1 / Qwen2.1 / Qwen-Image-2.1 / Edit）

一番多い。選ばれる理由と不満がセットで語られている。

**選ばれる・評価される点**
- アーキテクチャが cross-attn や MMDiT よりパラメータ効率が高そうで、multi-turn editing にも自然に合う（253）。本体は Qwen3-VL 側で、DiT は image decoder にすぎない、という見方（432）。
- 軽い・速い。同 step で Krea2 の約半分（261）。強みは「軽くて早い」、品質の出しやすさは Krea2、という整理（292）。8GB VRAM 対応サイズがある（343）。Edit は QIE より軽い（373）。VRAM10 / RAM32 でも背景透過ができた（299）。
- 編集が実用的。丸を描いて消す／直す（266）、outpainting（268）、背景透過は IOpaint より細部が良い（299, 315, 436）。Edit を `upscale` だけで 2 倍アップスケーラ代わりに使う話（423。画像はかなり変わるので低解像度向けかも）。
- ベンチが NanoBanana を超えている、という話（273）。今後は QIE2.1 では、という見方と、T2I はまだ Krea2 優勢という反論が並立（290, 292）。
- ComfyUI は公開前から対応、Forge Neo は未対応なので新モデル即試すなら ComfyUI（275）。公式 WF を置くだけでよく、Easy ノード必須ではない（288）。テンプレは step20、公式資料は step40 という食い違い（289）。Spectrum 対応の話（284）。
- 参照画像でのキャラ固定（2D）はかなり使える、参照能力は高い（355, 444）。
- プロンプトエンハンサ用 TE、i2i/t2i 用 qwen3.5 TE が Comfy 側に追加（302, 360, 362）。
- 素の NSFW は Krea2 と違い、フィルタで乳首すら出ない仕掛けはなく、デフォルトで出る（388, 375 は Edit で実写なら素でも出る、と）。無検閲 GGUF が出た（295, 402）。ただし「追加学習なしの無検閲に意味があるか」「元からエロ学習は薄いのでは」という疑問（372, 408）。
- 見た目は顔が量産寄り・頭身スリム・CG 感が強く、二次寄りの好みなら QI に寄りやすい（377）。二次を描かせると GPT-Image 2.0 味（387）。
- LoRA 学習環境はある（382）。AIToolkit で 1024、約 4.0s/it。Anima より遅く Krea2 より速い。オフロードで VRAM14GB・RAM60GB、RAM があれば 16GB VRAM でもいける（393）。ファイルサイズ的に Krea2 より学習しやすそう、Kohya 対応待ち（392）。

**選ばれない・不満**
- T2I の人物・実写は Krea2 優位という意見が多い（292, 342, 359, 367, 377）。ここであまり盛り上がっていない＝イマイチでは、という空気（338）。
- エロの出来は素の Krea2 並みに残念、という評価（378）。参照させても胸がそのまま出ず、生成され直した微妙なものになる（422。制限のせいかという疑問）。
- 二次の指の溶け、複雑なポーズが弱い。Krea2 は指が強い。複雑なポーズは Krea2 どころか Z-Image 以下では、という酷評（388, 403）。
- 参照画像で一気に重くなる。T2I は 1 分未満〜20 秒という報告がある一方、参照ありだと 10 倍以上、3060 では生成 2 分でも記録上 7 分（344, 347, 353, 358, 443）。5070 Ti / RAM32 で 1 枚 4 分は異常側、という流れ。resolution 0 の i2i は入力サイズそのままなので大きいと遅い（352）。
- 以前 Krea2 で通ったデータセットの LoRA はぐちゃついた（383）。学習環境がまだ無い、という古い認識と「もうある」が併記（378, 382）。

**プロンプト用 VLM（QI ワークフロー文脈）**
- ローカルで画像＋指示からプロンプトを作りたい、という質問（386）。候補として Qwen3 系 27B 無検閲か Gemma、ただし VRAM ゲーで Grok の方がコスパ、という答え（390）。Qwen3-VL-4B は数秒だが曖昧指示への想像力は弱い（391）。キャプション用に qwen3-vl-8b の abliterated / nsfw-caption 量子化を使っていた、という話（413）。システムプロンプト次第（421, 413）。専用カスタムノード＋Comfy 謹製 TE で済む、という紹介（396）に対し、まともにプロンプトが出た試しがない、max_length が大きいと 1 時間近く、という不満（433）。

## NovelAI（NAI）

- ちびキャラ系絵師をネガティブに入れると画力が明確に上がる。回りくどい挙動の原因は Danbooru データセットでは、という推測（279）。**選ぶ／調整する理由は「ネガで画風を抑えると画力が上がる」体感。**
- NAI で作った漫画を X と pixiv に投稿。X はいいね 4 桁やリポスト、pixiv はブクマが少ない（閲覧:ブクマで良くて 10:1 程度）。少量プロンプトのポン出しだと思われているのでは、という解釈（411）。需要の話として、非エロは伸びにくい、X は世界中に見える、という反応（412, 414）。
- NTR のビデオレター風シチュに使用（419）。演出として film grain、vignetting、scanlines、ビデオテープ風画質（420, 424）。**選んでいる理由の明示はなく、漫画投稿とシチュ遊びの実用例。**

## anima

**選ばれる／使い続ける理由**
- 自然言語に対応していて、タグだけより色々できる（398, 446）。学習は Danbooru と短い自然言語の両方で精度を出す、という運用（434）。
- 学習速度は Qwen2.1 より速い（393）。
- 模様はリアス以上に出ることがある（439）。ただし安定はしない。

**キャプション（選択というより運用上の争点）**
- キャラ／画風 LoRA で自然言語キャプションが要るか（369）。昔は Danbooru タグだけでいい、という話があった。Claude は自然言語を付けろと言うが、LLM は無関係な誤キャプションを付ける（369, 371）。
- 整理（398, 434, 435, 442）: SDXL までは Danbooru 以外はノイズ。Anima は自然言語にも反応するが TE が弱く、詳細に書いても限界。生成時にタグしか使わないなら自然言語キャプションの意味は薄い。着せ替えや精度を求めるなら短い自然言語は必要で、書いたものを生成時にも使う。学習文と画像がある程度一致することが大事。LLM 全任せは不可、たたき台にして手動確認。WD14Tagger を参考に全部手書き、という実例（434。例: `school uniform jacket with breasts patch`）。Kohya の VLM キャプションスクリプトは 90〜95% はそのまま使えるが失敗もある（442）。TE が効いている時と単語だけ拾っている時があり、派生モデルだとうまくいかずベースに戻すと意図通り、という塩梅（440）。

**弱点（他モデルに流れる理由）**
- 動きを付けると 3 キャラで崩壊。複数人の掛け合いは Krea2 の独壇場、という対比（332）。Anima で再現を頑張ってもできなかった（365）。283 は Anima プロンプトのみでできたのでは、という誤認で、294 で Krea2 と訂正されている。
- 手指が汚い（397）。
- 自作 LoRA で頭が大きくなりがち。教師画像が妥当なら学習不足の可能性。SDXL と進み方が違うのでステップを上げ、途中保存で確認（429, 430）。
- 凝ったキャプションは TE 限界で認識しない（435）。
- 舌の残像、唾液と motion lines の区別が弱い。教師が約 30 枚だとこの辺りが限界（445）。
- フタナリで片方の胸が小さくなるのは相変わらず。基本男女で学習しているので諦めるべきでは、という見方（446）。

## MiniMax H3（H3 / RefMod / ImageStudio / H3 Edit）

このログで最も具体的に運用が語られているモデルです。

- **選ばれる理由**: 参照画像をRefModにまとめて再利用できる。顔アップ・三面図・追加参照を毎回別々に渡さず、一つに梱包できる点が便利とされている。
- **動画モデル由来の編集**: MiniMax-H3 Editは、深く入れる・抜くなど中間のコマを取りやすい。元が動画モデルだから、という理由。代償は画質が微妙なこと。
- **画像編集のプロンプト応答**: 画像編集ではMiniMaxの方がプロンプト応答が良い、という比較がある。参照した胸の形をそのまま馴染ませられる、というImageStudio評もある。
- **アニメの一貫性**: 一貫性を保ったまま動かす用途では、H3の画像生成が良い部分もある、とされている。
- **軽量版**: `ComfyUI-MiniMax-H3-W4A4-VSA` は速く、12GB VRAM向けの候補として挙がっている。
- **プロンプト作成**: ローカルで画像読み込み付きのプロンプト作成を完結させるとVRAMが重い。そのためGrokに参照画像とMinimax公式プロンプトガイドを渡すやり方が実用策になっている。スパグロ契約の主用途が、動画生成ではなくローカルMMH3向けプロンプト作成だという発言もある。GeminiはH3用の過激なプロンプトも拒まず作る、と対比されている。

運用上の注意として繰り返し出ている点は次のとおりです。

- RefModでも本体プロンプトにキャラ要素は必要。簡略キーワードや `sks girl` 程度でも乗る、という報告がある。
- 参照画像のポーズに強く引っ張られる。通常の参照画像より強く寄るため、切って使うのをやめたという声がある。使いどころ次第では有用、とも。
- ワークフロー理解は「Create H3 RefMod Masterで事前作成 → Load H3 RefMods → Apply H3 RefMod」。デフォルトだと形が崩れる。Load側のComponentsをVisualにするとマシになるが、再現度はまだいまいち、という感想。
- Fantastic側なら「Draft from Refmod」で参照関係を自動入力できる。
- プロンプト自動化案として、VLMで参照画像をキャプション化しメタデータに含める、`subject_definitions` で `<Subject 1>` をアンカーなし定義する、梱包画像の1枚をVLMに渡してから `<Picture 1>` を手修正する、などが議論されている。メタデータだけだと直接解析より質が落ちないか、は未解決のまま自己解決で閉じている。

参考ドキュメントとして `ComfyUI-Fantastic-MiniMaxH3-PromptBuilder` が挙がっています。

## Krea2（言及のみ Krea3）

人物・実写・複数人制御の本命として選ばれています。Qwen-Image 2.1との比較は除外対象側の話なので、Krea2が選ばれる理由だけ残します。

- **人物の仕上がり**: 肉付き・頭身・肌の生命感がリアルに近い。「未加工の生写真」寄り。T2Iの人物系はKrea2優位、品質を出しやすい、という位置づけ。
- **複数人制御**: 複数人の掛け合いはKrea2の独壇場、という評価。キャラごとに体型（無指定、眼鏡、デブ、ガリガリなど）を指定できる。1発は運なので複数回出す前提。
- **手指**: 指が強い。腕が増えることはあっても指は増えにくい、と比較されている。
- **NSFW**: 素ではフィルターで乳首すら出ない仕掛けがある。LoRAで解ける。カスタム手段によって生成物が変わる。素のエロ性能は弱いが、学習やLoRA後の実用で選ばれている。
- **キャプション**: TEが強く、Danbooruにない柄なども自然言語で詰められる。キャラだけで数百文字使っても生成に影響しにくい。その分、プロンプトと構図がほぼ1:1で、少し変えると良かった部分まで変わる。タグを並べて放置ガチャ、という旧来の回し方はしにくい、という不満がそのまま弱点。
- **利用態度**: 使い慣れているので2次も3次もKrea2、という人と、実写は好みで分かれる、という人がいる。
- **Krea3**: 発表後、公式は動いていない。Krea2はサービスモデルの一部オープン化なので、3が出てもクローズドのまま、またはKrea2学習勢が一巡した頃にゆっくり、という見方。

## Grok

画像モデルではなく、プロンプト作成用に選ばれています。

- 参照画像＋Minimax公式ガイド＋希望する動き、を渡す普通の投げ方で足りる。
- **理由**: 画像読み込みありのプロンプト作成をローカル完結させるとVRAMが重い。27B級ローカルLLMは16GBでは足りず、コスパではGrokが最強、という比較。
- シチュエーションリストの生成にも使われている。

## プロンプト／キャプション用のLLM・VLM

生成そのものではなく、プロンプト自動化の候補です。

- **Qwen3.8 27B 非検閲** と **Gemma4 31B 非検閲** がローカル候補。このクラスは16GB VRAMでも足りない。MoEでFree TokenすればVRAMなしでもいけるらしいが、エロ性能の評価が出回っておらず実用か不明。
- **Qwen3-VL-4B-Instruct** は数秒で終わるが、曖昧な指示への想像力は弱い。
- 少し前の実用例として `qwen3-vl-8b-abliterated-caption-it` と `qwen3-vl-8b-nsfw-caption-v4.5`（Q6_K / Q8_0）。プロンプト用途なら極端な精度は不要で、システムプロンプト次第、という感想。
- システムプロンプトは、モデル説明書をChatGPTに投げて作って貼る、というやり方。
- **Gemini** はH3向けNSFWプロンプトを拒まない。ChatGPTが同じか、は未確認。
- **Codex** は、生成の崩れを見てキャプション修正案を出す用途で頼りになる。トークン消費が重いので、手動の一次厳選が先。
- **Claude** は、昔入れたカスタムプロンプトが引き継がれて全拒否になっていた、というトラブル報告。空にしたら動いた。モデル選定の話ではない。
