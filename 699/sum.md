### QI2.1
- 公式仕様とスレの体感を分けて整理する。
- 対比の軸は「観点 / 公式 / スレの体感」。
- 位置づけ: 生成と編集が同一重み、視覚部7B、最大10枚参照、ネイティブ2K、RGBA透過。体感は軽い編集モデルで万能ではない。
- 速度: ComfyUI 0.37.0から公式テンプレ、T2I例は1024・25ステップ。12GB級でも動き、4070/12GBでデフォルト約70秒、5070 Tiで編集2MP・bf16約21秒という自己申告。
- 画質: 公式はタイポグラフィと質感が売り。体感は25ステップでは少なく、40〜50・cfg 4前後で上がる。物体の崩れや、手前を横切る物体で一貫性が落ちる。
- 編集: 円・注釈・マスクで局所編集。服装・髪型はMiniMaxで失敗したものが通った例あり。参照への厳密な当てはめはMiniMaxが上で、「似た感じ」にとどまる。
- 透過: 背景除去テンプレあり、VAEがアルファを持つ。細部がよく、キャラと背景を分ける自動化向き。
- 顔・画風: 中華顔やGPT Imageの量産顔への批判と、Xで流行る系への期待が併存。イラスト指定はFlux 2 KleinやMiniMaxの方が強い、という人もいる。
- 日本語: 文字レンダリングは売り。パチスロ筐体などの表示は比較的よい。編集の日本語指示はFlux 2 Kleinの方が高い、という比較も。
- プロンプトは特別な文法より自然言語。公式PE（Comfy同梱）あり、日本語入力は楽だが品質向上は不明。公式テンプレはネガ欄があるのにcfg 1がデフォルトで、ネガが効かない指摘もある。
- 人体崩れは、ポーズ固定・cfg上げ・ネガとステップ増で減った報告（例: cfg 3.5、step 40）。デフォルトでは足りない、という声が複数。
- T2Iの素の人物は好みが分かれ、Krea 2優位が優勢。落ち着きどころは「QIは編集と速度、Kreaは人物の完成度」。4MPのポン出しならQI一本、という反論も。複数人の参照合成は集合写真にならず崩壊した失敗報告もある。

### 編集・参照の使い分け
- 合意に近い分担は次のとおり。
- 服装・髪型・部分修正・アウトペイント・透過はQI2.1が通りやすい。
- 参照画像への厳密な当てはめと、動画の参照一貫性はMiniMax H3。
- 人物の質感・指・画風はKrea 2。肌の産毛まではFlux 2 Kleinに軍配、という見方もある。
- ポーズはどちらも弱い。OpenPoseを挟めばスワップ可能という報告と、輪郭スケッチの方がテキストより安定という助言。
- キャラシートはKrea 2よりQI2.1の方がレイアウト指定が通る。
- 視点移動はまだEdit-2511の方が強いかも、実用はMiniMax、という温度感。
- 参照を増やすと急に重い。T2I単体なら1分未満、参照ありだと数分（3060〜5070 Ti級）。解像度ウィジェットの0は入力サイズ継承で、大きい入力はそのままi2iを遅くする。
- プロンプト自動化は、VLMで参照を全部キャプションするより、画像をクラウドLLMに渡して作りアンカーだけ手直しする方が無難。ローカルVLM完結はVRAMが重い。セリフ自動生成は方向性は合ったが8Bでは不足、27B級が要る。

### ComfyUIの運用メモ
- 有益だった点だけを残す。
- 同一画像しか出ない原因はデフォルトWFのシード固定。サブグラフを展開しKSamplerをrandomizeに。UIは外に出しておけ、という不満とセット。
- AVIF保存はアルファ非対応でValueError。PyAVのSVT-AV1はアルファを扱えない。
- 更新で壊れる例: MiniMax側ノードの入力追加、タブ移動でFast Muterがおかしくなる。フロントを特定版に下げて暫定復旧、という自己申告。
- Forge Neoは最新モデル対応が遅れ、即試すならComfyUI、という見方。
- `--fast fp16_accumulation` は人によって爆速とPython落ちに割れる。全体に効くのでKJ NodesのModel Patchで個別設定が安全。同フラグと一部Attentionノードの併用で、Krea 2 / QI2.1がプロンプトを無視したバグレポートもある。
- Attention系ノードは低速化の原因になる環境があり、外した方が速いこともある。高速化はspectrumだけで足りる、という報告。
- 背景透過は、生成時に出さないのと後から除去するのは別。ノード（WASのImage Rembg等）でも可能。
- RadeonドライバにPyTorch / ComfyUI / LM Studio / Ollamaが同梱、という話はスレ内情報のままで未確認。

### LoRA
- Krea 2はRAW学習が公式推奨で、スレの実務談とも一致。

### MiniMax H3（動画）
- 温度感は、初動は革命的だったが勢いは落ち、二次のr2vは絵柄が寄りすぎてi2vの方がまだまし、ローカルでここまで、という評価。画風指定はQIやKreaに劣り、お淑やかで振り切りには至らない対比もある。
- 同一設定でも10秒指定で90分、12秒で20分、途中stepから急に伸びる再現性のある異常遅延。バグらない環境もあり環境依存という見方。初動のit/sが遅く見えても放置すると普段の時間に収束する報告もある。0.6MP・15秒で約810分は誤記か誇張の可能性が高い。1.2MP・20秒は5090でもOOMという質問に、モデル依存でH3は15秒が上限という返し。
- Live2D風に元絵を崩さず動かしたい質問には、用途が逆（音声参照はref2v、元画像を動かすのはi2v）、FL2V系は音声を無視する、という指摘。成功例は「台詞をプロンプトに書く＋音声参照」が通り、生成音声はノイズが乗るのでリップシンク確認後に元音声へ差し替える運用。Live2D自体は自動まばたきを触っても自然にならず、3Dに近い力作業、という感想。

| 顔・画風 | — | 中華顔、GPT Image の量産顔に寄る、という批判と、Xで流行る系に近い、という期待が併存。イラスト指定は Flux 2 Klein や MiniMax の方が強い、という人もいる |
| 日本語 | 文字レンダリングは売り | パチスロ筐体などの表示は比較的よい。編集の日本語指示は Flux 2 Klein の方が高い、という比較も |

プロンプトは特別な文法より自然言語です。公式のプロンプトエンハンサ（Comfy同梱の PE 用テキストエンコーダ）もあり、日本語入力は楽だが品質向上は不明、という感想でした。公式テンプレはネガティブ欄があるのに cfg 1 がデフォルトで、ネガが効かない、という指摘もあります。

人体崩れは、ポーズを固め、cfgを上げ、ネガティブとステップを増やすと減った、という報告（例: cfg 3.5、step 40）があります。デフォルトのままでは足りない、という声が複数です。

T2Iの素の人物は好みが分かれ、Krea 2 優位という意見が優勢です。落ち着きどころは「QIは編集と速度、Kreaは人物の完成度」。4MPのポン出しなら QI 一本、という反論もあります。複数人の参照合成は、公式例のような集合写真にはならず崩壊した、という失敗報告もあります。

Text Encoder を小さいものに換えた話（0.8B級）は、多言語と文字品質は落ちても生成・編集自体は動く、という自己申告です。公式のテキスト側は Qwen3-VL-8B です。

## 編集・参照の使い分け

合意に近い分担は次です。

- **服装・髪型・部分修正・アウトペイント・透過**: QI2.1 が通りやすい。
- **参照画像への厳密な当てはめ、動画の参照一貫性**: MiniMax H3。
- **人物の質感・指・画風**: Krea 2。肌の産毛まで、は Flux 2 Klein に軍配、という見方もある。
- **ポーズ**: どちらも弱い。OpenPose を挟めばスワップは可能、という報告と、輪郭スケッチを渡す方がテキストより安定、という助言。
- **キャラシート**: Krea 2 より QI2.1 の方がレイアウト指定が通る、という報告。
- **視点移動**: まだ Edit-2511 の方が強いかも、実用は MiniMax、という温度感。
- **二次元の本命**: Anima。タグと自然言語の両方が通り、絵師・版権の履修が厚い。QI単体への移行はまだ、という空気。

参照を増やすと急に重くなります。T2I単体なら1分未満、参照ありだと数分、という体感（3060〜5070 Ti級）です。解像度ウィジェットの 0 は入力サイズ継承で、大きい入力はそのまま i2i を遅くします。

プロンプト自動化では、VLMで参照画像を全部キャプションするより、画像をクラウドLLMに渡してプロンプトを作り、アンカーだけ手直しする方が無難、という意見が優勢でした。ローカルVLM完結はVRAMが重い。画像からセリフを自動生成する実験は方向性は合ったが、8Bでは不足で、27B級が要る、という結論です。

## ComfyUIの運用メモ

有益だった点だけ残します。

- **同一画像しか出ない**: デフォルトWFのシード固定。サブグラフを展開し、KSampler を `randomize` に。UIは「外に出しておけ」という不満とセット。
- **AVIF保存**: アルファ非対応で `ValueError`。PyAVのSVT-AV1はアルファを扱えない、という報告。
- **更新で壊れる**: MiniMax側ノードの入力追加、タブ移動で Fast Muter がおかしくなる。フロントを特定版に下げて暫定復旧、という自己申告。
- **古いIllustrious系WF**: 使えないノードが多く、エージェントに同等ノードを作らせる回避談。
- **Forge Neo**: 最新モデル対応が遅れ、即試すなら ComfyUI、という見方。
- **起動オプション**: `--fast fp16_accumulation` は人によって爆速と、Python落ちに割れる。全体に効くので、KJ Nodes の Model Patch で個別設定が安全、という助言。同フラグと一部Attentionノードの併用で、Krea 2 / QI2.1 がプロンプトを無視した、というバグレポートもある。
- **Attention系ノード**: 低速化の原因になる環境があり、外した方が速いこともある。高速化は spectrum だけで足りる、という報告。
- **背景透過**: 生成時に出さないのと、後から除去するのは別。ノード（WASの Image Rembg 等）でも可能。

Radeonドライバに PyTorch / ComfyUI / LM Studio / Ollama が同梱、という話はスレ内情報のままです。未確認です。

## 他の画像モデル

## MiniMax H3（動画）

2026年7月31日公開のオープンウェイト動画モデルです。Hailuo 3.0 と呼ばれることもありますが、公式名は MiniMax H3 です。ネイティブ2K、24fps、おおむね5〜15秒、音声（台詞・効果音・環境音）を同一パスで生成します。参照は画像最大9、動画3、音声3。ComfyUIでは T2V/I2V 用の fl2va と、参照用の ref2va が別重みです。テキストエンコーダは Qwen3-VL 32B 級です。最大尺15秒、というスレの指摘は公式仕様と一致します。

スレの温度感は、初動は革命的だったが勢いは落ちた、二次の r2v は絵柄が寄りすぎて i2v の方がまだまし、ローカルでここまで、という評価です。画風指定は QI や Krea に劣る、お淑やかで振り切りには至らない、という対比もあります。

運用上の不具合として、同一設定でも10秒指定で90分、12秒で20分、途中stepから急に伸びる、という再現性のある異常遅延が共有されています。バグらない環境もあり、環境依存という見方です。初動の it/s が異常に遅く見えても放置すると普段の時間に収束する、という報告もあります。0.6MP・15秒で約810分、という数字はそのまま信じると非現実的で、誤記か誇張の可能性が高いです。1.2MP・20秒は 5090 でも OOM、という質問に対し、モデル依存で H3 は15秒が上限、という返しがありました。

Live2D風に元絵を崩さず動かしたい、という質問には、用途が逆（音声参照は ref2v、元画像を動かすのは i2v）、FL2V系は音声を無視する、という指摘が出ています。成功例では「台詞をプロンプトに書く＋音声参照」が通り、生成音声はノイズが乗るのでリップシンク確認後に元音声へ差し替える、という運用でした。Live2D自体は自動まばたきを触っても自然にならず、3Dに近い力作業、という感想です。

## ハードウェアと周辺

- **VRAM**: 12GB級ではブラウザ切替や解像度の欲張りで溢れ、ファンが静か＝電力が使われていない、という症状が複数。再起動、`--reserve-vram`、別端末から `--listen`、ComfyUI更新が対処として挙がっていますが、原因は特定されていません。検証環境の一例は RTX 6000 Ada 48GB / RAM 128GB で、家庭GPUとは別物、という自覚があります。
- **NVFP4**: Blackwell必須ではない、という情報。低VRAMでは「NVFP4エミュレーションの遅さ」と「int8をPCIe経由で読む遅さ」の実測が要る、という整理です。
- **Mac mini M6**: 2026年8月発表、9月出荷の実在マシンです。DrawThings + Anima が M4比で3倍、という数字は投稿者の自己申告で、Appleの「M4比AI 4倍」という宣伝とは別物です。32GBに 31B を載せると応答は数分、という報告もあります。
- **1660s** でも easyReforge 経由で Illustrious を楽しんでいる、という遅参組の報告があります。
- **Micronの2GB GDDR7生産終了**は、2026年9月下旬の報道と一致します。供給は Samsung と SK hynix の2社になり、Micronの3GBは継続、という内容です。すぐ欠品する、とまでは報道されていません。
- **電力**: 家庭マイニングは日本の電気代で赤字、という主流意見。PC貸しは計算資源を戻せない・踏み台リスクで非推奨、という警告。データセンター集約と家庭エッジの論争に結論はありません。
- ビューワ自作、マウスジェスチャ、左右比較の手間、Xとpixivの反応差、といった周辺話があります。
