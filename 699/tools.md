# 🆕 新規トピック（前回からの差分）
### 全体
- ツール話題の中心は画像生成モデル本体よりUI・ノード・学習環境・プロンプト用LLMの使い分けで、名称はウェブ照合し選定理由は各節に残す。

### 選ばれている理由
- 最近のモデルは素の性能が高くComfyUI公式対応が進んだため、野良UI需要は下がっているという評価。
- Radeonドライバ更新にPyTorch・ComfyUI・LM Studio・Ollamaのインストーラが付き、初心者のローカル導入経路になっている。
- MCP対応はトークン消費が安いという理由で、エージェント連携が選ばれている。

### 不満と回避
- デフォルトQwenテンプレはシード固定で毎回手動変更が必要かつ設定変更不可。対処はサブグラフ展開してKSamplerをrandomizeにし、ランダム化は最初から外に出すべきという指摘。
- 公式テンプレの初期step 25は少なく40〜50がよいという意見。ネガティブ欄はあるがCFG 1デフォルトでネガティブが効かない。
- サムネイル右クリックでエクスプローラを開く程度は標準であってほしい。自作で解消した例がある。
- AVIF保存は未対応の可能性があり、PyAVのSVT-AV1はアルファ非対応でValueErrorになる。
- i2iでresolutionが0だと入力画像サイズをそのまま使うため、大きい参照画像だと遅くなる。
- ハングは最新版で緩和されるという話だが、固まるとキャンセルも効きにくく再起動している。

### 起動オプションと注意
- `--fast fp16_accumulation` が必要という話に加え、VAEをint8にするとデコードが速く見た目はfp16と区別がつかない。
- 同フラグは全体に効くので、KJ NodesのModel Patch Torch Settingsでモデル個別に当てる方が安全。
- 同フラグとComfyKittinAttentionの併用でプロンプトを無視し、Pythonが落ちずPC再起動が必要になる不具合報告。
- VAEバグ（#15416）は未修正で、回避のため遅いAI ToolkitのVAEを使い、速度より安定を優先している例がある。
- Desktop版では本体設定ではなくノード側へ切り替え、VAE差し替えだけで生成時間がかなり短縮され、fp16_accumulationの効果はごくわずかだった。
- attention系ノードが低速化の原因になることがあり、sol attnもkitchen attentionも外した方が速く、高速化はspectrumだけで足りるという選別。本体組み込みで不要になったのではという推測も。
- 以前よりComfyUI側の最適化で生成がかなりマシになっているという記憶ベースの言及。

## 総観

このログ群での中心は **ComfyUI** です。新モデルをすぐ試す入口、公式テンプレート、カスタムノード、別端末操作、MCP経由のエージェント操作まで、用途が広がっています。一方で「操作に慣れない」「デフォルトが使いにくい」「更新でノードが壊れる」という不満が続き、Forge NeoやDraw Things、自作ノードへ逃げる動きもあります。

学習は **musubi-tuner / kohya / AI Toolkit** の三すくみに近く、対応の早さと低VRAMのしやすさで選ばれています。プロンプト作成は、ローカルVLMがVRAMを食うため、クラウドLLM（Grok、ChatGPT、Gemini、Codex、Antigravity）に寄せる記述が多いです。

## ComfyUI

### 選ばれている理由

- 最近のモデルは素の性能が高く、**ComfyUIが公式対応しているので野良UIへの需要が下がっている**、という評価がある。
- 新モデルをすぐ試すならComfyUI、という整理が明確。例として、Forge Neoは Qwen-Image-2.1 未対応だが、ComfyUIは公開前から対応している、と書かれている。
- Neoを使う人は「WebUIから離れられない」「ComfyUIの操作に慣れない」層だと見られている。
- 公式ワークフローを指定場所に置くだけでよく、Easyノード時代より簡単、という反応もある。テンプレートの Qwen2.1 WFをそのまま使っている報告もある。
- Radeonドライバ更新に PyTorch、ComfyUI、LM Studio、Ollama のインストーラが付き、初心者のローカル導入経路になっている。
- MCP対応ツールとして動かすとトークン消費が安い、という理由でエージェント連携が選ばれている。

### 不満と回避

- デフォルトのQwenテンプレートはシード固定で毎回手動変更が必要、設定も変えられない、という苦情。対処はテンプレートをサブグラフ展開し、KSamplerのシードを `randomize` にすること。ランダム化は最初からサブグラフの外に出すべき、というUIのギャップ指摘がある。
- 公式テンプレの初期step 25は少ない（40〜50がよい、という意見）。ネガティブ欄はあるのにCFG 1がデフォルトでネガティブが効かない。
- 更新で「あっちが直るとこっちが壊れる」。MiniMax H3 Reference to Videoの入力追加、MiniMax Image Studio、タブ移動時のFast Muterが壊れた例がある。フロントエンドを **1.52.7** に下げたら暫定で直った、という共有がある。GitHub版が **v0.37.0** になっていた、というバージョン共有もある。
- 過去のイラストリアス系WFは使えないノードが多く、代替探しが面倒。
- サムネイル右クリックでエクスプローラを開く程度は標準であってほしい、という不満。自作で解消した例がある。
- AVIF保存は未対応の可能性。PyAVのSVT-AV1がアルファ非対応で `ValueError`。
- i2iで resolution が 0 だと入力画像サイズをそのまま使うため、大きい参照画像だと遅くなる。
- ハングは最新版で緩和される、という話。固まったらキャンセルも効きにくく再起動している。
- `--reserve-vram` で0.6GB空けても、ブラウザ切替でCUDAではなく3D側に負荷が逃げる、という環境トラブル。
- tadaupは上げるとメタデータが消えやすい。WF共有時の注意。
- 別端末から `--listen 0.0.0.0` で操作し、VRAMを節約する使い方。オフロードはあっても解像度は厳しいので、ギリギリ生成のときにやる価値がある、という理由。

### 起動オプションと注意

- `--fast fp16_accumulation` が必要、という話。加えてVAEをint8にするとデコードが速く、見た目はfp16と区別がつかない、という採用理由。
- 同フラグは全体に効くので、KJ Nodesの Model Patch Torch Settings でモデル個別に当てる方が安全、という回避理由。

- VAEバグ（#15416）は未修正で、遅いAI ToolkitのVAEを不具合回避で使っている例がある。速度より安定を優先している。
- Desktop版では、本体設定ではなくノード側に切り替えた話。VAE差し替えだけで生成時間がかなり短縮され、`fp16_accumulation` の効果はごくわずかだった。

| H3 RefMod系 | Create → Load → Apply。Fantastic側は参照関係が自動入力。デフォルトは破綻しやすく、ComponentsをVisualにするとマシ | ドキュメント（ComfyUI-Fantastic-MiniMaxH3-PromptBuilder）が参考になった |
| W4A4量子化ノード | `ComfyUI-MiniMax-H3-W4A4-VSA` | 速い。12GB VRAM勢はこれで決まりかも |
| 音楽ノード | SheetSage2のABC譜をYuE2 Generate MusicとKサンプラーで原曲寄せ | 似せ具合をサンプラー設定で調整できる。LoRAの代替になり得る、という見方 |
| ワイルドカード vs 自作 | 既存は毎回ランダム止まり。欲しかったのはシチュ固定でカメラだけN回、リストの順送り／シャッフル | 欲しい機能がすぐ手に入る。ノードはChatGPT、リストはGrok |

| SAM3 | アニメ画風でも検出率が高いものがほしい。足の修正にも使える、という発見 | 検出率 |

RefMod用には、参照画像を毎回VLMでキャプション化し、メタデータとして持たせてプロンプト作成を自動化したい、という案がある。梱包画像のどれかをVLMに渡し、アンカー部分だけ手またはAIで直す、という流れ。

Jevの自動調整は、比較の出し方が不公平（Attentionなし vs Jev調整あり）で効きはごく小さい、という批判。比較するなら調整なしAttention vs 調整ありAttention、という指摘。

高速化ライブラリ（SageAttention、Kitchen、SolAttn、Spectrum、Sparse）はMinimax H3向けに名前が並ぶが、どれがよいか分からず、設定も環境依存。**品質が落ちるので使わないのが正解**、という不採用意見がある。速度より品質を取る、という理由。

壊れたWFの修復は、エージェントに同等ノードを作らせる、Codexに直させる、簡単な改良ならチャットにWFを投げれば足りる、という使い分け。ComfyUI用途でCodex Astraは勿体なく、GPT Solで十分、ただしトークン消費のWork側誘導は拒否する、という選択理由がある。

## プロンプト・デバッグ用のLLMとエージェント

### クラウド

- **Grok / SuperGrok**: 参照画像＋公式プロンプトガイド＋動きの指定を投げてプロンプトを作る。契約理由は動画生成だったが、実際はローカル向けプロンプト作成で最も使っている。**画像読み込み付きのプロンプト作成をローカル完結にするとVRAMが足りない。コストとVRAMを考えるとGrokが最強**、という比較。
- **Gemini vs ChatGPT**: H3用プロンプト生成で、Geminiは規制の強い題材にも乗る、という比較。性能差の中身はログ上は未検証。
- **ChatGPT**: 不調の切り分け（ログとWF JSON）、システムプロンプト作成、自作ノード生成、参照処理の高速化（全体7分が全体2分）、意味不明な高速化投稿の解説依頼。プロンプト作成用に制限の緩い版がほしい、という要望。
- **Antigravity**: クラウドLLMにもエロ系プロンプトを書かせやすい。会話に書かせるより、ローカルのtxtへ書き出させる方が検閲が緩い、という手順差が選ぶ理由。
- **Deepseek**: ポーズ文からプロンプトを作らせて試した。細かいアングル指定がないと安定しない、という結果報告。
- **Claude**: 全拒否の原因は、古い世代のときに入れた「性能が上がる」カスタムプロンプトの引き継ぎ。空にしたら動いた。その後は混雑エラー。設定の持ち越しが罠、という話。
- **Codex**: 計画・実装・ノード／アプリ作成を任せられるのが選ばれる理由。消費の速さは不満。Proでも減りすぎ、という声と、ProX5でも1日で尽きる、という声が並立。デスクトップはChat Proのログをそのまま渡せる。リセット情報は開発者tiboのXとリセット監視サイト、という共有。
- **Astra / Sol / Luna**: 通常作業はSol、レビューなど重い仕事はAstra。Astraは消費が速すぎるのでSolで足りる、という不採用寄り。ウェブアプリやカスタムノード程度ならSol、PhotoshopやGTA5級のフルスクラッチ向けがAstra。Chat側のProで設計・指示を細かく出してからCodexに渡すケチケチ運用。Computer Use／リモート操作は秒速でトークンが溶ける。Blenderモデリングは10分強でクレジットを使い切る、という評価。
- **OpenClaw**: 上位プランの枠から常時稼働。1日約50万トークン・約1000回呼び出し。画像生成は暇つぶし側で、本体はシステム開発エージェント。

通常チャットの高設定は制限を気にしなくてよい、Work誘導だけ断る、という運用メモもある。最上位Proはチャットでも月制限あり。Xhighは思考が長すぎ、簡単な質問には中〜高の方が便利、という使い分け。

### ローカル（Qwenの非画像生成を含む）

画像読み込みありのプロンプト作成はVRAMを食う。24GBでも画像生成と同時起動は厳しい。このクラスのLLMは16GBでも足りない、という整理。クラウドにローカル環境の情報を出したくない、という抵抗もローカルを使う動機になっている。

- Qwen3.8 27B（heretic-ara-Q5K_L などの量子化）: 写真をシステムプロンプト経由で食わせ、画像用プロンプトを作った例。edit用シスプロの誤使用でもそれなりに出たので可、という使い方。ComfyUIの TextGenerate（8B）では性能不足なので、こちらを持ってくるべきだがVRAM容量ゲー。
- 意図の汲み取りは弱い、という比較。雑な説明から展開を読む力は Gemma 4 31B の方が段違い。ベンチでは測れない、プロンプトを考え出す力の話。ただし指示どおりだけやってほしい人には余計、という両論。
- **Gemmaが選ばれる理由は、曖昧な説明からの意図読みと速さ**。26B-A4Bを速度優先で使い、不満は少ない、という報告。
- Qwen3-VL-4B-Instructは数秒で終わるが、曖昧な指示への想像力は弱い。小さいものから試す方針。
- 以前の実用候補は `qwen3-vl-8b-abliterated-caption-it` と `qwen3-vl-8b-nsfw-caption` のQ6/Q8。プロンプト用なら超高精度は不要で、システムプロンプト次第。雑な指示は雑な返りになる。
- プロンプト生成向けに調整されたLLMも公開されている。品質が上がったかは不明。**日本語で入れられるので楽**、というのが採用理由。
- MoE＋Free TokenならVRAMなしでもいけるらしいが、実用評価はまだ不明。
- 英語が苦手なら日本語プロンプトをLLMに翻訳させればよい。言語より表現力が重要、という理由。仕様が分からなければNotebookに情報を集めさせて要約させる、という調べ物用途。

## 周辺ツール

- **IOpaint / クリスタ / RMPG**: IOpaintだと汚れやすいので、いちいちクリスタで抜いていて面倒、という不満。透過品質の比較対象。Codexで背景透過ソフトを作らせたが、既存のクリスタの方が性能が高い。**既存専用ソフトを選ぶ理由は性能**。
- **Eagle**: 生成自体は2分でも、記録だと2枚で7分。待ち時間の計測・管理に使われている。
- **自作画像ビューア**: 閉じるキー、アイコンサイズ、起動高速化。閉じる操作はショートカットよりマウスジェスチャ推奨。
- **比較用アプリの要望**: 左右に並べた画像を同時更新して見比べたい。なければ自作。
- **GPT Images型の対話制作**: 対話式でローカルイラストを作りたい、という要望。既存の一発生成WFでは足りない、という意味。
- **Live2D**: 裏側は絵を手で歪ませる泥臭い作業で、3Dを動かすのに近い労力。自動機能でもまばたき1つがうまくいかない。大きい動作は動画のシームレス再生の方が早いか、という比較。ただし動画は細部の不一致、透過編集、細かい調整不能、不自然さがあり、Live2D側に残る理由にもなっている。用途の一つは「参照画像から逸脱させずLive2D風に固定」。
- **Tripo**: イラストから直接3D化は失敗し、Tripo経由にしてから修正。トポロジーはガチャすれば綺麗でベース向きだが、そのままは使えない。**ベースの形がよい**のが採用理由。最終的にはBlenderを覚えることになった。クラウドで3D化できるが、課金していてもNSFWは3日程度しか保存されない、という言及。無料で触ったがイマイチ、という評価もある。
- **Meshy**: ビキニ程度でも違反判定になるため、NSFWが通るTripoの方がよい、という比較。
- **Blender**: AstraのComputer Use／リモート操作でモデリング。参照を渡しても弾かれなかった例はあるが、消費が激しすぎて使いにくい。連携自体は以前から可能で、Astraが特段うまいわけではなく、実用にはまだ遠い。ワークフロー案は「画像 → AstraでBlender素材化 → Opusでゲーム実装」。
- **vast（GPU貸し）**: 選ばない理由として、好きな時に計算資源を戻せない契約、貸した相手の踏み台・マルウェア散布リスク。
- **Civitai**: オールインワンWFの配布場所。アニメ→リアルLoRAが検索から消えた、というプラットフォーム側の話。
- **nano-banana**: ベンチ比較の相手として名前が出るだけで、使い方や選定理由はない。krea2＋QI2.1の組み合わせはnanobananaを超えた、という比較で、超えられた側。
- **fal**: 「falが出すまではこれ」という待ちの言及のみ。
- **MiniMax ImageStudio**: 参照部位をそのまま馴染ませられる、という理由でEdit用途。Qwen側の参照は同条件で微妙、という対比。
- **Computer Use**: 画像生成・動画生成モデルを使わず動画を作る、という話の正体。各種ツールやソフトを実際に動かして作っている。文字とアイコンが動くものはベクターで直接作っているらしい。人物が出ると崩れる。トークン減りが速く、x5では足りない。

Lora Managerは、Prompt Enhancer WFでは入れておいた方がよい、という推奨。LoRA Loaderは便利なのに浸透していない。1 LoRA＝1ノードのon/offには向かないと思っていたが、**LoRA Stacker** があるので多数切替に使える。これが使われ始めた理由。

### 周辺サービス

- **Draw Things** は Apple Silicon 向けの無料ネイティブ画像生成アプリ（Mac / iPad / iPhone）。作者側は M5 Max が M4 Max 比で箱出し約3.3倍、という測定を2026年4月に出している。ログの「M6でM4比3倍以上」と方向は合うが、今回の検索では M6 の公式比較数値は確認できなかった。Windows非対応で、Windows側の代替としてComfyUIが案内されている。 [[26]](https://releases.drawthings.ai/p/metal-quantized-attention-pulling) [[27]](https://ernie-image.app/blog/ei-092-drawthings-mobile-ernie-image-en-20260614)
- **SAM 3** は Meta が2025年11月19日に公開した、テキストと見本画像で検出・分割・追跡するモデル。2026年3月27日に動画効率を上げた SAM 3.1 がある。ログの「アニメでも検出率が高いSAM3がほしい」「足の修正にも使える」は用途の話で、アニメ特化を公式が保証しているわけではない。 [[28]](https://ai.meta.com/research/publications/sam-3-segment-anything-with-concepts/) [[29]](https://ai.meta.com/blog/segment-anything-model-3/)
- **Tripo と Meshy** はどちらも画像／テキストから3D化する商用サービス。公開比較では、Tripoは生成が速くトポロジーが軽い、Meshyはテクスチャやリギング向け、という整理が多い。ログの「NSFWが通るのはTripo、Meshyはビキニ程度でも違反、有料でもNSFWは3日程度しか残らない」は利用者報告であり、今回参照した比較記事ではコンテンツポリシーの差までは確認できなかった。 [[30]](https://blenderai.org/compare/tripo-vs-meshy) [[31]](https://www.3daistudio.com/blog/hitem3d-vs-meshy-vs-tripo-comparison)
- **ComfyUI-Lora-Manager**（willmiao）は実在し、LoRA Loaderに加え **Lora Stacker** がある。ログの「Stackerがあるので多数切替に使える」はリポジトリ構成と一致する。 [[32]](https://comfy.icu/node/Lora-Loader-LoraManager) [[33]](https://github.com/willmiao/ComfyUI-Lora-Manager/tree/main/py/nodes)
- **IOPaint** はローカルのインペイント／アウトペイントツールで、rembgによる背景除去と、アニメ向けセグメンテーションのプラグインがある。ログの「汚れやすいのでクリスタで抜いている」は品質比較の利用者判断。 [[34]](https://github.com/Sanster/IOPaint)
