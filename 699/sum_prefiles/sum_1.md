# なんJ(5ch)会話ログ レポート

対象は、ローカル画像・動画生成（主に **Qwen-Image-2.1 / QI2.1**、**MiniMax（Image Studio / H3）**、ComfyUI）を中心にしたスレ。口調はいつものなんJで、技術話と脱線・下ネタが混在する。画像本体はログに含まれず、感想と手順のテキストのみ。

## 1. 全体の空気

- 新モデル **Qwen-Image-2.1** の初速レビューが主軸。
- 比較対象は MiniMax Image Studio / H3、Krea2、Z-Image、Anima、NAI、Ideogram 4。
- 評価は「軽い・編集は使える・ただし万能ではない」。驚きは少なく、使い分け案件という空気。
- 後半はライセンス、LoRA、NAIのポイント失効、釣り投稿で話題が散る。脱線自体を「Qwenの微妙さの表れ」と自嘲する書き込みもある。

## 2. Qwen-Image-2.1 の性能・速度

| 観点 | スレ内の傾向 |
|---|---|
| 軽さ | 12GB VRAM級でもデフォルトで動く、という報告。int8で7GB台という話もあり、12GB勢の足切りは低い |
| 速度例 | 4070 / VRAM12GB / RAM16GBでデフォルト約70秒。5070 Ti 16GBで拡散とTEをbf16、編集2MPで約21秒。旧2511 bf16（約40GB）は1分超の記憶 |
| 画質の上げ方 | 公式WFのstep 25は少ないので40〜50、cfg 4程度で品質向上・ネガティブも使える、という助言 |
| 弱点 | 物体の崩れ、手前を別物体が横切ると一貫性が落ちる、t2iとしての素の性能は高くない、という評価 |
| 日本語テキスト | パチスロ筐体などの日本語表示は比較的よい、という感想（キャラ好みはKrea2） |

公式テンプレはネガティブ欄があるのに cfg 1 がデフォルトで、ネガが効かない、という指摘あり。

## 3. ComfyUI の初期ハマり（有益情報として残った点）

同一画像しか出ない原因は、**デフォルトWFでシード固定**、しかも設定変更不可に見えたこと。

対処として共有された手順:

1. Comfy同梱のデフォルト Qwen テンプレを開く
2. サブグラフを展開
3. KSampler のシードを `randomize` に変更

「サブグラフの外に出しておけ」という改善要望と、「見て簡単そうに見せて、いじるときはサブグラフ展開が楽」というUI批判がセット。有益情報を貶す空気への不満も出ている。

その他の不具合:

- AVIF保存はアルファ非対応で `ValueError`（1chグレースケールと3ch RGBのみ、PyAVのSVT-AV1はアルファ非対応）
- ComfyUI更新で MiniMax 側のノード入力追加が壊れる、タブ移動で Fast Muter がおかしくなる（フロントを 1.52.7 に下げて暫定復旧、という報告）
- 古いリアス系WFは使えないノードが多く、代替探索が面倒。エージェントや通常チャットにWFを投げて同等ノードを作らせる、という回避談

## 4. 編集能力の比較（Qwen 2.1 vs MiniMax）

合意に近い整理:

- **服装・髪型スワップ**: MiniMaxで失敗していたものが Qwen 2.1 で通った例あり。使い方次第で一長一短。
- **参照画像への厳密な当てはめ**: MiniMaxの方が強い。Qwenは「似た感じ」にとどまる。
- **ポーズ**: どちらも弱い。ポーズスワンプ成功例のプロンプト募集あり。テキストだけでは不安定で、輪郭だけでも手描き参照を渡す方が一発、という助言。
- **日本語での編集**: Flux2 Klein の方が高い、TEは同じ8Bでも差がある（無印とVLの差では、という推測）。
- **キャラシート**: Krea2より作りやすい、という報告。表情差分・三面図などのレイアウト指定が通る。裸指定もLoRAなしで通るが、性器描写は弱い、という見方。
- **透過**: 透過画像の生成能力が高く、別モデルでキャラと背景を分ける自動化に向く、という評価。
- **t2iの衣装**: 強いので Krea2 と使い分けできそう。
- **視点移動**: まだ 2511 の方が強いかも、ただし実用は MiniMax でよい、という温度感。

Qwen のプロンプトは、特別なルールというより自然言語（英語指示）。日本語入力用に調整されたプロンプト生成LLMも公開されており、楽だが品質向上は不明、という感想。

画像からセリフを自動生成する実験（Comfyの TextGenerate で i2t、TE流用）は方向性は合ったが、8Bでは不足。Qwen3 27B級のLLM連携が必要で、そうするとVRAM容量ゲー、という結論。

## 5. 他モデルの位置づけ

- **Krea2 / Z-Image**: 拘束・緊縛で縄が破綻。Qwen 2.1 のバニラでも縄の質感・本数・結び目は気になるが「ここまで出れば良い方」。積極的に乗り換える理由は薄い、という人も Ideogram 4.0 に戻っている。
- **Anima**: 二次エロの実用基準。絵師タグ・版権・タグを履修しきったFTは他になく、Qwenからの移行はまだ、という見方。Anima初期ライセンスと QI2.1 は既視感がある、という指摘。
- **MiniMax H3**: 革命的で最初は盛り上がったが、今は勢いが落ちた、という説と「どこが盛り上がったのか」という冷笑が併存。二次の r2v は絵柄が寄りすぎ、i2vの方がまだまし。X上の Wan / Seedance と比べると差はあるが、ローカルでここまで、という評価。
- **Singularity**: Xでは絶賛、スレではほぼ無反応。動きは良くなるが3次寄り・シネマティックで、2Dアニメ専用勢には無用。画風は繊細、バニラや FastH3 はコミカルでポップ、という対比。Seedance生成データで学習していそう、という感想。
- **NAI5**: 全体バランスが良く、日本語プロンプトの忠実さがローカル到達のゴール感覚、という個人評価。
- **Z-Image公式アニメ**: 学習ツールのみ配布で終わり。オープンソース可否で揉めていた時期のずれが惜しい、という回顧。

## 6. ライセンス（スレ後半の実質論点）

争点は「生成物は商用可か」「LoRA・FT・配布はどこまで可か」。

共有された公式（Qwen Developers）の趣旨:

- 出力はライセンス対象マテリアルに含まれない
- ユーザーは生成画像その他コンテンツの権利を保持する

スレ内の読み:

- 一般的OSSに近い。学習に使ったコードや技術は自由、モデル本体のクラウド等商用や派生は禁止、生成物は個人の自由、という整理。
- 生成物まで商用禁止にすると追跡不能で魔女狩りになる。NAIやPixAI的サービスのタダ乗りを禁じる文言、という解釈。
- 一方で「生成物もチューンモデルもLoRAも金のやり取りは個別ライセンスが必要」という厳しい読みもあり、**趣味の無償公開は可、寄付を募る大型二次エロFTは来ない**、という見方が優勢。
- 実写は個人趣味LoRAがライセンスを守って無償公開してくれそう、という期待。
- Ideogram 4 程度のエコシステム止まり、という悲観と、X上の有名人による緩和要望に対し公式が悪くない返事、という観測が併記。
- 編集データセットを大っぴらに公開してよい、はローカル勢にとってプラス、という受け止め。
- 企業利用なら生成物の扱いを毎回明示すべき、という苦言。

その後 **AI Toolkit が Qwen 2.1 LoRA に対応**した、という報告があり、16GB VRAMでもLoRAが作れるかもしれない点は今後大きい、とされている。

## 7. MiniMax H3 の LoRA 学習メモ

musubi-tuner での ref2va 1f 学習報告が具体的。

- 1024画像はメモリ溢れ。400×400、9組18枚、`blocks_to_swap: 35` で 4090 がギリギリ。
- `max_train_epochs` 16 で約10分。2時間コースも試行。
- 脱衣シーン学習の初期結果: LoRAの効果はあるが変化量は小さい。1f学習の弊害で動きは硬くなる一方、ブラの質感は改善気味。LoRAなしは動きは良いが参照画像の質感に引っ張られ、アクションがオーバー。
- 使い道の第一候補は結合描写の改善（動きが直線的なので質感改善だけでも効きそう）。
- 4090ですら512は厳しいなら、大多数には H3 LoRA は無理、という冷めた反応。次世代は多層LLM・多層DiTでオフロードが難しく、ライセンスだけでなく設計でエコシステム難易度が変わる、という分析（YuE2-3Bはさらに厳しい例として言及）。

高速化の話では、JevによるAttentionスパース化で RTX 4070 の動画生成が 6分7秒→3分34秒（約42%短縮）という投稿があるが、スレでは「これはどういう意味だ」と半信半疑。品質維持のまま速度2倍、というXの宣伝はほぼ嘘、という不信が強い。int8昆布級なら言ってよい、Spectrumは色以外ほぼ変わらず時間3/4でありがたい、という留保つき。

## 8. NSFW用途の温度感（成人向けの話題として）

スレの実用関心のかなりの部分は成人向け生成。レポート上は手順を再掲せず、論点だけ残す。

- モデルごとに「素で通る部位・ポーズ」と「学習データが無く悪夢生成になる視点」が分かれている。
- パイズリ等は部位トークンを強く書きすぎると全体描写に寄り、サイズ指定を外すと挟みが改善した、という経験則。
- Anima系は自然言語キャプションが弱く、従来タグと強調数値頼り、という分析。
- クラウドLLMは拒否しやすいが、エージェント経由でローカルファイルへ書き出させると緩い、という話と、参照画像（輪郭スケッチ）を渡す方がテキストより安定、という助言。
- 性器がLoRAなしで通るMiniMaxはまだ、という質問が残っている。

## 9. 脱線・ノイズ

本筋ではないが、ログの体積は大きい。

- **NAIのポイント（アナル）失効**: V5規約で残存する定期購入分が失効する日、という話。残数消費、契約日で期限は人による、長期放置分が一律削除されるのか、で動揺。
- **年齢ネタ**: 敬老の日、40歳が初老、AI歴の体感が8年、SD1.5は昨日、ChatGPT登場からまだ4年、など。
- **ポスター釣り**: 大学名を出した画像が公式ポスターかDF（なりすまし）かで荒れ、その後「見事な釣り」で沈静。論点は真偽より、実在の大学・企業名を生成物とともに公開の場に出す危うさ、公式転載と公式騙りの違い、著作権上の引用要件。特定個人・団体を話題にすべきではない、という着地。
- 反AI・誤判定・「見抜ける」正義、まとめ班が薪をくべている、というメタ言及。

## 10. スレの結論に近いもの

1. **QI2.1はレギュラー入り候補**。軽い編集モデルとして便利。驚きは少ないが、服装・髪型・透過・キャラシートでMiniMaxやKrea2と使い分けできる。
2. **最初に踏む罠はシード固定**。サブグラフ展開して randomize。
3. **ポーズと厳密参照はまだ弱い**。参照画像＋最低限のポーズ文が安定。
4. **ライセンスがエコシステムを止める**。生成物の権利はユーザー側、という公式回答で一段落。LoRA・商用FT・大型二次エロは期待薄。無償の個人LoRAと AI Toolkit 対応が次の観測点。
5. **MiniMaxは熱量が落ちた**が、参照一貫性や動画ではまだ強い領域がある。H3 LoRAは4090級でも厳しく、個人学習は限定的。
6. **二次エロの本命は依然Anima**。Qwen単体での移行はまだ、という空気。

## 11. ログの限界

- 画像・動画の実物がなく、品質評価は書き手の主観。
- レス番号が飛んでおり、参照先（>>7, >>9, >>37, >>66, >>120, >>134, >>166, >>191 など）の本文が欠落。
- 同一人物の継続報告と、冷やかし・釣りが混ざっており、速度やVRAMの数値は検証済み仕様ではない。
