## 流行の推測（冒頭まとめ）

本ログ群で最も支配的な話題は**MOSS(moss-image)**である。LoRA学習レシピ、bbox、Prompt Enhancer(PE)の検閲回避、DMD高速化、SFT/base/Kromoss/cotton mossの使い分け、ワークフローのクソデカ化まで、選定理由・設定値・派生の全段階が議論された。次に目立つのはローカルLLMの**Strata(Qwen系量子化)**で、MOSSのPE・対話型プロンプト編集・キャプション作成の下請けとして複数パートで採用実績が報告されている。画像生成では**Anima(illustrious含む旧来系)への回帰・引き篭り**がmossのプロンプト煩雑さへの反動として観測され、**Krea2**はキャラ再現と手の正確さの比較対象として、**NAI5/Noob2**は待ちの新モデルとして言及が続いた。動画系は**MiniMax H3**の実用報告が散見され、**Muse**はエロチャット・PE役・画像レビュー用途で賛否が割れた。チャッピーは「GPT-6でバカになった」「雑談が冷たい」と否定的な印象が目立ち、**Geminiは雑談対応がうまい**と再評価されていた。

## 画像生成モデル

### MOSS / Moss-Image（moss, モス）

今回とくに盛んに議論された話題は**MOSSのプロンプト追従性と検閲・絵柄コントロールの得失**である。

- **プロンプト追従性（採用理由の中心）**：正面絵で左右の手が9割9分正しい。比較としてKrea2は8割そこそこ、Animaは半分切るレベルと検証された（>>956）。
- **bbox**：「BBOXが素直で楽しい」（>>372）、「bboxがめっちゃ便利。それだけ」との評価（>>930）。一方で「最初の作成以外まともに扱えなくて殆ど使ってない」（>>572）という不使用例も併存し、「bboxだけが取り柄で低能なユーザーはAnimaとSDXLに帰った」という皮肉もあった（>>930）。
- **検閲とPE**：エロ系のprompt_enhancer使用時、TE(CLIP)にuncensoredなLLMを使うとプロンプト追従性が下がるため「Prompt Enhancer用のuncensored LoRAを噛ます必要がある」（>>483）。「TEをuncensoredなものにするか、TEにバイパスloraを噛まして無検閲化する必要がある」（>>471）。PEの出力をpreview textで見ると「その要求には応じられません」とプロンプトに追加されていることがある（>>471）。デフォルトPEは部族語が改変されてコントロール困難ですぐ切った報告もある（>>556）。「単語はそのまま通して」と書いておけばよいかという運用Tipsも提示された（>>556）。enable_prompt_enhancerは切った方が良いとの指摘もあり、初見時に2.5d/anime/princess/castleがプロンプトに入っていたせいかキャラがデ〇ズニー寄りになり、mermaidに反応してnsfwを拒否した実例が報告された（>>451）。
- **エロ用途の弱点（不採用・併用の理由）**：「エロくした途端に劣化し、手の位置を明確に指定しないと隠す傾向。anima以上に細かく指示しないといけない」（>>377）。ガチエロはアーティストスタイルを使うかLoRA自作で対応する必要がある（>>240）。「子宮脱の様なグロマンになりやすい」（>>690）、「deep penetrationが効いてくれない」（>>645）、「hymen（処女膜）の表現は理想が出ない」（>>746）。
- **絵柄**：「AI臭さの消し方がわからない」「civitaiでオカズに使えるものが見当たらない」（>>510）。「手描きのノイズ感をすべて呑み込んで平均化してしまう」ため、score_9,8,7を入れるスレ民の中で**score_6をポジに入れて手書き感を出す**という工夫が報告された（>>527, >>530）。「のっぺりした画風でゴミすぎ」との厳しい評価（>>749）に対し「画風は自分で調整しようよ」の反論（>>750）、「マスピ顔は中国韓国のゲーム寄り」の擁護（>>786）があった。「絵師タグの効きはきつく、画風を変えたいなら画風LoRAしかなさそう」（>>264）。
- **SFT / base / Kromoss / cotton moss の使い分け**：baseでは「その辺にいる女」風の絵が出るためbaseで抜く用途（>>426）、「基本sftで良いが、多様性やとがった表現が欲しい時にbaseを使う」（>>428）という運用。「SFTはbaseよりプロンプトの追従性が割と悪く、二次絵で複数人出すと画面も分割されやすい」（>>430）。「SFTよりもステルスアプデされたKromossが使いやすい」（>>604）。cotton mossはturbo LoRAをマージしているためプロンプトの効きがやや弱くなり、Prompt Weightを23程度に上げる推奨（>>954）。base用の4steps turboが無いのかという疑問も出た（>>429）。
- **LoRA学習レシピ（Tips、数値はログ表記のまま）**：素材21枚、CAME、学習率5e-05、120step、Dim32 Alpha32、timestep_sampling "truncated_logit_normal"、discrete_flow_shift 3、logit_mean -1.09、logit_std 0.95、timestep_sampling_offset使用、4090で学習2時間。プロンプトは自然言語jsonに書き直し（2日かかった）。生成プロンプトはAnimaプロンプトから流用で機能（>>346）。「int8で学習してもLoRAがint8で保存されるわけではない」（>>263）。「顔が似る段階までは早いがそこからの調整が長い」（>>921）。
- **Flow shift系（Tips）**：wikiの初期値5に対しComfyUIテンプレにModelSamplingAuraFlowが入っていない疑問（>>664）、ノード未挿入なら5と同じ意味との指摘（>>666）、解像度に応じて自動決定するWFの話、「4KでもShift値は10くらいではないか」（>>715）、「DMD 8stepだと蒸留のせいでシフト値をいくつにしても影響がなさそう」「スケジューラがsimpleになっているためツッコミどころがある」（>>671）、「Linear Quadraticにすると陰影が意図に近い」（>>672）。
- **DMD高速化とサンプラー（Tips）**：DDIMはNAI 1.5時代に常用していたサンプラーだがクセ強になっている。DMP++ 3M SDEはEulerより輪郭がクッキリしてアニメ絵に適している（>>904）。
- **サンプラー検証以外の高速化**：int8convがアンロックにより爆速になった。ただし品質変化は分からない（>>315）。
- **lighting**：調整が弱く全体的に明るすぎる。cotton mossで検証しても暗い部屋では効きにくく、ベースモデル自体の問題と推測（>>935, >>936, >>943, >>962）。「animaやリアス（illustrious）では効いていたorange lightingやpink lightingもイマイチ」（>>966）。
- **ワークフロー**：「t2i, i2t(Strata), プロンプトエンハンサー(Strata/CLIP)、LLM(Strata)対話型プロンプト編集、画像からプロンプト/MOSS-Image JSON抽出→BBox流し込み、30Step/8Step/4Step/2段Kサンプラー、LLMに指示出してBBox弄る流れ」が確立しつつあり「クソデカ化している」（>>381）。ポーズは西川ニキのポーズ集からdepth経由で流し込めば考えなくて済む（>>399-400, >>403）。和風縛りはsummaryに「She is bound with thick red intricate ropes in Japanese Shibari style」を入れbboxで補強しガチャで調整。ただし「時々pedoっぽくなるのが困る」（>>406, >>415-416）。ComfyUIのMOSS-imageワークフローではseedがランダムになる問題と対処法が議論された（>>569, >>570, >>575, >>576, >>578）。
- **その他の性質**：variation seedが使え、0.05くらいで程よく変わるため構図調整に便利（>>929）。JSON記述でキャラ定義すれば通常のキャプションでも変数参照が効く（>>731, >>760）。「版権物が出にくい以外は概ね高評価」（>>925）、「絵柄のコントロールが難儀すぎる」（>>926）。開発者が「データセットは殆ど実写系でアニメ系は一部」と発言しておりアニメ勢は待つべきとの声（>>990）に対し、「学習画像がべらぼうに多いのでアニメ系もかなり含まれている」との推測（>>991, >>992）。「5Bで地味に凄い」が「軽さはテキストエンコーダー(9B)の性能に依存しているのではないか」（>>549, >>555）。「Danbooruタグは本当の意味で部族語として扱われて雑に認識されているだけ」（>>557）。GPT imageも絵柄制御はほとんどできず、MOSSもそれに近いイメージ（>>427）。三面図はWFを付ければ一発で出た例（>>656, >>669）がある一方、まともに出ない報告（>>648）もあった。moss baseとsftの関係をanimaのbaseとマージモデルの関係に例える説明（>>418-419）に「anima base V10でショボイ画になったことはなく派生モデルすら使ったことがない」の反論（>>422）。

### MiniMax（H3 / minimaxh3 / ref2va）

- **i2vでの採用**：moss-image-sftで作った人魚画像をminimaxh3のref2va（i2v）で動かしたら違和感なく動いた。wan2.2でもさほど乖離なく動いた。「i2vは数えるほどしか試していないため人によっては意見が分かれる可能性」（>>438）。
- **動作報告**：VRAM8GB/RAM16GBでも遅いが動いた（>>4）。ベンチマーク：BF16（アンロック前）253.27秒 / INT8（通常）155.07秒 / BF16（アンロック後）126.64秒（>>127）。H3環境ではアンロックでかなり速くなるというXの報告（>>63）。アンロック検証（3090）：4分39秒→3分31秒、実消費電力24.02Wh→18.25Whで24%削減（>>815）。

## LLM・チャット系

### Strata（IQ3_S / IQ4 / Qwen3.8-Flash-Next系量子化）

- **MOSSワークフローの下請けとしての採用**：対話型プロンプト編集LLM、プロンプトエンハンサー（Strata/CLIP）、i2t、画像からプロンプト/MOSS-Image JSON抽出→BBox流し込みまで組み込まれ「ワークフロー無事クソデカ化」（>>381）。
- **採用理由（比較）**：Qwen3.5 9BのPEはお手軽だが、StrataのIQ3_Sと比べると画像に明らかに差が出るため結局Strataを使ってしまう。LLM自体はStrataの方が高速で差は数秒延びる程度（>>506）。
- **速度**：Strata v0.2.7でチャット120tok/s→210tok/sに高速化。環境はPCIEgen5x8 5090＋DDR5 256GB（>>209）。「hui入れてjson弄るとメチャクソ速くなる。制限解除モデル使用」（>>216）。4070Tiのアンロック環境でMOSSのint8convが爆速になった（>>315）。「Opus5.5だと12分」との比較あり（>>325）。
- **Qwen3.8-Flash-Next（Strata用モデル）**：vision対応がありMOSSのLoRAでキャプション作りに良さそうという見方（>>221, >>232）。LLM連携で日本語で指示し英語の自然文を出力させ、編集は絵を見て日本語で指示。プロンプトは基本触らない（>>447）。Qwen3.8との組み合わせで長編指定だけで15000字の出力があった（>>651）。
- **問題点**：モデルロードが遅くなった（前24秒→今40秒、デスクトップ版初回1分以上）（>>647）。IQ4量化版は「Claudeで10分もかからない作業を1時間以上かけて駄目だった。チャットは速いが日本語が怪しい」（>>657）。clipのINT8convrotにqwen35-9b-hauhaucs_uncensored_lora_rank4_fp32.safetensorsを適用すると相性が悪い（>>719）。「4090の寿命縮むのが怖くて使わなくなった」ユーザーも（>>657）。

根拠：>>209, >>216, >>221, >>232, >>315, >>325, >>381, >>447, >>506, >>647, >>651, >>657, >>719

## 総評

1. **MOSSは「bbox・プロンプト追従性の高さ」と「絵柄・エロ・検閲の手間」の綱引き状態**。手の正確さ9割9分・bboxの利便性・LoRA組み合わせても追従性が落ちない点で選ばれ続けている一方（>>956, >>372, >>717）、画風LoRA・PEの無検閲化・score_6投入・Shibari指定などの追加工作が前提となっており、「Animaに引き篭る」ユーザーと「Anima並クオリティは無理、技術の確信待ち」ユーザーの二極化が起きている（>>378, >>979）。アニメ版・5B版の登場が次の分岐点と見られている。

2. **Strata（Qwen系量子化）がMOSSワークフローの標準下請けに定着**。PE・キャプション・対話型プロンプト編集・bbox操作の全てに組み込まれ（>>381）、Qwen3.5 9Bより画質に差が出るとして使い続けられている（>>506）が、IQ4の日本語品質とモデルロード時間（>>657, >>647）が次の課題。

3. **旧来系（illustrious/Anima/NAI5）は「手軽さ・即効性・エロ特化」で生存**。「用途がエロなら一生リアス」「1girlならリアス、漫画や文字入りはmoss」の棲み分け（>>688, >>713）が示す通り、mossのプロンプト煩雑さ（>>377）が旧来モデルの選定理由を相対的に強めた。NAI5は部族語完対応と点指定で評価される一方、背景・小物の弱さが指摘された（>>694, >>702, >>707）。

4. **クラウド系は用途別の再編が進行**。小説は「claude一択」（>>661）、雑談はGemini、画像実務はチャッピー（ただしタッチが均一で味気ない、GPT-6で劣化との声）、museはエロチャット・PE・レビュー役で快適だがSMS認証BANリスクとAPI前提が制約。Noob2（年内10B・T2I+Edit）とQwen4世代Animaが次期モデルの関心事としてスレ全体を貫いている（>>519, >>937）。
