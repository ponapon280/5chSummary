# 生成AI関連「ツール」話題 抽出レポート

## ComfyUI (comfy)

- **UI描画のGPU消費問題**：ComfyUIの画面が簡素であるにもかかわらず、生成中にGPU使用率が10%程度上昇する現象がある。Comfy画面を最小化（非表示）して生成する場合と全画面表示で生成する場合で、生成時間が1割程度変わる。原因として、表示が変わるたびに無駄な再描画処理を行い、SSDへの無駄な書き込み（最大5MB/s程度）が発生していることが挙げられる。タスク別監視で確認可能。（957, 972, 984, 989）

- **iGPU（統合グラフィックス）への画面描画分離の利点**：マザーボードのiGPU（APU）にモニターを挿し、ブラウザやComfyUIの画面描画をiGPUに任せ、dGPU（生成用グラボ）を常にフリーな状態に保つ手法が有効。生成時のVRAM消費を抑えられ、4Kの場合はiGPUでは荷が重い可能性もあるが、超簡単でお手軽。（981, 986, 988, 993）

- **ComfyUIテンプレートへの新モデル対応**：Pika（minimaxの高速化LoRA）がComfyUIのテンプレートに既に組み込まれている。（874）

## WebUI / 生成ツール全般

- **muse（ローカル動作）**：museでローカル動かせる環境がある。画像生成もLoRA作成もmuseに任せればよいとの声。（866）
- **Grok Bot / OpenAI dot**：museと同様にLoRA作成等が可能。（867）
- **anytest**：構図のみに限定して使いたいという需要があり、bboxでも代用可能との見解。（959）

## LoRA作成・学習ツール

- **LoRA学習の計算資源**：Animaの開発者が4090×4台のローカル環境で学習を行っており、新ベースモデルの学習には時間がかかっている。VRAM12の弱小環境ではturboloraマージ等の工夫をしている。（965, 954）

## その他ツール・環境

- **Hermes Agent（API）**：API経由でエロ画像プロンプトを試したところ拒否され、スキル内部に拒否文を追加されたため、無検閲ローカルLLMに繋ぎ変えて無制限出力可能にした。（995）

- **cotton（LoRA）**：turboloraをマージしているためプロンプトの効きが弱くなる問題があり、Prompt Weightノードで強度を23に上げる対策を推奨。moss用の試作品的な位置づけ。（954, 962）

- **lightingスライダー（civitai）**：mossのlighting調整弱さに対する対策として、civitaiに転がっているlightingスライダーの利用を提案。（952）

- **variation seed（moss機能）**：0.05程度で程よく変化するため、構図は良いがなんか微妙な時の調整に便利。（929）

- **bbox（moss機能）**：キャラプロンプトに関係なくhead/upper body/lower bodyと適当に囲うだけで構図が安定して効く。（958）

- **blender**：AIからフルスクラッチしたキャラのモデリング等でblenderを使用。（918）
