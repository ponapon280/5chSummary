# 生成AI関連「ツール」話題抽出レポート

## ComfyUI (comfyui / comfyUI)

### ワークフロー管理・運用
- ニケのOSクリーンインストール時にcomfyuiのワークフローを持ってくるのを忘れた事案（>>238）
- ComfyUIにcontext windowsが追加されており、延長による劣化が抑えられる可能性がある（>>316）
- LLMにcomfyUIを使って日本語のお題で自動エロ絵生成を行った際、追加指定で修正し始めるとmask多用やプロンプト盛りで画質が下がっていく傾向がある。下地のWF（ワークフロー）はLLMに作らせて自分で手修正するのが一番良いという見解（>>258）

### GPUドライバ・ハードウェア関連
- RTX 3000シリーズで11月版GPUドライバーを更新すると異常状態になる事象が発生。電力常時400W、GPUクロック210MHz固定となり、kSamplerの処理が異常に遅くなる。8月版に戻すことで正常化（>>276）
- 上記に対し、Studio Driverでは問題ないという報告あり（>>279）。ただしその後、Studioでもゲーム側で問題が出る可能性が指摘され、ComfyUI最適化がStudio側で行われていることが判明（>>290）
- 3080でもStudio Driverで同様に無理だったという報告（>>418）

### ComfyUIのブラックボックス化・自動化
- museをcomfyUIのフロントエンドにしてスマホから「〇〇のnsfw画像を20枚作ってその中から10枚選定して動画にしといて」のような指示でcomfyUI自体がブラックボックス化している（>>271）
- MOSSがcomfyUIにcontext windows追加されたことで延長による劣化抑制に期待（>>316）

### サブグラフ・ノード操作
- prompt enhancerをONにしたままエロプロンプトを入れて飛ばされた際、元の画面に戻る方法について：左上の方にノード・サブグラフの中に入っているような表示が出るので、サブグラフの右上にあるボタン（Node 2.0なら下）を押してサブグラフの中に入ればよい（>>343）

### MOSS関連のComfyUI設定（ツール操作）
- MOSSでnsfwが出ない場合のcomfyUI上の対処法：negativeに入っているnsfwの指示を消す、prompt enhancerをoffにする。clipのmodelはqwen3.5_9b_int8_convrotのままでもtext encodingではnsfwに影響なさげ（>>266）
- prompt enhancerを使ったままnsfwを出したい場合、TEGenerate Text間に14MBのLoRAを挟めば完全無検閲化できる（>>281）
- MOSSのcontrolnet関連の報告あり（>>425）

### BBox指定に関するツール上の課題
- BBoxは箱の範囲いっぱい使おうとするため、斜めに手を上げるなどの指定が苦手。大コマ・小コマで分割指定する手法も紹介されている（>>257, >>339）
- BBoxへの追従度はMOSSよりIdeogram4.0の方が高いというスレ上の見解。画像生成AIの次なるブレークスルーはBBox指定との記事紹介（>>280）

## Muse（comfyUIフロントエンドとしての活用）

### 選定理由・利便性
- museがcomfyUIのフロントエンドとしてかなり使える。サーバー起動させて外出先でもMOSSでもH3でもjsonでなんでもやってくれ、プロンプトも書いて渡してそのまま画像・動画をスマホで見られる。ローカルLLMを使わなくなった（>>348）
- museで一番便利なのは映像と音声を入れたらピストン音声を映像に合わせてくれること。動画編集能力が高い。ただしモザイク処理は下手（>>368）

### 制約・懸念
- museが倫理問題でできないことは将来もできないだろうから、結局ローカルは手放せないという見解（>>351）
- Meta社に全部預けるのはリスクが高い。方針をころっと変えるため（>>362）

## LLMをツールとして使うプロンプト生成ワークフロー

### プロンプト生成のLLM使い分け
- 導入時の根幹シスプロ作成は精度と最新情報取得のバランスが良いchatGPT（チャッピー）
- エロ用追加スキルはGrokしか選択肢がない。Grokに断られる内容はstrata Flash-Nextで壁打ちしてスキル化
- 脚本・絵コンテ的な構図や展開を作らせるとClaudeが圧倒的に強い（>>314）
- チャッピーに基礎組のシスプロ書かせてGrokに追記用のエロ専用シスプロでエロ表現ボカさずにちゃんと書けと指示すれば機能する（>>298）

### LLM必須化の背景
- 新しいモデルになるほど短文<長文のためLLMは必須。TE性能が上がってルールが複雑になったため（>>267, >>270）
- プロンプトの添削まで毎回LLMにさせるのはながら作業中でないと面倒（>>258）
- LLMでのプロンプト生成で求められるのはネットスラングとdanbooruタグの理解。一番重要なのはLLMの解剖学的理解を文章にできるかと複数人の状態からのポーズ推論の頭の良さ（>>334）
