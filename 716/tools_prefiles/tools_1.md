# 生成AI関連ツール話題 抽出レポート

## ツールの呼び出し・連携に関する話題

### StrataとComfyUIの呼び出し関係
- **StrataからComfyUIを呼ぶ用途**: プロンプトを書かせたり修正させたりするため（183）。LLMからAPIでComfyUIを叩く方が絶対良いという意見（202）に対し、結果が同じならStrata→ComfyUIの経路の方が早いという見解（206）。ただし、ComfyUI内で行いたい作業が多いならComfyUIからでも良いという意見（207）。どちらから操作を完結させるかの違いであり、用途に応じて使い分ければ良いという見解も示されている（205）。
- **ComfyUIからStrataを呼ぶ用途**: スレ145で「comfyuiからstrata呼んでるニキらはどのカスタムノード使っとるんや？自作？」と質問があり、自作でもよさそうという回答（175）。また、StrataにはOpenAI互換APIがあり、そのAPIでStrataに接続してLLMを使役するという説明（160）。
- **両方向の活用**: AIエージェントのStrata（のQwen3.8FN）にComfyUIを使って画像生成させることも、ComfyUIからStrataに画像生成のプロンプトを渡してエンハンスさせることも両方できるという指摘（172）。

### Strata (画像ビューワーとしての活用)
- **開発言語**: Rustの開発環境を調べてビューワーの再構築を試みる動きがあり（27）、Rustは速くてモダンな言語で適しているという意見（36）。
- **特徴と課題**: 公式のはRAM食い過ぎだが「RustingStrata」で調整すれば64GBでかなり余裕になるという意見（30）。ただしメモリ48GB環境では常にカツカツとのこと（34）。画像表示部分で拡縮をできるようにしているが引っ掛かりを感じており改善を希望。LLM起動でVRAMカツカツな影響もあると推測（28）。現状50MB〜200MB位（画像拡大時）のメモリ使用量であり逼迫してはいない（44）。サムネイル表示部はWindows管理の物を使いまわせるかと思ったが管理がややこしそうで都度読み込みにしており、SSDからだから数百枚程度なら遅さは感じない（41）。
- **性能と最適化**: ビューワーなら処理の速さよりもメモリ削減の方が恩恵が大きいという意見（39）。言語自体の速度よりもアルゴリズムとデータ構造が重要であり、画像ビューアならキャッシュの使い方も大事という指摘（36）。
- **開発経緯**: 朝にビューワーの件で相談した者が、Rustの開発環境とテストアプリで動作確認できたため、Pythonで動いてるビューワーの再構築を試みる予定。アドバイスくれた人に感謝（180）。Strataに丸投げしているため細かい仕様は気にしていないが、もう少し構造周りを勉強して必要そうなら考えてみる（41）。

## LLM・コーディングツールに関する話題

### Strata (AIエージェントとしての活用)
- Strata（のQwen3.8FN）はComfyUIと双方向で連携可能（172）。Qwen3.8FN IQ3_Sはローカルで使うには絶妙なバランスの負荷と性能との評価（174）。

### Vibe Coding（バイブコーティング）全般
- **経緯と評価**: 去年試したら無能でケツ拭きばかりする羽目になり使うのを辞めたという経験談（104）。バイブコーティングとプロンプトビューアーと保存庫を作ってもらったら便利だったという声（79）。
- **課題**: 最初の一発目は良いが、修整重ねていく内にAIも自分もアホになって最後には投げ出す。システム開発の経験と問題を切り分けられる知識は必要（110）。初心者がやると規模が大きくなった時絶対いつか破綻する（77）。他人がAIで作ったプログラム引き継いでバグが出たら発狂する（96）。
- **ツール利用**: チャッピー（ChatGPT）に聞きながらComfyUIに挑戦しているが自力ではキツい（218）。チャッピーに聞いてバケモンのアカウント名で透明化するアドオンを皆使っていると思っていた（189）。
