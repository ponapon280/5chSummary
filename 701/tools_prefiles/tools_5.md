## ツール関連話題の抽出

### ComfyUI / ComfyUI関連ノード

- **ComfyUIのバージョン問題（rgthreeノード）**: frontend 1.52.7を使い続けている。1.53.6では「Fast Groups Muter/Bypasser (rgthree)」のtoggleRestrictionをalways oneまたはmax oneにしても効かず、defaultになってしまうため、切り替えて遊ぶ用途には致命的（874）。別レスでも同様にプロパティパネルで設定しても意図通り動作しないことを確認（944）。

- **comfyui-fizgig-h3-still**: minimaxH3の静止画生成用としてcomfyui-fizgig-h3-stillを導入済み。Krea2を今更入れるのが面倒だったため選択（905）。

- **comfyuiのCUDA依存**: Mac Studio（ユニファイドメモリ）はLocal LLM向けで、comfyuiはLocal LLMよりCUDA依存度が高いため、MacよりもCUDAが動く大きなPCの方が向いている。Macの方が帯域幅は大きいがcomfyui用途には不向き（966）。

### NivisViewer（画像ビューワツール）

- **機能要望と開発者の回答**: ユーザーから複数の機能要望が寄せられた（855）。開発者（NivisViewerニキ）の回答（949）：
  - **サムネイルサイズ変更ショートカット（Ctrl＋マウスホイール）**: 対応予定なし。理由は、サムネイルは一種類のサイズで取得・キャッシュしており、サイズ変更のたびにサムネキャッシュや一覧画面の再作成が必要になり、モッサリするため。「速さはすべてに優先する」方針。
  - **タグ表示の下階層フォルダ対応**: 開発者自身に不要なため対応予定なし。
  - **仮想フォルダ（アルバム機能、PureRef的なD&Dで内部リンク表示）**: 開発者に不要なため対応予定なし。ただしソース公開しているので各自でCodex等に投げて機能追加するのは可。
  - **お気に入りフォルダの色カスタム**: 便利なので実装すると回答。
  - **設計方針**: 直感的なファイル操作と快適な閲覧がウリ。PureRefを使っていないためPureRef愛用者が気に入る部分を取り入れられない懸念がある（992）。
  - 利用者は漫画ビューワとしてメイン使用中。お仕事用画像一覧は引き続きPureRefを使用（991）。

### Claude Code / Codex（AIエージェント開発ツール）

- **フォルダ読み込み禁止設定**: 読み込ませたくないフォルダを設定してcodex, claude codeを使うべき（900）。設定でファイルパスを与えて読めと指示しても読み込まないことを確認（952）。
- **エージェント権限制限の限界**: 権限が無い場所は読めないが、ユーザーの指示を達成するために迂回方法を使って読みに行こうとする可能性がある（954）。エージェントの権限制限はエージェント自身が行っているものであり、構造的にアクセスできない仕組みにはなっていない。OpenAIやAnthropicの実験でAIに突破された事例がある（958）。
- **安全な隔離方法**: Windows ProにアップグレードしてWindows SandboxかHyper-Vを使う方法（865）。Dockerコンテナはセキュリティ境界にはならないという指摘もあり（973）、物理的にネットワークから隔離されたスタンドアロン環境で動作させるのが最も厳密（961）。NTFS権限でエージェント用アカウントを作って見えなくする方法もあるが面倒でディスクを傷める（970）。
- **開発PCの分離**: 開発用AI母艦は別PCにすべき。RTX Sparkの安いやつを開発のみAI用にする提案（863）に対し、Sparkの安いやつという前提が無茶苦茶という反応（892）。Macbook Neoが開発用母艦としてコスパが良いという意見（866）に対し、メモリ8GBでは母艦は無理という反応（869, 873）。

### Irodori TTS（音声合成ツール）

- **v4.1 smallの不具合**: 「アイドルマスター」や「アイマス」と入力すると毎回違う謎単語をしゃべる現象。「アイドル」「マスター」単独では正常。Quantizedが原因かと思い元モデルでもダメ、HuggingFaceのデモページでも再現（983）。「イマス」「アイドルほにゃららター」のようになる（996）。
- **平仮名で回避**: V2時に同様の事例があり、カタカナの「ア」を平仮名の「あ」にしたら正常に読んだ。アが入ってると毎回駄目なわけではない（986）。
- **v4-Large-Quantizedで解決**: Irodori-TTS-v4-Large-Quantized/int8-weight-onlyでは「アイドルマスター」が正常に出力された。軽くておすすめ（998）。

### ElevenLabs（音声生成ツール）

- **無料枠での利用**: 無料で普通にポン出しできる（853）。無料枠でも結構作れる（870）。有料クラウドサービスだが大手（854, 856）。
- **comfyuiとの対比**: 音声系はcomfyみたいにモデル入れてポン出しとは行かないのがややこしい（851）という意見に対し、無料でポン出しできるという反応（853）。
- **性能**: 短い参照で違う口調や感情でも良い感じに作れる。喘ぎ声などの指示にも対応。英語で性的なニュアンスの指示を入れるとされる。有料のノードもあった（875）。

### 3D生成ツール（tripo / claude連携）

- 生成AIで作った三面図や4面図をclaudeとtripoに渡して3Dキャラを作る手法が流行っているが、そのままゲームにぶち込めるレベルなのか疑問（846）。

### Windows Sandbox / Hyper-V

- 開発用AI環境の隔離手段として、Windows ProにアップグレードしてWindows SandboxかHyper-Vを使うのが良い（865）。

### Docker

- エージェント隔離先としてDockerへの格納を提案する意見（970）もあるが、Dockerコンテナはセキュリティ境界にはならないとの指論もある（973）。

### ハードウェア選択に関するツール動作要件

- **RTX Spark**: WindowsかつConnectX-7なしなのでDGXより安くないとおかないとの見方。ARMのためAMD64コードはエミュレーションになる（974）。動画生成もやるならRTX Sparkの方が良いが、50～60万は廉価版の可能性（959）。CUDA動作の可否が効率に直結するためSpark選択の根拠になる（955）。
- **RTX PRO6000**: すべての要件（ローカルLLMエロチャ、画像・動画作成、irodoriTTS、3Dエロゲ、省電力）を満たせる唯一の候補だが、シリコンバレーで働いている人くらいしか買えない値段（981）。
- **5060ti / 5070tiデュアル**: 妥協案として5060tiまたは5070tiの2枚積み＋メモリ搭載を推奨（981）。動画回せるPCがない状態ならVRAM16GBデュアル＋メモリ256GBを推奨（956）。
- **Mac Studio**: ハイエンドモデルはハード要件を満たすが最適化されておらず不便（981）。ユニファイドメモリはLocal LLM向けでcomfyuiには不向き（966）。
- **レンタルGPU推奨**: 車買える値段の買い物をする前にrunpod等のレンタルGPUで試すべき（966, 981, 982）。Google AI Pro 3000円でPRO6000が20時間くらいついてくる（935）。
