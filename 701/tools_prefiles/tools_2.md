# 生成AI関連ツール話題 抽出レポート

## ComfyUI / Comfy

- **カスタムノード化とTransformers要件**: いろどりlargeをカスタムノード化した際、T5Gemma2を取り扱う関係でTransformersが5以上必須。Transformersが4の環境ではAPI通信が必要になる（264）
- **krita + ComfyUI連携**: kritaにComfyUIを連携させて漫画を描いていた人物がおり、真似して試みているがネームを切るのが難しいという（309）
- **ComfyUIのRAM節約による不具合**: ComfyUIがRAMを節約して使うようになってから、35個動画作るたびにブラウザリロードしないと生成が進まなくなる現象が発生（VRAM100% RAM60%で動かない）（366）
- **ComfyUI公式save videoノードの遅さと自作ノード**: Claudeに作らせたsave videoノードが爆速。1MP20秒の動画をComfyUI公式のsave videoノード（MiniMax-H3テンプレに入っているもの）で保存するとノード処理だけで40秒近くかかっていた。原因は色んな変換を全部CPUでやっているため。VHS（Video Combine）にはNVENCで変換する項目があるがごくわずかしか速くならない（処理の一部しかGPUに渡していない）。全部の変換作業をGPUで処理する保存ノードをClaudeに作らせたら38秒かかっていた変換保存処理が6秒になった（390）
- **VRAM節約系カスタムノード**: 16GB勢がVRAM削りに削って1MP15秒まで滞らないようにした。VRAM節約系カスタムノードを使い、モニタ出力を別の駄グラボに任せて対処。1.1MPはダメ（388）
- **ComfyUI解説本**: スレで名前が出るComfyUI解説本を勧める人はいない。そのお金でエージェントを使うかプランを上げるのが正しいという返答がスレにある（349）
- **IrodoriをComfyUIで初使用**: IrodoriをComfyUIでやってみて「めちゃくちゃ楽しい」との感想。TextやVoiceDesignだとほぼアニメ声しか出ないがCharacter Voiceで実写を使うと普通の人の声になる。気に入った声を参照用に保存したいが適切な長さやセリフの指定が分からない（426）

## Blender MCP

- **Blender MCPで3Dモデル処理**: ゲームからリッピングしたモデルを頂点計算しながら裸に剥く作業をOpus5.5とBlender MCPでサクサク安く処理。以前はAstraでトークンを焚べながらComputer Useさせていたが、Opus5.5はComputer Useは効率悪いと自分から断ってきた（286）
- **MCP推奨・Computer Use非推奨**: Computer Useはダメ、MCPから動かすべき（344）。これによりPC操作ずっと取られずに済むようになった（420）
- **部屋の3Dモデル作成**: Codexに3Dモデル作らせる際、部屋みたいなのをワンショットで作らせるのはリファレンス画像渡してComputer Useを使っても微妙。オブジェクトごとに作り直させるターンが発生する（339）
- **部屋の工業系モデル作成**: 部屋みたいな工業系ならchatでpythonを書かせてBlenderで実行させるのも手（340）

## irodori-TTS

- **irodoriTTS用ツール作成**: Grokに頼んでirodoriTTSで出力したwavファイルにもろもろのメタデータを仕込めるようにしてもらい、さらにそれを閲覧できるツールまで一瞬で作ってもらった（251）
- **irodori-tts largeの課題**: irodori-tts large用の学習用yamlがなかった（320）。運用利点が見つけられず、ポテンシャルが引き出されていない。VRAM12GBの環境では厳しい可能性（330）。作者もサイズが大きくなった割に性能が微妙そうと話している（385）

## NivisViewer（自作ビューワーツール）

- **NivisViewerの更新**: 自作ビューワNivisViewerを更新。webpも快適に開けてファイラ機能も兼ね備えた快適ビューワに育った。タグを表示文字列と埋め込む文字列で分けて管理しやすくした（368）
- **DropboxのDL挙動問題**: オンラインのDropboxファイルを検出するとDLし始める挙動が問題。左サイドバーのフォルダツリーからの処理が抜けていた。現在はオンラインのみのファイルを検出したら読み込みを避け、「同期アプリでダウンロードしてから更新してください」と案内する方式に統一している（369, 389）
- **ユーザーからの要望対応**: ダークテーマはWindowsでダークテーマ選んでいれば自動対応。サムネイル上の星（レート）表示は設定→Browser→サムネイル上の情報→レートを表示するを切って消せる。更新確認ボタンやgithubページへのボタンの追加要望あり（415, 419, 423, 429）

## Krea2

- **Krea2のEdit-Outfit-Transfer**: minimaxやクラウドサービスみたく参照画像を上げて操作する系の生成で、Krea2だとEdit-Outfit-Transferが公式WFだけで簡単に出来た。animaのやつはややこしいのしかない模様（361）
- **5060Ti環境での推奨**: core ultra7 265k/32gb/rtx5060ti 16GBの環境に対し、AnimaかKrea2が最強、編集はQwen2.1EDITという回答（401, 402）

## その他ツール関連

- **Translategemma 4Bをノード翻訳に使用**: ノードでの翻訳にTranslategemma 4Bを使ってみて「なかなかええ」との評価。Google翻訳は検閲拒否がないしAPI経由のログインなしでBANリスクもないが、Gemma4はダイレクトでエグい文章を作ってくるためオンラインに上げるのは気が引ける（353）
- **nodes/sampler.pyの修正**: ComfyUIのノード処理でプロンプト更新が原因で動かない問題について、nodes/sampler.py の `if self.has_prompt_changed(text):` を消し飛ばしたら動くようになった（337）
- **FastH3のWF設定**: YouTubeのVeteranAIのFastH3のWF内にあるモデル周りのノード3つの設定をそのまま移植すると高速化。1stepあたり60秒から40～50秒に減少。Step下げるよりこちらが効いている（384）
- **minimax h3 ref2va 1f学習**: jsonl方式で学習。学習素材16組32枚、画像の大きさ400、RTX4090でブロックスワップ38、epoch100で学習時間3.5時間ほど。通常メモリは96のうち半分を使用（334）

## ツール選定理由

- **Blender MCPが選ばれる理由**: Computer Useと比較してPC操作を取られずに済むため（420）。Opus5.5自身がComputer Useは効率悪いと判断してMCPを推奨してきたため（286, 344）
- **Krea2が選ばれる理由**: 公式WFだけでEdit-Outfit-Transferが簡単に出来るため。animaの同等機能がややこしいのしかないのに対してシンプル（361）
- **irodoriTTSをComfyUIで選ぶ理由**: TextやVoiceDesignだとほぼアニメ声しか出ないがCharacter Voiceで実写を使うと普通の人の声になるため（426）
- **自作save videoノードが選ばれる理由**: 公式ノードがCPUで全変換処理を行い40秒かかるのに対し、自作ノードはGPUで全処理を行い6秒で完了するため（390）
