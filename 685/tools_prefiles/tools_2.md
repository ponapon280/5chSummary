**抽出されたツール関連話題（モデル関連は除外）**

- **runpod（クラウドGPUレンタル）**  
  ローカルGPUでは満足できないor将来的に家庭用GPU文化が廃れる可能性を考慮して利用。  
  **選ばれる理由**: 新しいことを試したいが飽きっぽい性格のため買い切りより柔軟に使える、複数コンテナ連携は厳しいが手軽に高スペックを試せる、半年〜1年後の価格高騰リスクを考慮しても今は現実的。

- **ComfyUI（comfy） / ComfyUIワークフロー**  
  - comfyui31へのバージョンアップ後の挙動（2回目以降の生成がモデルロードからやり直しになり遅くなる）。  
  - dynamic VRAMの影響やVersion31特有の遅延問題。  
  - Context Loopフローにアップスケーラーを追加（VAEDecode後など）。  
  - Patch Sol-Attn (MiniMax) などのノード追加による高速化（PR取り込みで15秒長尺が爆速化）。  
  **選ばれる理由**: ノードの繋ぎやカスタム拡張が柔軟で、特定機能（Sol-Attn、キャッシュ系除外など）を組み合わせやすい。

- **Context Loop / Contex Loop**  
  モーションコンテキストやキャラクターシート参照を使った動画生成ワークフロー。  
  - 最終フレーム切り替え仕様（Picture 1/2から継続指定）。  
  - Grokを使った専用プロンプター（画像→ストーリー→JSON出力）。  
  - 難易度が高いが、具体的な構成を考えられる人なら使える。  
  **選ばれる理由**: 入力がなくてもmotion contextを扱える、AIにガイドやサンプルを見せてプロンプト生成を補助してもらえる、長いシーケンスや参照画像の扱いが強い。

- **MiniMax H3 / H3 Extender関連ツール**  
  - H3出力＋イラストRef＋フォトリアルRefの組み合わせ（画風統一・服移植など）。  
  - H3 Anima Tokenizer（danbooruタグだけでアニメ生成）。  
  - face detailerやノイズ除去関連の拡張。  
  **選ばれる理由**: 参照画像の画風混在を制御しやすい、プロンプトでsubject_definitionsを細かく指定できる、リアルとイラストの橋渡しがしやすい。

- **Grok（プロンプト支援ツールとして）**  
  Context Loop専用プロンプターとして使用（画像を渡してJSON生成）。  
  **選ばれる理由**: システムプロンプトが公開されており流用しやすい、ストーリーからJSONまで自動化できる。

- **その他ワークフロー関連**  
  - ビデオコンテ（尺を体感できるツール）。  
  - noise inversion + 2倍アプスケなどの後処理フロー。  
  - kitchen + sol + FirstBlockCacheなどの組み合わせによる速度改善テスト。

モデル名（Anima, H3自体がモデル扱いになる場合など）は一切抽出していません。Qwenシリーズの言及はありませんでした。
