# 元の本文
今回とくに盛んに議論された話題は、ローカルLLMエージェントとComfyUIの連携、およびStrataを巡るハードウェア要件と運用手法である。

※以下のレス番号は統合元パート内の通し番号であり、元スレの通し番号とは限らない。

# ComfyUI

**インストール・環境管理**
EasyWan22の使用は推奨されていない。長期間メンテナンスされておらず、現在はインストールに失敗する（>>5）。ComfyUIのインストール方法は多数存在するためテンプレで案内がある（>>5, >>7）。Comfy Desktop版はスナップショット機能でアップデート前にロールバックできるため、Portable版より推奨される。ただし自作の未登録ノードは戻せない（>>436）。Pull時にコンフリクト解消でDiscardを選ぶと、追跡対象外ファイルも巻き添えで消え自作スクリプトが消し飛んだ体験談がある（>>437）。

**テンプレートとワークフロー自作**
P-H3-Image系のテンプレートには0.95MPへ参照画像をリサイズするノードが入っておりデフォルトはbypassされている。一方MiniMax-H3-Imageのテンプレートでは4MPリサイズがデフォルト有効であり、テンプレの違いは実際に試した結果を反映したものとされる（>>163）。H3-Imageは16MP/6ステップ推奨で、生成時は16MPで出し保存前に4MP以下に縮小するのがセオリー（>>205, >>207）。comfy公式テンプレートからupsamplerとenhancerを取り除き自分流に組み替える事例がある（>>50）。テンプレートを壊して別ノードで組み替えただけの場合は新発見として報告すべきでないとの注意がある（>>53）。

**エージェント・LLMとの連携**
Qwen3.8FNにエージェントとComfyUIの連携を相談したところ、人間がComfyUIから直接操作し、必要な時だけJSONを送り返す方式が提案された（>>160）。ComfyUIはMCPに対応しているため、ローカルLLMからJSONでやり取りするだけでエロプロンプト自動実行が可能になる（>>569）。Museに2分の曲と素材を与え、MiniMax h3 Context Loopのワークフローを食わせてMV用にノード追加・結線変更させ、26シーン分のプロンプトとJSONを出力させた事例がある（>>890）。ローカルLLMを使ってComfyUIに組み込むワークフローを自動構築させる用途で、GitHub forkして改変しComfyUIに組む作業を自動化できる（>>852）。Strata上のQwen3.8FNはComfyUIのバグ修正やカスタムノード作成が実戦投入レベルで可能（>>978）。StrataとComfyUIを同一PCで共存させる場合、`--vram-reserve-mib`設定でVRAMを指定容量空けてRAMに逃がすことで対応可能（>>984, >>990, >>992）。座標指定などはComfyUIのノードで配置できるため、LLMにプロンプトを書かせる意味はあまりないという意見がある（>>155）。

**挙動・不具合**
アップデートによりUI周辺モジュールの不整合でエラーが出たりworkflowが読めなくなる事象がある（>>427, >>430）。animaをComfyUIでインペイント試したところ顔がかなり変わってしまう報告がある（>>546）。

# Strata

**選ばれている理由**
ローカル側リソースを使わずに動かせる点が便利（>>844）。CodexやClaude等のクラウドLLMでは健全なアプリを作らせていても検閲的に断られることがあるが、Strataではそれがなくトークン残量を気にせず無限に使える（>>994）。仕事用データを扱わせられる点が最大のメリット（>>996）。Qwen3.8FNの量子化モデル（IQ3_S等）を使えばコーディング、アプリ作成、ComfyUIバグ修正が可能（>>978）。

**性能・挙動**
省メモリ設定では6tok/sで使い物にならなかったが、メモリを限界まで使う設定にしたら58tok/sで10倍の速さになった（>>972）。仕組み上あちこちにデータ移動が発生するためDRAM帯域やPCIe帯域が重要（>>931, >>935）。メモリに負荷がかかり強制再起動が何度も発生した報告があり、Strataを使わなくしたら起きなくなったため見えないところで無茶をしている可能性が指摘されている（>>933）。一方RAM192GB環境では再起動は一度も起きていない（>>952）。IQ3_Sを使った後はIQ3_XXSでは性能満足できなかったとの報告がある（>>980, >>981）。Clineを使用したコーディング報告がある（>>981）。

**ハードウェア要件**
5060ti + RAM96GB環境でSATAドライブに入れているため読み込み待ちが発生（>>982）。RAM128GBについて「生成中に触れるかどうか」が快適さの差であり、生成中触らないなら64GBや32GBでも十分（>>927, >>928）。PCIe帯域について5000番台上位では最低5x8(4x16)が欲しい（>>935）。CPU交換で秒間トークン数に11.5割程度の差が計測された（>>919）。

**モデル選択運用**
UnslothのIQ4XSから試したが貧弱環境では顕著に遅くなったためIQ3_Sに落ち着いた（>>991）。画像解析してプロンプト出力ならQwen3.8、エロ小説やエロチャならGemma4、動画のエロシナリオをGemma4で作ってQwen3.8に渡してプロンプト出力させる連携が推奨されている（>>999）。llmfan46のGemma4を使用している報告がある（>>988）。

**スレ上の評価**
「ゴミレベル」「動くことを誇張しすぎており使い物にならない」との評価がある（>>819, >>822, >>826）。5090/128GB環境でも人体構造を正確に把握できておらず頻繁に止まるとの報告がある（>>825）。極度な量子化が劣化を伴うことを作者が目立つ場所に書くべきとの指摘がある（>>828）。Strata単体ではvisionがないためharnessと併用が必要（>>830）。Strataの問題はStrata自体ではなくQwen側に責があるべきとの見方がある（>>827）。

# MCP・エージェント連携

**MCPの仕組みと運用**
MCPは「これやって」「おかのした」をJSONだけでやり取りできる機能。ComfyUIも対応しているためローカル非検閲LLMでエロプロンプト自動実行が可能（>>569）。エージェントにワークフローを送ると希望の設定・プロンプト書き込み・JSON返却をしてくれる。エラーを吐いてもログを見せると対策してくれるがケアレスミスはする（>>542）。ローカルエージェントに雑命令で30枚生成をセットしておけば風呂に入っている間におかずが完成する（>>584）。ただし雑命令をそのままプロンプトに入れても絶対無理（>>571, >>584）。エージェントに頼む時シスプロを一緒に送っているためそれが邪魔になる可能性があり、Gemma4 UncenをCLIで試した時はエロ文が出せるのにエージェント経由だと怒られた事例がある（>>572）。

**他ツールとの連携**
StrataやProject MayaにDeepSeek HernesやHermesを繋いで「こういう感じのエロ画像作っといて」で寝るだけの運用が可能（>>567）。LM StudioはMCP連携機能ぐらいだと思っていたができることが急に増えた（>>568）。

# Muse（エージェント・ツールとしての利用）

**利便性**
エージェント入門としては手柄で良い。ただしLLMとしては賢いとは言えない（>>64）。自然言語でざっくり「いい感じに」指示するだけでお任せできる（>>126）。10月中に契約した者にとっては神ツール（>>782）。無料で使えてエロもいける点が最強とされる（>>690）。意思トークンをほぼ使わない（>>678）。ローカルLLMと比較して生成・評価・改善サイクルが早い（>>831）。museが面白すぎて5090や増設RAMもお休み中になるレベル（>>532）。museに漫画作成を依頼するとanimaでそれっぽいものが作成可能。手動でちょい修正すれば使えるレベル（>>526）。irodoriテストを実施しフリー合成音声を使用、セリフや射鳴のタイミングも自動判任で生成（>>444）。

**検閲挙動**
NSFWについてロリや未成年には厳しいが成人女性ならほぼガバガバ。ただし「全身ふさふさの犬獣人の女の子」「戦争に敗れた国の奴隷女性」「義理の母」はセーフ（>>876, >>884）。ComfyUIで生成を依頼しても「見た目が幼すぎるため作れない」と断られるが、中の人が成人であることを説明すると生成してくれる（>>726, >>728）。サービス期間が終われば死ぬからそれまでの我慢という見方がある（>>966）。

**運用上の注意**
GCP上のVMにMCPサーバを作らせ自PCの隔離WSL VMにGeminiアプリを繋ぐ構成でエージェントっぽいことができるが、MCPサーバの構築論・管理保守論は個人ではほとんど体系化されていないため超絶注意が必要（>>753）。museだけあれば十分系の人は逆にmuseを使わなくてもよくねという見方がある（>>843）。

# Fizgig

作成済みLoRAからブロックごとの影響を調べる機能があり、絵柄を抜く用途に使える（>>390）。絵柄まで学習させたくない場合にstudio機能で何とかならないかという言及がある（>>228）。LRを激しく上下させるリスタート多めの設定がうまくいく体感あり。タイムステップサンプリングがランダムにノイズを乗せる学習方法のためslideは形をフラット寄りに変形させているだけと考えられる（>>459, >>479）。ある程度エポックが進んだらシフト値をエポック毎に上げ下げするオプションが追加された（>>476）。時間かかりすぎるためデフォルト値は参考にするが基本信用していない（>>484）。スケジューラは基本constantを使うべき。DiTモデルはタイムステップサンプリング導入済みのためconstantでもいい気もする（>>473）。

プロンプトで編集（衣装・背景・髪型変更）やカメラアングル変更が可能。ローカル提供はないがアングル変更の精度はいい。元画像の手足が見切れていると破綻する（>>545, >>547）。ローカルがないなら意味ないという否定的意見もある（>>549）。

# クラウドLLM・エージェントツール

**Codex**: Museにcodex操作をさせてエロ系タスクを依頼したところcodexがタスクを断ったためダミーデータを送ってやらせようとした事例がある（>>845）。エージェントはトークン消費が多くタダで使わせる道理はない（>>872）。
**Cline**: Strataでのコーディング時に使用している報告がある（>>981）。
**opencode**: opencodeのDeepSeekとNovelAIの連携を使えば制限はほとんどないとの情報がある（>>900）。
**runpod / Vast.ai**: GPU暴落の流れが見える間は、runpodやVast.aiでVRAMマシマシGPUを借りてクソデカモデルとDeepSeek Flashを同時に動かすのが推奨されている（>>866）。
**GrokBot**: NSFW対応とのツイートが流れてきた。動画のエロも解禁されつつあるらしい（>>446, >>450, >>460）。キャプション作成に使用中だがGrok 4.7は日本語のやり取りがお値段の割にひどくGemma 4の方がマシだった（>>446, >>447）。性行為や性器をはっきり描くプロンプトは作れず水着やセクシー表現にとどまる（>>463）。GrokのImagineがサ終するという噂あり（>>464）。
**Dynamic Prompts**: お気に入り画像を食わせたらよさげな画像が出るシステムはないかという問いに対し、Dynamic Promptsでワイルドカード複数組む遊びは実施済み（>>531）。
**OpenClaw**: museにやらせる際のガードレール設定用として触っていたが自信がないという報告あり（>>538）。
**DeepSeek**: 5090/128GB環境ならDeepSeekでいいのではないかという提案がある（>>829）。
**filemany**: サイズ違いの同じ画像を重複とみなして弾きたい場合に役立つが、サイズが変わるとバイナリハッシュ比較で引っかからない課題がある（>>763, >>765, >>767）。
**Stability Matrix**: 単なるランチャーとして認識されている（>>443）。バージョン以外の更新方法を選んでおけば即時更新可能。直接gitを叩くような手段（>>441, >>442）。OS再インスト後もすぐ復帰でき、本環境アプデ前に別環境で試験できるためそのままでもいいという意見（>>438）。

# LLMによるプロンプト自動生成・tagger

H3やMOSSの学習を引き出すワードを出してくれるツールがいくつか出ているがどれもポンコツであり、結局は参照機能でイメージを伝える方が早い（>>136）。画像を参照させて出てくる自然言語をうまく言語化できないプロンプトを返してくれるLLMがなく、taggerの役割でも不十分との指摘がある（>>136）。

# その他ツール

**Qwen3.8FN**: argonちゃんに慣れると他のLLMでは満足できなくなるとの感想がある（>>236）。GeForceで遊べるローカルの中では最高性能とされる（>>833）。DeepLで翻訳するかQwen3.5を使えば多少日本語が通る（>>835）。
**Qwen（AIコーディング）**: 昔ならアプデ待ちレベルの小さな対応でもAIを使えばすぐにコード改修できた。lbwのfork版から本家anima対応版への移行時にパラメータ28個/29個で動くよう手を加えた事例（>>440）。チャッピー（ChatGPT）への相談で怪しいビットを潰して安定化させた話題がある（>>977）。
**bbox**: 漫画作りに捗るがフキダシの形状が安定しない。フキダシや文字入れはクリスタでやればいいという意見もあり、DTP的な能力が求められるためAIに任せたいという要望がある（>>724, >>752, >>754, >>758）。
**SnapRef / irodori**: ゼロショットは事後学習に含まれるのかどうかをSnapRefやirodoriを使って考えたとの言及がある（>>729）。
**Nichijou-tts**: 新しく出た音声ツール。MireiやTakaneの復活を希望する声あり（>>446）。

# 総評

1. Strata上のQwen3.8FN（IQ3_S等）によるComfyUIワークフロー自動構築・バグ修正・カスタムノード作成が実戦投入レベルで機能しており、ローカルLLMエージェント連携の主軸となっている。
2. MCP対応によりローカルLLMからComfyUIへJSONでプロンプト自動実行させる手法が確立されており、雑命令で30枚生成をセットすれば放置で完結する運用が実現している。
3. Strataはメモリ負荷による強制再起動リスクやハードウェア帯域依存が高く、RAM容量・PCIe帯域・量子化モデル選択が快適性を左右する。
4. LLMによるプロンプト自動生成ツールやtaggerはポンコツが多く、結局は参照機能でイメージを伝える方が早いとの評価が定着している。
